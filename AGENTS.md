# Правила проекта DoK-port

- Приоритет: восстановление «Подземелий Кремля» по PKR/PKE и прежде всего
  полноценный GBA-порт. Windows/Linux служат для инструментов и проверок;
  SDL2-порт и PortMaster — последующие цели, не условие начала GBA-разработки.
- Работа по отдельным задачам и чатам: `docs/gba-plan.md`, `docs/handoff.md`,
  паспорта в `docs/tasks/`. Перед задачей читать актуальную передачу контекста;
  после задачи обновлять её и статус в плане. Не считать предыдущий чат доступным.
- Существенные выводы, структуры, форматы, различия версий, ограничения
  и решения фиксировать в Markdown в `docs/`. Указывать образец, адресную
  систему, доказательства; явно отделять гипотезы от проверенных фактов.
- Компиляторы устанавливать и использовать из общего каталога инструментов
  пользователя. Не добавлять отдельную копию toolchain в каждый проект.
  Текущая общая установка Zig и настройки VS Code описаны в `docs/building.md`.
- Оригиналы в `originals/` не изменять. `originals/`, `mqa/`, `build/`
  и полный экспорт `decompiled/` не включать в Git и поставку порта.
- Анализ исходных EXE выполнять в Ghidra. Проверять SHA-256 образцов до
  и после анализа. Сохранять проекты, журналы и воспроизводимые скрипты.
- Различать файловое смещение, индекс NE-сегмента, адрес Ghidra и
  runtime-селектор DPMI. Адреса вставок WASDify не считать входами оригинала.
- Полезные материалы прежнего исследования находятся в `C:/Source/wasdify`;
  их происхождение и найденные ограничения описаны в `docs/wasdify-findings.md`.
- Автоматический C-псевдокод хранить отдельно от редактируемых модулей движка.
  Не объявлять его собираемым C/C++ или проверенным эквивалентом оригинала.
- Для каждого перенесённого модуля проверять типы, far/huge pointers,
  calling convention и значимые ASM-эффекты по листингу. Обоснованные
  исправления ошибок оригинала документировать отдельно от восстановления.
