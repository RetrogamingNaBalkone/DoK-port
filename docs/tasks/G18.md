## Анализ

## Реализация

Соединить подсистемы в замкнутый цикл игры на трёх уровнях, добавить начальные/финальные экраны. Сброс уровня должен освобождать события, актёров и платформенные потоки.

## Критерии готовности

Можно начать, умереть/повторить, перейти между всеми уровнями и завершить игру. Проверены RUS/ENG и отсутствие старых событий/снарядов после перехода. Переходы можно воспроизводить тестовыми сценариями без ручного прохождения каждый раз.

Проверки выбирать по реальным рискам задачи. Сравнение C/Python полезно, но само
по себе не доказывает совпадение с работающей DOS-игрой. Если тест или запуск
не выполнен, указать это явно и не отмечать соответствующий критерий готовым.

## Результат

26 октября 2026 года: **задача выполнена; реализация, независимые проверки и review завершены**.
Подробности и доказательства: [game-flow.md](../game-flow.md),
`analysis/g18-review.json`.

Восстановлен фактический цикл PKR/PKE: выбор LEVEL1–3 → BINTRO → игра →
EINTRO → выбор уровня. В оригинальном startup нет автоматической кампании
и переноса инвентаря между независимо созданными мирами. При повторе того же
мира сохраняются inventory/maps/visited/actors/events/projectiles, восстанавливается
исходный native pose subset и HP=max. Lives уменьшаются `DEC word` с wrap16,
Game Over закрывает мир. HP<0 обрабатывается как исходный finish sentinel.
ENDTXT относится к выходу из главного меню, а не к придуманному четвёртому этапу.
Continue возобновляет приостановленную сессию; New Game полностью заменяет её.

Проверка сомнения об очках: исходные EXE содержат ветвь score==world total,
но во всех шести исходных LEVEL отсутствуют class3/category99 предметы и total=0.
Штатные выходы требуют входа в FCMap B2, **собирать очки не требуется**.
Вывод основан на PKR/PKE, не на сравнении с «Старым Золотом».

Артефакты: `src/flow.c`, `include/dok/flow.h`, `gba/flow_backend.c`,
production consumer в renderer/movement/UI, stop/reset подсистем и platform streams;
`tests/test_flow.c`, host/native/independent ARM verifiers, read-only Ghidra driver,
`scripts/build-gba-flow.ps1`, aggregate `scripts/report_flow.py`.
Оригинальные тексты читаются непосредственно из существующего ROM без дублирования.

Frozen `build/g18/dok-diagnostic.gba`: **32881620 bytes**,
SHA-256 `46e4bfa412dd1abb6b729d4a9ed014802e99430b1dbc47ffb70d2de077eeb3c0`.
ELF/map/build-report находятся рядом. До32MiB осталось672812 bytes.
EWRAM248688/free13456, IWRAM20684/free3892 до8KiB stack reserve.
Наблюдённый main stack2360/margin5576, IRQ80/margin80.
Renderer4735872…5234880 cycles;30FPS не достигнуты, детализация сохранена.

Проверено:

- Windows flow/UI host fixtures и Linux static/ARM7TDMI Thumb compile.
- Свежий read-only Ghidra RU/EN; SHA обоих EXE до/после совпали.
  Original x86:16 equality,14 death и2 far-helper/CX30 vectors;
  sound/HUD/runtime copy отмечены как внешние hooks.
- Независимый аудит всех шести исходных LEVEL и выходов2/2/4 на язык.
- Независимый ARM: реальные клавиши, все6 уровней и все14 RU/EN BINTRO/EINTRO/ENDTXT
  с точными source FONT8 pixels на всех страницах; смерть/повтор/три жизни/Game Over;
  Continue и новая игра; сброс keys/map/visited; исходный отрицательный HP sentinel.
- Настоящие door/AI/visual owners, снаряд и loop PCM сохраняются при retry и
  suspended Continue; FINISH/END/new world удаляют их и UI queue без старых событий.
- Root визуально проверил8 точных PNG-представителей RU/EN экранов;
  полный набор исходных страниц дополнительно проверен побитно автоматически.
