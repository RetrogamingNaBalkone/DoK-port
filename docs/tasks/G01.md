# G01: Диагностический GBA-ROM и общие инструменты

## Контекст нового чата

Рабочий корень: `C:\Source\DoK-port`. Сначала прочитать `AGENTS.md`,
`docs/gba-plan.md`, `docs/handoff.md`. Главная цель — GBA; SDL2 не является
зависимостью. Этот паспорт не предполагает доступности предыдущей переписки.

**Зависимости:** Нет. Проверить их фактические результаты в плане и файлах.
Выполнять только границы этой задачи; соседние задачи — отдельные чаты.

## Входные материалы

- `docs/building.md`
- `docs/handoff.md`
- `scripts/build-native.ps1`
- `.vscode/`
- `официальные источники инструментов из docs/gba-plan.md`

Читать указанные материалы выборочно по задаче. Сначала проверить уже имеющиеся
результаты, затем исследовать пробелы; полный decompiled-экспорт в чат не загружать.

## Анализ

Проверить уже установленные GBA-инструменты и эмуляторы. Выбрать рабочий путь получения полноценного ROM: startup, linker layout, заголовок, IRQ/VBlank. Общий Zig умеет компилировать ARM objects, но это ещё не готовый ROM. Установки выполнять в общий каталог пользователя, не копировать SDK в проект.

## Реализация

Собрать минимальный .gba без игровых данных: видимый диагностический экран, чтение кнопок, счётчик кадров. Добавить воспроизводимую команду сборки, linker map и способ запуска/отладки. Настроить сбой/диагностику настолько, чтобы следующие задачи могли видеть зависания.

## Критерии готовности

Чистая сборка даёт ELF, .gba и map. ROM реально запускается в GBA-эмуляторе; кнопки меняют экранный индикатор, кадры идут. Указать версии инструментов и пути. Запуск на физической GBA отмечать отдельно, не требовать его наличия для платформенного прототипа.

Проверки выбирать по реальным рискам задачи. Сравнение C/Python полезно, но само
по себе не доказывает совпадение с работающей DOS-игрой. Если тест или запуск
не выполнен, указать это явно и не отмечать соответствующий критерий готовым.

## Ожидаемые артефакты

gba/ с платформенным каркасом; команда/скрипт сборки; docs/gba-platform.md; build/gba/ с ROM, ELF, map и логом запуска.

Это планируемые пути, не утверждение об их существовании. Имена можно уточнить
при реализации с обновлением паспорта и передачи контекста.

## Передача результата

Существенные выводы — в тематический Markdown. Для анализа EXE указать образец,
адресацию, инструкции/доказательства и неизвестные части; сверить SHA оригиналов
до/после. Для GBA сохранить ELF/ROM/map и фактические измерения, когда применимо.
Обновить этот паспорт, строку G01 в `docs/gba-plan.md` и `docs/handoff.md`.
Передать точные команды, изменённые пути, результаты, ограничения и следующий ID.

## Результат

**Готово, 24 октября 2026 года.** Реализация: `gba/startup.S`, `gba/gba.ld`,
`gba/main.c`, `scripts/build-gba.ps1`, `scripts/gba_rom.py`,
`scripts/verify_gba.py`, `scripts/run-gba.ps1`, задачи VS Code.
Описание устройства и ограничений — `docs/gba-platform.md`.

Команда: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba.ps1 -Verify`.
Результаты в `build/gba/`: ELF, ROM, настоящий LLD map, build-report.json,
run-log.json, PNG кадров. ROM — 2560 байт, статические data/bss — 40 байт EWRAM.
Чистая сборка в `build/gba-clean/` дала тот же ROM SHA-256.

Использован имеющийся общий Zig 0.13.0 (LLD 18.1.6). Установлен общий mGBA
0.10.5; автоматический запуск выполнен в отдельном общем ядре mGBA
`0.11-212-7a12d6d` через Libretro. Источники/хэши — `analysis/gba-tools.json`.
Отклонение: devkitARM не понадобился. Для надёжного Thumb выбран явный
`thumb-freestanding-eabi`; исправлены и соответствующие native cross checks.

`analysis/g01-verification.json`: десять кнопок и их экранные индикаторы,
комбинация A+B+R+L, 120 IRQ за 120 аппаратных кадров, 40 обновлений экрана,
panic по START+SELECT, reset после заполнения выделенной EWRAM байтом `0xA5`.
Кадры просмотрены. Шесть native-тестов и Linux/Thumb compile checks
проверены отдельной командой `scripts/build-native.ps1 -CrossChecks`.

Физическая GBA, оригинальный BIOS и интерактивная GDB/GUI-сессия не проверены.
Диагностика не содержит ресурсов игры и не подтверждает поведение DOS-движка.
Следующий ID по рекомендованному порядку — G00; G02 доступна по зависимости.
