# Хранение исследовательских материалов вне build

Дата: 27 октября 2026 года. Статус: выполнено.

## Цель и граница

По запросу пользователя перенести проекты Ghidra и сохраняемые результаты
исследований из `build/`. После уточнения пользователь прямо запросил
удалить всё, что незачем хранить: полное сохранение экспериментальных сборок
отменено. Не менять оригиналы и игровые статусы. Это обслуживание общего
хранилища, не реализация SP01.

## Размещение

- `research/ghidra/` — проекты, предыдущие проходы и настройки Ghidra.
- `research/evidence/` — экспорты, векторы, наблюдения DOS, исследования ресурсов.
- `research/experiments/` — текстовые снимки исходников и отчёты G20A/G20C,
  один контрольный комплект 2775; остальные сборочные выходы удаляются.
- `build/` — текущие сборки, кэш и используемые ими пакеты/базовые объекты.
- `analysis/` и `docs/` — существующие сводки и описания под контролем Git.
- `decompiled/` — существующие полные экспорты; их не переносим повторно.

Полные локальные материалы `research/` исключаются из Git и поставки.
Хранить каждый экспериментальный ROM/ELF и каждый generated bank не требуется.
После очистки старые `.incbin` в снимках и пути в отчётах могут указывать на
удалённые банки и сборки. Повторный эксперимент требует генерации данных и
нового запуска, старый отчёт не подтверждает результат новой сборки.

## Приёмка

1. Сохранить соответствие путей и SHA-256 каждого переносимого файла.
2. Перенести только проверенные пути внутри проекта, без перехода по ссылкам.
3. Обновить действующие скрипты и документацию; новые запуски не должны
   возвращать эти материалы в `build/`.
4. Не переписывать исторические JSON-манифесты, журналы и снимки исходников.
   Старые пути в них разрешаются по таблице переноса; хеши относятся к
   исходному запуску. Изменение пути в драйвере меняет его хеш: старый отчёт
   не становится подтверждением нового запуска.
5. Проверить SHA-256 после переноса и неизменность оригиналов, ROM пользователя
   и оставленных входов сборки; выполнить доступные проверки новых путей.

## Исполнение уточнённого запроса

План удаления и пофайловые хеши: `research/_migration/prune-generated-files.json`;
сводка: `analysis/storage-cleanup-20261027.json`.
Драйвер `scripts/prune-generated-storage.ps1` проверяет абсолютные пути,
reparse points и размеры, удаляет только перечисленные обычные файлы внутри
проекта, затем сверяет SHA-256 сохраняемых файлов. Рекурсивного удаления нет.

Сохранить: UI01 с её ELF/map и текущими QA-материалами, контроль 2775,
frozen G18 как pixel oracle; исходники опытов и текстовые отчёты;
Ghidra и исходные доказательства; все сохранения пользователя;
базовые объекты `select-menu-fix`, `level1-fixes`, `g20`, общий
`build/gba/assets` и host-инструменты `build/gba/host`.

Удалить: остальные ROM из artifacts; прочие экспериментальные ROM/ELF/map,
объекты и generated banks; старые GBA test PNG/WAV/IDX; Zig cache и downloads.
Оригинальные наблюдения DOS в `build/gba/g20b/dos-{ru,en}` сохранить без повторных
копий оригинальных игр. Старые JSON-отчёты не переписывать.

Адресная система не меняется. Новый анализ EXE этой задачей не выполняется.

## Результат

### Уточнение: подробные отчёты вне Git

По отдельному согласованию пользователя 42 крупных исторических JSON
(15 076 353 B) исключаются из Git; полные файлы сохраняются локально по
прежним путям, без изменения байтов. Существующие producers/consumers не
требуют перенаправления. В `analysis/summaries/` сохранены компактные итоги
(444 818 B) с SHA-256 и JSON Pointer к опущенным выборкам. Классификация —
`analysis/report-policy.json`; команды публикации и проверки —
`tools/reports/summarize_reports.py` и тот же скрипт с `--check`.

Каталоги, структуры, параметры и различия оригиналов, в том числе большие
inventory/balance/animation/level tables, не сокращались. Актуальные UI01
итоги также сохранены. После клонирования полный локальный прогон требуется
получить отдельно; сводка не является машинным oracle. История Git не
переписывается. Игровые статусы не меняются.

Снятие 41 ранее отслеживаемого файла с учёта выполнено через `git rm --cached`
с точным списком (42-й отчёт ещё не был добавлен в индекс); локальные файлы
остались. Проверены все 42 исключения, отсутствие этих файлов в индексе,
соответствие SHA-256 сводок полным JSON и сохранение 14 крупных наборов
уникальных данных в индексе. Сводки проверены `--check`. После разделения
analysis занимает для Git около 4,6 МиБ, всё дерево — около 8,6 МиБ.
Новые файлы не добавлялись в индекс; коммит не создавался. Удаления из индекса
подготовлены, сводки и политика видны как новые файлы для следующего коммита.

### Предыдущая очистка сборок

Удалено 42 702 файла, 20 524 069 116 байт (19,11 ГиБ), затем 2423 пустых
каталога. SHA-256 всех 25 656 сохраняемых файлов совпали с инвентаризацией
до очистки. Оригиналы, сохранения, Ghidra, исходные доказательства и выбранные
сборочные входы не изменены. Старый перенос целых архивов заменён выборочным
хранением; его прерванная полная проверка не заявляется выполненной.

Осталось непосредственно после очистки: build 679 549 971 B,
research 731 659 453 B, artifacts 32 158 381 B. Проверки добавили только
небольшой отчёт `build/storage-check/ui01-latency.json`.

Проверены синтаксис 157 Python и 45 PowerShell скриптов, исключения Git.
Текущая UI01 в mGBA: 16 фазовых случаев A/Start прошли, boot 10 кадров,
наибольшая задержка UI 5 кадров. Полная игровая регрессия не выполнялась:
код игры очисткой не менялся. Старые collectors с удалёнными выходами требуют
новой сборки; автоматической подмены хешей нет.

Подходящие для Git файлы рабочего дерева на момент проверки: 23 648 412 B
(22,55 МиБ), включая новые файлы; из них analysis 19 461 361 B. Это размер
содержимого, не сетевой размер будущего push. Сжатые объекты существующей
истории Git — 6,07 МиБ. Проверено `git ls-files --cached --others
--exclude-standard`, `git count-objects -vH` и `git check-ignore`.
