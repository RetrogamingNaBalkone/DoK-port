# G20A: определение усечений для бюджета GBA

## Контекст нового чата

Рабочий корень: `C:\Source\DoK-port`. Прочитать `AGENTS.md`,
`docs/gba-plan.md`, `docs/handoff.md`, `docs/gba-performance.md`.
Не предполагать доступность предыдущей переписки.

**Основание:** прямое уточнение пользователя 26 октября 2026 года:
G20 оптимизирует без заметных на целевом разрешении усечений;
при невозможности уложиться в бюджет G20A определяет усечения.
**Зависимость:** проверенный профиль и ROM G20. G20 пока открыта по 30 FPS;
это подзадача для дальнейшего решения бюджета, а не обход критерия готовности.

## Входные материалы

- `docs/gba-performance.md`, `analysis/gba-final-budget.json`;
- frozen `build/g20/dok-diagnostic.{gba,elf,map}` и его SHA;
- `analysis/g20-cameras.json`, `analysis/g20-game-profile.json`;
- диагностические normal/all-awake/capacity сцены и G18 pixel oracle;
- прежние пользовательские границы: 120 колонок сцены приняты, UI240,
  общие карты/баланс, цель 30 FPS и сохранение игровых правил.

## Анализ и результат

Сопоставить дальнейшие алгоритмические возможности с вариантами усечений.
Для каждого варианта дать **измеренный** выигрыш полной игры, разницу кадров
на родных 240×160 и влияние на движение/анимации, память и звук. Показать
лучшие, типичные и тяжёлые виды всех уровней; не оценивать только screenshot
в увеличении или пустую сцену. В G20 лучший непустой стартовый обзор превышает
бюджет в 2,45 раза, худший — в 5,70 раза; малый локальный выигрыш недостаточен.

Оформить сравнимые варианты с конкретной ценой качества и предложить выбор.
Не подменять графические сокращения изменением AI, количеством снарядов,
ограничением врагов, dropping ticks или сменой правил. All-awake CPU overload
оценивать отдельно: снижение raster cost его не устраняет.

## Граница реализации

Разрешены отдельные экспериментальные сборки/переключатели для сравнения.
Базовый G20 и исходный G18 oracle сохранить. Эта задача **определяет** усечения;
не закреплять различимые сокращения как release default без явного выбора
пользователя. Предъявить проверяемые варианты до такого выбора.

## Критерии готовности

- Есть таблица замеров, изображения родного размера и описание потерь каждого
  варианта; оценки отделены от измеренных фактов.
- Есть конкретное решение о допустимом качестве и дальнейшей реализации,
  а не недоказанное обещание 30 FPS.
- Нет скрытого изменения cadence/правил и переполнений в сравниваемых сценах.
- Статус G20/G21 отражает фактический остаток бюджета. G20 не закрывается
  только по факту выбора варианта без проверки его полной реализации.

Ожидаемые артефакты: `docs/gba-quality-options.md`, сравнительный JSON в
`analysis/`, приватные ROM/PNG в `build/g20a/`. Это планируемые пути.
