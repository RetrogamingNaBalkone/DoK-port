## Реализация

## Критерии готовности

Закрытая дверь блокирует, открытая пропускает, нужный ключ проверяется по правилам оригинала. Повторная активация и связанные glyph не ломают состояние. Подтверждены используемые триггеры всех трёх уровней; неизвестные ветви перечислены.

Проверки выбирать по реальным рискам задачи. Сравнение C/Python полезно, но само
по себе не доказывает совпадение с работающей DOS-игрой. Если тест или запуск
не выполнен, указать это явно и не отмечать соответствующий критерий готовым.

## Результат

**Готово, 25 октября 2026 года.** `include/dok/interactions.h`,
`src/interactions.c` подключены к общему LEVEL1-ROM и Start/Use. Door events,
keys/locks, фазы/crop, pass flags, occupancy и повторный glyph проверены.
Class6 наследует базовый no-op Use; class13 маршрутизирует enter event0x800
к дверям `h`/`k` LEVEL2/3, обходя замок. Class12 conveyor соединён с коллизиями,
условие завершения передано G18 через FINISH; предметы/выдача ключей — G12.

Полная спецификация/ABI/адреса и явное отличие времени —
[doors-triggers.md](../doors-triggers.md). Native FPS-зависимые фазы заменены
контрольным профилем30 и независимой сеткой333,333,334 native ticks;
герой/зоны сохраняют416 ticks. Неподтверждённые поля и ветви перечислены там.

Ghidra RUS/ENG, SHA до/после совпали. На язык6000 Door/base-векторов,
622 sensor routes и120 crop-векторов Unicorn; это не полный DOS-session.
Инвентарь всех трёх исходных уровней обеих версий сохранён. Host:
108 door definitions,30 class6,20 sensor-клеток,2006 class12-клеток.
13 Windows suites прошли, Linux static/Thumb compile прошли.

ключ, два направления crop, проход/occupancy/закрытие, повторный вход sensor,
conveyor четырёх направлений, FINISH, сохранение активной двери при языке,
guards/reset. 12 динамических кадров и1455 камер, HUD/палитра,443520 strips,
linked payloads и время прошли. Linux execution, CMake/MSVC, физическая GBA,
оригинальный BIOS и новый полный DOS-session не выполнялись.
