# Частичные структуры игрового состояния

Этап 2, 23 октября 2026 года. Ниже восстановлены конкретные поля исходных
PKR/PKE; полного объявления классов и переносимой игровой логики пока нет.
Схемы WASDify сверены с новой декомпиляцией конструкторов, фабрики,
обработчика событий, выбора оружия и изменения характеристик.

## Far-pointer и очередь событий

Far-pointer занимает 4 байта: смещение `uint16` и селектор `uint16`.
Селектор защищённого режима нельзя переводить в адрес формулой `segment*16`.
Новый `dok_far16` сохраняет только эти два числа и никогда не разыменовывается.
Для чтения реального процесса нужен отдельный адаптер дескрипторов DPMI/LDT;
он в этот модуль не входит.

Заголовок владельца событий занимает 16 байт:

| Смещение | Поле |
|---|---|
| `+0` | Число активных событий, uint16 |
| `+2` | Ёмкость, uint16 |
| `+4` | Far-pointer массива событий |
| `+8` | Far-pointer следующего владельца в кольце |
| `+12` | Far-pointer предыдущего владельца |

Событие занимает 16 байт: deadline `uint32` по `+0`, interval `uint32` по `+4`,
far-callback по `+8`, parameter `uint32` по `+12`.
Доказательства: инициализация RUS `1038:0000` / ENG `1010:13AA`,
планирование RUS `1038:0108` / ENG `1010:14BE`, ранее исследованный адаптер
`wasdify/kremlin_save_events.py`. Игра использует ёмкость 4, но условие
добавления `count < capacity-1` оставляет максимум три активных события.
Это нужно сохранить или осознанно изменить при переносе очереди.

## Игрок

Конструкторы RUS `1068:1657` и ENG `1020:1B61` выделяют **222 байта (`0xDE`)**.
Они обнуляют 18 слов от `+0xAA` — это девять 4-байтовых указателей оружия,
а не только три указателя по числу клавиш выбора. Допустимый набор индексов
для каждой игровой команды предстоит восстановить отдельно.

| Смещение | Тип | Смысл |
|---|---|---|
| `+0x10` | uint16 | Смещение таблицы виртуальных методов, не host-pointer |
| `+0x12` | uint16 | Native type; у героя 1 |
| `+0x26/+0x2A/+0x2E` | int32 × 3 | X/Y/Z |
| `+0x32` | int16 | Направление в градусах |
| `+0x5E/+0x60` | int16 × 2 | Жизнь / заряд |
| `+0x62/+0x64` | int16 × 2 | Их максимумы |
| `+0x72` | uint16 | Биты ключей |
| `+0xAA` | far16 × 9 | Таблица оружия |
| `+0xCE/+0xD0` | int16 × 2 | Текущий / ожидаемый слот |
| `+0xD6/+0xD8` | int16 × 2 | Жизни-попытки / счёт |

Значения и знаковость сверены с методами характеристик и движения,
конструкторами, `player_select_weapon`, а также полевой схемой WASDify.
Конструктор задаёт три попытки, нулевые слоты и нулевой счёт.
Остальные байты содержат дополнительные поля, таймеры, ссылки и базовые
подобъекты. Они не объявлены «padding» и не должны отбрасываться при
последующем переносе полной логики.

Новые `dok_player_state` и `dok_native_event` — обычные структуры результата
чтения. Их размер и расположение полей зависят от host ABI; они **не являются
дисковым форматом** и не накладываются на память игры через cast или packing.
Читалка извлекает LE-значения по подтверждённым смещениям, проверяет длину
и требует native type 1 для игрока.
Она не нормализует угол, не лечит отрицательную жизнь, не разрешает указатели
и не исполняет callback.

## Граница между оригиналом и новым движком

Селекторы, vtable-адреса и callback-адреса нужны для анализа оригинала.
В будущей модели движка их заменят обычные ссылки либо логические ID;
формат сохранения не должен сериализовать память native-класса целиком.
Сейчас реализован только безопасный адаптер чтения. Полный мир, AI,
владение ресурсами, таблицы виртуальных методов и очередь с поведением
оригинала остаются следующим этапом.

В Ghidra созданы типы `/DoK/Native16/Far16Token`, `ResEntry30`,
`ResourceManagerPartial12`, `IndexedImage18`, `Event16`, `EventOwner16`,
`PlayerPartial222`. Неизвестные области оставлены неопределёнными.
Типы не применялись автоматически к сомнительным параметрам функций:
исходные сигнатуры Ghidra ещё требуют ручной проверки.

## Проверки

G06 восстановил исполнение очереди и время: [time-events.md](time-events.md).
Переносимый scheduler сохраняет исходные особенности обхода и отдельно
документирует исправления опасных lifecycle-сценариев. Частичная native-читалка
по-прежнему не исполняет DOS far callbacks.

`tests/test_native_state.c` проверяет отрицательные значения, крайние
int16/int32, порядок байтов, девятый указатель оружия, обе половины far-pointer,
границы входного буфера, отклонение другого класса и сохранение результата при отказе.
Проверена Windows-сборка и исполнение; выполнена кросс-компиляция адаптера
для Linux x86_64 и ARM7TDMI Thumb. Исполнения на Linux/GBA и восстановления
живого процесса этим адаптером пока не было.
