# GBA: итог оптимизационного goal и оставшиеся расходы

Актуализация бэклога27 октября после завершения этого исследования:
пользователь поставил [G20C](tasks/G20C.md) (native sparse-run опыт без потерь)
перед [UI G20B](tasks/G20B.md), а [Performance G22](tasks/G22.md) — после UI
и [плейтестинга G21](tasks/G21.md). Это новые отдельные задачи;
границы и результаты завершённого исследования ниже не меняются.

**Дополнение после G20C:** [native sparse-post trial](gba-sparse-posts-trial.md)
выполнен и отклонён: full CPU heavy5+9,67–28,32%, spatial880 медианы+1,03–5,64%,
живые120-frame маршруты медленнее. Картинка в парной выборке exact;
контроль2775 сохранён. Следующий этап — G20B. Ниже offline статус относится
к моменту завершения G20A; native результат хранится отдельно в
`analysis/g20c-sparse-posts.json`.

27 октября 2026 года. **Текущий goal завершён на анализе и handoff по прямому
уточнению пользователя. Performance-сборка не реализована.** Численные цели
не достигнуты на всей проверенной выборке: это завершение исследования в
согласованной границе, а не приёмка бюджета G20 или релиза G21.

## Выбранная архитектура и сборка

Основной путь — аппаратные базовые пол/потолок и CPU foreground,120×128
с растяжением в240×144, интерфейс240×160. Сохранены пониженные потолки,
исходные карты, динамика, visibility leases, AI и игровые правила.
Готовые масштабы выключены (`NO_SCALES`); работают static geometry cache,
prelit16/column-major материалы, отсечение coverage/backface и rectangle path.
Аппаратные материалы базовых плоскостей32×32 с тремя полосами LIGHT0/7/15
уже являются принятым для сравнения упрощением, CPU LIGHT16 сохранён.

ROM: [DoK-port_hardware_cached_prototype.gba](../artifacts/gba/DoK-port_hardware_cached_prototype.gba),
15 938 936 байт, SHA-256
`2775bdd0caaac64b4fd99e4c6d675587fad2da9c795468dc52efacb5d53edaab`.
Последняя сборка из текущих исходников: `research/experiments/g20a-final-costs/hw_v128_entity_rect/`;
она побайтно воспроизводит этот ROM. Исходный игровой ROM и отдельные96/72
артефакты сохранены; нового release default не назначено.

EWRAM261292/free852; IWRAM24408/free168 до отдельного резерва стеков8192.
Наблюдаемые main stack2528/margin5408, IRQ80/margin80. Память ограничивает
добавление новых рабочих буферов; наблюдаемый стек не доказывает все пути игры.

## Достигнутая скорость

Native-clock mGBA,16 777 216 cycles/s, WAITCNT4317, без overclock,
replacement BIOS, PCM22050Hz. Core SHA-256
`5cac11c643d7f8dfa50c68855f2f2240ff7cc0b4cd0312dd9e17a639c85667e4`.
FPS ниже — предъявления, не обратная величина только CPU-стадии.

|Сценарий|LEVEL1|LEVEL2|LEVEL3|
|---|---:|---:|---:|
|Поворот/огонь120, RU/EN|19,85|16,86|21,79|
|Ходьба/поворот/огонь120, RU|17,96|17,92|20,54|
|Ходьба/поворот/огонь120, EN|18,10|17,92|20,54|
|Минимум spatial440, frozen world/PCM|9,95|9,95|14,93|
|Последний короткий live24 контроль, RU/EN|19,37|19,11|27,57|

Разная длина/маршрут тестов не позволяют подменять120-frame строки более
удачными24-frame результатами. Spatial440 — распределённые доступные клетки,
а не минимум каждого возможного состояния игры. Универсальные15+,24,1 по
внутреннему тикеру и30 не подтверждены. Сохранение simulation debt не означает
достаточной скорости симуляции. Artificial all-awake fixture всё ещё перегружает
CPU (около0,07–0,38FPS); это отдельный игровой предел, не обычный коридор.

Последние production heavy замеры из `research/experiments/g20a-sector-shear-v4/control-target.json`:

|World/cell/heading|CPU cycles, медиана|FPS|
|---|---:|---:|
|L1/520/225|1 457 472|9,95|

Для масштаба, непрерывный CPU-бюджет15/24,1/30 составляет примерно

Это необходимый масштаб изменения, не прогноз FPS: VBlank, звук, живая логика
и внутренний тикер оцениваются отдельно.

## Почему выбран этот путь

Плановые крупные сравнения закрыты. Отрицательные результаты относятся к
конкретным реализациям и их scope; они не доказывают аппаратный предел GBA.
Общий реестр — [выбор архитектуры](gba-architecture-selection.md).

|Проверенный вариант|Результат против2775|Решение|
|---|---|---|
|Streaming segment BSP/quad|Spatial440:0 быстрее,424 медленнее,16 равны; median CPU+51/+57/+36%|Не выбран|
|Полный DDA/depth-owner по строкам|Heavy5 CPU3,55–4,31×|Не выбран; это не Doom clip/visplane|
|Настоящий sector BSP/clip histories/shared roof spans, HW base|Heavy5 CPU1,37–1,87×|Не выбран|
|Тот же sector clip с прямым Mode4 bitmap|Heavy5 CPU1,86–2,35×; возврат базовых planes наCPU дорог|Не выбран|
|Прямой world OBJ с CPU coverage|Heavy5 CPU1,49–4,41×|Не выбран|
|Sector-fed GPU, диагональные полосы|Heavy5 CPU2,06–3,12× после admission failure/fallback|Не выбран|
|Sector-fed GPU, широкие affine PC shear fragments|Heavy5 CPU2,10–2,38× после fallback; actual PPU loss в4 pressure views|Не выбран|
|Exact-camera image cache|При движении только1–6 повторов из120, при стоянии120|Не выбран как главная архитектура; native cache FPS не измерен|

Последний [shear trial](gba-sector-shear-trial.md) квалифицирован на58 native
позах,6 active-GPU Mode4 cycles,18 weapon fixtures;46 поз используют OBJ,
8 — ненулевой PC. В5 тяжёлых видах production возвращается наCPU после
подготовки GPU. Диагностический обход admission показал реальную потерю
732/8/222/1368 PPU pixels в4 видах; пятый не прошёл fit bound. Это не FPS
полной GPU-сцены. Изменённый силуэт не принят как minor. Full GPU static
renderer не реализован; иное представление команд было бы новым исследованием.

Сравнение с PrBoom имеет конкретный ответ: автор GBADoom сообщает около35FPS
в простых и10FPS в сложных местах, использует mipmapping и убирает distance
lighting. Это не парный benchmark наших сцен. Сложность геймплея сама по себе
не определяет стоимость видимых интервалов/плоскостей/масок. Мы проверили BSP,
sector spans, bitmap и OBJ альтернативы; на наших тяжёлых сценах они не
обошли выбранный гибрид. Источники и ограничения сравнения находятся в
[архитектурном разборе](gba-architecture-selection.md).

## Что сейчас дорого

Новый профиль128 из `analysis/g20a-final-costs.json` уточняет распределение:

|Вид|Маскированные грани, M cycles|Непрозрачные грани|Горизонтальные поверхности|
|---|---:|---:|---:|
|L1/520|0,251|0,195|0,533|
|L1/3640|0,110|0,165|0,645|
|L2/1592|0,507|0,177|0,290|
|L2/2871|0,507|0,204|0,319|
|L3/1544|0,273|0,245|0|

Это отдельный **инструментированный held профиль без forced PCM**. Класс грани
включает setup, clipping, coverage и sampling, а не только alpha-проверку.
Draw orchestration вынесен вROM ради места для instrumentation; таймеры имеют
накладные расходы. Таблицу нельзя складывать с production CPU выше или
использовать для обещания выигрыша от удаления одного вида операций.
В L1 основной остаток — программные пониженные потолки; вL2 — masked грани;
вL3 потолков в выбранном виде вообще нет. Единого дорогого sampler для всех
миров нет. Живой профиль2775 L2 также оставляет около25% CPU на подготовку
геометрии и около7% на игровую логику; это другой workload.

Ограниченная проверка source posts выполнена как **offline feasibility audit**:
исходные post-LIGHT колонки точно восстанавливаются из nonzero runs. Среди
96 518 колонок банков16 LIGHT:152 пустых,38 024 сплошных,58 342 смешанных;
2 629 621 нулевых texels из10 949 206. Прямой auxiliary формат с offsets,
uint16 count и uint16 begin/end требует1 081 206B с дедупликацией одинаковых
колонок. Это реализуемо поROM, но **не native sparse-post renderer/FPS trial**.
Доля нулей в банке не равна доле экранного времени. Coverage, minification,
квантование границ и возврат статистики требуют работы и для run формата.
Пропуск нулевых runs допустим только по контракту masked image; ноль
непрозрачной текстуры выводится как black alias, его нельзя превращать вдыру.
Уже проверенные zero-span bitmap и empty-column пути общего выигрыша не дали.
Полный sparse-run sampler оставлен как неизмеренная kernel-гипотеза;
он не объявлен невозможным или доказанно проигравшим. Новую реализацию в
текущий goal не расширяем. Мелкий opaque batch дал лишь доли процента медианы
spatial440/96, минимумы не изменил; продолжать перебор kernels без нового
бюджетного основания не требуется для данного handoff.

Прежняя оценка «ещё10–25% без заметных изменений» была гипотезой до крупных
отрицательных опытов. Сейчас нет измеренного общего резерва такого размера.
Остаток без потерь возможен, но обещать24,1 или30 после локальной доводки
оснований нет. Даже теоретическое ускорение одной маскированной стадии не
решает тяжёлый потолочный L1, и наоборот.

## Возможные сокращения для будущего Performance

Это анализ следующего этапа. **Ни один новый Performance-профиль здесь не создан.**

|Вариант|Что известно о выигрыше|Цена картинки и обязательная проверка|
|---|---|---|
|96 строк CPU-слоя|Уже измерено10–12% CPU; spatial minima11,95/11,95/19,91|Потолки сохранены, UI детальный; проверить native motion/выбрать качество.15+ всё ещё не везде|
|72 строки|Уже измерено18–21% CPU; minima13,78/11,95/19,91|Заметно грубее, сохранён только как сравнение|
|Сокращение draw distance в почти чёрной зоне|FPS не измерен; базовые HW planes уже cap3600|LIGHT15 начинается3720, RGB5 max3/2/2. Может быть незаметно на240×160, но не все texels нулевые. Парные native кадры и движение; отдельно считать близкую/дальнюю стоимость|
|Грубее sampling/LOD пониженного потолка|Единичные HW потолочные виды дали−21/−31% CPU, обычные live маршруты ухудшились|Геометрию/низкую высоту можно сохранить; размывание/полосы/стыки и выбор режима требуют новой общей проверки|
|Упрощённые дальние объекты/материалы|Для CPU основного пути общий выигрыш не доказан; GPU mip варианты проиграли|Мелкие детали, popping и alpha silhouette. Mip сам по себе не уменьшает число выходных pixels|
|Меньше CPU LIGHT rows|Уже проверено, достойного общего выигрыша не получено|Полосы/скачки света; не первый приоритет при prelit16|
|Процедурный пол/потолок|Старый опыт медленнее; HW base уже дешёвый|Меняется характер материала без доказанного выигрыша. Отложено|

Подробный [dark-distance audit](gba-dark-distance.md) учитывает допустимость
незаметных тёмных различий на маленьком экране. AI wake radius0xBA — только
первичная Chebyshev-активация, активные враги продолжают работу; бой может
обойти radius. Поэтому «draw distance меньше → AI radius меньше» не является
автоматически эквивалентным балансом. Для графического опыта сохранить AI и
leases; изменениеAI возможно только отдельным явно согласованным опытом.

## Проверки, ограничения и передача

Выбранный2775 ранее прошёл396+440 парных PPU кадров, ARM sampler/rectangle
векторы,48 cache mutation cases и suites sprites/water/UI/flow/AI/combat/items/
interactions в описанном в [стоимости кадра](gba-render-costs.md) scope.
Последняя чистая сборка ещё раз byte exact. У проигравших вариантов проверки
уже и не переносятся на полноценный релиз. Новые native профили не меняют
игровой renderer. Оригиналы в этом проходе не читались для ASM-анализа и не
изменялись; данные — package SHA3efa5d…4351, адреса — offsets package/world
coordinates, не адреса EXE.

Остаются реальные ограничения: physical GBA/original BIOS не проверены;
294 Pause/Resume oracle выявляет промежуточные кадры и у2775 (старые282
transitions этого не покрывали); artificial all-awake overload не решён;
универсальный15+ не получен. Нельзя объявлять G20 budget илиG21 release готовыми.

Следующему исполнителю: начинать с этого документа и
`analysis/g20a-final-handoff.json`, выбрать отдельную разрешённую задачу.
Если запрос будет наPerformance, сначала измерять screen-area/cost тёмной
дальности с сохранёнными leases/AI и сравнить с готовым96-row кандидатом;
не возобновлять все проигравшие архитектуры и не считать этот список
разрешением строить новую сборку без задачи. G20A завершена как сравнение/
анализ/передача текущего goal; G20 остаётся открытой по бюджету, G20B/G21 ожидают.
