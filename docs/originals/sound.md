# Звуковые ресурсы: PCM, заголовок и экспорт

G16: действующий одноголосный GBA FIFO/DMA backend, native play/stop/loop/identity,
actual mGBA WAV и пользовательское прослушивание описаны в [gba-audio.md](../gba/gba-audio.md).
Ниже сохранён форматный этап4; его историческое отсутствие GBA-вывода не относится к G16.

Этап 4. Разобраны все 23 звуковых блока каждой исходной версии.
Это 36-байтовый заголовок с сигнатурой SVM и несжатые 8-битные сэмплы.
Каждая версия содержит 961526 сэмплов; все 23 пары RUS/ENG совпадают
побайтово, включая заголовки. Общих догадок по одной сигнатуре теперь
недостаточно: ниже зафиксированы проверенный профиль и его границы.

## Формат блока

Все многобайтные числа записаны little-endian, включая невыравненный word
версии по `+5`. Сэмплы начинаются с `+36`; для всех исходных блоков
выполняется `resource_size == 36 + sample_count`, без дополнительных данных.

| Смещение | Размер | Подтверждённое значение или роль |
|---|---:|---|
| `+0` | 2 | Сохранённое native-значение; в образцах `0x04FD`, не magic формата |
| `+2` | 3 | ASCII `SVM` |
| `+5` | 2 | Версия, 1 |
| `+7` | 1 | Исходные флаги, `0x09` |
| `+8` | 2 | Число бит сэмпла, 8 |
| `+10` | 2 | Дополнительное поле формата, 0; другие значения не разобраны |
| `+12` | 2 | Параметр C, 255; значение по смыслу пока не установлено |
| `+14` | 2 | Параметр D, 128; значение по смыслу пока не установлено |
| `+16` | 4 | Номинальная частота сэмплов |
| `+20` | 4 | Число байтов сэмплов |
| `+24` | 4 | Runtime far-pointer данных; в исходных ресурсах ноль |
| `+28` | 4 | Неустановленное поле; ноль в исходных ресурсах |
| `+32` | 4 | Неустановленное поле; ноль в исходных ресурсах |

22 коротких блока имеют частоту 22050 Гц. Блок №110 содержит 474361 сэмпл
при 11025 Гц, около 43,026 секунды. Назначение C/D не объявляется
громкостью или панорамой без дополнительного доказательства.

Первое слово заголовка важно не перепутать с идентификатором формата.
Конструктор задаёт vtable `0x04F2` в RUS и `0x0502` в ENG, тогда как в
обоих наборах файлов лежит `0x04FD`. Метод привязки копирует поля начиная
с `+2`, сохраняя собственный vtable объекта. Метод записи в поток также
формирует native-значение отдельно. Новый декодер игнорирует первые два
байта; формат определяет по SVM и проверенному набору полей.

## Доказательства в Ghidra

| Функция | RUS, адрес Ghidra | ENG, адрес Ghidra |
|---|---|---|
| Инициализация объекта звука | `1108:0000` | `1060:153A` |
| Привязка блока из RES | `1108:00EC` | `1060:1632` |
| Чтение заголовка и сэмплов из потока | `10E8:007C` | `1058:1254` |
| Однократный запуск | `1108:01F7` | `1060:173D` |
| Запуск с повтором | `1108:0232` | `1060:1778` |
| Остановка | `1108:026D` | `1060:17B3` |
| Проверка воспроизведения | `1108:02B9` | `1060:17FF` |
| Заполнение DMA-буфера | `1118:046E` | `1070:046E` |
| Начало аппаратного вывода | `1118:0829` | `1070:083D` |
| Программирование DSP/DMA | `1118:0222` | `1070:0222` |

Потоковый загрузчик читает ровно `0x24` байта заголовка, затем выделяет
`sample_bytes` и читает столько же байтов. Привязка ресурса при нулевом
far-pointer и ненулевом размере задаёт `samples = resource_base + 0x24`.
Новый модуль всегда берёт проверенный диапазон файла и не использует
сериализованные указатели, даже если их байты ненулевые.

DMA-путь копирует сэмплы без декомпрессии, порциями до `0x800` байт.
При окончании данных и включённом повторе восстанавливаются начальные
указатель и размер. Однократный запуск очищает бит `0x40`, запуск с повтором
его устанавливает; бит `0x80` обозначает активное воспроизведение.
Привязка дополнительно выставляет `0x20` и заимствует данные ресурса;
прочие значения и все режимы этого бита отдельно не исследовались.

Базовый запуск RUS `10F0:005E` держит один текущий объект звука и отказывает
в новом запуске, пока предыдущий отмечен активным. Два DMA-буфера в этом
пути не являются двумя независимыми голосами. Добавление многоканального
микширования в SDL-порт будет отдельным изменением поведения.

В аппаратный запуск передаётся младшее слово частоты (`1118:088D`).
DSP-путь использует целочисленное деление при вычислении настройки частоты.
WAV сохраняет номинальную частоту из ресурса и не эмулирует её аппаратное
квантование. Совпадение длительности и высоты звука с конкретной конфигурацией
DOSBox/Sound Blaster требует отдельной проверки.

Скрипт `AnnotateSounds.java` добавляет `SoundHeader36` и 20 смысловых меток
в оба проекта. Неустановленные области остаются неопределёнными. Выдержки
C и инструкций находятся в `research/evidence/stage4/<ru|en>/`; первичный полный
экспорт этапа 1 не перезаписывался.

## Реализация C11

`ports/gba/include/dok/sound.h`, `ports/gba/src/sound.c` предоставляют:

- Проверенное представление mono unsigned PCM8 без выделения памяти.
- Порционное преобразование в signed PCM8: `sample - 128`.
- Порционное преобразование в signed PCM16: `(sample - 128) * 256`.
- Формирование 44-байтового заголовка WAV PCM8/mono.

Ноль звуковой амплитуды — исходное значение 128. Крайние значения 0 и 255
переходят в −128/127 для PCM8 и −32768/32512 для PCM16. Усиление,
нормализация, эффекты, микширование, повторы и пересчёт частоты не применяются.
Signed PCM8 пригодится для будущего GBA-бэкенда; готового вывода на консоли
в этом модуле нет.

Поддержан только наблюдавшийся профиль: SVM, версия 1, флаги `0x09`,
8 бит, дополнительное поле `+10 == 0`. Другие комбинации отклоняются как
неподдержанные; это не полный универсальный декодер всех вариантов SVM.
Частота должна быть от 1 до 65535, диапазон сэмплов должен точно совпадать
с длиной блока. Пустой буфер сэмплов допустим для анализа, хотя в исходных
ресурсах таких блоков нет. Проверки отказа не меняют выходные результаты.

WAV-экспортёр дописывает один нулевой байт выравнивания при нечётном
количестве сэмплов. Этот байт входит в RIFF-размер, но не в размер data
и не в число сэмплов. В каждой версии четыре исходных блока имеют
нечётную длину; они проверены отдельно от общего сравнения PCM.

## Результаты и проверки

Для каждого блока C-инструмент `dok-sound` создаёт:

- `pcm8.wav` — исходные unsigned-байты для прослушивания.
- `pcm_s8.raw` — signed PCM8 без заголовка.
- `pcm_s16le.raw` — signed PCM16 little-endian без заголовка.

Файлы находятся в `research/evidence/sounds/<ru|en>/<resource_index>/`.
[Галерея для прослушивания](../../research/evidence/sounds/index.html) содержит WAV и
огибающие исходных сэмплов. WAV технически проверены; оценка на слух и
игровое воспроизведение в этом этапе не выполнялись.

`tools/originals/analyze_sounds.py` независимо декодирует все 46 блоков, сравнивает
полные PCM8/S8/S16-последовательности, а не только несколько сэмплов.
Стандартный Python `wave` проверяет формат, частоту, число каналов и каждый
байт WAV-данных. Дополнительно проверяются RIFF-размер и выравнивание.
SHA-256 оригинальных EXE/RES проверяется, все файлы остаются неизменными.

Тесты C проверяют знаковые крайние значения, границы порций и буферов,
переполнение запросов, усечение на каждой границе синтетического блока,
отклонение неверного формата, игнорирование native-полей, пустые данные
и нечётный WAV. Windows-тесты выполнены. Инструмент кросс-компилируется
для Linux x86_64, модуль — в ARM7TDMI Thumb object; запуска на Linux/GBA нет.

Каталоги и хэши: [RUS](../../analysis/originals/sounds-ru.json), [ENG](../../analysis/originals/sounds-en.json),
[сопоставление версий](../../analysis/originals/sounds-comparison.json).
Проверка оригиналов, аннотаций и собранных файлов:
[stage4-verification.json](../../analysis/originals/stage4-verification.json).

```powershell
C:/Source/wasdify/.venv/Scripts/python.exe tools/originals/analyze_sounds.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ghidra/annotate-stage4.ps1
```

Нужны готовые ресурсы этапа 2, общая установка компилятора и Python 3.11+
без сторонних пакетов. Следующий крупный блок работы — полная грамматика
LEVEL и создание типизированной модели уровня/объектов, затем перенос
игрового цикла и платформенных бэкендов.
