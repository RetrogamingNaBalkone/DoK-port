# Наследуемый анализ WASDify

Источник: `C:/Source/wasdify`, изучен 23 октября 2026 года. Этот каталог
использован для чтения; его файлы и исследовательские проекты не изменялись.
Контрольные суммы исходных документов, скриптов Ghidra и файлов патчей записаны
в [wasdify-sources.json](../../analysis/originals/wasdify-sources.json).
Это фиксация источников, а не копия всего проекта.

## Как использовать прежние материалы

Приоритетны `docs/games/dungeons-of-kremlin/`, исходники
`ports/gba/src/wasdify/patches/kremlin_*` и скрипты `scripts/Ghidra*.java`.
В документах сохранены исторические редакции: фраза «патч не реализован» в старой
секции может быть отменена дополнением в начале файла. Текущее состояние
сохранений описывают `save-load-status.md` и `save-load-integration.md`.

Скрипт `GhidraPkrPerformance.java` дал проверенный характерный пролог
`8C D0 90 45 55 8B EC`, позволяющий находить косвенно вызываемые методы.
Новый экспорт дополнительно ищет обычные прологи со стековым кадром; такие
границы остаются эвристическими. Имена ролей из прежнего анализа передаются
через [seeds-ru.tsv](../../analysis/originals/seeds-ru.tsv) и [seeds-en.tsv](../../analysis/originals/seeds-en.tsv).
Для каждой строки указано прежнее доказательство. Это новые смысловые метки,
а не восстановленные авторские имена функций.

## Ввод и движение

Источник: `wasd.md`, `kremlin_wasd.asm`, `kremlin_wasd.py`.
Игра использует клавиатурный ввод и DOS mouse API INT 33h. Угол хранится
в целых градусах. Общую функцию движения вызывают герой и AI; обработку
пользовательской мыши нельзя безусловно помещать внутрь этой общей функции.

Важная поправка после проверки нового листинга: адрес добавления угла
`14:0DB0` / `5:12BA` в `wasd.md` относится к размещению функции патча.
В оригинальном RUS `1068:0DB0` попадает внутрь инструкции `TEST` по `0DAE`,
а не на вход функции. Поэтому эти две строки удалены из таблиц входов
оригинала. Адреса в документации патчей необходимо проверять по исходному EXE.

В WASDify дробный остаток мыши хранится отдельно и расходуется только героем.
Для порта полезен сам контракт разделения ввода и физики. Чувствительность
0,2° и назначения WASD — поведение патча; не следует приписывать их оригиналу.

## Рендеринг и шрифт

Источники: `performance.md`, `render.md`, `font-scaling.md`, `numeric-hud.md`.
Программные горизонтальные и вертикальные текстурные циклы пишут в отдельный
буфер. Освещение применяется таблицей на каждый тексель; вывод готового
буфера использует VESA-банки. В ASM значимы GS/FS/ES и переносы через 64 КБ.

Выбор режима содержит известную ошибку: явные `-r1` и `-r2` передают один
режим `0x101`. Правка WASDify меняет первый на `0x100`. Оригинал в новом
проекте оставлен с исходным поведением. SDL2-бэкенд следует отделить от
растеризатора и палитры; для GBA потребуется самостоятельное решение
по бюджету памяти, разрешению и скорости. Измерений GBA пока нет.

Исходные FONT8/FONT16 и цикл рисования глифа не следует смешивать
с масштабированием, добавленным патчем. Адреса методов приведены в таблицах seeds.

## Оружие: заново подтверждённое поведение

Источник: `weapons.md`. Свежий C-псевдокод обеих версий подтверждает:
`player_select_weapon` читает текущий слот `player+0xCE`, затем far-указатель
из таблицы `player+0xAA + slot*4`, затем поле оружия `+0x81`. Результат
записывается в `player+0xD0` до проверки наличия запрошенного оружия.

Это небезопасное чтение через потенциально пустой указатель. В C-псевдокоде
RUS `1068:1FCD` и ENG `1020:257D` сохранена одна и та же последовательность.
Обозначения полей и типы пока частичные; переносить выражение буквально в
нативный C нельзя, поскольку Ghidra разрывает сегмент и смещение указателя.

Прежнее исследование отдельно подтверждает повреждение курсора кольцевой
очереди при вставке события нового оружия. Исправление чтения слота и
исправление курсора — две разные правки. В порте нужно явно решить,
какие ошибки оригинала исправляются; текущая декомпиляция сохраняет оригинал.

## Мир, классы и сохранения

Источники: `save-load-levels.md`, `save-load-state-gaps.md`,
`kremlin_save_profile.inc`, `kremlin_save_native_tables.inc`.
Уже исследованы фабрика объектов, динамические снаряды, поля героя, карты,
двери, ресурсы объектов и очередь событий. Для продолжения работы эти схемы
ценнее, чем повторный поиск всех полей по необработанному псевдокоду.

Единого сдвига между языками нет: прежний анализ даёт `+0xB0` для части
глобальных данных, `+8` для очереди и `+16` для callback-дескрипторов.
Эти правила относятся к конкретным проверенным образцам и областям памяти.
Их нельзя применять ко всем адресам без проверки.

Примеры подтверждённых полей игрока: жизнь `+0x5E`, заряд `+0x60`,
максимумы `+0x62/+0x64`; таблица оружия `+0xAA`, текущий/ожидаемый
слот `+0xCE/+0xD0`. Источники: `numeric-hud.md`, `weapons.md`.
Готового полного объявления класса C++ из этих фрагментов пока нет.

KRN1 — добавленный формат сохранений WASDify, а не исходный формат игры.
Рабочие адреса и селекторы нельзя сохранять как переносимые ссылки;
прежний код заново связывает логические ID со свежим миром. Это полезная
основа для будущего общего игрового состояния SDL2/GBA.
