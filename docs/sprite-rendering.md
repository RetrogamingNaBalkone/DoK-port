# Спрайты сцены и визуальный проигрыватель — G11

26 октября 2026 года. GBA использует программные billboard в общем
индексном framebuffer и общем coverage-композиторе стен/поверхностей.
Аппаратные OBJ не нужны для этого пути: сохраняются LIGHT, прозрачные
пиксели, пересечения со стенами и разрешённые120 колонок сцены/UI240.

## Оригинальные инструкции и адреса

Образцы: PKR.EXE SHA-256
`12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`, PKE.EXE
`cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
Все адреса ниже относятся к Ghidra NE loader, а не файловым смещениям,
NE-индексам или runtime-селекторам DPMI.

| Назначение | RUS | ENG |
|---|---|---|
| Последовательный кадр / clamped кадр |1050:0054 / 00DF|1018:0F62 / 0FED|
| Base animation callback |1068:0421|1020:0901|
| Billboard constructor |10B0:0CCB|1040:0CE3|
| Builder мира |1098:30C1|1030:3571|

`scripts/analyze-sprites.ps1` повторно открывает сохранённые проекты Ghidra,
проверяет SHA до/после, сохраняет журналы, `evidence.asm`, отдельный
непроверенный `automatic.c`, сегменты для воспроизводимых instruction probes
и manifest в `research/evidence/sprites/{ru,en}/`. Оригиналы не записываются.

Функции используют far CALL/RETF, параметры удаляет вызывающий код.
DS переключается на SS, входные структуры читаются через LES/ES;
far-pointer занимает offset16+selector16, результат кадра возвращается DX:AX.
В переносе хранятся ROM resource ID и borrowed views, эти указатели не копируются.

Размер кадра умножается на signed word native+17; остаётся младшее слово
IMUL. Половина ширины получается SAR16 **до** расширения в32 бита:
для−3 результат−2. Billboard требует depth>0, lateral endpoints равны
`lateral±SAR16(width,1)`, верх Y−height, низ Y, key=
`max(0,depth−SAR16(width,2))`. Проекция использует исходный denominator
depth+200 и low32/SAR15 из [геометрии](rendering-geometry.md).

TMap class3/6/9/10 располагается в центре клетки; MMap class3 также
использует центр, class9 — текущие actor X/Z. Основание
Y=`word(−FCMap.height_parameter−object.height_parameter)`:
RUS1098:45B1–4615 и4FFD–5052. Масштаб+17 не является радиусом коллизии.
Общий профиль пакета сохраняет принятый баланс; переключение языка
меняет ресурсные ссылки, не размеры и геометрию мира.

`verify_sprites_original.py` исполняет900 векторов исходного x86-конструктора
двух EXE в Unicorn, включая180 случаев отрицательной нечётной ширины.
Перехватывается только служебный конструктор массива; IMUL, SAR, IDIV,
screen clipping и key исполняются из Ghidra-exported bytes.
Это отдельные инструкции, не запуск полной DOS-сессии.

## Рендер и ROM

`src/renderer_sprites.inc` строит billboard records в том же bounded face list,
что стены и двери. Общая сортировка сохраняет собственный ключ billboard;
ближние пиксели закрывают дальние, прозрачные дырки сохраняют дальний слой.
LIGHT применяется перед проверкой прозрачности. Кадры анимаций получают
runtime image flags8, независимо от stored flags; общий RES не изменяется.

`image()` выбирает текущий кадр по строгому индексу из ROM. Неверный индекс,
ресурс или переполнение capacity возвращают ошибку; обращения за концом
последовательности не превращаются в следующий ресурс. Статические wall/door
column banks сохранены, остальные Sprite и кадры берутся непосредственно
из исходного row-major payload. Новые cold функции находятся в ROM.
Проверенный GBA-профиль принимает положительные world width/height до4096;
отрицательные размеры native instruction-пробы исследуют отдельно, runtime
отвергает их явно. В предоставленных сценах они не нужны.

Workspace предоставляет16 `dok_renderer_sprite` для позиционированных
снарядов/эффектов. Каждый содержит object index и XYZ, заимствует descriptor
и текущий ROM-кадр. G11 проверяет их изображение и перекрытие; создание,
движение, урон и удаление снаряда относятся к G13. `g_sprite_probe` — только
контрольный ARM-вход для выбранных сцен, не игровой ввод.

Двери сохраняют scheduler/crop G09: деление размера на extent выполняется
до умножения на frame, сдвиги0x48/0x108, закрытые/открытые состояния и
коллизии не заменены billboard. Эффекты пола сохраняют sampler G10.
Небезопасная native-маска0x4000 не появляется в исходных Sprite и не введена.

## Время, конец и игровые состояния

`src/visual.c`, `include/dok/visual.h` используют G06 scheduler. Default,
attack/death и impact-ссылки выбираются по ROM binding slot. В компактном runtime
word+14 прежнего резерва компактного объекта теперь `visual_resource`;
размеры объекта36 и ARM runtime33864 байта сохранены. Начальный ROM требует
там0, активный проигрыватель записывает стабильный resource ID.

`dok_visual_play` публикует frame0, исходный interval и параметры A/B.
Их смысл не переименован в координаты/масштаб. Однократная последовательность
оставляет последний кадр и выдаёт completion event при следующем deadline;
циклическая начинает с frame0. Callback не меняет здоровье, monster.state,
оружие, карту или ownership. G13/G15 принимают решение о последствиях
атаки/смерти; визуальная готовность не заменяет игровое состояние.

Base getter RUS1068:04E2–0508 начинает200-шаговую lease только при budget0.
Callback1068:0430/0437 уменьшает lease; при исчерпании следующий callback
отменяет событие. Возобновление видимого объекта сохраняет текущий кадр.
Спящие class9 автоматически не пробуждаются и не переходят к атаке;
их стартовый кадр виден, дальнейшие игровые состояния принадлежат G14/G15.

Исходные `0x86A0` остаются signed−31072. MOVSX в1068:0482/04EF
подтверждает знаковое расширение до32 бит. Deadline вычисляется модульным
uint32 сложением и проверяется исходным unsigned>=; отрицательный интервал
не заменён нулём или бесконечной паузой. Raw `dok_visual_poll` выполняет один
sweep, включая особенности shrinking owner count из G06.

Production `dok_visual_advance` обрабатывает шкалу333/333/334 ticks по G06/G09,
вызывается из416-tick motion catch-up и сохраняет долг после128 quanta.
Видимость для touch берётся из последней рассмотренной сцены, обрабатывается
внутри каждого simulation quantum и сбрасывается при смене уровня.
Тяжёлый renderer не ограничивает анимацию одним шагом за показанный кадр.
Положительные интервалы округляются до следующего visual quantum; это
явная политика GBA, не утверждение о точном времени native main loop.
Native water interval0 означает один шаг за sweep; в порте это visual30Hz,
без busy loop. Состояния18/end/перезапуск также не ждут нового draw.
Счётчик `frame` воды хранит **следующий** crop index: native callback
1068:0757–0771 сначала конфигурирует crop старым значением, затем делает INC.
Текущая отображаемая фаза отдельно хранится в compact `animation_a` под
`DOK_RUNTIME_CROP_PHASE` (known bit8). Это внутреннее переиспользование места
для class12/13, не значение native+20; `DOK_RUNTIME_ANIMATION_A` не ставится.
При counter18 показана crop17; cancel/rearm сохраняют crop17 до следующего
callback, который публикует crop0 и counter1. G10 controlled sampler по-прежнему
принимает прямой `frame` phase, когда внутренний crop-known bit не установлен.

Host-проверка сравнивает byte-identical mutable objects и event owners после
доставки одинаковых300000 ticks порциями10/416/5000 во всех трёх уровнях.
ARM-проверка фиксирует несколько фаз между соседними presentations.
Raw mailbox отдельно проверяет точные native signed deadlines.

## Проверки и воспроизведение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba-sprites.ps1 -CrossChecks -OriginalEvidence
# Повтор только проверок уже собранного ROM:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba-sprites.ps1 -RegressionOnly
```

Общая установка Unicorn: `C:/Source/wasdify/build/research-deps`; файл проекта
не содержит отдельной установки инструментов. В ограниченной среде чтение
этого общего каталога может требовать разрешения sandbox.

`tools/visual_probe.c` проверяет1750 ROM-последовательностей,9714 deadline
переходов,322 прохода отрицательных интервалов в повторяющихся bindings,
first/last/loop/completion и9 coarse/fine
timelines. Это тест нового C-проигрывателя; отдельно подтверждены native ASM.
Отдельно проверена точная последовательность water crop0…17 перед INC,
cancel при18 и сохранение последнего crop через rearm.
Независимый Python читает исходные RES: проверяет размеры/положение предметов
и врагов стартовой сцены,8 проекций positioned projectile, ближние masked
пиксели и полное закрытие дальнего снаряда стеной/дверью.

ARM/mGBA проверяет8 последовательностей RU/EN с двумя известными
отрицательными death intervals, metadata/frame events/deadlines/end,
автоматическое продвижение воды,24 вида трёх projectile templates в двух
языках, два расстояния и первый/последний кадры. Geometry oracle использует
исходные размеры; подтверждена реальная запись видимых пикселей.
Статические scene/language/poison-reset и полная camera regression намеренно
замораживают visual timeline; отдельный тест проверяет её движение.

Отчёты: `analysis/g11-*.json`, общий acceptance
`analysis/g11-review.json`; ELF/ROM/map и контрольные PNG — `build/g11/`.
Итоговый отчёт связывает текущие исходники, исходные образцы, ROM и проверки.
Физическая GBA, полноценная DOS-сессия, Linux execution и CMake/MSVC execution
не проверялись. Полная попиксельная эквивалентность DOS и30FPS полной игры
не заявляются; оптимизация остаётся G20.
