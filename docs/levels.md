# LEVEL: грамматика и определения объектов

Этап 5, 24 октября 2026 года. Образцы: неизменённые PKR.EXE/PKR.RES (RUS)
и PKE.EXE/PKE.RES (ENG), SHA-256 — в
[журнале проверки](../analysis/stage5-verification.json). LEVEL1–3 имеют индексы
18–20 в каждом RES. Это текст CP866, а не сериализованные C++-объекты.

Восстановлен порядок чтения всех классов фабрики, кроме отвергаемого class=11.
Добавлен собираемый загрузчик определений на C11. Он ещё не создаёт игровое
состояние: конструкторы, размещение экземпляров по картам, AI, столкновения
и исполнение эффектов остаются следующими этапами.

## Доказательства и адреса

Здесь все адреса `selector:offset` — адреса **Ghidra NE loader**, не файловые
смещения и не runtime-селекторы DPMI. PKR: основной парсер `1048:004c`, фабрика
`1068:0000`, чтение строки `1048:092e`, поиск значения после `=` — `1048:0a2c`,
целого — `1048:0a8f`, строки — `1048:0ae2`. PKE: основной парсер `1018:0152`,
фабрика `1020:018c`.

Фабрика вызывает метод по far-указателю из `vtable+4`. Адреса восстановлены
по NE relocation, а не по незагруженным байтам `ffff:0000`. Таблица vtable
находится в NE Data51 PKR / Data27 PKE. Источник соответствий: присваивания
vtable в фабрике и конструкторах. Скрипт `prepare_levels.py` разрешает relocation,
а `AnnotateLevels.java` повторно декомпилирует и сохраняет инструкции обработчиков.

Суффикс — шестнадцатеричное смещение в **native-объекте**, а не в файле LEVEL.
W — знаковое слово 16 бит; L — знаковое число 32 бита; C — один символ после
пропуска пробельных байтов; I/A/S — имя изображения/анимации/звука; T — остаток
строки, максимум 39 байт. Например, `AE8` — имя анимации для поля `+0xE8`.
Имена ресурсов регистрозависимы. Поле C сохраняет байт CP866, а не код Unicode.
Класс 5 присутствует в фабрике, но в шести исходных LEVEL не используется;
его грамматика проверена по коду и синтетическому примеру.

Общий заголовок определения:

```text
glyph class_id flags width_parameter height_parameter marker [class-specific fields]
```

В PKR последовательность вызовов `1048:0727…0759` — char, unsigned word,
unsigned word, signed word, signed word, signed word. Последнее слово сужается
до младшего байта marker (`1048:0761…0769`). Временный дескриптор имеет размер
22 байта: class+0, glyph+2, width+3, height+5, sprite far+7, animation far+11,
sound far+15, flags+19, marker+21. Тип `LevelObjectDescriptor22` добавлен в Ghidra.
Размеры и выравнивание этого дескриптора нельзя переносить на host-структуру C.

Обработчик классов 2/4/6 — пустая функция без обычного пролога; на этапе 1
она не вошла в эвристический список функций. Теперь вход подтверждён relocation
и разобран в Ghidra. Остальные обработчики сверены с инструкциями; в частности,
L использует `1158:245c`, W — `1158:20f0`, C — `1158:26d4`/`27cc`.

## Секции и значимые особенности

Секции: `[Game Ini]`, `[Palette]`, `[Light]`, `[Game Object]`, `[TMap]`, `[MMap]`,
`[FCMap]`. Исходный парсер заменяет CR на LF прямо в кеше ресурса. Переносимый
парсер принимает CRLF, CR и LF без изменения исходного буфера. Пустые строки
и строки с `#` в первом байте пропускаются; пробелы перед `#` не удаляются.

Названия секций и ключи сравниваются ASCII-регистронезависимо по длине известного
префикса (`1000:20d0`), поэтому родной парсер принимает и суффиксы после ключа.
Имена ресурсов сравниваются иначе: точно и с учётом регистра. После первого `=`
исходный helper пропускает только ASCII-пробелы. Пробелы справа в значении имени
Flic/Sound/Palette/Light остаются частью имени; Sprite извлекается отдельным токеном.

Game Ini читает восемь слов: Level Width, Level Height, Level Length, Cell Side,
Cell Height, Floor Color, Ceiling Color, Min Dis. Порядок первых трёх в native
буфере — **width, height, length**. Все шесть файлов задают 64×1×64, 480, 960,
10, 143, 238. `Step Ver=4` присутствует в данных, но этот парсер его не читает:
нет соответствующего сравнения/присваивания. Новый API считает такие строки
в `ignored_step_ver`; приписывать им влияние на движение нельзя.

Sprite, Flic и Sound — сохраняющиеся настройки для последующих определений.
Их значения не сбрасываются на каждой строке. Sprite задаёт имя и отдельные
флаги изображения; это не flags объекта. Flic задаёт текущую анимацию. Пустое
значение Sound отключает звук. `_` в позиции glyph преобразуется в пробел.
Повторный glyph обнаруживается через таблицу на 256 far-указателей; новый
загрузчик возвращает DOK_LEVEL_DUPLICATE.

В оригинале поле flags загруженного Sprite изменяется в общем кеше изображения.
Модель хранит настройку каждой декларации, а не копию native-кеша: при создании
runtime потребуется учитывать общие изображения. В шести проверенных LEVEL
повторных назначений разных флагов одному Sprite не обнаружено.

Поле монстра `+0xE7` читается через char-extractor. Текстовое `3` означает
`0x33`, то есть 51, а не целое 3. Такое чтение подтверждено в **обеих** EXE.
Поле триггера `+0x66` тоже символьное. Текст уведомления читается getline с
буфером 40: сохраняются начальные пробелы, копируются максимум 39 байт,
затем NUL. Все исходные уведомления укладываются в этот предел.

TMap/MMap/FCMap содержат сырые строки по width **байт**, пробел значим.
Новый API хранит три плоскости подряд без native-рамки: TMap, MMap, FCMap.
Символ `.` встречается в MMap/FCMap и не имеет определения объекта; загрузчик
сохраняет его, не объявляя ошибкой. Значение и обработку пустых клеток следует
подтвердить при восстановлении размещения объектов. В TMap все glyph определены.

## Модель C и проверяемый профиль

`include/dok/level.h`, `src/level.c`: загрузчик без malloc и SDL. Вызывающий код
передаёт буфер определений и три карты. Строки — заимствованные диапазоны
`offset,size` в неизменяемом CP866-ресурсе. `glyph_index[256]` хранит index+1,
zero обозначает отсутствие определения. Поля объектов имеют тип, native-смещение
и значение; непроверенные значения не получили вымышленных игровых названий.
`raw_tail` сохраняет доступ ко всей исходной части после общего заголовка,
включая текст, который native-буфер мог бы обрезать.

Модель описывает **данные до runtime-преобразований**. Например, обработчик
снаряда меняет знак L3C, инициализирует координату из height_parameter и выводит
одно поле из другого. Загрузчик не выполняет эти операции и не разыменовывает
native-указатели. Одного чтения LEVEL недостаточно для эквивалентного игрового мира.

Профиль рассчитан на имеющиеся оригиналы: width/length 1…64, height=1,
все семь секций и восемь настроек, три полные карты, не более 256 определений,
имена до 15 байт, строки до 178 байт. Это **не доказанные максимумы движка**.
У родного парсера есть небезопасное копирование строк/карт и неявные результаты
ошибок stream; они не воспроизводятся. Новый код отвергает незакрытые скобки,
NUL, неизвестные секции/параметры, неверные размеры, лишние токены, отсутствующие
числа и переполнение. Знаковые слова требуют −32768…32767; flags/class допускают
unsigned 16. Изменение геометрии после начала карт запрещено. После ошибки
частично записанные модель и буферы нужно отбросить. Буферы не должны пересекаться.

Для GBA нет обязательного объекта с 256 определениями: caller может выделить
ровно нужную ёмкость. Текст и ресурсы остаются внешними; RAM-раскладка полного
мира и ROM-пакер ещё не определены.

## Проверки и различия локализаций

`dok-level LEVEL.bin` выводит JSON: строки в hex, числа и native-смещения явно,
карты побайтово. `analyze_levels.py` независимо разбирает исходные байты Python
сканером, сравнивает **всю** C-модель, разрешает все ссылки по RES и проверяет
категории изображений, анимаций и звука. Полные определения/тексты остаются
в игнорируемом `build/levels/`; в `analysis/` — отчёты и различия без текстов.

Проверены 6 LEVEL, 780 определений, 7610 class-specific значений, 4474 употребления
ссылок (включая сохраняющиеся Sprite/Flic/Sound и ссылки класса). SHA-256 обеих
EXE и обоих RES совпал до и после. В Ghidra сохранены 32 смысловые метки и один
новый тип; свежие C/ASM — `build/stage5/<ru|en>/`.

Различия не ограничиваются переводом: в LEVEL1 меняются L38, WA4, LBA, WAE
некоторых монстров, параметры width и marker; width отличается также в LEVEL2/3.
Назначения основных изменённых полей class=9 впоследствии проверены по
использованию в обеих EXE: [enemy-parameters.md](enemy-parameters.md).
Список glyph, смещений и числовых значений —
[level-definition-differences.json](../analysis/level-definition-differences.json).
Отличия карт разобраны в [resources.md](resources.md). Общие файлы уровней для
двух локализаций нельзя подменять друг другом.

Синтетические тесты проверяют все 13 схем, границы целых, signed long minimum,
40000 в long двери, символ `3`, наследование деклараций, пробел-glyph, три вида
переводов строк, обрезку уведомления, все усечённые префиксы тестового файла,
дубликаты, нехватку буфера, неизвестный класс и повреждённые карты/секции.
Проверены Windows-тесты, сборки Linux static и ARM7TDMI Thumb; Linux/ARM-файлы
не запускались. Это не тест эквивалентности с работающей DOS-игрой.

Воспроизведение после извлечения RES и анализа анимаций:

```powershell
./scripts/build-native.ps1 -CrossChecks
C:/Source/wasdify/.venv/Scripts/python.exe scripts/prepare_levels.py
./scripts/annotate-stage5.ps1
C:/Source/wasdify/.venv/Scripts/python.exe scripts/analyze_levels.py
./build/native/dok-level.exe build/resources/ru/0018.bin
```
