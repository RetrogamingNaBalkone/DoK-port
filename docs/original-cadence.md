# Частоты логики и графики оригинала

Проверено 25 октября 2026 года на PKR.EXE RUS, SHA-256
`12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`.
Адреса — NE-loader Ghidra, не файловые смещения и не DPMI-селекторы.
Источник времени и scheduler обеих версий — [time-events.md](time-events.md).
Новый проход конкретного callback и presentation ниже выполнен только для RUS.

## Логика

Общей фиксированной частоты всей логики нет: события имеют собственные
интервалы, ввод также обрабатывается главным циклом. Для героя найден период
**416 native ticks ≈41,49 мс / 24,10 Гц** при шкале `1193182/119 ticks/s`.

Доказательства по ASM:

- Constructor `1068:1657`, участок `16D1…16E8`: PUSH 0x1A0, копирование
  8-байтного descriptor из `1190:0512`, owner-pointer, вызов `1038:0108`.
  Descriptor содержит far callback `1068:2127` и parameter 0.
- Callback `1068:2127` обрабатывает взаимодействия героя с объектами;
  в `1068:22A7` вызывает `actor_update_movement`, `1068:0A85`.
- Главный цикл в `1008:0DAF` вызывает `dispatch(0)` один раз перед сценой.
  Это не отдельное прерывание с частотой24Гц.
- Scheduler назначает повтор от времени после callback, без догоняющего
  исполнения пропущенных периодов. 24,1Гц — номинальный верхний ориентир
  этого события; фактическая частота ниже и зависит от времени кадров.

Шкала около10кГц и INT1C около18,2Гц — не частоты обновления героя.
Сетка около100,267 шага/с в GBA probe — отдельное решение порта.

## Графика

Сцены строятся и выводятся в каждом проходе главного цикла, с переменной
частотой по производительности CPU и сложности сцены. Фиксированный лимит
30/60/70FPS в проверенном игровом пути не найден.

`1008:0F04` вызывает vtable+0x34. Constructor backend `1120:01D8`
устанавливает vtable `1190:0E10`; слот `1190:0E44` указывает на
`1120:08DD` (present_region). Она копирует сцену и дополнительные области
через `1138:0932`, затем вызывает `1138:051D`. Последняя для многобуферного
режима вызывает VBE `INT10/AX=4F07`, **BX=0**; запрос ожидания retrace через
BL=80h отсутствует. Для однобуферного режима вызов пропускается.
Проверенные функции копирования `1138:086A…0A5A` не ждут retrace.

Ожидание бита3 порта3DAh есть в `1110:0329`, но его вызывают процедуры
установки/очистки палитры `1110:0355/037A`, а не обычный вывод каждого кадра.
Частота физической развёртки монитора отличается от частоты новых игровых
кадров. Реальный FPS конкретного PC/DOSBox этим статическим разбором не измерен;
поведение VBE BIOS также не исполнялось заново.

## Воспроизведение

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/analyze-cadence.ps1`
открывает сохранённый RUS-проект Ghidra read-only и запускает
`scripts/InspectCadence.java`. ASM, vtable, descriptor, журнал и manifest —
`build/cadence/ru/`. SHA-256 EXE до/после совпали. Автоматический C использован
для навигации; приведённые связи подтверждены ASM и данными Ghidra.
