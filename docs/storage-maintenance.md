# Очистка тестовых артефактов

## Повторная очистка 31 октября 2026 года

Компактный результат — [storage-cleanup-20261031.json](../analysis/storage-cleanup-20261031.json).
Освобождено 5 142 323 770 байт (4,79 ГиБ): 608 658 053 байта кешей и
завершённых тестовых FAT/индексов, 470 458 686 байт промежуточных N23 `.o`/`.d`,
4 063 207 031 байт за счёт сжатия 282 завершённых build-журналов без потерь.
После проверки каталог занимал около 17,6 ГиБ; параллельные прогоны продолжают
создавать данные, поэтому размер не является фиксированным.

Причины повторного роста:

- Девять проверок `performance/` и `flow/check_regression.py` задавали собственный
  `ZIG_LOCAL_CACHE_DIR`, обходя helper предыдущей очистки. Они переведены на
  `map/compiler_cache.py`: общий global cache, временный local cache и уборка
  при завершении процесса, включая исключения.
- `performance/run_logged.py` сохранял несжатые native stdout/stderr и полные
  JSON-отчёты, уже записанные наблюдателями отдельно. Теперь он потоково пишет
  `<указанное-имя>.gz`, сохраняет все байты обоих потоков и исходный exit code.
  Повторное использование имени запрещено. Для чтения: `gzip -dc <журнал.log.gz>`
  либо `gzip.open(path, 'rt', encoding='utf-8', errors='replace')` в Python.
- `performance/build.py` оставлял ARM-объекты каждого неизменяемого кандидата.
  Теперь `build_cleanup.py` убирает только его `obj/*.o` и `obj/*.d` после make,
  включая неудачную сборку. `.su`, ELF/map/ROM, generated inputs и исходники
  сохраняются; `NDS_KEEP_COMPILER_CACHE=1` отключает уборку для отладки.
  Новые build manifests включают helper и его зависимость среди build drivers.

Три работающих target (`candidate22-ru`, `candidate22-en`, `standalone01-ru`)
исключены из удаления. Упаковщик пропускает открытые для записи журналы через
Windows sharing modes. Исследовательские архивы не упаковывались и не удалялись.
Неизвестный FAT N13P и два недоступных временных каталога сохранены, без смены ACL.
Первоначальный план удаления остановился до удаления файлов на активном FAT;
применён отдельный `delete-plan-idle.json` с явными исключениями.

Локальные манифесты, raw SHA-256 журналов, gzip SHA-256 и проверка сохранности:
`research/evidence/maintenance/cleanup-20261031/`. Для каждого упакованного
журнала также существует `<журнал.log.gz.json>` с исходным именем, размером
и хешем. Старые отчёты не переписывались. Если исторический verifier требует
буквальный `.log`, восстановить его из `.gz` по исходному пути и проверить
SHA-256 из receipt; прежний путь теперь отсутствует до такого восстановления.
Это касается только build-журналов, а не замороженных архивов `research/`.

Повторная упаковка завершённых журналов (без `--apply` — только план):

```powershell
py -3.14 -B -X utf8 scripts/compress_build_logs.py --manifest research/evidence/maintenance/<новый-прогон>/logs.json --apply
```

Очистка кешей/FAT использует прежние команды ниже; для активного target добавить
к команде `plan` повторяемый `--exclude build/nds/<target>`. Недоступные каталоги
попадают в `skipped`, остальные ошибки по-прежнему останавливают планирование.
Проверены 29 тестов уборки/журналирования и синтаксис 40 Python-файлов.
Для 130 003 защищённых файлов проверены наличие и размер, 54 SHA-проверки
оригиналов, контрольных сборок и текущих N23 ROM/ELF/map прошли.
Полная игровая регрессия не запускалась; игровые статусы и следующий ID не изменены.

## Предыдущая очистка 30 октября

30 октября 2026 года по поручению пользователя удалены воспроизводимые
компиляторные кеши и завершённые NDS-образы тестовых SD-карт. Точные пути,
размеры, SHA-256 и логическое содержимое дисков сохранены локально в
`research/evidence/maintenance/cleanup-20261030/delete-plan-final.json`.
Небольшие файлы, включая настройки, дополнительно сохранены в hex.
Компактный итог — [отчёт](../analysis/storage-cleanup-20261030.json).

Исходники, оригиналы, проекты Ghidra, отчёты, исходные доказательства,
контрольные кадры/PCM, ROM/ELF и входы сборок сохраняются. В частности,
финальный архив N21P остаётся побайтово прежним. Нестандартные или неизвестные
образы не удаляются автоматически. Исторические отчёты могут ссылаться на
удалённые временные FAT: вместо самого диска сохранены его хеш и файловый
состав; новый прогон создаёт диск из исходных ресурсов заново.

## Автоматическая уборка в NDS-инструментах

Проверки `ports/nds/tools/map/check_*.py`, ранее создававшие собственный
`zig-global-cache` на каждый опыт, используют общий `build/zig-global-cache`.
Локальный кеш имеет уникальный каталог процесса в `build/nds/.compiler-cache`
и удаляется при завершении Python, включая необработанное исключение.
Исполняемые файлы, объектные доказательства и отчёты не удаляются.
Для сохранения локального кеша перед запуском установить
`$env:NDS_KEEP_COMPILER_CACHE = '1'`.

Базовый NDS libretro frontend убирает принадлежащие прогону
`save/melonDS DS/dldi_sd_card.bin` и `.idx` при завершении процесса, после
освобождения core и всех проверок FAT. Обычный `close()` образ не удаляет:
некоторые наблюдатели проверяют диск после выгрузки игры. Сохраняются отчёт,
кадры сбоя и компактные сведения о содержимом диска. Чтобы оставить образ
для ручной отладки, установить `$env:NDS_KEEP_EMULATOR_DISK = '1'`.

Образ `run_frontend_emulator.py --mode settings` сохраняется намеренно:
следующий отдельный процесс проверяет реальный перезапуск через
`--mode restart --reuse-image <образ>`. Переданный `--reuse-image` остаётся
входом пользователя; автоматически удаляется только копия нового прогона.
После законченного набора проверок промежуточный settings-образ можно убрать
описанной ниже процедурой. Принудительное завершение процесса может оставить
временные данные; автоматическое удаление при аварийном завершении ОС
не гарантируется.

## Повторная очистка

Создать новый манифест, не перезаписывая прежние результаты:

```powershell
py -3.14 -B -X utf8 scripts/prune_test_storage.py plan --manifest research/evidence/maintenance/<новый-прогон>/delete-plan.json
& scripts/prune-test-storage.ps1 -Manifest research/evidence/maintenance/<новый-прогон>/delete-plan.json
& scripts/prune-test-storage.ps1 -Manifest research/evidence/maintenance/<новый-прогон>/delete-plan.json -Apply
py -3.14 -B -X utf8 scripts/prune_test_storage.py verify --manifest research/evidence/maintenance/<новый-прогон>/delete-plan.json
```

Первый PowerShell-вызов только проверяет план. Перед удалением заново
проверяются все размеры и SHA, Git index, абсолютные границы workspace,
reparse points и отсутствие открытого владельца SD-образа. Удаляются только
регулярные файлы из узкого списка: кеши и известные тестовые FAT с индексами.
Неизвестный FAT и его индекс сохраняются. `originals/`, `research/`,
`analysis/` и `artifacts/` не входят в область удаления.

## Воспроизводимость прежних проверок

Уборка меняет Python-инструменты, а не игровой код или ROM. Для проверки
старых хешей инструментов использовать сохранённые версии в
`research/evidence/nds/n21p/final-sources/`. Прежние manifests и отчёты
не переписываются. Соответствие старой версии, архивной копии и новой версии
инструмента записано в `retained-verification.json` рядом с манифестом очистки.
Новые helper/test файлы закреплены отдельным maintenance-манифестом.
Новые прогоны выполнять под новым label, не перезаписывая frozen targets.
