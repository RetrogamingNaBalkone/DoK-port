# Хранение сборок и исследований

Готовые файлы в `artifacts/` полностью исключены из Git, включая README и
контрольные снимки. Добавление правила игнорирования не исключает уже
отслеживаемые файлы: 3 ноября 2026 года они отдельно удалены из индекса
через `git rm --cached`. Файлы на диске этой командой не удаляются.

Отчёт об очистке: [storage-cleanup-20261103.json](../analysis/storage-cleanup-20261103.json).
Полные списки удалений, SHA-256 и проверка повторной сборки находятся локально
в `research/evidence/maintenance/cleanup-20261103/`.

## Что сохраняется

Оригиналы, Ghidra-проекты и экспорты, текущие ROM/ELF, общие пакеты ресурсов,
подготовленные входы Makefile и необходимые базовые объекты сохраняются.
Удалены устаревшие воспроизводимые выходы компилятора и копии NitroFS.
Исходники и снимки исходников не удаляются как результаты компиляции.

Исторические отчёты и наблюдения NDS, старые отчёты, кадры и аудио,
холодные снимки исходников из `build/gba/` и `build/nds/`, старые эксперименты
и прежние проходы декомпиляции упакованы без потери данных в
`research/experiments/storage-archives/`. ZIP содержит исходные относительные
пути и `__dok_storage_manifest__.json` с размером и SHA-256 каждого файла.
Перед удалением распакованных файлов проверяются все архивные записи и
повторно проверяются исходники. Архивы также исключены из Git.

Таким образом, старые исследовательские проверки могут требовать
восстановления своего каталога. Сводки в `analysis/` и документы остаются
доступны; машинные проверки должны читать полный восстановленный отчёт.

## Восстановление по необходимости

Один файл либо каталог из архивов:

```powershell
py -3.14 -B scripts/storage_archive.py restore research/evidence/nds/n22
py -3.14 -B scripts/storage_archive.py restore build/nds/n23/candidate12-ru
```

Восстановление проверяет SHA-256, не перезаписывает существующие файлы и
не извлекает пути вне разрешённых деревьев репозитория.

Для копий, удалённых первым проходом по совпадающим архивным данным:

```powershell
py -3.14 -B scripts/prune_archived_builds.py restore --manifest research/evidence/maintenance/cleanup-20261103/archived-builds.json --path build/nds/n22/frontend-ru
```

Если исходный архивный файл уже помещён в ZIP, восстановление сначала
извлекает его из ZIP. Временные GBA-банки и устаревшие выходы компилятора
восстанавливаются повторной сборкой по паспортам соответствующих задач.

## Повторное накопление

GBA-сборщики используют один уникальный кэш Zig на дерево запуска.
Дочерние Python/PowerShell-процессы используют тот же кэш; удаляет его
только владелец после завершения всех дочерних команд, в том числе при ошибке.
Переменная `DOK_KEEP_COMPILER_CACHE=1` оставляет кэш для отладки.
Принудительно завершённый процесс может оставить кэш, который затем
удаляется `scripts/prune_test_storage.py` и его PowerShell-драйвером.

`prototype_gba_bsp.py` регистрирует создаваемые банки до записи и удаляет
их вместе с объектами через `finally`. При самостоятельном вызове генератора
его заказанные выходы сохраняются. `--keep-objects` сохраняет банки и
объекты для ручной перелинковки. ROM, ELF, map, отчёты и исходники прототипа
обычная очистка сборщика сохраняет.

`build_gba_frontend.py` после линковки удаляет собственную временную базу:
объекты, банк столбцов, ROM и ELF. `--keep-base-objects` сохраняет их для
следующих прототипов. Драйверы `check_g20d.py` и `check_g22.py` явно передают
этот флаг там, где база используется повторно. Самостоятельные базовые
сборщики сохраняют свои входы для последующей линковки.

Новые исторические данные можно упаковывать после завершения прогонов:

```powershell
py -3.14 -B scripts/storage_archive.py history --port gba --archive research/experiments/storage-archives/gba-history-NEW.zip --apply
py -3.14 -B scripts/storage_archive.py history --port nds --archive research/experiments/storage-archives/nds-history-NEW.zip --apply
```

Имена архивов должны быть новыми. Профиль исключает текущие контрольные
деревья, подготовленные данные и файлы моложе суток. Для удаления старых
выходов компилятора сначала формируется проверяемый manifest:

```powershell
py -3.14 -B scripts/prune_superseded_builds.py plan --manifest research/evidence/maintenance/superseded-NEW.json
py -3.14 -B scripts/prune_superseded_builds.py apply --manifest research/evidence/maintenance/superseded-NEW.json
```

После смены выбранных сборок обновлять списки сохраняемых каталогов в
скриптах обслуживания. Не применять старый список к новым активным целям.
