# Игровой цикл G18

Дополнение27 октября: [UI01, второй плейтест](ui01-playtest2.md).
Из PLAY Select открывает MAP=7, B/Select возвращают в PLAY с блокировкой
кнопки до отпускания. Start+Select работает также при Select-first через
MAP. MAP не меняет состояние flow PLAY, но `gba_flow_active`=0: часы и
мир остановлены, музыка меню не запускается. Посещённость сохраняется
при retry (новое раскрытие может добавляться), новый уровень её обнуляет.
Текстовые страницы BINTRO/EINTRO/ENDTXT используют28 столбцов и отступ8px.

Проверяется по оригинальным PKR/PKE и общему RU/EN GBA-ROM. Уровни в оригинале
выбираются независимо: завершение показывает `EINTROn` и возвращает выбор уровня.
Автоматической кампании LEVEL1→LEVEL2→LEVEL3 и переноса инвентаря между отдельными
мирами в исследованном startup нет. Порт сохраняет этот порядок.

## Исходные доказательства

Все адреса ниже — адреса **NE-загрузчика Ghidra**, а не файловые смещения,
индексы сегментов NE или runtime-селекторы DPMI.

| Образец | SHA-256 до и после анализа |
|---|---|
| `originals/pkr/RUS/PKR.EXE` | `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28` |
| `originals/pkr/ENG/PKE.EXE` | `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b` |

`scripts/analyze-flow.ps1` запускает `InspectFlow.java` read-only в сохранённых
`research/ghidra/projects/{ru,en}/Kremlin.gpr`. Листинги, бинарные сегменты, журналы,
манифесты SHA и отдельный непроверенный автоматический C находятся в
`research/evidence/flow/{ru,en}/`. Автоматический C не является кодом движка.

| Назначение | RUS | ENG |
|---|---|---|
| Выбор уровня 1–3 и имён ресурсов | `1008:02F7` | `1008:044B` |
| Startup, создание/уничтожение мира, заставки | `1008:0719` | `1008:086D` |
| Проверка смерти/завершения героя | `1068:193E` | `1020:1EFC` |
| Восстановление исходной позы | `1098:125B` | `1030:133F` |
| Изменение характеристик | `1068:1CC2` | `1020:2276` |
| Проверка category1000/score/total | `1068:1E79…1E95` | `1020:2429…2445` |

Startup выбирает имена `LEVELn/BINTROn/EINTROn/BSPRn/ESPRn/GAMEPn`.
После выбора показывается BINTRO, затем строится новый мир. Возврат
`player_check_death==3` завершает текущий мир: startup уничтожает его,
показывает выбранный EINTRO и повторяет выбор уровня. Отмена выбора показывает
`ENDTXT` (RUS data `1190:02BC`) и выходит. Поэтому ENDTXT на GBA доступен
пунктом «Выход»: аппаратное выключение картриджа заменено возвратом в меню
после исходного финального текста. Это адаптация платформы, а не новый уровень.

Входы — `__cdecl16far`, указатель героя передаётся парой offset/segment,
читается `LES`; `RETF` оставляет caller cleanup аргументов. Счётчики и HP —
signed16, decrement lives — машинный `DEC word`, с wrap16 и проверкой на ноль.
Восстановление позы вызывает `1000:5CB3` с **CX=30**, far source `world+716`
и far destination `hero+26`; runtime copy снимает восемь байт аргументов.
Нельзя заменять этот участок копированием всего compact actor64.

При HP==0 исходник проигрывает once звук `hero+A6`, уменьшает lives и при
нуле возвращает2. Иначе очищает старую клетку MMap, восстанавливает только
native диапазон `+26…+43`, записывает glyph героя в новую клетку и HP=max,
возвращая1. Сохраняются остальные актёрские поля, мир, двери, предметы,
инвентарь, ключи, score, живые/мёртвые враги и существующие события/снаряды.
Моделируемая часть pose: x/y/z, heading, angle34, mode, base_speed,
step_distance. Неизвестные native поля не объявляются восстановленными.
HP<0 возвращает3; HP>0 —0.

`scripts/verify_flow_original.py` исполняет оригинальные x86-функции:
16 equality vectors,14 death vectors (включая lives0 и −32768) и два отдельных
native restore-helper вызова с проверкой far-аргументов/CX30. Sound/HUD
перехватываются как внешние вызовы; copy helper в death fixture подменён
проверенной 30-byte операцией, а сам helper отдельно исполняется с внешним
runtime memcpy sink. Остальные сравнения, `LES`, арифметика, clamp клеток,
записи HP/lives/occupancy и far return выполняются машинным кодом образцов.
Это контролируемые срезы, не целая DOS-сессия. Отчёт:
`analysis/g18-original-flow.json`.

## Выходы и вопрос об очках

В PKR/PKE действительно осталась ветвь category1000: сравнить `hero+D8`
с `world+710` и при равенстве записать HP=−1. Class12 получает category из
`+66`; его проверка запускается из hero update. World builder считает total
по размещённым class3/category99 предметам.

**Во всех шести исходных LEVEL1–3 RUS/ENG таких предметов нет и total=0.**
Соответственно, штатная проверка равенства —0==0: для прохождения
«Подземелий Кремля» собирать очки не требуется. Это нельзя описывать как
игровую цель из «Старого Золота». Отдельная проверка исходных RES,
`scripts/audit_flow_exits.py` / `analysis/g18-exit-audit.json`, подтверждает
нулевые totals и реальные клетки выхода B2 в FCMap:2/2/4 на LEVEL1/2/3
каждого языка. Внутренняя исходная ветвь сохранена; искусственный nonzero
score используется только как отрицательный fixture проверки условия.

## Поведение картриджа

Актуализация UI01/G20B,27 октября: при включении показывается оригинальная
заставка; A/Start открывает отдельное главное меню: «Начать игру», «Язык»,
«Управление», «Выход». «Показатели» удалены из главного меню и паузы после
пользовательского плейтеста. «Начать игру» открывает отдельный список
трёх исходных названий. Up/Down выбирают уровень, A/Start создают новый мир
и показывают BINTRO; B возвращает главное меню без сброса мира.
«Продолжить» остаётся только в паузе. После выхода в главное меню запуск
всегда создаёт новый мир; сохранений нет и не планируется.
Оформление, музыка и проверки — [gba-frontend.md](gba-frontend.md).
Boot открывает только каталог ресурсов; мир создаётся при выборе уровня.
Перед созданием проверяются обе выбранные локализации и общий numeric profile.

За BINTRO следует игра. HP0 показывает экран повтора; A/Start восстанавливает
исходную позу и HP, сохраняя текущий мир. При lives0 показывается конец игры,
затем выбор нового мира. Реальное событие `DOK_INTERACTION_FINISH` переводит
игру в EINTRO; после текста сессия закрыта и открыт список уровней,
следующее начало создаёт новый мир.
Пункт «Выход» закрывает сессию, очищает снаряды/звук и показывает ENDTXT.

A/Start листают страницы и продолжают; B возвращает предыдущую страницу,
с первой страницы — главное меню. Select меняет язык представления.
Кнопка перехода блокируется до отпускания; блокировка обновляется на каждом
sample, включая игровой режим. Игровые кнопки и Start+Select=пауза сохранены
из G17. На текстовых экранах simulation clock остановлен с сохранением
remainder и deadlines; hardware Timer2/3 и текущий PCM продолжаются. Поэтому
во время смерти AI не атакует повторно и не возникает catch-up после повтора.
Retry не уничтожает законные события и снаряды того же мира.

## Смена мира и ресурсы

Событие FINISH только ставит pending flag: фактический переход выполняется
после завершения callback dispatch. Новая игра сперва снимает collision overlay
`dok_collision_overlay(0,0,0)`, удаляет снаряды с восстановлением занятых клеток
старого мира, сбрасывает sprite list и останавливает PCM/DMA1/Timer0/1.
Затем проверяются обе локализованные ROM views, восстанавливается весь runtime,
заново создаются motion/input/debt/collision context, interactions/items,
combat, AI и visual scheduler/owners; сбрасываются caches и UI queue/messages.
Ни один старый borrowed world context не переносится в новый мир. FINISH,
«Выход» и Game Over также снимают overlay, очищают все scheduler owners/events,
UI queue и звук; старый runtime сохраняется только как безопасный фон меню.
HP<0 потребляется как исходный finish sentinel отдельно от HP==0.

Оружие хранит локальные object tokens, а не native far pointers. Между
независимо выбранными уровнями не переносится ни token, ни инвентарь:
используется initial_player нового LEVEL, включая жизни3 и score0.
Это устраняет опасную ошибку переноса одинаковых индексов разных definitions.
Язык меняет только presentation view; геометрия и общий согласованный balance
одинаковы для RU/EN. Отличия исходных версий анализируются отдельно.

`BINTRO1…3/EINTRO1…3/ENDTXT` читаются напрямую из уже существующего assets ROM,
без дублирования payload и без обрезки до UI notification limit240.
Исходный CP866 FONT8 рисует30 колонок×14 строк с y20, CR игнорируется,
LF переводит строку, NUL/`$` заканчивает текст. Страницы сохраняют пустые строки
и весь видимый текст; заголовки используют FONT16, footer находится y144.
Экран240×160 и игровая сцена240×144/120 независимых колонок сохранены.

## Воспроизведение и ограничения

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba-flow.ps1 -CrossChecks -OriginalEvidence
```

Driver выполняет Windows host fixtures, Linux static/Thumb compilation, ROM,
оригинальные x86-срезы и аудит RES, независимые ARM flow/UI и регрессии
renderer/interactions/time/28 AI/23 PCM. Последний aggregate требует отдельную
визуальную проверку точных PNG и связывает source/ELF/ROM/map/отчёты.
Части pipeline допускают отдельный запуск; `-RegressionOnly -CrossChecks`
использует готовые build/host artifacts. Фактически выполненные команды,
окончательные SHA, память и stack фиксируются в результате G18 и handoff.

Test ABI: `g_flow_probe` — четыре uint32 `request,ack,op,arg`; op3 только
явно включает legacy fixture (не производственный ввод). Он отключает
flow consumer, сохраняя обычную паузу UI; полноценный flow verifier начинает
с настоящего boot без этой команды. Прямых mailbox-команд «завершить» или
«умереть» нет: fixtures используют production stats/combat/zone callbacks.
`g_flow_diag` —14 uint32: `magic=464C3138,state,level,session,lives,score,
transitions,resets,pending,text_id,text_size,page,pages,errors`.
Состояния:0title,1intro,2play,3death,4outro,5ENDTXT,6gameover.
Уровень/page нумеруются с0; text_id — stable ROM ID, не native address.

Физическая GBA, оригинальный BIOS и целая DOS-сессия не проверены.
Linux static/Thumb компилируются, запуск Linux/MSVC/CMake не заявляется.
30FPS не достигнуты: оптимизация остаётся G20; детализация не снижалась.
Слуховое подтверждение остаётся принятым пользователем G16, численные PCM
регрессии G18 не объявляются новым человеческим прослушиванием.
