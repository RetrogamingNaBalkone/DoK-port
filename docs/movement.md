# Ввод и движение героя (G07)

25 октября 2026 года. G07 выполнен: общий C-модуль, адаптер GBA-кнопок,
фиксированные обновления и камера подключены к общей сцене LEVEL1.
В G08 подключены коллизии и occupancy: [collision.md](collision.md).
Ниже сохранён снимок G07 до этой интеграции; актуальный ROM — `build/g08/`,
следующий этап — G09. Детализация G06A сохранена: 120 колонок сцены, UI240.

## Намеренная правка управления

Пользователь в ходе G07 явно поручил исправить скользящую инерцию оригинала.
В игровом `dok_motion_update` поступательное движение **сразу начинается
с рабочей скоростью и сразу прекращается при отпускании**. Смена направления
действует на ближайшем фиксированном обновлении, без разгона и докатывания.
Противоположные команды на одной оси взаимно гасятся. Направление отпущенной
клавиши не используется для последующего перемещения.

Разгон поворота, шаги и округления перемещения пока сохранены. В частности,
отрицательный quarter-step округляется вниз, а положительный — к меньшему
целому; это может давать небольшую асимметрию направлений. Диагональный ход
не нормализуется. Эти свойства не являются поступательной инерцией.

`dok_motion_original` — отдельно названная ручная реконструкция исходной
арифметики для проверки доказательств. В игровом цикле вызывается исправленный
`dok_motion_update`. Автоматический псевдокод остаётся в `research/evidence/movement/*/automatic.c`;
он не включён в движок и не считается собираемым C.

Адреса `14:0DB0` / `5:12BA` в старых материалах WASDify относятся к функции
патча; это не входы оригинала. В RUS `1068:0DB0` лежит внутри `TEST` по `0DAE`.

Native ABI: far-call, 16-битный стек; аргумент actor — пара offset/selector
в `[BP+6/+8]`, доступ через `LES ES:BX`. `DS` устанавливается из `SS`.
Clock возвращает uint32 через DX:AX, что собирается `SHL/SHRD`.
Подшаг принимает signed word distance и word strafe, не native/host pointer.
Far/huge pointers и ES-таблицы заменены обычными C-ссылками и ROM-таблицей;
адреса DOS-объектов и vtable в GBA не переносятся.

## Подтверждённая исходная арифметика

`+1C` — flags; `+32` — heading word; `+34` — угловой параметр word;
`+38` — базовая скорость int32; `+3C` — signed distance int32;
`+7C/+7E` — текущий поворот/шаг signed word; `+82` — последний знак поворота;
`+90/+94` — int32 накопители движения/поворота; `+98` — знак разгона;
`+9A` — последние flags перемещения. Для последнего в G07 введён отдельный
`dok_motion` на актёра: ABI упакованного G03 runtime не изменён.
У исходного героя LEVEL1 `+34=5`, `+38=120`, y=−300, bounds=−274/−326.

В оригинале поступательный накопитель меняется на ±elapsed, ограничивается
0…10000. При отпускании используются сохранённые flags до затухания скорости.
Накопитель поворота растёт до10000, без стрелок сбрасывается. Одновременный
поворот и ход вперёд/назад синхронизируют оба накопителя по большему.

Фактор шага: unsigned `((elapsed << 8) mod 2^32) / 416`, затем половина
при совместном повороте/ходе и signed clamp256…768; Run удваивает,
slow-effect `0x04000000` делит пополам. Поворот получается из low32
`angle_parameter * factor * turn_accumulator`, signed IDIV10000, SAR8,
сужается до word и сверху ограничивается18. Смена знака поворота даёт первый
шаг1. Поэтому исходный поворот влево из покоя может несколько обновлений
оставаться нулевым; это проверено, не заменено равномерным вращением.

Шаг: low32 IMUL(speed,factor), SAR8, low32 IMUL(accumulator), signed IDIV10000,
сужение в signed word. Шаг≤0 обнуляет поступательный накопитель. Heading
складывается/вычитается как word и корректируется один раз на360.
Все low32/word wrap и arithmetic shifts выражены явно, без signed overflow C.

Каждая команда поступательного перемещения делает **три** подшага
`sign_extend(SAR16(signed_distance,2))`. При heading h кандидат каждого подшага:
`x += SAR15(low32(sin[h]*distance))`,
`z -= SAR15(low32(cos[h]*distance))`. Стрейф использует h+90.
Таблица Q15 с масштабом32768 взята из уже проверенного G04 `renderer_trig.inc`;
в этом тесте x87-инициализатор заново не исполняется. Порядок команд:
вперёд, назад, стрейф влево, стрейф вправо. Native обёртка также меняет карты
занятости и door counters — это остаётся G08/G09.

Исходный код небезопасен при выходе повреждённого heading за таблицу.
Реконструкция сохраняет word-арифметику heading; **только при чтении таблицы**
free-flight нормализует индекс полноценным signed modulo360. Это защитная
правка для некорректного состояния, не доказательство исходного поведения
за границами таблицы. Векторы такого состояния проверяют скалярный расчёт
без запроса перемещения.

Вертикального интегратора или прыжка в этих функциях нет. y и bounds не
изменяются; их использование при коллизиях предстоит G08. Клавиши DOS +/−
создают команды `0x8000/0x10000`, но `actor_update_movement` их не обрабатывает.
Приписывать им изменение высоты героя оснований нет.

## Кнопки и время GBA

| Кнопка | Команда |
|---|---|
| D-pad ↑/↓ | Вперёд/назад (`0x10/0x20`) |
| D-pad ←/→ | Поворот (`4/8`) |
| L/R | Стрейф влево/вправо (`0x80000/0x100000`) |
| B, удержание | Бег (`0x2000`), совместно с ходьбой/стрейфом/поворотом |
| A, удержание | Fire (`0x200`); исполнение оружия — G13 |
| Start, нажатие | Use (`0x800`); исполнение взаимодействия — G09 |
| Select, нажатие | RU/EN, без смены мира и состояния движения |
| Start+Select | Существующий диагностический panic, код `0x10` |

D-pad и плечи совместимы, например ↑+L — ход со стрейфом, ↑+← — ход с поворотом.
Адаптер хранит held/pressed/released; Start передаётся один раз и сохраняется
до ближайшего шага, даже если между двумя опросами шаг не наступил.
Переназначение пока выполняется в `dok_input_commands`, пользовательского меню
нет. У DOS стрелки соответствуют тем же движениям, Alt+←/→ — стрейф,
Shift — Run, Ctrl — Fire, Space/Enter — Use. WASD и прямая мышь патча
не приписываются оригиналу.

Конструкторы обоих EXE назначают событие героя с `PUSH 0x1A0` (416 ticks).
В GBA используется тот же номинальный квант: **416 native ticks≈41,49мс,
24,103 обновления/с**, отдельно от G06 диагностической сетки100 ticks
и частоты вывода. Подробнее о DOS: [original-cadence.md](original-cadence.md).

`gba_motion_poll` получает время из G06 timers2/3, накапливает долг через
`dok_steps`, выполняет до128 обновлений за poll и сохраняет оставшийся долг.
Это сознательное отличие от native scheduler, который не догоняет пропуски:
скорость порта не должна зависеть от достигнутого render FPS. Ввод читается
раз за CPU-кадр; новое held-состояние применяется к доступным фиксированным
шагам в этом poll. Исторических аппаратных событий внутри пропущенного кадра
адаптер не восстанавливает; короткий press/release целиком между опросами
может быть пропущен. Frame interpolation пока нет.

Камера берётся из изменённого runtime player перед renderer. Test-only mailbox
`g_camera_probe` включает отдельный режим камеры для G06A-регрессии;
`g_motion_probe.test_mode` замораживает live motion и исполняет заданное число
416-tick шагов. Оба отключены после обычного reset и не заменяют GBA-кнопки.

## Проверки и пределы доказательств

- Ghidra: оба оригинальных EXE, листинги, байты, конструкторы/descriptors,
  SHA до/после; `analysis/g07-movement-evidence.json`.
- Unicorn2.1.4: **2667 векторов на язык**, из них2367 исходной арифметики
  и300 исправленной политики. Выполняются экспортированные Ghidra x86-инструкции
  обновления и тригонометрического кандидата. Clock перехвачен; collision
  принимает координаты без препятствий. Обёртка трёх подшагов перехвачена
  и воспроизведена по ASM; её occupancy/door эффекты не проверяются.
  Покрыты signed wrap, большие elapsed, накопители, отрицательные скорости,
  границы угла, совместные flags. Reference-векторы —
  `research/evidence/movement/reference-vectors.json`.
- Native: исполнены11 Windows-наборов, включая новый movement suite;
  Linux static test binary и ARM7TDMI Thumb module скомпилированы.
  Linux binary и CMake/MSVC в этом проходе не запускались.
- ARM/mGBA: тот же edge suite, пошаговая траектория с C/ПК,
  реальные кнопки через libretro input, кадры с движущейся камерой,
  мгновенная остановка без последующего дрейфа, Use без повторов при удержании,
  RU/EN с сохранением позы, poisoned-RAM reset и guards.
  `analysis/g07-gba-verification.json`, PNG `build/g07/movement-*.png`.
- Регрессия: все1455 камер LEVEL1–3, независимый стартовый HUD/палитра,
  все443520 сочетаний банка и linked payloads, G06 clock/scheduler/reset.
  `analysis/g07-{camera,renderer,time}-regression.json`,
  `g07-host-verification.json`, `g07-column-verification.json`.

Это не полный запуск DOS-игры и не проверка DOS-коллизий. Нового динамического
DOS reference-run в G07 не было. Совпадение C/ARM не выдаётся за совпадение
с полной DOS-игрой; исходная арифметика проверена отдельным x86-исполнением.
Физическая GBA и оригинальный BIOS не проверялись.
