## Почему сейчас около 30, а не около 60

В текущей тяжёлой сцене работа ARM9 занимает около 31–32 мс, а для одного
нового кадра на развёртке 59,826 Гц доступно примерно 16,715 мс. Геометрия
занимает около 10,29 мс, отдельный native producer раскрытия карты — 7,40 мс,
GPU submission — 6,85 мс. Это уже около 24,5 мс без остальной simulation,
sprites, 2D-оружия, эффектов, HUD и карты. Disclosure входит в sprites total;
повторно складывать эти два столбца нельзя.

Это измеренные потери нынешнего конвейера, а не установленный аппаратный
предел DS. Конвейер ещё тратит CPU на повторное восстановление и обход одной
структуры сцены разными потребителями, на разреженные immutable object fields
и на перенос неизменных пикселей. Сравнение частоты других шутеров без одинаковой
сцены и замера не объясняет конкретную стоимость этих функций. Достичь 60
одной сменой частоты карты нельзя: требуется убрать примерно половину текущей
CPU-работы. Такого результата пока нет и он не обещается.

Текущий короткий пакет всё ещё имеет интервалы по 3 VBlank и минимальное
окно ниже половины развёртки. Даже строгий бюджет около 30 ещё не принят;
короткий heavy packet также не заменяет итоговый полный RU/EN sweep.

## Отклонить неподтверждённую микрооптимизацию

Tiny-row unroll в map raster не показал выигрыша. На одном и том же frame3:
5,3907 мс C11 → 5,7297 мс C12 (+6,3%). В case39 cold redraw:
5,5707 → 5,8516 мс (+5,0%). Оба сравнения относятся к реальному raster,
а не к сумме других изменённых стадий. Byte-exact proof доказывает корректность,
но не эффективность. Рекомендовано вернуть короткий исходный memset loop.
Root принял это решение; typed endpoint equality рассматривается отдельно.

## Историческая гипотеза следующего выигрыша

Компактная per-call glyph/+54 table устраняет многократные линейные поиски
одного и того же поля, сейчас выполняемые для клетки и её четырёх соседей
в geometry и native producer. У `dok_level_field_at` до 19 полей на объект.
Это подготовка данных для текущего прохода, а не persistent cache с invalidation.
Исполнитель готовит таблицу 1024 байта: native в существующем scratch, scene
локально. Требуется ARM stack proof не хуже принятого исходного N21; C11
ранее убрал один 1108-байтовый stack cell, но арифметика размеров не заменяет .su.

Передан исполнителю строгий checklist:

- Таблица должна следовать фактическому 1-based glyph_index и сохранять
  invalid index/field_count поведение. Нельзя строить эквивалент только через
  objects[i].glyph при произвольном synthetic model.
- По offset0x54 берётся первое совпадение. Наличие/тип поля и WORD(value) —
  разные свойства: старый field54 читает WORD(value), а surface validation
  отдельно требует существующее поле kind WORD.
- Текущие TMap/FCMap, runtime flags override и live bindings/image dimensions
  не превращаются в immutable metadata. Сохраняются source plane/order rules.
- Borrow заканчивается с вызовом. Общая scratch memory позже используется
  overlay и другими стадиями; таблицу нельзя оставлять скрыто заимствованной.
- Публичные candidate/output/error contracts и private ignored-tail contract
  сохраняются; validation нельзя молча заменить предположением о валидном мире.

Раскрытие всё ещё работает каждый presentation, хотя actual map raster
в heavy packet выполнен только **3 раза из 154**. Это объясняет, почему
ограничение частоты нижнего растра само по себе не снимает 7,4 мс producer.
Полностью visited gather допускает математический no-op, но initial snapshot
содержит всего 14 visited при 236 native records: такой predicate в этой сцене
вряд ли полезен. Общий cache native inputs сейчас добавит больше сложностей,
чем компактная подготовка полей.

## Ещё 1,37 мс доказанной пустой работы

Во всех **154 из 154** heavy gameplay probes оружие имеет visible=0, image=0.
Тем не менее каждый кадр очищаются, flush'ятся и переносятся DMA 39 424 байта
пустого overlay. Стадия занимает около 1,37 мс. Это конкретный кандидат
дополнительной экономии, не предположение о редкой смене оружия.

Рекомендован узкий fast path hidden→hidden после известного blank VRAM.
Visible кадры продолжают использовать нынешний полный путь; visible→hidden
выполняет один clear. Level load и возврат из frontend инвалидируют blank-valid
state. Shared scratch и raw texture pointers не сохраняются; общий pose cache
не нужен. Audit/reference path и независимые LCD-проверки остаются полными.
Малый флаг можно разместить в существующей платформенной структуре только
после sizeof/offsetof доказательства; рост BSS/RAM заранее не предполагается.

Подготовка полей и hidden-overlay skip переданы напрямую исполнителю.
Выигрыш каждой правки должен подтверждаться одинаковым heavy packet, затем
полным набором, без снижения точности раскрытия, эффектов или прежних guards.
