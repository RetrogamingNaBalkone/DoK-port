# N09: доказательства исходного ввода и кинематики

29 октября 2026 года. Этот документ описывает PKR/PKE и независимое исполнение
их инструкций. Новое NDS-ядро описывается отдельно в [N09-input](N09-input.md).

## ABI и состояние

Native far call использует 16-битный стек: actor — offset/selector в `[BP+6/+8]`,
доступ через `LES ES:BX`; DS устанавливается из SS. Входной elapsed — uint32,
возвращённый clock через DX:AX и собранный `SHL/SHRD`. Pointer arithmetic не
переносится в host указатели. Подшаг получает signed WORD distance и WORD strafe.

| Offset actor | Значение |
|---|---|
| `+1C` | uint32 flags, после сохранения команды очищается маской `FBE7DFC3` |
| `+26/+2A/+2E` | signed32 x/y/z |
| `+32/+34` | signed WORD heading / angular parameter |
| `+38/+3C` | signed32 base speed / текущий distance |
| `+7C/+7E` | signed WORD turn step / linear step |
| `+82` | WORD предыдущий знак поворота |
| `+86` | native stopwatch, 10 байт |
| `+90/+94` | signed32 поступательный / угловой накопитель |
| `+98/+9A` | signed WORD знак разгона / uint32 последние flags движения |

Конструктор обнуляет оба накопителя, оба шага, distance и last turn, задаёт
accel sign = 1. Поле `+9A` этот конструктор не пишет; при нулевом накопителе
оно не используется до первой команды движения. Порт вправе явно начать его
с нуля как безопасную инициализацию, а не приписывать эту запись DOS.

Stopwatch создаётся остановленным, с elapsed = 0. Motion сначала вызывает
stop/read, в конце start. Поэтому первый вызов после создания получает elapsed
0, последующие — время от конца предыдущего motion. Start не суммирует прошлые
интервалы; активный read записывает `now - baseline`. Событие героя имеет период
416 native ticks, но реальный scheduler опрашивается независимо от этого периода;
см. [N08-time](N08-time.md). В oracle elapsed подаётся явно; работа PIT и callback
героя целиком здесь не эмулируются.

## Исходная арифметика

При любой поступательной команде `0x10/0x20/0x80000/0x100000` знак разгона
становится +1, сохраняются текущие flags в `+9A`; иначе знак −1. Накопитель
`+90` меняется на low32 `sign * elapsed`, затем signed clamp 0…10000. Угловой
`+94` получает low32 `+elapsed` и ограничивается сверху 10000; отрицательная
граница отдельно не исправляется. При отсутствии поворота он сбрасывается.

Фактор — unsigned `((elapsed << 8) mod 2^32) / 416`. Если есть поворот и
вперёд/назад, оба накопителя приравниваются большему, фактор делится SAR на 2.
Потом signed clamp 256…768, Run `0x2000` удваивает фактор, slow `0x04000000`
делит SAR на 2. Минимальный clamp действует и при elapsed = 0.

Поворот: low32 `angle_parameter * factor * turn_accumulator`, signed IDIV10000,
SAR8, сужение до signed WORD, ограничение только сверху 18. При смене направления
первый шаг принудительно 1. Left прибавляет угол, затем при signed heading ≥360
один раз вычитает 360; right вычитает угол, затем при signed heading <0 один
раз прибавляет 360. Это не полноценное modulo для повреждённых состояний.

Шаг: low32 `speed * factor`, SAR8, low32 умножение на movement accumulator,
signed IDIV10000, сужение до signed WORD. Если шаг ≤0, он и накопитель обнуляются.
При отпускании ещё используется запомненное направление, пока накопитель не
затухнет. Это **исходная поступательная инерция**, которую NDS сохраняет.

Движения вызываются последовательно: forward (−step), backward (+step),
strafe left (−step), strafe right (+step). Противоположные команды не отменяются
до вычисления. Отрицательный SAR может оставить суммарный дрейф; диагональ
не нормализуется. Одновременные left и right также исполняются по очереди.

Wrapper принимает signed WORD полного distance, делает `SAR AX,2; CWDE`,
публикует quarter distance в `+3C` и исполняет ровно три кандидата. После цикла
восстанавливает в `+3C` **полный sign-extended WORD аргумент**, а не quarter.
Если ни одного wrapper не вызвано, прежний distance сохраняется.

Кандидат берёт heading, при strafe прибавляет 90 как WORD, затем по одному
исправлению ≥360 и <0. После чтения Q15 sin/cos:

```text
x = low32(x + SAR15(low32(sin[h] * distance)))
z = low32(z - SAR15(low32(cos[h] * distance)))
```

Y не меняется. Порядок low32 IMUL, SAR, IDIV и сужения существенен; замена
wide float или C signed overflow не эквивалентна этим инструкциям.

## Ввод оригинала

Оригинал строит отдельное командное слово, обнуляя его перед опросом.
Стрелки left/right дают turn `4/8`, с Alt — strafe `0x80000/0x100000`;
up/down — forward/back `0x10/0x20`, Ctrl — held Fire `0x200`, любой Shift —
held Run `0x2000`. Space и Enter дают один Use `0x800` **по отпусканию**.
NDS-раскладка из плана — отдельная адаптация этих команд, не DOS scan mapping.
Plus/minus создают `0x8000/0x10000`, но motion не меняет высоту по этим bits;
прыжок или вертикальный интегратор отсюда не следуют.

Это уточнено исполнением настоящих IRQ1 и обоих readers: fresh make пишет
state3 (held bit1 и pending bit2). Reader Use сравнивает строго `state == 2`,
поэтому при удержании state3 возвращает false и не очищает pending. Break
выполняет `state &= 2`; следующий Use poll получает true и делает `state &= 1`,
оставляя0. Повторного Use при удержании или следующем poll нет. Held reader
возвращает исходный state и очищает bit2; это другой API. Одновременные Space
и Enter опрашиваются оба в одном poll, оба pending очищаются, команда одна.
NDS X/B сохраняют эту release-семантику; имя сервисного поля — `use_triggered`.

## Независимое исполнение и границы

[audit_movement.py](../../../ports/nds/tools/audit_movement.py) исполняет
экспортированные инструкции через общую исследовательскую установку Unicorn
2.1.4. Python/C модель кинематики в oracle не импортируется. Выполняются сами
motion, wrapper и trig candidate; исходные near/far переходы, WORD стек и
prefix32 сохраняются. Перехвачены только stop/read/start, held/edge keyboard
readers и collision boundary. Вспомогательные игровые UI-ветки не активируются.
Эти 256 комбинаций проверяют сборку команд из управляемых значений readers;
они сами по себе не доказывают семантику reader. Её отдельно проверяет
`OriginalKeyboard`: подлинные IRQ1, held reader, Use reader и game poll,
с инъекцией только портов `0x60/0x61` и наблюдением PIC acknowledge `0x20`.
Четыре последовательности (Space, Enter, оба, короткий tap) содержат make,
несколько polls, break и повторный poll; ещё восемь проверок на язык исполняют
два readers для каждого state0…3. Стек IRQ использует настоящий IRET.

Wrapper получает управляемый мир 64×64, cell480, tile0/class0 и реальные
буферы occupancy. Его три подшага и записи occupancy исполняются инструкциями,
но эта fixture не подтверждает коллизии, дверные counters, entities и полную
DOS-сессию; их восстановление относится к N10/N11. Candidate collision принимает
запрошенные x/z. Каждый substep сохраняет quarter distance, strafe и исходный
candidate x/z, так что host можно сравнить также по промежуточным вызовам.

Все 722 слова sin/cos загружаются прямо из ранее записанной original RU RAM
`research/evidence/reference/ru-03/level1-memory.bin`, linear `0x1CA9B0`, SHA-256
`c8ff1347518aae86af31b8ed2c6f6443c4c63c9157b4a52bf76d53c7f5c95629`.
Исходный x87 initializer заново не исполняется; для EN подставлена та же RU
таблица как явно заданный вход, а не заявлена независимая EN RAM-проверка.

Векторы включают все 360 корректных heading и границу 360, 8 направлений, разгон/отпускание,
противоположные команды, комбинированный поворот/ход, Run/slow, elapsed 0,
границы 415/416/417, большие uint32, low32 overflow, signed speed и накопители.
Повреждённые heading/angle проверяются только при speed0 без чтения таблицы:
исходный выход за её границы безопасным не считается. Оба EXE должны дать
идентичный state и каждый промежуточный candidate. Дополнительно исполняются
256 комбинаций исходных held-клавиш и четыре сочетания Space/Enter.

Первичный крупный отчёт `research/evidence/nds/n09/original-motion.json` хранится
локально. Он содержит входы и результаты каждого исходного исполнения, снимки
последовательностей и manifest-пины; компактные численные итоги передаются в
паспорт N09. Отдельный `--probe` сравнивает новое host-ядро, не заменяя oracle.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/nds/tools/export_movement_evidence.ps1
C:/Source/wasdify/.venv/Scripts/python.exe -X utf8 ports/nds/tools/audit_movement.py
C:/Source/wasdify/.venv/Scripts/python.exe -X utf8 ports/nds/tools/audit_movement.py --probe build/nds/n09/motion_dump.exe
```

Результат: **9960 изолированных векторов и 106 последовательных вызовов на язык**.
Оба EXE дали одинаковые 17 scalar/state полей и каждый candidate; исполнены
**29802 + 285 подшагов на язык**. Независимый NDS host probe совпал по всем
10066 вызовам, включая каждый distance/strafe/x/z подшага. Проверены также
256 held-комбинаций и четыре Use-комбинации на язык. Primary report имеет
14404151 байт, SHA-256
`7722226888fd05e1ad243012a48b98f0ab3d3a17cc7ffae94fa43155544245ea`;
host `motion_dump.exe` — 153600 байт, SHA-256
`467bb49d6218aca7a05b1d0dc98f75b26687978ef0e766da35e2c9e70ed7e43f`.
Повторная компиляция в общем gate может изменить host binary pin; новый отчёт
фиксирует фактически запущенный executable.

Первый host-прогон отверг некорректный стресс-вектор: экстремальный угловой
накопитель дал heading −748, после чего native прочёл соседнюю память вне trig.
C отказал безопасно. Генератор перевёл такие повреждённые угловые состояния
в scalar-only speed0; отдельный oracle guard теперь запрещает чтение индекса
вне 0…360. Игровое ядро этим исправлением не менялось. Малый журнал опыта —
`research/evidence/nds/n09/experiments/rejected-unsafe-index.json`.

Совпадение host/ARM9 между собой не выдаётся за доказательство исходного
поведения; полная DOS-сессия и физическая DS/DS Lite здесь не проверены.
