# N06: визуальный контракт двух экранов

Уточнение пользователя при N19, 29 октября 2026 года: большие числа должны
располагаться ближе к иконкам. Runtime использует левое выравнивание
здоровья в x23 и заряда в x97 с видимым зазором 2–3 px; подробности —
[дополнение UI](N06-ui.md). Описанные ниже растры N06 остаются историческими.

29 октября 2026 года. Контракт фиксирует проекцию, читаемый интерфейс и
контрольные изображения до реализации аппаратного renderer. Исходные
доказательства и адресация — [камера](N06-camera.md), [DOS-захваты](N06-references.md),
точные позиции и полные тексты — [UI](N06-ui.md). Фактическая приёмка и команды —
[паспорт N06](../tasks/N06.md).

## Принятые решения

| Область | Контракт |
|---|---|
| Верхний экран | 256×192; сцена y=0…153, HUD y=154…191 |
| Исходный показ | DOS 320×200 на мониторе 4:3; физический pixel aspect 5:6 |
| Сцена | 320×160 → 256×154, X×4/5, Y×77/80; исходный обзор сохранён |
| Статические фоны | Полные 320×200 → 256×192, X×4/5, Y×24/25 |
| Principal point / focal | (127.1,76.01875) / (160,192.5), index coordinates |
| Обзор | 77.3194034812° горизонтально, 43.6026060730° вертикально |
| Глаз | native depth+200; асимметричный frustum, не стандартный perspective(256/154) |
| HUD | FONT16 для HP/заряда/оружия; FONT8 для попыток, счёта и сообщений |
| Числа | Полный signed16 −32768…32767, без сокращений и сжатия глифов |
| Тексты | Исходные FONT8/FONT16 и CP866; все байты до native NUL/$; пагинация |
| Нижний экран в игре | Карта 256×160, закреплённые кнопки масштаба и центра 32 строки |
| Нижний экран заставки | Полный текст по страницам; A вперёд, B назад |

Отдельное округление 153.6→154 даёт вертикальное отклонение 0.2604167% от
идеального 4:3. Оно сохраняет исходные крайние лучи. Увеличивать обзор ради
154 строк нельзя. Геометрический oracle сохраняет исходные low32 arithmetic,
SAR и signed IDIV; непрерывная GPU-матрица — отдельная адаптация с проверкой N07.

HUD перестроен для читаемых чисел и иконок слева: HP x4/24, заряд x82/100;
три ключа x156/172/188, оружие x220. Значения занимают шесть клеток FONT16.
Строка попыток/счёта y174, сообщений y182; полоски отношения к максимуму y172
сохраняют смысл изменения максимума. Сообщения имеют 28 колонок и явный номер
страницы; многоточие не заменяет остаток текста. Максимальная исходная строка
36 байт помещается на двух страницах. Периоды жизни/переключения сообщений
восстанавливают N08/N19, offline-макет их не задаёт.

Карта сейчас представлена схемой неизвестного чёрного поля, условным указателем
и тремя кнопками «−», «+», «Центр»/«Center». Это принятие расположения; цвета
visited, раскрытие клеток и touch ещё не реализованы и проверяются в N20.
Вся локализация показывает один RU-мир; исходная EN-поза и EN-числовые поля
не меняют мир. Игровые сохранения не вводятся.

## Эталоны и происхождение

`compose_visuals.py` читает неизменный N04-пакет и три новых **clean PLAY RU**
захвата: `research/evidence/nds/n06/dos/ru/levelN-clean/play-clean.*`.
Снимки получены штатным вводом эмулируемой клавиатуры после завершения native сообщения попытки;
оно не дублируется выдуманной строкой HUD. Согласованность VGA индексов,
DAC6 и независимого RGB проверена; scheduler работает, глобальная пауза
не заявлена. Фаза отдельных эффектов неизвестна. Шесть исходных EN/RU
сеансов с сообщением и шесть clean сеансов сохраняются раздельно.

Измеренная PLAY-палитра содержит `max(0,GAMEPn−1)` в DAC6; причина этого
состояния не доказана. Эталоны сцен и нового HUD используют **измеренную**
палитру, DAC6→RGB5 через `channel>>1`. Это не изменение N04 assets и не правило
для всех будущих кадров. Статические фоны используют resource RGB555 N04;
различие с наблюдаемой фазой DOS title отмечено отдельно. N13 восстанавливает
fade/LIGHT/воду и поведение палитры во времени.

Offline PNG расширяет RGB5 до полного диапазона RGB8 (31→255) для просмотра.
Закреплённый libretro core выводит через RGB6: `(c5<<3)|(c5>>3)`, 31→251.
Поэтому byte equality preview PNG и emulator PNG не требуется: точное
сравнение выполняется по RGB5 и отдельно по доказанной формуле RGB8 core.
Это различие представления цвета не меняет измеренную исходную DAC-палитру.

Nearest sampling использует центры целевых пикселей:

```text
sx = floor((2*x+1)*320/512)   x=0…255
sy = floor((2*y+1)*160/308)   y=0…153
```

В scene не попадают исходные строки HUD. Для RU/EN одного уровня все верхние
154 строки побайтово одинаковы. Все HP/charge/lives/score исходного кадра
взяты из captured actor; начальные максимумы 100/100, отсутствие ключей и
weapon0 — из исходных RU-определений героя, проверенных в N05. Это отдельные
входы макета, не поля полной runtime-структуры InitialWorld. Подготовленные
canvas не исполняют события или движение.

| Case IDs | Содержание |
|---|---|
| 1…6 | Три clean RU уровня × RU/EN HUD, нижняя схема карты |
| 7…8 | Исходный титул × RU/EN приглашение продолжить снизу |
| 9…10 | Синтетические signed16 пределы HUD, все ключи и weapon3 |
| 11…14 | BINTRO1 RU/EN: первая и последняя полные страницы, BSPR1 сверху |
| 15 | Синтетические физические круги, principal cross, все 32 уровня RGB5 |
| 16 | Синтетическая проверка высот ceiling−951/−561 и горизонта |

Case16 опирается на реальные FCMap parameters и ASM, но его прямоугольники —
аналитический контроль, **не исполнение DOS в низком коридоре**. Исходные
клетки, offsets, численные vertices/near cases находятся в
`height-near-fixtures.json`. Полноценные низкие потолки/уступы проверяются N07.

Текущие растры и внешний index — `build/nds/n06/frames/`; `manifest.json`
содержит имена, состояния и SHA каждого кадра. `visual-report.json` и PNG
сравнений лежат в `research/evidence/nds/n06/`. Физический aspect сравнивается
при DOS 320×240 и DS 320×240; оригинал 320×200 не показывается как квадратные
пиксели. Три contact sheets показывают все 34 страницы 16 текстов в родном
размере DS. В Git идут только инструменты, спецификации и компактный JSON;
игровые растры и payload остаются локальными.

## Разделение проверок и последующая приёмка

N06 проверяет факты DOS/ASM, новый численный oracle, offline layout и показ
готовых bitmap на ARM9 независимо. Совпадение нового C с Python не заменяет
исходные ASM/RAM. ARM9 viewer читает FAT/DLDI, проверяет SHA и непрозрачность,
публикует обе стороны только после успешного чтения. Он не использует 3D engine.

N07 сравнивает **геометрию**: principal point, крайние лучи, depth+200, clipping,
численные границы vertices/высот, стартовые poses всех трёх уровней. Щели,
ошибочные поля, потерянные поверхности, расширенный FOV и неверная высота —
ошибки, а не допустимые отличия sampling. Texture interpolation, subpixel
raster rules и DS precision оцениваются отдельно; побитовое равенство DOS
растру не обещается. Far plane, единицы GPU, VRAM working set и ранние
эмуляторные бюджеты принимаются в N07 до точечных оптимизаций.

N13 сравнивает **цвет/эффекты**: исходные индексы и реальные DAC, LIGHT tables,
fade, воду, отражения и движущиеся поверхности. Простая RGB-модуляция не
принимается эквивалентной таблицам без доказательства. Нельзя маскировать
ошибку палитры допуском для sampling.

N19 сравнивает **интерфейс**: границу 154/38, точные позиции, полные числовые
значения, очистку старых разрядов, три ключа/четыре weapon slots, все сообщения
и story pages. Пагинация обязана сохранять каждый исходный печатный байт и
порядок. Runtime cadence и активный мир проверяются дополнительно к layout.

Реальная DS/DS Lite, microSD/loader, читаемость LCD и FPS проверяются в N24
на итоговой сборке по поручению пользователя. N06 не измеряет производительность
игры и не закрывает аппаратный риск renderer.
