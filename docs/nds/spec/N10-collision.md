# N10: горизонтальная проходимость и занятость

Реализация: [collision.h](../../../ports/nds/include/dok/collision.h),
[collision.c](../../../ports/nds/core/collision.c). Решения приняты до реализации.
Это независимые native C11-типы NDS; код GBA не используется как основа.
Карты и определения заимствуются у принятого [N05](N05-world.md), порядок
подшагов и кинематика — у принятого [N09](N09-motion.md). Ввод, AI, GPU mesh,
часы и очередь событий в collision core не входят.

## Источники и адресная система

Адреса — Ghidra NE loader исходных PKR/PKE, не файловые смещения, индексы
NE-сегментов, DPMI runtime-селекторы или вставки WASDify. Первичные указатели
найдены по [исследованию collision](../../gba/collision.md); автоматический
C-псевдокод не объявляется проверенным эквивалентом и не включён в движок.
Ветви нового C сверены с ASM; независимое выполнение исходных инструкций
и контрольные SHA оформляет отдельный N10 evidence/oracle.

| Роль | PKR RU | PKE EN |
|---|---|---|
| Четыре угла footprint | `1098:0448` | `1030:052C` |
| Resolver со скольжением | `1098:0901` | `1030:09E5` |
| Тригонометрический кандидат | `1098:0E13` | `1030:0EF7` |
| Три подшага, MMap и счётчики дверей | `1068:0EB1` | `1020:13BB` |

PKR.EXE SHA-256 `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`;
PKE.EXE SHA-256 `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
Ниже описаны именно эти горизонтальные процедуры, а не все виды столкновений
игры, снарядов или вертикальных эффектов.

## Чистый слой исходной геометрии

`dok_collision_view` заимствует MMap, TMap, flags и known по 256 glyph.
`dok_collision_native_clear` и `dok_collision_native_resolve` не меняют мир.
Первый принимает исходный signed WORD radius, второй использует world Min Dis.
В штатных уровнях ширина/длина64, Cell Side480, Min Dis238. Проверяется квадрат
с полушириной238, а не персональный круг героя. Все четыре допустимых центра
узкого прохода — origin+238…origin+241 — сохраняются.

Порядок footprint: `(x−r,z−r)`, `(x−r,z+r)`, `(x+r,z−r)`, `(x+r,z+r)`
сначала в MMap, затем те же четыре точки в TMap. Lookup допускается только
при установленном бите0x10 flags объекта (`object+0x15`, младший байт общего
слова flags). Класс, текстура, sprite flags и flags команды движения эту
проверку не заменяют. Неизвестный glyph закрыт: это безопасная замена
недопустимого far-pointer lookup, а не доказанное DOS-правило повреждённой карты.

Арифметика x±r, dx/dz, NEG и вычисление центра/края явно выполняется по
модулю2³² без C signed overflow. Signed IDIV на положительный Cell Side
усекает к нулю; частное сужается в signed WORD, затем прижимается к карте.
Так воспроизводится native clamp и для отрицательных/крайних int32 запросов.
Размеры чистого представления ограничены1…64, Cell Side положителен;
нулевой/отрицательный делитель отвергается до вычислений. Это граница API
порта, не обещание исполнять повреждённый world с native division fault.

Resolver выбирает X первым только при signed `abs(dx)>abs(dz)` после
исходного условного NEG32; равенство идёт по Z. Следуют точные ветви:
основная ось, полный кандидат, центр соседней оси, край исходной клетки.
Край при движении в минус — `old−old%side+r`, в плюс —
`old−old%side+side−r−1`. При экстремальном dx=INT32_MIN NEG32 остаётся
INT32_MIN: новый код не подменяет это математическим abs64.

Исходная асимметрия сохранена: RU `09F6…0A8C` вычисляет ограниченный центрZ,
но `0A90…0AD7` безусловно заменяет его центром клетки меньшего endpointZ.
У X такой замены нет. Это наблюдаемая инструкциями особенность, а не
попытка улучшить геометрию.

## Владение и admission

`dok_collision_state` заимствует единственный mutable `dok_initial_world`.
Карты не дублируются. Собственные bounded таблицы — flags uint16[256],
door_count uint16[256], known byte[256]; класс и ссылки берутся из immutable
определений/seed. `glyph_index` N05 имеет формат index+1, zero означает отсутствие.
ID объекта не считается glyph. Полная ссылка `{epoch,id,generation}` проверяется.

`dok_collision_bind` проверяет RU, настройки, все исходные map glyph,
однозначные определения и seed references до публикации состояния. Flags
копируются из effective определения, door_count начинается с0 по исходному
конструктору. Время жизни definition, CP866 asset и initial_world дольше всех
заимствований. Корректно типизированные state/context/plan предоставляет caller;
нет malloc, SDK, рекурсии, DOS-layout casts или хранения указателей в uint32.

`dok_collision_begin` вызывается ДО `dok_motion_update`, проверяет эпоху,
полную ссылку, размещённый класс1/9, bounded origin, собственную/пустую MMap
клетку и scalar calculation N09. Наибольший по модулю quarter-step должен
быть строго меньше половины клетки; иначе отказ до любых side effects.
Class5 пока не допускается: N05 не выдаёт ему размещённую позу; динамический
жизненный цикл будущих снарядов требует отдельного API N15. Scalar candidate
не публикуется, и callback никогда не читает переданный motion state.

Begin выдаёт одному context исключительное право на мир до `end`.
В этот промежуток запрещены другие акторы, setters, reset, render lease и
произвольные изменения карт. Immutable trig N09 проходит свой preflight до
первого callback. Если update отказал до callbacks, context закрывается `end`;
занятость не изменялась. Revision резервирует12 подшагов до uint32 exhaustion.
Переполнение revision не оборачивается в живую старую query identity.

## Query/commit каждого подшага

`dok_collision_query` читает только полный `dok_motion_substep` и context.
Проверяет текущую позу/ordinal; чужую origin occupancy не стирает. В чистом
lookup ровно старая MMap клетка логически заменяется пробелом. Другие клетки
с тем же glyph сохраняются: повторные размещения N05 не дают общего self-ignore.
Query создаёт plan с revision; `commit` отвергает устаревший/reused plan.
Поля plan приватны по контракту: нельзя редактировать или подделывать их.

Для короткого корректного запроса сначала вызывается исходный resolver с
native clamp, затем проверяется итоговый footprint: полностью внутри реального
мира и свободен. Raw candidate заранее не отбрасывается только за выход края:
закрытая граница может разрешить скольжение вдоль стены. Недопустимый итог
возвращает old x/z. Слишком большой запрос тоже возвращает old x/z.
Исходные scalar-инерция и оставшиеся подшаги N09 продолжаются.

Обычный blocked/adjusted подшаг остаётся полноценной occupancy-транзакцией:

1. У class7 в старой TMap клетке счётчик уменьшается, только если ненулевой.
2. Старая MMap клетка записывается пробелом.
3. Результат resolver/admission принимается; при блокировке это старая поза.
4. У class7 в итоговой TMap клетке счётчик увеличивается по модулю65536.
5. В итоговую MMap клетку записывается glyph актёра.

Query выполняется без временного изменения карт; перенос вычислений перед
commit эквивалентен этим инструкциям, потому что проверка не читает счётчик,
а исключение старой клетки воспроизводит запись пробела. Callbacks между
пунктами не вызываются. Важный исходный эффект: door_count0 при остановке
в той же клетке становится1 после трёх подшагов, не0. Вход в другую дверь
с count65535 увеличивает её до0. Это не saturation и не логическое число акторов.

`dok_collision_move` непосредственно соответствует неизменному N09 move_fn.
Для admitted requests commit не может отказать при соблюдении исключительного
владения. Дополнительная защита от ошибочного вызова возвращает старую позу,
не пишет мир и отмечает BAD_REQUEST. Это нарушение caller contract, не обычное
столкновение и не способ продолжать повреждённую игровую сессию.

Защитные отличия NDS явно отделены от native oracle: закрытый реальный край
вместо одного clamp; отказ до callback для плохих settings/ref/origin/quarter;
unknown glyph закрыт; чужая origin occupancy сохраняется; итоговый occupied
результат не публикуется, автоматического выталкивания/телепортации из стены нет.
Синтетические open-edge/occupied vectors должны классифицироваться как эти
отличия, а не объявляться совпадением исходных инструкций.

## Двери, высота и представление

`set_flags` и `set_door_count` — контролируемая граница N11 вне active context,
с полной ссылкой и revision. Count setter разрешён только class7. Нет key checks,
Use, door events/animation, vtable или AI. Тонкая визуальная дверь до изменения
flags блокирует всю клетку этим исходным путём.

Footprint/resolver не читают FCMap, y и upper/lower bounds; не добавляются
искусственные вертикальные ступени, интегратор высоты или пересечение по Y.
Class12 floor может менять gameplay slow bit ДО motion в другом исходном
callback: это отдельный эффект N13. Отсутствие вертикальной проверки здесь
не означает отсутствия высот/воды/эффектов во всей игре.

Камера использует чистую интерполяцию N09; rejected/adjusted substep сбрасывает
history. Даже интерполяция не считается автоматически безопасной в углу.
После выбора presentation pose `dok_collision_camera_clear` проверяет bounded
footprint и исключает только текущую self MMap клетку. При блокировке caller
использует последнюю committed simulation pose. Query не меняет flags, карты,
счётчики, motion, часы и события. Heading/30–60 presentation observations не
создают дополнительных simulation callbacks. Native y при этом не изменяется.

## Проверки и память

[Общий suite](../../../ports/nds/tests/collision_cases.c) использует caller-owned
`dok_collision_test_workspace` и одинаково исполняется host/ARM9. Он покрывает
четыре целых центра узкого прохода, обе ведущие оси и tie, скольжение, source
clamp/защиту края, signed limits, неизвестный glyph, full-ref refusal, admission
большого шага, query без mutation, stale plan, revision exhaustion, door flags,
0→1 и65535→0 counters, FCMap/y/bounds, duplicate self glyph и чистую камеру.
Прогон unit suite не заменяет независимое native x86 исполнение или маршруты
трёх реальных RU-уровней; полные результаты и команды фиксируются в паспорте N10.

Workspace тестов включает definition и initial_world, поэтому больше128 КиБ
scratch; runtime probe переиспользует правильно типизированную world region до
загрузки renderer. Он не остаётся вторым резидентным игровым миром. Runtime
collision state содержит только компактные таблицы и borrowed pointers;
фактические размеры host/ARM9 фиксируются проверками сборки. Hardware DS/DS Lite
отложен до итоговой N24 и не считается проверенным эмулятором.
