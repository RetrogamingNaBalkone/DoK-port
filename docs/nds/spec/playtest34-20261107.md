# N23: плейтест DraStic, заставки, попадания и управление

7 ноября 2026 года. Работа остаётся частью N23; N24 не начата.

## Наблюдения пользователя и границы результата

Пользователь прошёл первый уровень в DraStic: около 60 FPS, без вылетов во время
прохождения. Это не замер всей кампании и не подтверждение физической DS.
Затем получен отдельный отказ **diag33-ru**: после запуска уровня приставка
остаётся без ввода примерно 5–7 минут. На фотографии:

```text
Stage 6 Code 00010000
main.c:1065 / render_one
Op simulation Status 3
A 00003414 B 00000000
Game 0 AI 0 Combat 0 / Effects 0
Pose 15120 22800 H 90
GPU 00000000 00000000
Audio fault 0 U 0 S 0
```

Строка сверена с исходниками именно `research/evidence/nds/n23/candidates/diag33-ru/`;
ROM SHA-256 `e310a0a53534381ae763dd68c66980606172854e094c6d42f7f524103f1f83e6`.
Это NDS runtime/source line, не адрес DOS/Ghidra. `3` — `DOK_STATUS_INVALID_STATE`.
`nds_effects_begin()` объединял ошибку диспетчера, callback fault и чтение часов
в один статус. Нулевые Game/AI/Combat/Effects сужают поиск к диспетчеру/часам,
но **отказ часов пока только гипотеза**. На нижнем экране фотографии осталась
карта; историю событий по этому снимку прочитать нельзя.

Новая сборка сохраняет исходный статус и этап: `Sim 1` — dispatch, `Sim 2` —
runtime callback fault, `Sim 3` — water clock read; `rc` — первичный status,
`evt` — scheduler fault. `Clock` — последний реально возвращённый SDK counter,
`Last` — последний принятый world clock counter, оба uint64 hex. Getter не
перечитывает таймер после отказа. Позднее кадровое чтение часов имеет собственную
операцию `clock`. Искусственные backwards-clock и scheduler-fault проверки
проверяют диагностику, а не воспроизводят причину DraStic. Счётчик не зажимается,
игровые часы не сбрасываются, отказ не объявлен исправленным.

## Текущее поведение

- Вступление и завершение уровня без заголовков «Начало уровня» и «Уровень завершён».
  Номер страницы справа внизу, только при нескольких страницах. С первой страницы
  интермедии нельзя вернуться назад; с последующих B открывает предыдущую страницу.
  Одностраничный текст предлагает `A: Продолжить`.
  A на последней странице выполняет прежний переход.
- В разделе «Управление» из главного меню и паузы вверх/вниз выбирают схему,
  A применяет, B отменяет выбор. Под схемой сразу показаны её кнопки.
- Современная: крестовина — движение/стрейф; Y/A — поворот; R — огонь;
  L — бег; X/B — двери. Классическая: вверх/вниз — движение; влево/вправо —
  поворот; L/R — стрейф; Y — огонь; B — бег; X — двери; A в игре не назначена.
  Select переключает оружие, Start открывает паузу в обеих схемах.
- Язык и схема сохраняются только в необязательном `fat:/dok/settings.dat`.
  Текущая запись: 16 байт, `DOKS`, LE version=2/length=16, language в байте 8,
  scheme=0/1 в байте 9, нулевые 10–11, FNV-1a первых 12 байт в 12–15.
  Ошибка записи не отменяет выбор в RAM. Игровых сохранений нет.

## Попадания: намеренное исправление исходной модели

Основание исходного клеточного lookup — [N15](N15-combat.md), восстановленный
`core/combat.c::contact()`. Исследование [GBA BUG01](../../gba/g21-bat-hit-fix.md)
использовано как объяснение дефекта, без переноса архитектуры или исходников GBA.
Новое исследование EXE в этой итерации не выполнялось.

При наличии bound AI выстрел class1 проверяет каждый исходный remainder/quarter
отрезок против полуоткрытого квадрата размера клетки, центрированного на текущей
x/z позиции монстра. Side480 даёт `[x−240,x+240) × [z−240,z+240)`.
Точные рациональные времена входа сравниваются cross-products без float;
касание исключённой границы не считается пересечением. Из акторов берётся
первый контакт, при равных временах сохраняется порядок определений.
Статические препятствия и закрытые двери проверяются на том же отрезке до
выбора актора; диагональный шаг не пропускает промежуточную стену.
Учитываются flags прохода и граница карты. Мёртвые, corpse и неразмещённые
определения не являются целями.

AI владеет динамическими позициями; combat заимствует const pointer при bind,
AI clear отсоединяет его. Проверка выполняется в эксклюзивной simulation phase.
Урон, decay, исходные SAR-векторы, wake без первого урона, интервалы событий,
эффект и отвод снаряда назад сохранены. Вражеские снаряды используют исходный
lookup. Это коррекция collision модели, а не заявление об эквивалентности DOS.
