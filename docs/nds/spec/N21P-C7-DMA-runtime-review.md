Открытое обязательство предыдущего [C7 review](N21P-C7-independent-review.md)

Перенос затрагивает активную развёртку. Его продолжительность — 51 067 timer

Это первый, loading-кадр сценария. Исключение loading из steady FPS не разрешает
исключать его из проверки корректности VRAM DMA. Одной перестановки CPU prepare
до GPU submit недостаточно: stream/HUD после wait могут занять остаток blank.

## Предложение для проверки исполнителем

Перед map commit проверять наличие достаточного остатка VBlank для фиксированного
DMA 49 152 байт. При слишком позднем или активном окне ждать **одну** следующую
границу и повторно проверить admission; не вводить неограниченный busy loop.
Консервативный cutoff должен иметь явный запас относительно измеренного transfer
time. Его пригодность для физической DS остаётся N24; actual DMA gate сохраняется.

Удобнее выполнить этот guard в main, где доступны presentation timestamps:

- extra wait записать отдельно, прибавить к общему wait и исключить из CPU work;
- timestamp совместного предъявления обновить до новой границы, согласовать
  VBlank counter и interval history; дополнительная развёртка не исчезает
  из cadence или touch latency;
- map CPU оставить суммой prepare и commit, исключив промежуточное ожидание;
- repeated верхний кадр до совместного предъявления не считать новым кадром;
- удерживать borrowed snapshot seqlock odd до завершения реального DMA.

Простое скрытое ожидание внутри commit исказит map CPU и может оставить старый
presentation timestamp. Перестановка map DMA перед stream commit — иной вариант,
но он требует отдельной проверки прежнего texture upload timing contract.

Это предложение, а не описание уже выполненной правки. После изменения нужны
тот же тяжёлый пакет и полный совместный маршрут, все DMA scanline-метки,
actual LCD pixels и честный учёт дополнительного wait.
