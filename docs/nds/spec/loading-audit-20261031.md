## Проверенная лишняя работа

1. `core/assets.c:dok_assets_find` ищет через `dok_assets_entry_at`: каждая
   проба читает 128 байт. `platform/assets/file_reader.c:read_at` каждый раз
   вызывает `fseek/fread`. Каталог не остаётся в session. Полный wire-каталог:
   1466 entries / 187648 байт. `core/balance.c:dok_presentation_bind` обходит
   весь каталог и ищет primary entries. При загрузке RU с обоими языками
   bind выполняется трижды: world load, EN definition и возврат на RU.
2. `render/sprite_assets.c:dok_sprite_assets_load` берёт все animation resources
   языка из presentation, без отбора по уровню. На каждом из трёх уровней
   проба получила одинаковые 24 анимации и 168 уникальных GPU images.
3. `render/frame_store.c:dok_frame_store_load` каждый раз читает и SHA-проверяет
   кадры, сжимает, затем распаковывает и сравнивает с исходными. Для каждого
   уровня заново обрабатываются 1249728 байт; результат — 283947 байт.
   Resident store устраняет чтения во время игры, но его подготовка выполняется
   на CPU DS вместо предварительной упаковки ресурсов.
4. До первого draw `platform/audio/runtime.c:nds_audio_runtime_init` читает
   и упаковывает 22 эффекта для определения размеров, сортирует, затем повторно
   читает и упаковывает в постоянные банки. Дополнительно целиком проверяет
   8 кусков музыки заставки. Проверено по коду; отдельного времени нет.
   `fatInitDefault` до заставки тоже без отдельного замера; вклад зависит
   от носителя/загрузчика.

Host-проба вызывает реальные world/presentation/sprites/frame store с обёрткой
reader и повторяет RU rebinding текущего пути. Она считает логические запросы,
не физические операции NitroFS/SD: буферы libc/носителя могут их объединять.
Не включены effects, audio, static geometry, UI, frontend append и первый draw.

98,63% вызовов здесь обслуживают каталог; это не доля времени загрузки.
Повторные поиски и подготовка банков — кандидаты на ускорение. Порядок
по времени требует ARM stage counters или парных сборок.

## Отсутствие индикации и следующий шаг

`platform/frontend/loop.inc` вызывает `level_load` синхронно перед
`frontend_restore_game` и следующим кадром. Внутри нет вывода прогресса.
`NDS_RENDER_FRAME_LOADING` — флаг диагностической истории, не экран загрузки.
На старте mount, asset open, audio init, UI init идут до первого frontend draw.

Далее N23: ARM timings mount/catalog/audio/world/bind/sprites/frame store/effects;
парные оптимизации с проверкой RAM и данных. Направления: компактный индекс
каталога, исключение повторных bind, предварительная упаковка frame/audio banks.
Сохранить resident data во время игры и целостность на выбранной границе.
Отбор анимаций должен учитывать death/projectile/effect кадры. Отдельно нужен
ранний экран загрузки с обновлением по этапам. Ускорение в разах пока неизвестно.
N23 открыта, N24 не начата. Другие порты не затронуты.
