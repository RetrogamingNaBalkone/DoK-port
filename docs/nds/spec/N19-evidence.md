## Шрифт, formatter и fixed-span сообщения

FONT8/FONT16 содержат по 256 глифов CP866, ширина 8, высота 8/16.
Каждая строка — один байт, маска идёт от `0x80` к `0x01`; размеры 2048/4096 B.
RU/EN fonts и все подготовленные HUD-банки совпали побайтово. Шрифт системными
буквами не заменяется, глифы не сужаются.

Проверенный ABI — `cdecl16far`, объект передаётся как offset:segment, `RETF`
не удаляет аргументы; caller выполняет cleanup, DS переключается в SS.
Font pointer `+1A` загружается через LES, индекс символа очищается до unsigned
byte перед умножением на высоту. Байтовая строка глифа расширяется CBW перед
проверкой маски; это не превращает индекс символа в signed char.
Координаты и clipping — signed32, границы включены. Цвета foreground/background
берутся из low byte `+1E/+20`, transparent mode равен 1. Виртуальный pixel call
получает объект и полные signed32 координаты.

Formatter потребляет байты до NUL либо `$`. LF прибавляет высоту шрифта к Y
и возвращает исходный X; CR пропускается. Остальные байты, включая CP866
128–255 и пробел, передаются глифу. Шаг X — отдельный signed WORD `+22`.
Ни CR/LF, ни `$` не относятся к универсальному предварительному очищению
fixed-span LEVEL text: это контракт строкового formatter.

Copy helper выполняет ровно 38 итераций в HUD `+2C…+51`, дополняет пробелами
после первого NUL, пишет NUL в `+52` и устанавливает dirty bits `0x22` в `+10`.
Сам copy helper **не трактует `$` как терминатор**; это проверено исполнением.
Старые GBA-сокращения двух RU-уведомлений отсутствуют во входах N19.

Исходный HUD хранит signed DWORD countdown в `+8D`. При перерисовке сообщения
он задаётся из DWORD DS:`00C2`, сдвинутого влево на два бита; helper уменьшается
на один вызов HUD, если исходное значение неотрицательно. Очистка происходит
при результате ровно 0; исходное 0 становится −1, отрицательные не меняются.
Это счётчик вызовов, его нельзя выдавать за исходный срок в N08 ticks.
Постраничный срок NDS — отдельно документируемая адаптация читаемости.

для человека, source span, file offset, resource/NE index, SHA и glyph/page
spans для **546 привязок**: 532 LEVEL и 14 констант дверей.
Максимум — 36 байт. Все исходные ведущие и конечные пробелы сохранены.
План 28×1 требует суммарно 589 страниц; одинаковые строки у разных объектов
не потеряли свои независимые привязки. `COOPER KEY IS NEEDED` сохранено

а не название отсутствующей картинки четвёртого ключа.

Каталог также содержит все 16 показываемых текстов: README, BINTRO1–3,
EINTRO1–3, ENDTXT в двух языках. Пагинация 30×9 требует 34 страниц; source
suffix после первого NUL/`$` учитывается отдельно. PANEL_DAT — конфигурация
`28 2 86`, а не текстовая заставка. Полные игровые bytes и каталог остаются
в ignored research/build. Компактные SHA и количества —
`analysis/nds-n19-ui-source.json`.

Растры берутся из RES с исходными индексами. Для иконок индекс 0 прозрачен;
это не глобальное правило world textures. NDS nearest по центрам готовит
сердце 17×14, заряд 13×16 и ключи 10×14 согласно принятой коррекции аспекта.
Текст использует GAMEP index 2, внутренняя заливка — 86. Пиксели рамки
соответствуют N06: после масштабирования ПАНЕЛЬ 256×38 сохраняются строки
0/36/37 и три крайних столбца с каждой стороны; внутренняя область очищается.

Жизнь, заряд, максимумы и score — signed16, включая результат исходного
ADD16; UI обязан вмещать −32768…32767. Все шесть LEVEL начинаются со
100/0 и максимумов 100/100; два оружейных pickup увеличивают максимум заряда
по 50, но повторяемое ADD16 не вводит универсальный предел 200.
Жизни героя — отдельный runtime WORD `actor+D6`, инициализируемый 3;
они **не являются** одним из `inventory.native_66_70[]`. Счёт `actor+D8`
начинается с 0. N21 владеет уменьшением жизней/новой попыткой. Ordinal текущей
попытки из startup — ещё один независимый счётчик, не подмена оставшихся жизней.
Оригинальные weapon slots допускают 0…8; реальные pickups занимают 1/2.
Обычные ключи имеют биты 1/2/4. В source RES нет отдельной картинки bit 8;
исходные размещённые предметы её не требуют.

## Локальный формат ui.dat

Файл `build/nds/n19/ui.dat` занимает 16 416 B, SHA-256
`5e5f6b24f5e387eb49e54e5d42b1e3bedada58a3482442e9816e08746cc583e9`.
32-byte header: magic `N19UI01\0`, затем шесть little-endian u32:
version 1, bank size 8192, languages 2, text index 2, fill index 86, reserved 0.
Далее RU и EN fixed banks по 8192 B; это ресурсный staging, не mutable world.

| Bank offset | Bytes | Содержимое |
|---|---:|---|
| 0 | 2048 | FONT8 |
| 2048 | 4096 | FONT16 |
| 6144 | 238 | Сердце 17×14 |
| 6382 | 208 | Заряд 13×16 |
| 6590 / 6730 / 6870 | по 140 | Медный / железный / золотой ключ |
| 7010 | 978 | Рамка: full rows 0/36/37, затем y1…35 pixels x0/1/2/253/254/255 |
| 7988 | 204 | Нулевое заполнение |

`build/nds/n19/generated/ui_native.inc` содержит две строки по семь точных
констант дверей `[2][7][39]`, их длины и SHA-256 двух bank. В ROM не встраиваются
fonts или raster payload; runtime валидирует header и SHA выбранного bank.
Массивы называются `dok_ui_native_text`, `dok_ui_native_text_lengths` и
`dok_ui_bank_sha256`. Этот include генерируется локально, в Git не добавляется.

## Host-проверка реального UI-модуля

`ports/nds/tools/check_hud_host.py` собирает `ui/hud.c` строгим Zig 0.13.0
в Windows DLL. Этот же C-модуль используется ARM9, однако запуск DLL не
объявляется исполнением ARM9. Тестовый wrapper дополнительно вызывает
внутренний bitmap primitive, чтобы проверить unsigned индексы всех 256 глифов
обоих шрифтов и локализаций, включая NUL/`$`, которые formatter не изображает.

Команда общего Python: `-B -X utf8 ports/nds/tools/check_hud_host.py`.
Результат `research/evidence/nds/n19/host-ui-check.json`; компактный итог —
`analysis/nds-n19-ui-host.json`. Исходники, DLL, wrapper, каталог и ui.dat
закреплены SHA; перед завершением проверена неизменность входов относительно
начала компиляции. Результат PASS:

- 1024 unsigned CP866 glyph vectors; glyph pixels берутся напрямую из RES.
- Все 589 страниц 546 исходных сообщений сравниваются целиком, по 9728 байт,
  с независимым `hud_pixel_oracle.render_hud(OriginalHudArt, …)` из исходного RES.
- Все 34 страницы полных заставок и 1697 синтетических страниц проверяют
  точные source offsets, col/row, CR/LF, NUL/`$`, пустые строки, пробелы,
  длинные слова и кириллицу.
- Все 65 536 signed16 значений проверены как числовые строки и как **полный
  растр четырёх полей одновременно** на каждом языке. Это 637 534 208 сравнённых
  байт на язык. Ускоренный независимый source-font oracle до прогона совпал
  с полным resource oracle в 75 случаях на язык.
- 864 случая: восемь сочетаний ключей, девять weapon slots, шесть крайних
  значений, оба языка. Отдельно 56 сочетаний current/maximum проверяют
  отрицательные максимумы, ноль, дробную длину полосы и clamp.
- 80 последовательных обновлений сохраняют предыдущий output и проверяют
  очистку сокращающихся чисел и исчезающих ключей. Ещё восемь кадров проверяют
  постоянные левые glyph-cell anchors x=23/97 при разном числе разрядов.

Всего 132 669 вызовов полного HUD с проверкой guard bytes по обе стороны
точных 256×38. Ни один пиксель сцены этому API не передаётся. Для исходного
рисунка сердца правый ink x=20, заряда x=94; при значении 0 текст начинается
на ink x=23/97, то есть промежуток 2 px. У значения 100 первые исходные
штрихи дают 3 px. Это пользовательская N19-адаптация фиксированных левых
привязок, а не старое выравнивание чисел вправо из N06.

## RU presentation без третьей модели

Для переключения на RU runtime передаёт `effective` также как `localized` в
`dok_presentation_bind`. LEVEL1 effective имеет принятые 39 изменений баланса;
он сохраняет точные исходные RU source bytes и spans, но его model digest
отличается от исходного RU. Прежняя проверка localized только как оригинала
поэтому отвергала такой alias. N19 выбирает `validate_sample(localized, 1)`
только при точном pointer equality `localized == effective`. Effective и раньше
проходил тот же полный профильный digest. Отдельные localized models продолжают
проходить строгую исходную проверку; отдельная копия balanced LEVEL1 не получает
разрешения alias. Это изменение устраняет лишнюю третью модель около 105 KiB,
не превращая профиль в произвольный пользовательский баланс.

Принятые до N19 исходники сохранены в
`research/evidence/nds/n19/initial/ports/nds/core/balance.c` и соответствующем
`include/dok/balance.h`. Изменение восстановленного компонента имеет отдельную
проверку: `ports/nds/tools/check_presentation_alias.py` собирает строгим Zig C11
новый `tests/test_presentation_alias.c` и неизменённые N05 `test_balance.c`,
`test_world.c`. Старые N05 отчёты не записываются, их SHA до/после совпали.

На трёх уровнях выполнены девять RU→EN→RU bindings и дополнительно прежний
nonalias RU путь. Сравниваются все 146 ресурсных записей выбранного языка,
все 10 024 результирующих привязки: 1064 текстовых spans и 8960 ресурсов.
Текст сравнивается побайтово с исходными localized source spans, IDs —
с именами/kind оригинального package catalog. 9900 обращений к числовым слотам
отвергнуты с сохранением output. Все mutable world bytes, включая заранее
изменённые visited, TMap, позицию героя и epoch, остаются неизменными после
каждого переключения; effective model и его source также не меняются.

22 negative cases проверяют повреждённый профиль, карту, source bytes,
source SHA, повторно вычисленный SHA изменённого source и недопустимый output
alias. Отдельная balanced LEVEL1 copy по-прежнему отвергается. Во всех случаях
out сохраняется. Новый тест: 126 255 checks PASS; исходные N05 balance:
21 236 checks PASS, включая 39 принятых изменений, 5000 presentation bindings,
19 отвергнутых моделей и два повторно подписанных пакета. N05 world:
5694 checks, failures 0. Это host-проверки, не исполнение ARM9 или DOS.
Отчёт `research/evidence/nds/n19/presentation-check.json`, сводка
`analysis/nds-n19-presentation.json`.

## Actual runtime: язык UI и стабильный sprite bank

Проверки одного `dok_presentation_bind` недостаточно для живой смены языка.
AI/combat и sprite bank удерживают ресурсные IDs локали, выбранной при загрузке
симуляции. Если UI переписывает `world.presentation`, следующий animation
lookup получает IDs другой локали, отсутствующие в уже загруженном bank.
Исправленный `nds_ui_language` публикует локализацию в отдельный
`NdsUiRuntime.presentation`; simulation descriptor остаётся постоянным.

`ports/nds/tools/check_ui_language_runtime.py` собирает **настоящий**
`platform/ui/runtime.c` вместе с UI, presentation и sprite-модулями. Host
`nds.h` заменяет только cache flush, DMA copy и массив BG_PALETTE. Это не
исходная ARM9 DMA, но логика language callback, разрешения сообщения,
HUD update и row upload исполняется из production C. Никакие строки
`nds_ui_language`, `nds_ui_notice`, `nds_ui_update` тестом не подменяются.

На трёх уровнях × двух simulation locales выполняются 18 фактических
RU→EN→RU calls, 1596 настоящих message/update отрисовок и 4644 шага исходного
NDS animation player. Каждый animation ID повторно разрешается через
неизменный simulation descriptor, находится в реально загруженном bank,
выбирается `dok_sprite_asset_select` на копии bank и успешно шагает
`dok_sprite_player_step`. IDs кадров сохраняют simulation locale.
Все UI text spans разрешаются из выбранной RU/EN модели и через actual update
дают ожидаемые HUD/VRAM bytes. Проверено 1596 различий локализованных текстов.

До и после смены языка сравниваются весь render world, sprite bank и его
загруженная metadata. Проверяются также собственные SHA before/after runtime
и публикуемые snapshots simulation descriptor. Результат: 35 622 checks PASS,
6 scenarios. Отчёт `research/evidence/nds/n19/ui-language-runtime-check.json`,
сводка `analysis/nds-n19-ui-language-runtime.json`.

Gate проверен контролируемой мутацией **локальной build-копии** runtime:
публикация UI снова направлена в `world.presentation`, UI descriptor при этом
заполняется, а новый внутренний SHA guard отключён. Production source не
меняется. Этот вариант проходит первый RU callback и 75 UI messages, затем
на втором вызове при переходе на EN отвергается независимой проверкой
неизменности всего world. Поэтому gate выявляет прежнюю ошибку владения
presentation, а не только наличие нового внутреннего assertion.
