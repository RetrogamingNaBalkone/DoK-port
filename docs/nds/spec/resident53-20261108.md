## Изменение

Stream planner сохраняет текстуры, не нужные текущему кадру, пока новые
запросы помещаются в свободную VRAM. Повторный key использует уже
загруженные texels без DMA. Это тот же массив128 StreamSlot и тот же
лимит393216 байт, без нового pixel buffer или увеличения регионов RAM.

При нехватке памяти сначала перерабатываются незакреплённые записи
с вращающимся курсором: совместимое выделение получает новый payload,
несовместимое освобождает место. Текущие demand закреплены заранее.
Курсор не даёт постоянно перезаписывать несколько свежих записей, оставляя
старые форматы бессрочно занимать остальную память. Если места всё равно
нет, оставшиеся незакреплённые записи удаляются, после чего сохраняются
прежние bounded relocation и полный rebuild. Это ограниченная политика
вытеснения, не LRU и не обещание удержать все кадры любой толпы.

Запись с pending0 принадлежит VRAM; её CPU pixels сбрасывается в NULL.
Истёкший raw/effect-cache pointer не сохраняет lease и не читается при
повторном показе. При переработке/rebuild свежий CPU descriptor берётся
из текущих закреплённых inputs. Reset уровня очищает весь пул и курсор.
Добавлено только4 байта состояния курсора. Порог32768 байт, fence,
prepare/commit, DMA deadline и удержание предыдущего LCD не ослаблялись.

## Проверка 256 цветов и объёма

- GPU текстуры — `GL_RGB256`, uint8 indices, ровно
  `bytes=storage_width*storage_height`. Отдельной RGBA/alpha-копии нет;
  прозрачность — index0 и флаг формата.
- Размеры для 3D GPU дополняются до степеней двойки. Например96×96 —
  9216 исходных индексов,128×128 —16384 байта storage. Это существующая
  издержка размещения; новая оптимизация формат не меняет.
- Палитра4096 WORD —16 вариантов освещения по256 цветов,8192 байта,
  а не4096-цветная текстура. Сам пиксель остаётся однобайтовым.
- Аппаратный capture готового основного экрана — отдельно RGB555,
  256×192×2=98304 байта в уже отведённом VRAM C. Это не расширение
  каждой текстуры до16 бит. Packed frames, raw RAM cache и GPU residency
  имеют разные назначения и собственные действующие лимиты.
- Максимальная фактическая texture residency выросла219648→393216 байт:
  стали использоваться прежние свободные места. Лимит384КиБ прежний.
  SDK heap196608, reserve655360 и остальные регионы прошли runtime gate.

Основания — текущие descriptor/SDK calls и локальный SDK videoGL.h,
где GL_RGB256 объявлен256-color palette. Нового исследования EXE нет;
оригинальные assets/палитры и другие порты не менялись.

## Доказательства

`check_stream53_host.py` исполняет реальные старый/новый planners с моделью
SDK:4000 кадров, по280032 проверок. Покрыты холодные/прогретые циклы,
смены форматов и прозрачности, давление памяти, принудительный allocation
failure и reset/rebuild, отказ fence без изменения записей, отравленные
CPU pointers у retired entries и соответствие скопированного pixel token
каждому запрошенному key. После давления памяти снова проверяется прогрев.
Количество DMA в прогретых участках:15840→0 и14400→0.

Модель использует96 физических слотов по4КиБ и не воспроизводит все детали
SDK fragmentation/палитры. В холодном churn выделений17959 против8281
у контроля: удержание не является ускорением каждого отдельного miss.
Восстановление после ошибок и реальную раскладку VRAM дополнительно
покрывают emulator gates.

Итоговая ROM: UI/input/RU–EN/settings/FAT/restart PASS; live/LCD всех трёх
уровней со сменой языка и touch PASS; шесть загрузок1/1/2/3/1/1 PASS;
обычные повороты LEVEL1 вправо/влево по480 video frames PASS.
Renderer/audio/map/memory guards без ошибок. Тяжёлые LCD135°/45° просмотрены.
NitroFS payload побайтно совпал с подготовленными ресурсами.
