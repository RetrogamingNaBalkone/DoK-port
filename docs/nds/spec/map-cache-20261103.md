# N23: сохранённый растр нижней карты

3 ноября 2026 года. Продолжение N23 по сообщению пользователя о просадках
при повороте и первых боях. Контроль — `animation26-ru`, результат —
`mapcache31-ru`. N23 не принята; следующий ID N23, N24 не начата.

## Причина и реализация

Смена сектора трёхпиксельной стрелки вызывала полную перерисовку карты:
очистку 256×160, проход полов и проход объектов/стен. Dirty key уже ограничивал
частоту динамических обновлений до 12 Гц, но не объём работы одного обновления.
Сверки снимков, class1 visited writes, DMA и публикация диагностик имеют свою
стоимость: время собственно растра не равно времени всей карты.

Теперь существующий INDEX8-буфер сохраняется между обновлениями. Три исходных
пикселя под стрелкой сохраняются перед рисованием и восстанавливаются в обратном
порядке. Если изменился только угол/положение стрелки при прежнем viewport,
фон/стены/полы/значки не растрируются заново.

Изменения MMap/TMap/FCMap и visited образуют прямоугольник восстановления.
Он включает изменённые клетки и соседей ±1/±width: исходная карта использует
линейные индексы, включая переход ±1 через границу строки. Внутри прямоугольника
вновь выполняются исходные два прохода с clipping всех примитивов, затем
рисуется стрелка. Это кэш готового видимого растра, без отдельного слоя статических
полигонов, без нового framebuffer и без изменения порядка наложения линий.

При изменении viewport, масштаба, map_available, языка, явной invalidation
или метаданных glyph (в том числе готовой двери/трупа) сохраняется полный путь.
Поиск изменившихся клеток пропускает четыре совпавшие клетки за раз через
выровненные WORD-загрузки с `may_alias`; невыровненные входы имеют byte fallback.
Сравнение полных planes откладывается до срока обновления, если pending turn
уже гарантирует dirty update. Class1 side effect продолжает выполняться на
каждом кадре, включая пропущенные перерисовки; PRE/POST floor debt сохранён.

Постоянное добавление — `dok_map_arrow_patch` (10 байт, с padding ARM-структуры
до 12 байт). Оно помещено в конец NdsMapRuntime: выравнивание visited и профильных
полей сохранено. Slab/reserve не увеличены. Порог и порядок texture DMA не менялись.

## Использование аппаратуры

Фактическая конфигурация: SUB `MODE_5_2D`, BG3 `BgType_Bmp8`, 256×256,
видимые 192 строки в VRAM H+I; карта занимает первые 160, кнопки — следующие 32.
Это аппаратный 2D scanout. Растр строится ARM9, переносится DMA в VBlank.
DMA не рисует линии. Аппаратные affine scroll/scale для карты сейчас не используются.
Полная карта/стрелка/кнопки находятся в одном bitmap: простое включение общей
трансформации переместит и масштабирует также стрелку и кнопки.

Эта задача меняет CPU raster reuse, а не аппаратную схему слоёв. Аппаратные
сдвиг/масштабирование требуют отдельной неподвижной UI/arrow-композиции,
согласования VRAM с MAIN capture и проверки пяти исходных масштабов. Такой
переход не объявлен выполненным. Полная передача visible bitmap в VRAM сохранена.

## Проверки, доказательства и воспроизведение

`analysis/nds-map-cache-20261103.json` содержит точные времена, FPS, SHA и
ограничения. Полные отчёты, логи и контрольные изображения:
`research/evidence/nds/n23/map-cache-20261103/`. Frozen исходники, SDK manifest,
ROM/ELF/map — `research/evidence/nds/n23/candidates/mapcache31-ru/`.

Host: 17 524 полных raster cases, 7 784 rectangle cases, 44 invalid guards,
четыре выравнивания, 9 628 385 280 сравнённых байт. Дополнительно каждый
валидный растр проходит 12 последовательных восстановлений/направлений стрелки.
Сравнение — с frozen production raster `animation26-ru`, а не новая независимая
проверка DOS. Исходные native pixel evidence — N20/N23, см. NDS-план.

Production runtime исполняется в четырёх сочетаниях audit/sector dirty.
Проверены 1 500 последовательных случайных изменений на размерах 7×9,
31×27, 64×64 и всех пяти масштабах: planes/visited/glyph, row-wrap edges,
hero, map_available; каждый показанный растр побайтно сравнивается с полным.
Сохранены прежние проверки class1 PRE/POST, DMA lifetime, pause, zoom,
touch, language, invalidation, кнопок и source/destination alignment.

ARM: melonDS DS 1.4.0, pinned core SHA в отчёте. Реальные кнопки Y/A,
120 кадров idle, по 480 кадров вращения в обе стороны, 60 settle.
Наблюдатель читает RAM/LCD и исходные pixel oracles, не пишет в эмулируемую RAM.
Это одинаковая длительность входного сценария; траектории симуляции при разных
FPS не идентичны. Отдельно проверены live/LCD трёх уровней с pause/RUEN/touch
и обычный LEVEL1-маршрут 100 клеток. Средние FPS разных bot routes не являются
чистым доказательством выигрыша оптимизации.

Промежуточные опыты сохранены и не выданы пользователю: 27 выявил потерю
выравнивания visited при вставке patch в начало структуры; 28/29 исправили
выравнивание и проверили arrow-only reuse. Первый turning observer ошибочно
использовал LEFT/RIGHT (strafe), результат сохранён отдельно; v2 использует
Y/A по фактическому input mapping. 30 убрал растр, но дорогой byte-поиск dirty
клеток съел выигрыш; 31 заменил его WORD rejection и полным fallback для редких
glyph metadata changes. Профили учитывают поиск, а не только raster.

SDK — общий Wonderful/MSYS2 из toolchain lock, host — Zig 0.13.0, Python 3.14.
Для SDK требовался запуск вне sandbox: bash signal pipe получал Win32 error5.
Оригинальные EXE не анализировались и не менялись; новой DOS-equivalence
не заявлено. Изменены только NDS-модули; игровые сохранения не добавлены.
Физическая DS и DraStic не проверены; полные N23/N24 gates остаются открытыми.
