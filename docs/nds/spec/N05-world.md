# N05: исходные определения и начальный RU-мир

Решение принято 29 октября 2026 года. Реализация независимого NDS-ядра:
[world.h](../../../ports/nds/include/dok/world.h),
[world.c](../../../ports/nds/core/world.c),
[test_world.c](../../../ports/nds/tests/test_world.c).
Данные приходят из внешнего [пакета N04](N04-assets.md), а не из встроенного
банка или GBA-модуля. Профиль баланса накладывается отдельным модулем на копию
определений. Парсер сам не выбирает профиль и не меняет исходный текст.

## Основание и предел восстановления

Использованы [грамматика LEVEL](../../originals/levels.md),
[подготовка мира](../../originals/world.md) и сохранённые Ghidra C/ASM:
`research/evidence/stage5/<ru|en>/` и `research/evidence/stage6/<ru|en>/`.
Во время написания этого модуля новый анализ EXE не выполнялся. Адреса ниже —
**Ghidra NE loader**, не файловые смещения и не runtime-селекторы DPMI.

| Факт | PKR RU | PKE EN |
|---|---|---|
| Основной LEVEL-парсер | `1048:004C` | `1018:0152` |
| Фабрика классов | `1068:0000` | `1020:018C` |
| Строка, assignment, число, строковое значение | `1048:092E/0A2C/0A8F/0AE2` | Сводка stage5 |
| Чтение класса 9, включая символьное E7 | `1068:3F80` | `1020:46E9` |
| Отражение карт и размещение актёров | `1098:0EF7` | `1030:0FDB` |

Это новые native C11-типы, не копии DOS-классов, vtable или структур GBA.
`InitialWorld` фиксирует проверенный начальный выбор объектов, карт и позы.
Полного игрового состояния, AI, событий, движения, оружия, door state,
constructor dumps и renderer в этом модуле нет. Последующие задачи получают
все исходные class fields, а не обрезанный набор характеристик монстров.

## Исходные определения

`dok_level_definition` заимствует полный неизменяемый `LEVEL_CP866` asset.
В нём сохраняются реальный SHA-256 его байтов, language/index/asset ID,
восемь исходных настроек, palette/light, все определения и три исходные карты.
Парсер принимает RU и EN для независимой сверки и получения представления;
это не разрешение строить игровой мир из EN.

Каждое определение сохраняет glyph, class, flags, width/height, marker,
наследуемые Sprite/Flic/Sound и отдельные sprite flags. Class fields имеют
kind, документированное native-смещение, числовое значение и точный span
исходного токена. Неизвестная семантика не заменяется вымышленным названием.
Схемы всех 13 допустимых классов восстановлены по stage5; класс 11 отвергается.
Максимальная схема — 19 полей героя.

Строки представлены диапазонами `offset,length` исходного CP866-ресурса.
`raw_line` хранит всё определение без CR/LF, `raw_tail` начинается сразу после
общего marker и сохраняет оставшиеся пробелы и поля. Текстовые поля хранят
**весь остаток**, включая начальные и конечные пробелы. Последующий потребитель
может взять максимум 39 байт согласно native getline(40); парсер считает
такие усечения, не теряя исходный текст. Имя ресурса сохраняет регистр и байты.

Значимые особенности грамматики:

- CRLF, CR и LF принимаются без изменения источника. Пропускаются только
  пустые строки и комментарии с `#` в первом байте. Пробельная строка карты
  остаётся полноценной строкой.
- Секции и ключи сравниваются ASCII-регистронезависимо по известному префиксу.
  Закрывающая `]` обязательна. Неизвестные секции/параметры отвергаются;
  `Step Ver` сохраняется в исходнике и учитывается как неисполняемый параметр.
- После `=` helper сначала пропускает только ASCII space. Flic, Sound,
  Palette и Light сохраняют правые пробелы; Sprite имеет отдельный token и flags.
  Пустой Sound отключает наследуемый звук.
- `_` в определении означает glyph-space. Повторный нормализованный glyph
  отвергается. Class/flags принимают unsigned16, слова — signed16, long —
  signed32 с явной проверкой переполнения, marker сужается до младшего байта.
- Поля CHARACTER читают один непробельный байт, поэтому текстовое `3` в E7
  означает `0x33`. Поля IMAGE/ANIMATION/SOUND сохраняют точные имена CP866.

Пределы профиля: до 256 определений, 19 class fields, 178 байт строки,
15 байт имени и 65536 байт исходного LEVEL; width/length 1…64, height=1,
положительные signed16 Cell Side/Height. Обязательны семь секций, восемь
настроек и три полные карты. Дубликаты секций/настроек и геометрия после
начала карт отвергаются. Это ограничения нового загрузчика имеющихся образцов,
не доказанные универсальные максимумы DOS-движка и не интерфейс моддинга.

## Карты, определения и начальная поза

Порядок source maps — **TMap, MMap, FCMap**, порядок InitialWorld —
**MMap, TMap, FCMap, visited**. `dok_level_validate_maps` отдельно сравнивает
всю геометрию и все байты трёх исходных карт с N04 `LEVEL_MAPS`.
Пакет N04 сохраняет исходный порядок строк; runtime-преобразование делает N05.

`dok_initial_world_build` принимает **только RU**, квадратные карты и ненулевой
epoch. Ограничение square сохраняет подтверждённый профиль оригиналов:
исходный native row flip начинает с width−1, хотя число обменов берёт length/2.
Для прямоугольных карт новый код отказывает, а не выдаёт исправленную математику
за исходное поведение.

Builder отражает строки трёх карт, заменяет `.` пробелом, проверяет наличие
определения для каждого итогового glyph и обнуляет visited. Он создаёт один
seed на **определение**, а не на клетку; неразмещённые определения сохраняются.
ID равен definition index+1, generation=1, epoch передаёт владелец. Позднейшее
удаление, reuse слота и выдача нового epoch требуют отдельного API жизненного
цикла; этот builder не выдаёт повторно живую идентичность сам.

Только MMap классы 1/9 получают размещение. Обход идёт по runtime-строкам,
затем столбцам; повтор glyph обновляет тот же seed и оставляет последнюю позу.
Герой — последняя встреченная class1-запись. Число клеток с актёрами и число
уникальных размещённых актёров хранятся отдельно. Class5 здесь не размещается.

```text
x = CellSide * column     + floor(CellSide / 2)
z = CellSide * runtimeRow + floor(CellSide / 2)
y = sign_extend16(NEG16(height_parameter))
```

Для −32768 отрицание остаётся −32768. Heading берётся из WORD по native-смещению `+0x32` исходного
определения. У героя upper/lower равны y+26/y−26 с modulo16; у монстра оба y.
Неразмещённый seed имеет `pose_known=0`: нулевые байты backing не объявляют
неизвестные native координаты равными нулю. Для TMap предметов class3 с W54=99
суммируется W56 по модулю 65536 с итоговой signed16 интерпретацией.

## Владение, память и отказ

Входной CP866 asset остаётся pinned, пока живы base, effective и их потребители.
Source pointer и spans заимствуются; владение не передаётся. Base неизменяема;
профиль создаёт отдельную effective-копию, меняя только разрешённые значения.
InitialWorld заимствует effective definition. Ни один тип не сериализуется
native memcpy на диск, в IPC или игровое сохранение.

Caller предоставляет раздельные **правильно типизированные** candidate и out.
При отказе candidate может измениться, out остаётся неизменным. Публикация
выполняется только после полной проверки; активный мир нельзя использовать
как candidate. Исходные bytes и output/candidate не пересекаются. Typed union
`dok_world_workspace` переиспользуется для parse/build в разные моменты;
наложение struct на объявленный byte-array не требуется.

Host x86_64: LevelDefinition 105056 байт, InitialWorld 27168, workspace 105056,
две definitions и seed вместе **237280 байт**. Compile-time gates требуют
workspace≤128 КиБ и resident≤384 КиБ. Native ARM9 размеры зависят от pointer
layout и фиксируются фактической сборкой/probe; host размеры не подменяют
эти измерения. Source CP866 хранится в 1 МиБ asset pool, не дублируется здесь.
Core не вызывает malloc, stdio или SDK, нет рекурсии и больших локальных массивов.

## Проверки

Самостоятельный strict C11 host test проверяет все 13 схем, integer limits,
CHARACTER `3`, persistent resources, raw spans, все усечённые префиксы fixture,
три вида перевода строк, неизменность out при отказах, N04 map comparison,
runtime plane order, повторное размещение, unknown pose, NEG16(−32768),
wrap category99 и запрет EN world. Независимый oracle и общая приёмка N05
дополняют этот синтетический тест реальными ресурсами и профильными изменениями;
их результаты, точные команды и границы передаёт [паспорт N05](../tasks/N05.md).

Эти проверки не являются исполнением AI/боя DOS или аппаратной DS-проверкой.
Физическая приёмка остаётся N24 согласно [validation-policy](validation-policy.md).
