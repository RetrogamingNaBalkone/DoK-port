# N03: контракты и владение состоянием

Решения приняты 29 октября 2026 года для независимого NDS-порта. Реализация:
[contracts.h](../../../ports/nds/include/dok/contracts.h),
[contracts.c](../../../ports/nds/core/contracts.c),
[host-проверки](../../../ports/nds/tests/test_contracts.c).
Это проектные C11-интерфейсы; они не объявляются восстановленными структурами
оригинала или доказательством эквивалентности DOS. Память и измерения дополняет
[общая архитектура N03](N03-architecture.md).

## Основания и адресная система

Источники — [матрица N01](N01-subsystems.md),
[native-state](../../originals/native-state.md),
[world](../../originals/world.md), [LEVEL](../../originals/levels.md),
[rendering-assets](../../originals/rendering-assets.md) и
[исследование времени](../../gba/time-events.md). Последнее используется как
сводка исходных ASM/DOS-доказательств; GBA-код, его фиксированная сетка шагов,
лимиты и решения жизненного цикла не перенесены.

Адреса ниже относятся к NE-loader Ghidra, не файловым смещениям,
DPMI-селекторам или вставкам WASDify. Образцы:

| Образец | SHA-256 |
|---|---|
| PKR.EXE RU | `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28` |
| PKE.EXE EN | `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b` |

| Подтверждённый исходный факт | Адрес RU / EN | Следствие для проекта |
|---|---|---|
| Владельцы событий и отдельные callbacks | `1038:0000` / `1010:13AA` | Состояние мира владеет событиями; логические ссылки заменят far pointers. N08 восстанавливает исполнение. |
| Игрок имеет отдельные состояние, позу и таблицу оружия | `1068:1657` / `1020:1B61` | Не заменять игрока универсальным packed record. Конкретные игровые типы появятся с соответствующими механиками. |
| Один объект на определение glyph; клетки могут ссылаться на общий объект | `1098:004F` / `1030:0079` | ID объекта не равен адресу клетки. Несколько полотен одной двери не требуют нескольких объектов. |
| Динамические слоты могут освобождаться и использоваться вновь | RU `1098:017D`, `1098:0205`, `1098:0278` | Ссылка содержит ID, generation и epoch мира. Одна позиция в массиве недостаточна против устаревшей ссылки. |
| Главный цикл вызывает dispatch(0) перед подготовкой сцены | Матрица N01 и time ASM | Нельзя молча заменить время одним update60 или считать render отдельным источником игровых ticks. |
| Общий кеш изображения меняет runtime flags; прозрачность проверяется после LIGHT | `10F8:0592` / `1060:06A2`, span `1010:0197…019F` | Immutable metadata пакета отделены от mutable runtime/cache. SceneSnapshot не означает, что исходный draw был чистым. |

В N03 не выполнялся новый анализ EXE. Адреса и исходные факты взяты из
сохранённых материалов N01; новые тесты проверяют только новые контракты.

## Роли и границы

| Роль | Данные N03 | Кто владеет и сколько живут |
|---|---|---|
| `dok_platform_services` | callback монотонного uint64-счётчика, точная рациональная частота, необязательная диагностика | Platform adapter владеет context. Оболочка хранит копию descriptor; context живёт до shutdown. |
| `dok_input_frame` | Номер выборки, held/pressed/released 12 физических кнопок, flags и координаты нижнего touch | Caller передаёт значение/const view. Хранение предыдущей выборки и gameplay mapping принимает N09. |
| `dok_game_state` | INITIALIZED/SHUT_DOWN, generation жизненного цикла и копии трёх descriptors | Caller предоставляет правильно типизированный объект. Поля семантически закрыты: приложение изменяет их только API. Игрового мира пока нет. |
| `dok_scene_snapshot` | epoch, lease ID, sequence и const presentation pointer | Будущий presentation owner выдаёт заимствованный immutable lease. В N03 сцены не создаются. |
| `dok_asset_catalog` | Ненулевые identity/revision и immutable opaque implementation | Caller владеет payload. NULL разрешён как descriptor без реализации, не как подтверждение готового пакета. Формат и рабочий набор — N04. |
| `dok_balance_profile` | Ненулевые identity/revision и immutable opaque implementation | Caller владеет payload. Значения и проверка RU-базы/общего профиля — N05. |

В ядре нет SDL2, libnds, `nds.h`, файловых дескрипторов, VRAM handles,
DMA-функций или вызовов malloc. PlatformServices не содержит фиктивных
callback для ещё не выбранных интерфейсов: чтение пакета — N04, render/present
— N07, звук — N18, запись только настроек — N21. InputFrame передаётся
отдельно; получение ввода не спрятано внутри ядра.

Контракты компилируются строгим C11. GNU C11 нужен платформенным единицам
трансляции с SDK inline ASM; SDK-заголовки не включаются в независимое ядро.
Указатели делают native layout host и ARM9 различным. Структуры нельзя
сохранять memcpy в пакет, save, ARM7 IPC или файл настроек. Игровые сохранения
вообще не входят в NDS-порт.

## Идентичность, числа и часы

Asset ID, object ID и world epoch имеют ширину uint32; ноль зарезервирован
для отсутствующей идентичности. Ссылка на объект содержит три ненулевых поля:
`world_epoch`, `object_id`, `generation`. ID не совпадает с glyph, номером
клетки, индексом NE-сегмента или native pointer. Повторный glyph по-прежнему
может обозначать один объект, встречающийся в нескольких клетках.

`dok_object_ref_is_valid` проверяет только форму ссылки. Он не разрешает
ссылку и не подтверждает, что объект ещё существует. `dok_object_ref_equal`
сравнивает три компонента; равенство двух нулевых ссылок не делает их
действительными. Таблица разрешения и выдача generation/epoch — будущий мир.
При исчерпании generation/epoch выдача новой идентичности обязана отказать,
а не завернуться в ещё живое значение. Счётчик оболочки lifecycle_generation
не является world epoch и не используется для разрешения объектов.

Сервис времени сообщает counts и `numerator/denominator` counts в секунду.
Например, N02 имеет частоту `33513982/64`; перевод в игровые ticks здесь
не реализован. uint64 platform counter не заменяет исходные uint32 deadlines.
N08 принимает исходные unsigned сравнения, wrap, отрицательные интервалы,
повторное чтение часов после callback, pause и порядок dispatch. Частота
вывода изображения также остаётся отдельной.

## Ввод

Биты физических кнопок названы в самом контракте, без SDK include. Кнопка
должна быть held, если одновременно обозначена pressed; released несовместим
с held. Неизвестные биты отвергаются. Это выборка между двумя опросами;
контракт не обещает сохранить промежуточное быстрое нажатие и отпускание.
`sequence` uint64 обозначает порядок выборок, не время, кадр или tick.

Touch принимает нижние координаты x=0…255, y=0…191 при held; pressed требует
held, released несовместим с ними. Координаты после отпускания игнорируются.
Проверка формы кадра не проверяет соответствие предыдущему кадру. Поворот
камеры, кнопки карты, подавление нажатия после перехода меню и назначение
кнопок намеренно не реализованы до N09/N20/N21.

## Жизненный цикл

1. Caller создаёт правильно типизированный `dok_game_state`, автоматический
   или статический. Перед первым init содержимое не читается. Повторный init
   живой оболочки запрещён договором; перед ним вызывается shutdown.
2. Init проверяет обязательный clock callback, ненулевую рациональную частоту
   и identity/revision двух descriptors. После проверки копирует config по
   значению и создаёт INITIALIZED shell с lifecycle_generation=1.
3. Init не загружает данные, не вызывает платформенные callbacks и не создаёт
   мир. `dok_game_inspect` явно возвращает has_world=0 и world_epoch=0.
4. Reset сохраняет descriptors и увеличивает lifecycle_generation. При
   UINT32_MAX возвращает LIMIT_REACHED, оставляя состояние неизменным.
   Это reset оболочки, не исходный death/retry и не очистка игрового мира.
5. Shutdown обнуляет заимствованные references, не освобождая чужой payload,
   и переводит оболочку в SHUT_DOWN. Повторный shutdown успешен. Reset после
   shutdown отвергается. Для нового init caller вновь предоставляет config.

Проверки конфигурации до записи обеспечивают транзакционный отказ init.
Выход `inspect` также не изменяется при отказе. Caller обязан передавать
живые корректно типизированные объекты; API не обнаруживает dangling pointers
и не обещает безопасность произвольного повреждённого адреса.

Выбран открытый небольшой shell с семантически закрытыми полями. Он даёт
корректное typed storage без malloc и без наложения struct на объявленный
`unsigned char[]`, которое создало бы проблемы effective type в строгом C11.
Raw-byte арены допустимы для байтов и memcpy; будущее typed world storage
нужно выделять с соблюдением типа, выравнивания и времени жизни отдельно.

## Подготовка сцены и побочные эффекты

Immutable SceneSnapshot означает запрет renderer/GPU/ARM7 писать в GameState;
он не объявляет чистой исходную подготовку или отрисовку DOS-сцены. Матрица
N01 оставляет открытыми записи visited и влияние видимости на состояние.
Проектная последовательность:

```text
core dispatch/ordered prepare -> immutable presentation lease -> renderer
                          <- visibility/effects result -> core commit phase
```

Это направление архитектуры, а не уже реализованный порядок исходной игры.
N07/N08/N20 определят содержимое результата, фазу применения, обработку
пропущенного/невыведенного кадра и lifetime lease на основании ASM и DOS.
Нельзя незаметно перенести игровое решение в GPU callback или применить
неподтверждённый GBA-веер раскрытия карты.

Payload остаётся жив до explicit release или согласованного следующего
prepare. Reset/мутация не должны молча инвалидировать живой lease: будущая
реализация либо отвергает операцию, либо завершает lease в явной core-фазе.
В N03 lease API и scene payload отсутствуют, outstanding leases невозможны.

## Область проверки

`test_contracts.c` проверяет shell lifecycle без скрытых callback-вызовов,
копирование descriptors без захвата владения payload, транзакционный отказ,
исчерпание generation без wrap, отказ после shutdown, IDs разных поколений
и миров, границы кнопок/touch. Инъекция UINT32_MAX и повреждённого state tag —
white-box тест границ, не разрешённый приложению способ изменения состояния.

Host/ARM9 компиляцию и точные команды/результаты фиксирует
[N03-architecture](N03-architecture.md). Эти тесты не проверяют загрузку мира,
настоящий scheduler, исходный retry, renderer, SD-доступ или физическую DS.
SceneSnapshot, AssetCatalog и BalanceProfile задают границы будущей работы;
наличие descriptors не закрывает соответствующие игровые задачи.
