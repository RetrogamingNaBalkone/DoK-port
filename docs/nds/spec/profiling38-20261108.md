## Наблюдение пользователя

Clock37-ru работала около20–25 минут: длительный простой в начале LEVEL1,

`Level 0` — нулевой индекс LEVEL1. Это NDS source line/runtime, не адрес оригинала.
Исходники и ELF сверены с сохранённым clock37-ru, ROM SHA-256
`9167b17d84bb109cbdd3745b08d119f9d52d4e8574aa68b214f09b1866102bc4`.
Фото идентифицирует метку; SHA пользовательского файла отдельно не считан.

Нижний экран содержит восемь событий: map предыдущего кадра, frame,
simulation, sprites, effects, submit, wait, map текущего. Последние отметки
`wait T0952C813`, `map T09560037`, параметры map `C0/C0`.
Критическая длительность DMA там не записана.

В clock37 эта строка возвращает отказ при одном из четырёх условий:
start<192, end>262, start>end, elapsed>=560190. Первые три ложны для192/192,
поэтому **проверенный непосредственный механизм — elapsed guard**.
Это другой путь отказа, чем прежний simulation/backwards world clock.
Неизвестный статус означал отсутствие API status, а не неизвестный код Map5.
Clock37 печатала Retry только при simulation/clock; его отсутствие на фото
не означает нулевого числа повторных чтений. Подтверждения утечки памяти,
фиксированного порога20 минут или исправления первого отказа пока нет.

## Проверка SDK

В исходном ELF clock37 `cpuGetTiming` имеет Thumb entry `0x02031125`,
инструкции с VMA `0x02031124`, размер60 байт. SHA-256 этих60 байт:
`6d98520f5374b05d4b73ff9accfbf482dbf382dca70ad650af88d98295f8516f`.
Это ELF/runtime VMA NDS; извлечение выполняется через section table, отдельно
от файлового смещения. Оригинальные DOS EXE в этой задаче не анализировались.

SDK читает LOW/HIGH/LOW/HIGH без маскирования IRQ. При LOW1>LOW2 выбирает
вторую пару, иначе первую. Между чтениями допустимо выполнение IRQ handler.
Достаточно долгие прерывания могут провести несколько переполнений LOW и
сделать выбранную пару несогласованной. LOW профилировщика с частотой BUS_CLOCK
переполняется примерно каждые1,956 мс. Это отдельный таймерный источник,
а не systemCounterGetTicks с периодом младшей части около125 мс.

Воспроизводимый Unicorn-тест исполняет **реальные инструкции SDK**:
индивидуальные MMIO чтения получают согласованные значения counter
`1234FFFE`, `1234FFFF`, `1235F000`, `12360000`. Две явные задержки IRQ между
чтениями моделируют продвижение таймера. Возврат `1236F000` опережает последний
counter на61439 cycles; вычитание из следующего обычного снимка после короткой
DMA даёт `FFFF2001`, что ложно превышает560190.

Это доказанный дефект устойчивости алгоритма к **заданному расписанию**.
Он не доказывает такое расписание IRQ у пользователя. Реальный late DMA,
особенности видимости регистров DraStic или другая ошибка измерения остаются
альтернативами: raw start/end на исходном crash screen отсутствуют.

## Изменение profiling38

Только N23 ARM9 линкуется с `--wrap=cpuGetTiming`. Wrapper сохраняет IME,
отключает IRQ dispatch на время реального SDK getter и восстанавливает прежний
IME. Нет ожидания, DMA, IPC, аллокации или изменения таймеров в этой секции.
Выбор таймеров, BUS_CLOCK units и обычное uint32 переполнение сохранены.
ARM7 и исторические probes не получают wrapper. Изменение потенциально
добавляет небольшую стоимость каждому profiling read; FPS физической DS не измерен.

Тест исполняет уже машинный wrapper кандидата при входном IME0 и IME1:
все четыре чтения выполняются при IME0, задержки IRQ не внедряются,
результат согласован, исходный IME восстановлен. Host57 checks также проверяют
возврат исходных uint32 значений, включая естественное переполнение.
В реальном ELF проверены14 вызовов wrapper:3 в map transfer и11 в render_one.

Четыре прежние проверки map DMA сохранены с теми же порогами. Их маска
становится известным diagnostic status:1=start<192,2=end>262,4=start>end,
8=elapsed>=560190. A содержит elapsed, B=start|(end<<16).
На crash screen добавлены DMA ticks и исходные From/To; Retry печатается
для любого fatal operation. Профиль сохраняет raw CPU start/end в `[12]/[13]`;
ABI размер/смещения NdsMapRuntime не меняются. При отсутствии передачи они нулевые.
Карта не повторно передаётся после частичной записи; сроки не зажимаются
и нарушения не игнорируются. Предыдущий clock37 retry остаётся.

## Быстрый цикл проверки

По просьбе пользователя не повторять получасовой простой в каждой итерации.
Основной цикл: детерминированная граница таймера/расписание IRQ, host regression,
точечная fault injection, короткий повторный запуск уровней. Длительная выдержка
нужна как отдельная итоговая проверка стабильности; она не локализует причину
и не заменяет эти воспроизводимые тесты. Ускорение обеспечивается контролируемыми
входами теста, без ускорения игровых часов поставляемой ROM.

```powershell
py -3.14 -B -X utf8 ports/nds/tools/performance/check_profiling_irq.py build/nds/n23/clock37-ru
py -3.14 -B -X utf8 ports/nds/tools/performance/check_profiling_irq.py build/nds/n23/profiling38-ru
py -3.14 -B -X utf8 ports/nds/tools/performance/check_map38_fault.py build/nds/n23/profiling38-ru
py -3.14 -B -X utf8 ports/nds/tools/performance/check_map38_restarts.py build/nds/n23/profiling38-ru
py -3.14 -B -X utf8 ports/nds/tools/check_playtest34_emulator.py build/nds/n23/profiling38-ru
py -3.14 -B -X utf8 -c "import json,sys; from pathlib import Path; sys.path.insert(0,'ports/nds/tools/performance'); from build import build; build('fresh-label-ru',json.loads(Path('build/nds/n23/clock37-ru/build-manifest.json').read_text())['feature_selection'])"
py -3.14 -B -X utf8 ports/nds/tools/package_rom.py --target build/nds/n23/profiling38-ru
py -3.14 -B -X utf8 tools/reports/summarize_reports.py --check
git diff --check
```

Новый build label immutable; при пересборке следующие команды направить в него.
Используются общий BlocksDS и Zig; MSYS2 сборка вне песочницы из-за signal pipe error5.
Виртуальный сценарий SDK явно задаёт MMIO/IRQ; map fault fixture заменяет функцию
передачи в RAM на синтетический completed-transfer report, DMA не выполняет.
Неизменённые render_one guard/fatal screen получают статус8 и raw timestamps,
история остаётся замороженной. Это не воспроизведение исходного DMA зависания.

Host map runtime: оба audit режима, примерно16,97 млн базовых проверок каждый,
добавлен реальный transfer через UINT32_MAX→0, elapsed1. Точная host команда
сохранена в сводке. Full UI/input/settings/FAT/cold restart PASS. Короткий
read-only input smoke:6 загрузок уровней1/1/2/3/1/1,3378 кадров,23,64 секунды;
map fault0 и исправные обновления после каждой загрузки, clock retry0.
Всё это контролируемые проверки, не прохождение LEVEL1 или длительная выдержка.
Снимок map fatal с raw временем и Retry просмотрен: строки помещаются на LCD.
