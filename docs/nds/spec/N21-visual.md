# N21: локализация игрового изображения без смены мира

Во время выбора RU/EN frontend меняет только представление. Числовые данные
мира, профиль, объектные ID, идентификаторы анимаций и simulation sprite bank
остаются прежними. Отдельный модуль `ports/nds/ui/frontend_visual.c` разрешает
локализованный кадр перед demand/cache/GPU, не переписывая исходный bank.

## Проверенные исходные данные

Первичные образцы: PKR `originals/pkr/RUS/PKR.RES` и PKE
`originals/pkr/ENG/PKE.RES`; исходные и конечные SHA-256 закреплены в
`research/evidence/nds/n21/visual-source.json`. Независимый анализ RAW RES
в `ports/nds/tools/frontend/audit_visual_assets.py` сравнил 111 пар игровых
image/animation/font/palette/LIGHT ресурсов:
110 побайтово равны, единственное отличие — POPAL. Для POPAL все заголовки,
метаданные анимации и первые пять кадров равны. В шестом кадре различаются
только три пикселя последней строки: x=155/156/157, y=69; RU=147/121/41,
EN=0/0/0. Это файловые координаты декодированного изображения, не адреса EXE.

N04 хранит шестой кадр с zero-based subindex=5, source_index=145,
source_kind=2 (animation), representation=5 (`GPU_INDEX8_POT`). Размер
изображения 158×70, хранилища 256×128, payload 32768 байт. Идентификаторы:
RU `0x42441405`, EN `0x82441405`. В GPU-растре отличия находятся по смещениям
17819, 17820, 17821 при stride=256. Остальные изображения можно продолжать
использовать из неизменного simulation bank выбранной при сборке локализации.

Исходный N04 package `build/nds/assets/dok-assets.ndspak` остаётся неизменным:
9230016 байт, SHA-256
`2f03ba02c9986b4e0bd321e94ca00df8a355f7dbb1dff5598a950d3366061511`.
Две независимые GPU-ожидания получены из RAW RES и сохранены в
`build/nds/n21/visual-popal-{ru,en}.bin`; они не извлекаются из тестируемого
packed store. Происхождение и хеши закрепляет source-отчёт.

## Контракт реализации

`dok_frontend_visual_init` находит оба действительных N04 entry и проверяет
ID, язык, source ID, source_kind/index/subindex, representation, размеры,
storage, длину и animation param1=8. Результат публикуется только целиком.

`dok_frontend_visual_resolve` подменяет только entry, у которого младшие
30 бит ID равны `(145<<18)|(5<<10)|5`. Для RU/EN возвращается соответствующий
проверенный entry из отдельного visual descriptor. Любое другое изображение
возвращается тем же указателем. Неподдерживаемый язык или недействительный
descriptor не создают новую подмену. Исходный указатель и simulation bank
никогда не редактируются. Renderer должен использовать один разрешённый entry
для demand, получения pixels и GPU texture ID; игровая анимация продолжает
обращаться к исходному ID.

`dok_frontend_visual_append_store` вызывается после обычного
`dok_frame_store_load`, **до** выделения raw cache из остатка asset slab.
Она дописывает только недостающие локализованные кадры. Каждый новый payload
проходит `dok_assets_load` (SHA-256 и N04 schema), исходный pack и обратный
unpack с побайтовой сверкой. Ни FAT, ни новый asset pool для последующей
смены языка не нужны. Существующие records и packed prefix не перемещаются.

Проверяются соответствие store/pool, границы packed records, уникальность
ID, сумма decoded bytes, лимит 256 records, общий capacity и отдельный scratch
не менее 65536 байт. Scratch не может перекрываться с pool. При любой ошибке
все опубликованные metadata и прежний packed prefix остаются неизменными;
неопубликованные хвостовые байты и scratch могут измениться. Новые records,
count/bytes/decoded_bytes публикуются только после успеха всех добавлений.
Повторный вызов идемпотентен. Во время дополнения tail не должен принадлежать
raw cache или иметь активных пользователей.

## Host-проверка и границы результата

Команда: `py -3.14 -B -X utf8 ports/nds/tools/check_frontend_visual.py`.
Общий Zig 0.13.0, C11, `-pedantic-errors -Wall -Wextra -Werror -O2`.
Полный отчёт: `research/evidence/nds/n21/host-visual.json`.

Выполнено 1049583 checks в двух отдельных host-сборках со стабильными RU/EN
банками. Загружены действительные N04 package, RU-мир и полные sprite banks;
для EN отдельно привязан исходный EN presentation так же, как в runtime.
В каждом исходном bank 168 кадров, включая ровно одну локализацию POPAL frame5.
После дополнения — 169 кадров, 284600 packed bytes. Начальные bank/records и
packed bytes сохранены. Для обеих UI-локализаций повторные require/cache decode
проверили все 32768 байт относительно независимого RAW RES-ожидания; после
загрузки packed store обращения к FAT отсутствуют. Реальные декодирования —
два, последующие проходы используют cache. Две перестановки RU/EN-ожиданий
были отвергнуты именно pixel oracle, включая отличающиеся три пикселя.

Проверены малый capacity/scratch, неправильный pool, перекрытие буферов,
ошибка чтения payload, count>256, заполненные 256 slots, неверная граница record,
повтор ID, неверная decoded sum, отсутствие valid session и отказ на втором
новом кадре без публикации первого. Хеши RAW RES, package и независимых
ожиданий одинаковы до и после прогона. Linux x86_64-musl static binary собран,
его выполнение не заявляется. Проверка реального demand/GPU и неизменности
живого мира в эмуляторе принадлежит общей N21-приёмке; этот host-результат
не является подтверждением её завершения или аппаратного быстродействия.
