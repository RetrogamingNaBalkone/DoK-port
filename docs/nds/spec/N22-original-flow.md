# N22: исходный игровой цикл, смерть и повтор

Проверено 30 октября 2026 года по сохранённым экспортам Ghidra PKR/PKE,
машинному исполнению контролируемых срезов и исходным RES. GBA-движок и
GBA-упаковщик не используются; прежнее исследование G18 служит указателем
на оригинальные функции. Этот документ не подтверждает приёмку NDS runtime
или полное прохождение DOS.

## Смерть и повтор

`player_check_death` принимает far-указатель героя: `LES [BP+6]`;
`RETF` оставляет caller cleanup. HP, maxHP, lives и score — signed WORD.

| Условие | Изменения | Возврат |
|---|---|---:|
| Штатный HP>0 | Нет | 0 |
| HP<0 | Нет; sentinel завершения | 3 |
| HP=0, DEC lives дал 0 | Once death sound из `hero+A6`; lives=0 | 2 |
| HP=0, DEC lives дал ненулевое значение | Тот же звук; уменьшение lives; очистка старой клетки MMap; restore30; запись glyph в новую клетку; HP=maxHP | 1 |

`DEC word` оборачивается: lives=0 превращается в −1 и допускает повтор,
−32768 превращается в 32767. Нельзя заменять это saturating decrement.
Векторы проверяют оба края, HP=−32768, совпадение исходной/конечной клетки
и координаты за границами карты. Native индекс: signed IDIV на cell side,
WORD-результат, затем clamp по ширине/длине; старая клетка становится `0x20`,
новая без дополнительного admission получает glyph героя. Дополнительно
проверены `INT32_MIN/MAX` и частные больше 65535: обрезка signed LOWWORD
выполняется до clamp, поэтому full32 clamp был бы неэквивалентен.

Отдельная первая ветвь `DS:C6==1` возвращает 3 независимо от HP и не меняет
lives/позу; это startup-параметр `-e/-E`, не обычная игровая команда NDS.
Его наличие и приоритет проверены отдельными x86-векторами.

Внутри death-fixture только внешние sound/HUD вызовы перехватываются и
записываются; restore-call подменён проверенной 30-байтной копией. Сам
оригинальный helper дополнительно исполняется отдельно: far source
`world+716`, far destination `world->hero+26`, `CX=30`, runtime-copy
`1000:5CB3` снимает восемь байт своих аргументов. Оригинальные LES, сравнения,
signed arithmetic, записи HP/lives/MMap и far return исполняются машинным
кодом. Полные 224 байта героя, 4096 байт MMap и 2048 байт fixture-мира
сверяются после каждого вектора.

Retry немедленный. Герой восстановлен до возврата 1; startup очищает
сообщение HUD и продолжает тот же цикл без ожидания A/Start. PKR
`1008:1000…1045`, PKE `1008:14DD…1522`. Передаваемая строка PKR
`1190:02BA` / PKE `10D0:028E` — ровно `20 00`, один пробел.
Это не надпись «Повторить» или «Конец игры». Сообщение обнуляет HUD routine
PKR `10C0:1278` / PKE `1050:15DB`; соответствующий ASM сохранён также в
`research/evidence/nds/n19/original/{ru,en}/evidence.asm`.

При результате 2 startup сразу освобождает мир и возвращает выбор уровня;
при 3 освобождает мир, показывает выбранный EINTRO и возвращает выбор.
Отдельного Game Over prompt или ожидания подтверждения в этих ветвях нет.
Если порт вводит такой экран, это должно быть записано как адаптация NDS.

## Матрица сохраняемых данных

Native restore копирует только `[hero+26, hero+44)`, 30 байт.

| Native поле | Действие при retry | Соответствие NDS |
|---|---|---|
| `+26/+2A/+2E`, DWORD | Восстановить | motion x/y/z |
| `+32/+34`, WORD | Восстановить | heading/angle_parameter |
| `+36`, WORD | Native copy | Отдельного scalar в `dok_motion_state` нет |
| `+38/+3C`, DWORD | Восстановить | speed/distance |
| `+40`, DWORD | Native copy | Отдельного scalar в `dok_motion_state` нет |
| `+5E`, WORD | maxHP из `+62` | hero HP |
| `+D6`, WORD | DEC с wrap16 | lives |
| `+1C`, DWORD | Сохранить | flags |
| `+7C/+7E/+82`, WORD | Сохранить | turn_step/linear_step/last_turn |
| `+90/+94`, DWORD | Сохранить | movement_accumulator/turn_accumulator |
| `+98`, WORD; `+9A`, DWORD | Сохранить | accel_sign/last_flags |
| Прочие поля героя | Сохранить | Инвентарь, оружие, ключи, charge, score и остальные свойства |

Неизвестные native `+36/+40` не объявляются новыми восстановленными NDS
полями. Полное обнуление motion либо копирование compact actor при retry
нарушает оригинальную границу восстановления.

| Область | Retry того же мира | Новый выбранный мир / завершение старого |
|---|---|---|
| Актёры, двери, предметы, карты | Сохраняются, кроме двух occupancy writes героя | Старые владельцы уничтожены; новый мир создаётся из LEVEL |
| События и снаряды | Сохраняются; не создаётся новый world | Старые события/ссылки/снаряды не должны перейти в новый world |
| Раскрытая карта/visited | Не сбрасывается | Начальное состояние нового мира |
| Инвентарь/ключи/оружие/score | Сохраняются | Конструктор нового героя, lives3/score0 |
| Звук | Once death sound; остальная политика платформенного воспроизведения отдельна | Остановить старые платформенные потоки при уничтожении мира |

Факт сохранения событий/прочих актёров следует из отсутствия их удаления
в death/helper и продолжения startup с прежним world, а не из утверждения
о прохождении целой DOS-сессии. Наблюдательная проверка NDS такого сохранения
остаётся отдельной частью N22.

## Независимые уровни и реальные выходы

Выбор LEVELn → соответствующий BINTROn → новый world → игра; finish → удаление
world → EINTROn → выбор. Автоматической кампании и переноса инвентаря между
независимо созданными мирами нет. Отмена выбора показывает ENDTXT и выходит.
Для PKR конец startup `1008:1328…1398` явно разделяет destructor, EINTRO
только для result3 и ENDTXT для отмены выбора.

Stats category1000 сравнивает `hero+D8` с `world+710` и при равенстве пишет
HP=−1. Builder total складывает только class3/category99 values из `+56`.
Во всех шести исходных LEVEL отсутствуют даже определения таких предметов:
total=0. Поэтому проверка штатного исходного score0 удовлетворена без сбора
очков; цель «собрать очки Old Gold» не добавляется.

Во всех версиях exit — class12/category1000 glyph `B2` в FCMap. Координаты
ниже — **строки исходного LEVEL**, x=cell%64, row=cell//64. Runtime NDS
использует собственное преобразование оси; нельзя передавать эти строки
как готовые runtime z.

| LEVEL | FCMap cells | Исходные x,row |
|---|---|---|
| 1 | 414, 415 | (30,6), (31,6) |
| 2 | 3610, 3611 | (26,56), (27,56) |
| 3 | 2788, 2789, 2790, 2791 | (36,43)…(39,43) |

Хеши исходных RES и каждого LEVEL, glyph/category, клетки и отсутствие
category99 закреплены в новом отчёте; архивы перепроверены после сканирования.
Этот аудит условий выхода не заменяет обычное прохождение LEVEL1–3.
