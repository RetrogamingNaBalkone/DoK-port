# N07: ранний аппаратный renderer

29 октября 2026 года. Архитектурные решения ниже приняты до профилирования.
Принято на host/эмуляторе; результат и ограничения — [паспорт N07](../tasks/N07.md).
Исходные поверхности — [N07-geometry](N07-geometry.md), аппаратный backend —
[N07-gpu](N07-gpu.md), независимые проверки — [N07-validation](N07-validation.md).

## Границы и поток данных

ARM9 читает неизменный внешний N04-пакет, восстанавливает определения и
начальное состояние RU-мира модулями N05. Новый streaming builder выдаёт
исходные world quads по клеткам. Подготовка сцены ограничивает gather исходным
прямоугольником, консервативно отбрасывает поверхности вне frustum и создаёт
immutable packet. Backend целиком проверяет packet до записи FIFO, подаёт
реальные текстурированные 3D-полигоны, получает аппаратные счётчики и swap.

Весь мировой mesh не хранится. Одна caller-owned область scene до 256 КиБ
содержит до 1536 quad и cell descriptors. Это provisioned capacity с отказом,
не разрешение удалить остаток мира. Диагностический main фиксирует ошибку
подготовки/лимитов целого кадра. Успех приёмки требует отсутствия таких ошибок
на выбранных стартовых и тяжёлых маршрутах, включая движение камеры.

Scene lease удерживает мир и bindings неизменными до потребления GPU. После
возврата submit CPU-потребление packet закончено; вызывающий освобождает lease
перед новой подготовкой. Для контрольного статического кадра lease сохраняется
до чтения независимым emulator harness. Никакие события игры, AI, физика или
сохранение прогресса здесь не вводятся. Actors/billboards интегрирует N12;
N07 проверяет стены, начальные двери, пол, потолок и вертикальные FC-границы.

Цвет фона вне конечного source gather пока чёрный. Это не обнаруженная
внутренняя щель: сохранение всех source surfaces проверяется отдельно. Но
чёрный фон **не объявляется исходным DOS-поведением**. N13 восстанавливает
Floor/Ceiling Color (в этих LEVEL поля 10/143), дальнее заполнение и LIGHT
по исходному коду/кадрам. Ранний N07 не принимается за визуально полный порт.

## Координаты, камера и общие рёбра

Один GPU unit равен **512 world units**. Локальный vertex16 равен
`local_world*8`, поэтому все целые исходные размеры, включая ceiling−951,
представляются точно. Origin выбирается на решётке 512 около центра клетки;
локальные X/Z обычного quad ограничены примерно ±496 world units. Глобальные
координаты карты не сужаются в signed vertex16.

Исходные Q15 sin/cos 0…360 проверены по всем 722 runtime words RU RAM и
математическому генератору из Ghidra. Для GE выбирается единая Q12 rotation;
это явная адаптация точности, отдельно сравниваемая с N06. Camera-relative
translation и origins вычисляются согласованно. Не допускается сочетание
точной Q15 origin rotation с округлённой Q12 local rotation: общие рёбра
разъезжаются уже до projection.

Численный контрпример выявил и второй источник щели: GE округляет произведение
projection×modelview отдельно для каждого origin. Поэтому backend вычисляет
общие combined linear columns один раз, а translation для origin на решётке
добавляет целые кратные этих columns. GE получает combined projection и
identity position matrix. Перенос origin на 512 компенсируется точно, общая
world-вершина даёт одинаковые actual clip XYZW. Это проверяется PosTest на
реальном Geometry Engine эмулятора, без увеличения допуска для швов.

Off-axis projection, depth+200, principal point и viewport 256×154 следуют
[N06-camera](N06-camera.md). Матрица задаётся явно, симметричный perspective
по aspect 256/154 не используется. Nominal near=200 world от эффективного глаза,
far=49152: этот far превышает диагональ всех трёх 64×64 карт с учётом D.
Q12 depth coefficients дают effective near≈200.0068/far≈49850.18; это измеренная
квантизация, не изменение source field. GPU clipping horizontal planes
отделён от исходной SAR20 ветки и не объявляется exact DOS rasterization.

## Исходная геометрия и исправления gather

Builder сохраняет проверенные размеры image×scale с WORD wrap, height/ceiling
параметры и UV. Двери имеют собственные исходные размеры, а class7 — private
копию image header. FC floor getter использует Sprite только для class12;
class13 использует обычное поле +0x5A. Shared image flags получают последнее
**присваивание** Sprite directive, не объединение OR всех flags. Прозрачность
по index0 при identity LIGHT применяется к vertical paths; горизонтальные
плоскости остаются непрозрачными по исходному ASM.

Original-instruction oracle проверяет все клетки и constructor arguments;
канонические XYZ/UV разворачиваются из них по проверенному constructor ASM.
Это не выполнение DOS raster и не полная runtime-анимация. Исходные EXE/RES
не меняются, GBA engine не используется как архитектурная основа.

Gather использует четыре исходные control points и их low32/SAR15/IDIV/WORD
арифметику. В оригинале near point с индексом p1 теряется при вычислении max после
перезаписи stack slot. N07 сохраняет min/max **всех четырёх** points, получая
консервативное надмножество source gather. Исправление выделено отдельно от
восстановления; оно может добавить клетку, но не удаляет исходно допустимую.
Сам gather — не найденная far plane и не произвольный distance cutoff.

Frustum culling оставляет небольшой guard band для Q12/raster rounding;
действительный clip выполняет GE. Различия texture interpolation и coverage
краёв оцениваются отдельно от пропавшей поверхности или неверной высоты.

Горизонтальные поверхности N07 используют обычное GE perspective clipping.
Исходная условная SAR20 depth-ветка не воспроизводится GPU; это выбранная
аппаратная адаптация, а не доказательство эквивалентности source near raster.
Сами исходные формулы и near fixtures сохранены в N06/N07 evidence; N13
отдельно оценивает взаимодействие этой адаптации с водой/отражениями.

Объединение X-runs разрешено только для смежных прямоугольников с одним
материалом и доказанным продолжением affine UV. У каждого объединения
сохраняются retained/consumed source IDs. Исходные texture resets не
заменяются повторением POT padding: в 65 192 измеренных позах объединений
нет. Положительный synthetic scene gate исполнил восемь объединений,
проверил provenance и точную геометрию; это работающая возможность, а не
счётчик с обещанием будущей реализации.

## Текстуры и память

| VRAM | Назначение |
|---|---|
| A+B+D, 384 КиБ | Проверенный полный набор статических textures текущего уровня |
| C, 128 КиБ | Нижняя tiled 4bpp диагностическая console |
| E, 64 КиБ | Верхний 8-bit HUD, прозрачные строки 0…153 |
| F, 16 КиБ | 3D palettes |
| G/H/I, 64 КиБ | Невыделенный резерв VRAM |

N04 GPU_INDEX8_POT содержит исходный полезный прямоугольник и padding. UV
остаются в logical texels, padding не растягивается на грань. Материалы
различают opaque/vertical color0 transparency. До активной сцены проверяется
весь static working set уровня; arbitrary nearest subset не используется.
Загрузка происходит на явной границе loading с выключенным 3D display.
Ни один texture upload не выполняется в середине активного raster.

Game palettes пока берутся из измеренного N06 clean DAC6 через channel>>1.
Это воспроизводимая контрольная фаза; LIGHT/fade/вода/отражения остаются N13.
HUD пользуется той же палитрой: каждый исходный цвет выбирает ненулевой
равноцветный индекс, исключая прозрачность полосы. Реальный HUD N19 ещё не
реализован; верхняя полоса — принятый статический макет N06.

Main RAM сохраняет N03 ceilings и аварийный резерв 655360 bytes: world384,
scratch128, scene256, assets1024, events64, audio256, I/O128 КиБ. Фактические
slabs, static/startup, alignment, SDK headroom и stack usage фиксируются
отдельно. Успех renderer probe не доказывает full-game peak.

## Диагностика и приёмка

`scene.dat` — только diagnostic cameras/HUD, без mesh или texture bank.
Его ABI описан в render_fixture.h; `assets.ndp` — точные байты N04 package.
`prepare_renderer.py --provisional` разрешён для разработки; окончательная
приёмка требует измеренных heavy candidates и manifest без provisional.

Верхний экран использует 3D engine и HUD, нижний — диагностику. История
сохраняет каждый подготовленный/показанный кадр, CPU ticks, VBlank interval,
actual vertex/polygon counts, sticky underflow/overflow, RDLINES и uploads.
W1C flags читаются и накапливаются до любых очищающих записей control.
FIFO empty/busy не считается временем полного GPU rasterizer.

Для математических модулей scene/geometry/backend выбран ARM instruction mode,
позволяющий ARM946E-S использовать длинное умножение; loader/остальной SDK
могут оставаться Thumb. Изолированный эксперимент не менял C-геометрию,
пакет или критерии. Неуспешный Thumb-профиль и последующий ARM-профиль
сохранены раздельно, вместо их удаления или подмены средним FPS.

Протокол интерактивного benchmark разделяет подготовку case, все реальные
rendered frames и READY. Console formatting выполняется перед READY и имеет
отдельную DIAGNOSTIC history-запись с полной стоимостью; это не texture I/O
и не измерение живой игры. Все активные кадры, включая первый, проходят
строгую проверку двух VBlank. Ожидание A и форматирование результатов не
выдаются за медленный/быстрый кадр renderer. История сохраняет loading,
SYNC, DIAGNOSTIC и actual render intervals; пользовательская READY-пауза
публикуется через probe и не входит в cadence. Будущая стоимость карты/UI
проверяется N20/N23.

Начало ACTIVE после loading/READY должно иметь определённую presentation
boundary. Повтор после исправления seqlock выявил зависимость первых тяжёлых
кадров от произвольной стартовой фазы: prepare+submit оставались около
825–830 тысяч ticks, но ожидание presentation добавляло до одного VBlank,
и два первых кадра превысили два VBlank. Ранний успешный прогон не доказывал
устойчивость этой границы. Неуспешный результат сохранён отдельно.

Принят явный SYNC record без PRESENTED на переходе inactive→ACTIVE, один на
case, с полным временем ожидания следующего VBlank. Первый render interval
начинается на завершении SYNC **до** публикации телеметрии, поэтому её
стоимость входит в первый кадр. Между обычными moving/steady кадрами SYNC
не вставляется; ни один первый render frame не исключается из бюджета.
Это контракт presentation benchmark, не реализация source clocks N08.
SYNC и render используют одну функцию ожидания с одинаковой точкой чтения
таймера сразу после возврата `swiWaitForVBlank`. Включение 3D layer и
публикация после этой точки входят в следующий interval; у последнего кадра
серии DIAGNOSTIC начинается от этой же boundary и сохраняет весь tail.
Таким образом отличие точки измерения не превращается в допуск к бюджету.

Независимый harness читает RAM без записи, проверяет матрицы и actual PosTest,
lease/generation, cache/RAM/VRAM, cadence всех steady/moving кадров. Flat
diagnostic cases подают те же поверхности и depth с цветами по hash source ID:
независимая projected coverage проверяет внутренние щели отдельно от текстур.
Коллизии hash исключаются из строгой проверки цвета; проверка покрытия union
от них не зависит. Textured starts всех трёх уровней сравниваются с N06 по геометрии/пропорциям.
Loading не скрывается в средних; stalls во время движения учитываются в кадре.

Физическая DS/DS Lite, microSD/loader и реальные FPS остаются итоговой N24.
Виртуальные интервалы и успешный рисунок не подтверждают аппаратную скорость.
