# N13P — решение об архитектуре с освещением

29 октября 2026. Поручение пользователя: N12 → N13 → N13P, решение об
архитектуре, остановка перед N14. Отдельно разрешено приближённое затемнение
на GPU. Главный критерий — дальние объекты исчезают во тьме, создавая ощущение
пугающей неизвестности. Это явная художественная адаптация NDS, не эквивалент LIGHT.

## Решение

Сохранить аппаратный 3D renderer, принятую проекцию, геометрию, UV, depth buffer
и streaming. **Заменить производственный путь освещения**: чёрный аппаратный fog
вместо точного разбиения поверхностей по16 строкам LIGHT и последующего weld.
Точный N13 остаётся эталоном; кэш разрезанной геометрии не выбран.

Архитектура полного движка ещё не доказана. После добавления живого боя остаётся
N17P, после двух экранов/звука/UI — N21P. Физическая DS/DS Lite — N24.

## Почему потребовалась замена света

Зафиксированная перед правками baseline — финальный N13, включая fade HUD.
`baseline-inputs.json` проверяет N07P/N12/N13 compacts, source/package/ROM hashes;
заменённые C/H/inc сохранены в `baseline-sources/`. Первоначальный provenance
manifest не переписан, дополнительные архивы перечислены отдельно.

Накопленный41-case маршрут содержит2740 новых presentations:37 случаев N13,
три90-frame максимальных LIGHT-позы и120-frame поворот у воды. Включены все154
исходных кадра актёров на каждом уровне, двери, crowded scenes, четыре направления
воды, прозрачность/depth и fade трёх палитр. Искусственный перебор кадров и fades
считаются отдельно от штатного маршрута. Исходные часы — явная fixture166 ticks
на service sweep; это не частота игрового цикла.

| Вариант | RU virtual FPS | EN virtual FPS | Вывод |
|---|---:|---:|---|
| Точный N13 LIGHT | 2,57 | 2,56 | Подготовка338–343 мс, p99 47 VBlank |
| Точный кэш готовой LIGHT-геометрии | 4,15 | 4,11 | Промахи на поворотах;170640 B RAM не оправданы |
| GPU black fog | около40 | около40 | Нормальные интервалы≤2 VBlank, минимум cadence29,913 |

Числа — по времени эмулятора DS, не FPS хостового ПК и не измерения физической DS.
Точные значения, холодные загрузки, audit overhead, RAM/VRAM и отчёты находятся
в [compact](../../../analysis/nds-n13p-performance.json).
У точного кэша совпали все41 контрольных изображения RU и EN, все462 исходных
frame hashes и callback traces. Ускорения оказалось недостаточно: проблема
заключалась в способе воспроизведения света в целом.

## Новый свет и художественный критерий

Аппаратный fog смешивает RGB пикселя с чёрным после текстурирования и depth.
Near/far planes, Z-buffer mode и Q12-проекция сохранены. Для32-entry fog LUT
используются offset29248, shift4; Z-depth инвертируется из принятой матрицы,
чтобы задать переход в мировых единицах. Белый контрольный объект имеет:

| Глубина с исходным camera offset200 | RGB в реальном растре эмулятора |
|---:|---|
| 600 /1600 /1920 | 255,255,255 |
| 2400 | 186,186,186 |
| 3000 | 105,105,105 |
| 3600 | 16,16,16 |
| 4000 /4800 | 0,0,0 |

Таким образом, близкое пространство читаемо, дальше видимость плавно теряется,
а удалённые фигуры полностью скрыты. Переход плавный, без геометрических полос
и T junction cracks. Сам по себе этот тест подтверждает тональную кривую;
композиция дополнительно просмотрена на парных игровых кадрах трёх уровней,
у воды и среди объектов. [Сравнение exact/GPU](../../../research/evidence/nds/n13p/comparison.png).

Исходная VGA6-палитра и её percentage fade доRGB555 сохраняются, на GPU выбирается
row0. Уровневые оттенки остаются; дальний цветовой remap LIGHT заменён смешиванием
с чёрным. Исходный index0 сохраняет прозрачный контур. Дополнительные отверстия,
когда LIGHT переводил ненулевой индекс в0, заменены RGB-затемнением. Это выбранное
отличие: дальние силуэты скрывает темнота, без переключения маски по центру грани.
Два отдельных controlled alpha/depth fixtures продолжают проверять точный старый
путь, но их успех не объявляется идентичностью production fog исходному LIGHT.

Геометрия обычного fog-кадра не разрезается. Состав объектов, кадры, вода, mirror UV
дверей, исходные callbacks и мир сохраняются. Отдельный reflected-world pass
в reviewed normal PLAY оригинала не обнаружен; произвольный новый проход не добавлен.

## Сопутствующие измеренные затраты

Первый GPU-прототип дал27,39 virtual FPS: свет уже ускорился, но проявилась
стоимость водяных crops. Их точные операции выполнены копированием максимум двух
отрезков на строку вместо software modulo каждого texel.540 actual native/C
phase pairs и150 synthetic crops на язык остались одинаковыми.

Равные по размеру неприкреплённые effect payload заменяются на месте, без сдвига
всего slab. Текущие pins сохраняются; отдельный replacement test проверяет
отсутствие повреждения и отказ при полностью прикреплённом наборе.
В одном getter sweep повторный glyph не может снова перейти18→0 без dispatch;
дедупликация сохраняет первый вызов и порядок scheduling, включая NoSpace.
1500 host sweeps и полные ARM9 callback traces проверяют это отдельно.

Для fog варианты света не нужны: effect pool уменьшен384→128 КиБ внутри того
же1 МиБ asset slab. Освобождённая RAM отдана сырым изображениям. Профиль двух
остаточных задержек у воды обнаружил чтение2 КиБ кадров действующих анимаций.
Их ограниченный набор теперь проверяется/читается при загрузке уровня вместе
с initial bindings; source time и набор объектов не сокращены. Холодная загрузка
опубликована отдельно. Reserve655360 B не заимствован.

Итоговый максимум —291 quads,287 GE polygons,1154 GE vertices,260096 B textures,
8192 B palette. Static startup274432 B, managed2293760 B, SDK headroom446464 B.
В худшем штатном кадре сумма измеренных prepare/submit/upload —30,45/30,52 мс
RU/EN при бюджете двух VBlank33,43 мс. Номинальный остаток около2,9 мс не включает
публикацию probe/history и не гарантирует бюджет боя. World slab занят379576
из393216 B; перед размещением новых состояний требуется проверка. Диагностические
trace buffers можно исключить из production, но это ещё не сделано и не зачтено
как уже свободная память. Именно поэтому N17P/N21P сохраняются.

## Воспроизведение и границы

Общий SDK/core/package — те же, что в N13: BlocksDS1.24.0-1, GCC16.2,
melonDS DS libretro1.4.0 с SHA из compact. Zig0.13.0 и Python3.14.6 — общие
установки пользователя. Каждая сборка хранит source/package manifests.

```powershell
py -3.14 -B -X utf8 ports/nds/tools/check_effects_performance.py --prepare --host
py -3.14 -B -X utf8 ports/nds/tools/check_effects_performance.py --target fog-ru --runtime
py -3.14 -B -X utf8 ports/nds/tools/check_effects_performance.py --target fog-en --runtime
py -3.14 -B -X utf8 ports/nds/tools/check_effects_performance.py --target fog-audit --runtime
py -3.14 -B -X utf8 ports/nds/tools/run_darkness_probe.py
py -3.14 -B -X utf8 ports/nds/tools/summarize_effects_performance.py
```

Сборка standalone quality ROM: в общем MSYS с `source /opt/wonderful/bin/wf-env`,
из корня репозитория:
`make -C ports/nds -f Makefile.n13 OUTDIR=../../build/nds/n13p/quality darkness-gate`.
N13 Makefile сохраняет точный reference default; N13P builder явно выбирает
`EFFECT_GPU_FOG=1`, `EFFECT_LIGHT_CACHE=0`. Следующие этапы должны использовать
выбранный fog-путь, не случайно вернуть default точного N13 reference.

Fast frames иногда опережают единственный effect-metadata probe: его число
samples опубликовано честно. Полная presentation history, все callback traces,
462 frame hashes, ready-case packets и source world CRC у audit не сокращались.
Новый профилировщик хранит худшую подготовку на case; source fixture SHA неизменён.
Для обычной сборки принят30-cadence gate, цель60 не достигнута. Audit overhead
не включён в обещание производительности обычной сборки. Будущий бой, звук и
touch-карта ещё расходуют незанятый бюджет; запас не считается гарантией их FPS.
Следующий ID — N14, автоматического продолжения нет. Игровых записей на microSD нет.
