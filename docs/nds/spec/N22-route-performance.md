# N22: замеры обычного прохождения для N23

Статус на 30 октября 2026 года: **три полных ordinary профиля собраны;
бюджет и приёмка N23 не пройдены**.
По уточнению пользователя N22 собирает сведения для оптимизации N23.
Короткие прогоны N21P не доказывают производительность полного уровня.
Полные LEVEL1 RU, LEVEL2 EN и LEVEL3 RU завершены на candidate02;
оба языка концовки проверены независимо. Функциональная приёмка N22
фиксируется отдельно от приведённых здесь измерений производительности.

## Метод и воспроизводимость

Обычный контроллер вызывает кнопки/touch через libretro. Профилировщик
`ports/nds/tools/flow/route_profile.py` после каждого `retro_run` только читает
опубликованные ROM кольца истории показанных кадров и N21P CPU stages.
Он не пишет RAM, не меняет игровой ввод, часы, AI, renderer или частоту обновлений.
Все новые `run_routes.py` включают профилирование; отдельный вход —
`profile_routes.py`. Прежние прогоны без колец нельзя объявлять измеренными.

Используется тот же расчёт cadence, что в принятом N21P
`run_joint_frontend_emulator.py:summarize`. Считаются все интервалы продукта
с `PRESENTED`, без `LOADING/WARMUP/DIAGNOSTIC/SYNC`. Паузы и UI отделяются
реальными разрывами VBlank timestamps, а не субъективной фазой контроллера.
Секундное окно охватывает целые интервалы длительностью не менее секунды;
отдельно сохраняется целое число новых кадров за секунду. В каждом профиле
считаются все скользящие окна для критерия и десять худших непересекающихся
участков с координатами, frame IDs, upload bytes и временами CPU.

Обязательный бюджет N23: не менее 99% интервалов ≤2 VBlank и в каждом
проверенном секундном окне cadence ≥ половины refresh. Refresh в этом
эмуляторе 59,826098 Гц; половина — 29,913049. Средние 30 FPS сами по себе
бюджет не закрывают. Цель 60 FPS проверяется отдельно.

Исходные `runtime-profile.json`, отчёт навигации/ввода, PNG и снимки Python
сохраняются вне `build/` с SHA-256. Исходные JSON остаются побайтно прежними;
manifest связывает их build-пути с research-копиями. Отдельная derived summary
добавляет секундные участки, не переписывая записанный прогон. ROM/ELF
закреплены; полные копии кандидата хранятся в его собственном архиве.
`--verify` проверяет research-копии ROM/ELF по исходным SHA-256 и не зависит
от сохранности `build/`. У первых архивов durable mapping выводится из
закреплённого имени кандидата и проверяется по bytes/hash; новые manifests
сохраняют mapping явно. Проверка архива не заявляет проверку произвольной
новой сборки, лежащей по прежнему build-пути.
Системные файлы эмулятора и образы FAT повторно не копируются.

Команды первого замера:

```powershell
py -3.14 -B -X utf8 ports/nds/tools/flow/profile_routes.py --target build/nds/n22/candidate-partial01-ru --level 1 --language 1 --run-id fps-l1-prefix --cell-limit 180
py -3.14 -B -X utf8 ports/nds/tools/flow/archive_route_profile.py --report build/nds/n22/candidate-partial01-ru/route-1-level1-fps-l1-prefix/report.json --destination research/evidence/nds/n22/route-profiles/level1-ru-prefix01
py -3.14 -B -X utf8 ports/nds/tools/flow/archive_route_profile.py --verify research/evidence/nds/n22/route-profiles/level1-ru-prefix01/manifest.json
py -3.14 -B -X utf8 ports/nds/tools/flow/summarize_route_profiles.py --manifest research/evidence/nds/n22/route-profiles/level1-ru-prefix01/manifest.json
py -3.14 -B -X utf8 tools/reports/summarize_reports.py
```

Первое архивирование успело записать и закрепить все файлы, затем завершилось
ошибкой только при печати результата (`average_fps` вместо `virtual_fps`).
Исправленная команда `--verify` независимо проверила все 26 pins архива.
Повторный запуск архивирования требует нового destination и не заменяет архив.

Полный локальный агрегат — `analysis/nds-n22-route-performance.json`,
[компактная Git-сводка](../../../analysis/summaries/nds-n22-route-performance.json).
Полные покадровые данные находятся в
`research/evidence/nds/n22/route-profiles/level1-ru-prefix01/run/`.

`discovery` уже содержится в `sprites`; детальные map stages содержатся
в `map`. Их нельзя прибавлять второй раз. `cpu_excluding_wait` измеряет
`render_one`, а cadence дополнительно включает frontend/flow/probe.
`wait_vblank` — ожидание, а не самостоятельный резерв CPU.
Поля старого sprite GPU-observer публикуются с задержкой на один кадр;
для корреляции здесь используются current-frame history upload bytes.

Самый долгий кадр — ID 2240, камера `(21805, -300, 15880)`, 4 VBlank
(66,860 мс), upload 49 152 bytes. В нём sprites заняли 29,574 мс,
geometry 6,509 мс, simulation 3,318 мс. Native discovery внутри sprites —
4,957 мс; остальные 24,616 мс пока не разделены fine timers.
В 12 самых дорогих sprites-кадрах был current-frame GPU upload.
Без upload (1417 кадров) среднее `sprites − discovery` — 1,247 мс,
максимум 2,055; с upload (1588) — 2,033 и 24,616 мс соответственно.
Связь пика с `texture_require`, frame-store decode или compaction raw RAM
cache — **гипотеза**, а не установленная причина.

Границы этапов проверены по закреплённым исходникам кандидата:
`main.c:sprites_prepare` включает gather/discovery, audio service,
`texture_require` и append. `dok_nds_stream_plan`, включая VRAM allocator
и relocation planner, вызывается позднее в `effects_prepare.inc` и входит
в `effects`. Следовательно, стоимость именно GPU planner не объясняет
29,574 мс внутри sprites. Максимум всего effects в этом prefix — 1,358 мс.

Для будущих процессов observer дополнен `resource_rows`: published CPU cache
hits/misses/evictions, frame-store decodes/decoded bytes, callback counters
и RAM high-water. Одна и та же стабильная render publication связывает
sprite probe; более поздний CPU profile подтверждает завершение gameplay
probe. Smoke на том же кандидате дал 38 resource records, включая warmup,
37 активных кадров; ROM не менялась. Архив — `route-profiles/resource-smoke01/`.
Эти счётчики нельзя ретроспективно приписывать первым prefix-прогонам.
Sprite CPU cache counters сняты до overlay, cumulative decode включает
overlay. `cpu_reads` при resident frame store не означает чтение microSD.

Повтор prefix 180 клеток с этими счётчиками дал **побайтно одинаковые**
массивы input transitions (992), route rows, presentation history и CPU
profiles по сравнению с первым замером. Все 3005 активных кадров получили
resource snapshot. Значит, добавленное чтение observer не изменило этот
прогон. Архив — `route-profiles/level1-ru-resources01/`, проверка —
`root-route-resource-review.py/.json` в N22 evidence.

В кадре 2240 подтверждены 3 misses CPU cache, **8 evictions**, 3 новых
decode на 49 152 bytes, texture read bytes 0. Raw cache: 261 824 bytes
перед кадром, 260 288 после при capacity 261 920. Другие пики:

| Frame ID | Sprites, мс | CPU cache misses | Evictions |
|---|---:|---:|---:|
| 1776 | 25,847 | 2 | 9 |
| 1700 | 24,959 | 2 | 7 |
| 2212 | 21,979 | 1 | 8 |
| 949 | 20,474 | 1 | 8 |

Закреплённый `render/frame_store.c:evict` вызывает `memmove` оставшегося
raw pool при каждом вытеснении. Повторная compaction — обоснованный кандидат
для N23; конкретные размеры/время отдельных перемещений, unpack и audio
service ещё нужно измерить. Texture read bytes 0 не доказывает отсутствие
музыкального I/O, для которого этот счётчик не предназначен.

Худший секундный участок — кадры 1765–1792, начинается у камеры
`(23278, -300, 19441)`, 27,018238 FPS. Средние sprites — 7,776 мс,
map — 3,613 мс. Другие независимые медленные участки: 1621–1648
(27,461160 FPS), 243–270 (27,918846 FPS). Координаты и полные stage
распределения закреплены в derived summary.

## Candidate02: длительные попытки после исправления RAM budget

Три обычных прогона текущей сборки закончились Game Over, без FINISH.
Это отрицательные функциональные результаты, сохранённые для анализа
производительности, а не пройденные уровни. Engine/render/audio faults
в этих попытках не зарегистрированы. Для каждого активного кадра получен
CPU profile; критерии N23 не пройдены.

LEVEL2 дошёл до двух ключей и 14 убитых противников, затем исчерпал попытки
при отходе за здоровьем. В его профиле map достигает 20,678 мс, включая
map raster 16,430 мс; simulation — 24,478, sprites — 33,755, overlay —
12,212 мс. Это максимумы разных кадров, складывать их нельзя. Среднее
map — 5,452 мс; CPU excluding wait — 25,374 мс. Полные распределения,
десять медленных непересекающихся окон, координаты и исходные вводы

после исправления RAM, но не доказывают причинность отдельных пиков.

Методики и маршруты разных попыток различаются. Таблица не является парным
сравнением эффективности перераспределения памяти или языков. Нужен
успешный полный маршрут текущей сборки для каждого из трёх миров.

## Candidate02: успешный полный LEVEL1 RU

`candidate-partial02-ru/route-1-level1-root-saved-v18-02a` завершён обычным
прохождением. Использованы четыре закреплённых исходника ранее успешной

wrapper. Все игровые действия выполнены joypad/touch callbacks.
1098 достигнутых клеток включают детуры и возвраты, 38 противников убиты,
одна смерть дала настоящий retry с сохранением мира. Получены все ключи,
W, FINISH cause3, EINTRO RU и возврат к LEVELS; FAT не изменён. Последняя
игровая pose `(14929, -300, 27391)` попадает в исходную exit-cell `(31,57)`.

Все **15 416 активных кадров** имеют CPU profile. Cadence:
**30,396122 FPS в среднем**, минимум за ≥1 с **22,933338 FPS**,
867/15416 интервалов >2VB (**5,637001%**). Гистограмма 1/2/3/4/5/6VB —
1370/13177/861/6/1/1. Проверено 15 391 секундное окно. Оба условия N23
не пройдены, несмотря на успешный функциональный результат.

Худший одиночный кадр 10509 занял 6VB, камера `(3779,-300,14161)`:
sprites 46,222 мс, simulation 9,717, map 12,132; CPU excluding wait
83,977 мс. Счётчики показывают 2 CPU cache misses и 14 evictions,
texture read bytes 0. Кадр 9388 — 5VB, sprites 39,113 мс, один miss
и 16 evictions. Эти пики подтверждают необходимость измерить стоимость
повторной compaction на реальном полном маршруте. Пока это корреляция,
отдельный timer compaction отсутствует. GPU planner остаётся в `effects`.

Архив `research/evidence/nds/n22/route-profiles/level1-ru-current02-complete01/`
сохраняет byte-exact report/profile, inputs, source snapshots и screenshots;
ROM/ELF ссылаются на неизменяемый архив candidate02. Это успешный LEVEL1,
но он не закрывает отдельные обычные прохождения LEVEL2 и LEVEL3.

## Candidate02: LEVEL3 с активной группой противников

`route-1-level3-root-ru-l3-v4` остановлен явным host abort из настоящей PAUSE
checkpoint43: HP23, одна жизнь, два ключа. **Это не Game Over и не FINISH**;
functional `passed:false` вызван решением прекратить неудачный маршрут,
а не ошибкой движка. Два прежних retry были настоящими игровыми смертями.
Отдельно закреплённое изменение host controller описано в
[протоколе маршрутов](N22-routes.md); ROM и игровой мир не подменялись.

Все 7686 активных кадров имеют CPU profile: среднее 32,238897 FPS,
секундный минимум 21,576626, >2VB 10,590684%, максимум 5VB. Бюджет N23
не пройден. Simulation достигает **38,293 мс** (p95 15,800), map —
12,039, sprites — 23,089 мс. Максимумы относятся к разным кадрам;
сам по себе пик simulation не указывает, какой callback или поиск дорогой.
Нужен отдельный разбор simulation с сохранением исходного cadence AI/events.

Read-only сопоставление счётчиков уточняет кадр 7185, камера `(2572,-300,18010)`:
за этот simulation прошли 61 AI callback, 2 combat и 1 hero callback, active AI 61,
events 64. Соседние пики также содержат 59–61 AI callbacks. Это реальная
нагрузка многих активных противников, а не доказанный повторный вызов одного
героя. Таймеров отдельных callbacks пока нет. Проверка закреплённого
`core/events.c` показывает, что dispatcher уже обходит список активных owners;
приписывать пик полному сканированию 512 inactive owners нельзя. Доказательство —
`research/evidence/nds/n22/root-simulation-review.py/.json`.

Архив — `research/evidence/nds/n22/route-profiles/level3-ru-current02-attempt01/`,
266 pins проверены. Сохранённые данные дополняют N23 тяжёлой активной сценой,
но успешный полный LEVEL3 ещё требуется. Исправление следующего маршрута
состоит в посещении W перед проходом к группе противников: развилка `(13,24)`,
затем food `(13,26)` и W `(17,30)`. Источники и точные шаги закреплены в
`research/evidence/nds/n22/level3-w-detour.json`; это план, а не доказательство
выполненного прохождения.

Последующий живой v5 уточнил риск этого плана: разделитель x22,z14…34 —
glyph K75, class4, flags8. Это препятствие движению, пропускающее снаряды;
оно не изолирует W-chamber от огня боаров. «Без actor cells» не означает
безопасное ожидание или поворот в комнате оружия. Значение flags и
наблюдавшийся урон требуют учитывать стрельбу через разделитель, а не
объявлять данный участок защищённым. Игровые правила из-за этого не менялись.

## Последующая неудачная попытка LEVEL3 с W

`route-1-level3-root-ru-l3-w-prefix-v5` исполнил свежий boot и записанный
физический ввод до checkpoint29 старого v4. До продолжения проверены все
4977 scalar rows, 1448 input/touch transitions, flow/frontend/pose/MMap/TMap.
Игровое состояние не загружалось. Затем W действительно получено; попытка
закончилась настоящим Game Over, FINISH отсутствует. После второго retry
навигационный controller продолжил старую цель и израсходовал последнюю жизнь.
Этот недостаток host controller исправлен отдельной обычной Start-паузой
при наблюдаемом retry; игровые правила и ROM не менялись.

Архив — `route-profiles/level3-ru-current02-attempt02/` в N22 evidence:
6977/6977 активных кадров с CPU profile, среднее 33,307268 FPS, минимум за
≥1 с 21,576626, >2VB 8,556686%, максимум 5VB. Это отрицательный контроль,
не успешный LEVEL3 и не парное сравнение оптимизаций. Следующий v6 использует
проверенный physical prefix до W и непрерывное движение вместо quiet-поворота
в простреливаемой комнате; результат ещё проверяется.

## Candidate02: успешный полный LEVEL3 RU

`candidate-partial02-ru/route-1-level3-root-ru-l3-east-v8` завершён:
все три ключа, W, 17 kills, два настоящих retry, FINISH → EINTRO RU → LEVELS.
FAT не изменён. Начало повторено свежим boot и физическими joypad/touch
событиями до проверенной PAUSE v7 checkpoint9; RAM и состояние игры не
загружались. После первого retry пройдены западные двери, подобрано лечение,
через g23–24,13 достигнут key4 в23,25. Второй retry сохранил keys7; выход
достигнут через северную c-дверь. Восточный периметр не позволяет обойти
западные двери до получения третьего ключа: северная c-дверь требует key4.

Все **11 020 активных кадров** имеют CPU profile: среднее **31,684141 FPS**,
минимум за ≥1 с **19,942033 FPS**, >2VB **11,588022%**, максимум 5VB.
Гистограмма 1/2/3/4/5VB — 2550/7193/1237/39/1; проверены 9084 окна.
Бюджет N23 не пройден. Simulation: p95 17,327 мс, максимум 31,180;
sprites максимум 33,034, map максимум 12,136, overlay максимум 13,154 мс.
Максимумы разных стадий нельзя складывать.

Архив — `research/evidence/nds/n22/route-profiles/level3-ru-current02-complete01/`.
Предшествующий v7 сохранён как отрицательный контроль
`level3-ru-current02-attempt03`, а не успешное прохождение. Его последняя
жизнь закончилась при фактическом движении после PAUSE; игровой FINISH отсутствует.
Блокировку открытой двери в v7 объяснили read-only проверкой исходных
правил collision: клетки перед героем занимали снаряды. Дверь была открыта;
изменения игровых данных или collision для обхода препятствия не делались.

Таким образом, для N23 собраны три полных ordinary профиля текущего
candidate02, оба языка концовки, а также отдельно обозначенные неудачные
попытки с тяжёлой активной группой AI. Это функциональный результат N22;
оптимизация и повторная проверка бюджета остаются N23.

## Входы оптимизации N23

1. Использовать три полных ordinary профиля LEVEL1 RU, LEVEL2 EN и LEVEL3 RU
   текущего candidate02, включая поздний бой, смерть/retry, двери, touch и выход.
   Дополнить их воспроизводимыми тяжёлыми видами RU/EN, водой и отдельным
   наблюдаемым откликом ввода. Успешные и неудачные маршруты различаются;
   средние между ними не являются парным сравнением оптимизаций.
2. На тех же участках разделить sprites на gather, discovery, audio service,
   `texture_require`/decode/raw RAM cache compaction и append. Проверить
   пакетное удаление жертв с однократной compaction вместо `memmove` после
   каждой жертвы, сохранив LRU, pins, точные pixels и source leases. Отдельно
   разделить effects/VRAM planner и commit. Проверить причину кадра 2240;
   сам факт одновременного upload не доказывает стоимость allocator.
3. Разобрать map spikes и условия перерисовки, затем simulation/geometry.
   Проверять конкретные изменения парным прогоном с теми же исходными входами,
   native поведением, pixels/leases и cadence, а не только отдельным timer.
4. Учитывать расходы самих измерений. Для финала сравнить обычный product
   профиль и диагностический fine profile; не выдавать их за одинаковый режим.

Ordinary отчёты сохраняют кнопки/touch и frame IDs, но это само по себе
не измерение задержки до видимого ответа. Например, у завершённого V18
`latency_summary` пуст; его нельзя объявлять пройденным latency gate.
Для соответствующей проверки N23 требуется отдельный наблюдаемый отклик.

Нельзя закрывать бюджет уменьшением cadence AI/discovery/input, числа объектов,
видимости или эффектов без отдельного решения пользователя. Аппаратный FPS,
stack high-water на DS/DS Lite и прослушивание остаются N24.
