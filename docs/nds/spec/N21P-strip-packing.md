# N21P: упаковка служебного порядка strip

Статус C14: host и ARM static proof пройдены; runtime-память, cadence и LCD/DMA
проверяет root отдельно. Это не самостоятельная приёмка N21P.

В C13 подготовленные field54-метаданные добавили 896 B к образу программы и
перевели выровненный startup с 524288 на 528384 B. Эмулятор остановился до первого
кадра: SDK heap192512 B ниже обязательных196608 B. Резерв655360 B не затронут,
минимум SDK и размер SCN trace512 не снижались. Отказ сохранён в
`build/nds/n21p/candidate13-heavy-cost-ru/boot-memory-failure.json`.

`StripDraw[2048]` хранил четыре индекса вершин и флаг reuse в пяти байтах.
Каждый индекс находится в0…3, reuse в0…1: достаточно9 бит. C14 хранит их в
`uint16_t`: индексы в битах0…7, reuse в бите8. Исходный порядок0,1,3,2 кодируется
как0x00b4. Лимит2048, алгоритм поиска общей грани, матрицы, validation и FIFO
остаются прежними. Типизированное сравнение пяти int32-компонентов C12 сохранено.

Команда `py -3.14 -B -X utf8 ports/nds/tools/check_strip_packing.py` извлекает
фактические старые и новые helper-функции из архивированного и текущего backend.
Проверены819200 сравнений,16384 случая AD==BD, все512 сочетаний четырёх индексов
и reuse, включая повторяющиеся индексы, и фактическая последовательность20-byte
вершин при emission. Текстовое восстановление ограничивает изменения backend
представлением и доступом к метаданным; отчёт
`research/evidence/nds/n21p/backend-strip-packed-equivalence.json` содержит SHA.

`arm-none-eabi-nm -S` для frozen C13/C14 ARM-объектов показывает `strip_draw`
0x2800→0x1000 B: экономия6144 B без нового выделения памяти. Доказательство:
`research/evidence/nds/n21p/backend-packed/ARM-proof.json`. Размер heap и стоимость
декодирования ещё должны быть подтверждены реальным запуском. ROM C14 RU:
`90a2c3a8685bb202bcf3a32870d2d96421397abf3174aa46209f8470282083ea`.

Отклонённый C12 row-unroll в C13/C14 отсутствует: `map_raster.c` возвращён к
короткому `memset`, поскольку byte-exact вариант замедлял raster на5–6%.
