# N09: границы ввода, симуляции и представления

Это архитектурное решение N09. Порт восстанавливается по PKR/PKE; ссылки на
ASM, адресные системы и границы оригинального oracle находятся в
[N09-evidence](N09-evidence.md). Инерция и последовательное выполнение
противоположных команд сохранены. Free flight в этой сборке — диагностическая
граница перед N10, без проверки стен, дверей и высот.

## Владение и порядок обработки

SDK-адаптер опрашивает все 12 кнопок и touch, затем снимает монотонный uint64
counter принятого N08. Образец содержит sequence и точные фронты относительно
предыдущего опроса. Очередь сохраняет образцы по порядку, controls сохраняет
каждый фронт до native service. Отказ переполнения останавливает диагностическую
сборку до следующего опроса: отклонённый образец нельзя молча заменить новым.
Переходы, целиком прошедшие между аппаратными опросами, программно невосстановимы.

Один цикл активной сборки выполняет poll → capture → ordered drain → controls
→ один sweep принятого N08 scheduler → camera snapshot → prepare/submit/release
→ VBlank/present. Scheduler не привязан к числу кадров, не выполняет catch-up
и не подменяется глобальным fixed timestep. Герой зарегистрирован с исходным
интервалом 416 native ticks; фактические сроки зависят от явных service samples.

Первый callback героя получает elapsed=0. Дальше elapsed измеряется от
stopwatch, перезапущенного **после** законченного движения. Вызов motion не
читает часы. Перед каждым callback оболочка пересобирает командные биты
`0x00182a3c`, сохраняя остальные world flags: FIRE/USE не должны оставаться от
прошлого вызова только потому, что исходная motion-процедура их не очищает.
Use/fire/Select пока публикуются командами; игровые эффекты принадлежат N11/N15.
Use — потребляемый фронт отпускания X/B, удержание не повторяет его. FIRE остаётся held-командой.
Исходный consuming edge-reader проверяется отдельно от held-reader; подробности
и точные адреса приведены в N09-evidence.

Start обрабатывается на UI-границе до передачи образца игре. Пауза замораживает
world clock и исключает dispatch. После каждого UI poll очередь и накопленные
команды очищаются, удержанные кнопки/touch подавляются до отпускания. Та же
граница вызывается при возврате. Release заблокированной кнопки поглощается;
следующее отдельное нажатие снова доступно игре. Время меню не входит в elapsed.

## Камера и рендерер

После законченного callback публикуется подтверждённая поза. Чистая camera
history хранит две позы и предсказывает последнее фактическое перемещение не
дальше 416 native ticks. Поворот проходит по кратчайшей дуге; отдельный helper
интерполяции оставлен для консервативной политики N10. Teleport/смена epoch/
разрыв непрерывности требуют reset. Пауза не требует reset при замороженных часах.

Представление не вызывает motion, события или коллизии и не записывает
предсказанную позу в симуляцию. Диагностическая сборка проверяет неизменность
motion/history вокруг каждого представления. Q16 heading округляется до
ближайшего целого для неизменённого N07 renderer, ошибка не более 0,5°.
Исходный endpoint heading=360 нормализуется только в представлении.

N07 world/material/scene/backend и N08 time/events/SDK clock подключаются без
изменений. N09 копирует точные принятые trig, assets и scene.dat; последний
содержит палитру/HUD и диагностические камеры, не готовую геометрию мира.
Новая геометрия не генерируется из GBA-кода. GPU и VRAM-политика остаются N07.

## Проверяемые границы

Shared replay использует одинаковую явную timeline input/service с 0/30/60
camera observations. Сравниваются полные состояния и последовательность
callback, а не только конечная позиция. Это доказывает независимость симуляции
от частоты **представления при той же timeline**. Произвольно разные моменты
опроса и обслуживания не объявляются эквивалентными исходному движку.

В live emulator route действуют настоящий SDK input, принятые часы/events и
аппаратный 3D backend. Наблюдатель читает seqlock ABI и подаёт только физические
кнопки/touch через frontend; RAM, часы, CPU и результаты не инъецируются.
Эмуляторные измерения не подтверждают FPS, задержки и совместимость физической
DS/DS Lite. Аппаратная приёмка итогового хеша отложена пользователем до N24.

RAM выделяется одной загрузочной аллокацией с семью принятыми N03 slab.
World/input/controls/motion/camera помещаются в world slab, event bank — в events,
shared replay workspace и загрузочный render workspace по очереди используют
scratch. После загрузки live цикл не вызывает malloc и не читает файлы.
Нижний экран пока диагностический; игровая карта относится к N20, touch не
управляет yaw. Сохранений игры и записи на microSD в N09 нет.
