# N21: исходные доказательства frontend

29 октября 2026 года. Этот документ описывает источники и подготовку данных;
приёмка runtime, ввод, настройки, звук и измерения приведены в паспорте N21
и `N21-frontend.md`. GBA-код в новые инструменты не импортируется.

## Подтверждённое исходное поведение

Заставка загружает `ЗАСТАВКА_ПАЛ`, рисует `ЗАСТАВКА_СПР`, запускает
`ЗАСТАВКА_ЗВУК` **один раз**, ожидает ввод и останавливает звук. После этого
вызван README: он использует GAMEP1 и снова запускает тот же звук один раз.
Фоновая бесконечная музыка меню из этого ASM не следует. Ресурс звука110
содержит474361 unsigned PCM8 сэмпл с исходной частотой11025Hz; его доставка
и таймер ARM7 приняты отдельно в N18.

Оригинальное меню предлагает три уровня и выход. Новая иерархия NDS с главным
меню, языком, управлением, предысторией и отдельной паузой — адаптация по
паспорту N21. Она не выдаётся за дословное восстановление DOS-меню.

`audit_original.py` исполняет исходный машинный код селектора из свежего
Ghidra-экспорта в x86/16 Unicorn. Проверено14 случаев: возвраты внешнего
menu driver0,1,2,3,4,5 и65535 для обоих языков. Graphics/menu/keyboard/runtime
внешние вызовы являются sinks; switch, арифметика, far-pointer writes,
подстановка номера и `RETF` выполняются исходными инструкциями.

- Выбор1–3 записывает `LEVELn`, `BINTROn`, `EINTROn`, `BSPRn`, `ESPRn`,
  `GAMEPn`, возвращает DX:AX=`0020:0000`.
- Выбор0/4 возвращает `0000:4000`; неизвестные значения — `0000:0000`.
- Возврат оставляет исходный caller stack после far return.

Точный отчёт — `research/evidence/nds/n21/original-selector.json`.
Это отдельное исходное доказательство; оно не подменяет проверку NDS-кнопок.
В том же прогоне выполнены ещё два исходных title и два README entry point:
каждый вызывает once ровно один раз, затем stop ровно один раз, loop не
вызывается. Title после stop действительно входит в README; README возвращает
исходный far caller stack. Аудиоустройство остаётся внешним sink: качество PCM
этими четырьмя случаями не доказывается.
Каждая загрузка fixture проверяет свежий N21 manifest, SHA его exporter/driver,
1008.bin, data.bin и ASM; после всего набора pins повторно сравнены. Шесть
отрицательных проверок подменяют в памяти чтение code/data/ASM обоих языков:
каждая отвергнута. Физические файлы этих проверок не изменяются.

## Данные и фон

Принятый пакет N04 SHA-256
`2f03ba02c9986b4e0bd321e94ca00df8a355f7dbb1dff5598a950d3366061511`
уже содержит семь offline статических INDEX8 изображений256×192 каждого
языка. Они независимо пересчитаны из RES и побайтно сравнены с representation6:

`sx = floor((2*x+1)*320/512)`, `sy = floor((2*y+1)*200/384)`.

Это принятая в N06 коррекция DOS320×200 с аспектом4:3 к256×192. Титульные
надписи и копирайт встроены в исходное изображение; новая надпись поверх не
добавляется. RGB555 берётся из соответствующей исходной VGA RGB6-палитры
через сдвиг каждой компоненты вправо на1.

| Экран | Исходное изображение | Палитра |
|---|---|---|
| Титульная заставка | ЗАСТАВКА_СПР | ЗАСТАВКА_ПАЛ |
| BINTROn | BSPRn | GAMEPn |
| EINTROn | ESPRn | GAMEPn |
| Меню/пауза | FON46×46, повторение | МЕНЮ_ПАЛ |
| README в новой иерархии | ЗАСТАВКА_СПР | ЗАСТАВКА_ПАЛ |
| ENDTXT в новой иерархии | фон меню | МЕНЮ_ПАЛ |

Строки меню/README/ENDTXT — компоновка NDS: исходный README очищает экран
с палитрой GAMEP1, не рисует заново ЗАСТАВКА_СПР. В NDS исходная титульная
картинка служит отдельным верхним фоном предыстории, полный текст находится
снизу. У ENDTXT нет отдельного исходного статического изображения.
Исходные TITLE/BSPR/ESPR payload не дублируются
в frontend.dat и не вшиваются в ELF. Мелкий неизменяемый FON повторяется при
изменении экрана, а не заново на каждом VBlank.

`extract_frontend.py` сохраняет38 записей в `build/nds/n21/frontend.dat`:
4684 bytes, SHA-256
`a51c74bbc400bed0674cba5b9cefd935ec74be3509f5cd26a1c68b3c98cd4a36`.
Заголовок32 bytes: magic `N21UI01\0`, затем шесть little-endian u32:
version1, entry count38, directory offset32, total bytes4684, reserved0,0.
Каждая запись каталога16 bytes: u32 kind,id,offset,bytes. Все spans находятся
внутри файла; сериализованных указателей нет.

| kind | id | Содержимое |
|---|---|---|
| 1 | `16*language+textIndex` | Исходные CP866 bytes без изменения |
| 2 | `16*language+level` | Исходное имя уровня без завершающего NUL |
| 3 | `16*language+backgroundIndex` | u32 image asset ID, u32 palette asset ID N04 |

language1=RU,2=EN. Порядок textIndex0…7:
README,BINTRO1,EINTRO1,BINTRO2,EINTRO2,BINTRO3,EINTRO3,ENDTXT.
Порядок backgroundIndex0…7:
ЗАСТАВКА_СПР,BSPR1,ESPR1,BSPR2,ESPR2,BSPR3,ESPR3,FON.
Image representations:6 для первых семи,2 для FON; palette representation7.

В каждом языке сохранены все восемь текстовых ресурсов. Пагинация N06
30 столбцов×9 строк FONT16 даёт34 страницы суммарно:

| Текст | RU bytes / страниц | EN bytes / страниц |
|---|---|---|
| README | 404 / 3 | 426 / 3 |
| BINTRO1 | 338 / 2 | 364 / 3 |
| EINTRO1 | 82 / 1 | 101 / 1 |
| BINTRO2 | 226 / 2 | 251 / 2 |
| EINTRO2 | 92 / 1 | 86 / 1 |
| BINTRO3 | 345 / 2 | 381 / 3 |
| EINTRO3 | 134 / 2 | 153 / 2 |
| ENDTXT | 227 / 3 | 219 / 3 |

Проверяется потребление всех исходных bytes до NUL/`$` ровно один раз;
CR/LF и суффикс после терминатора учитываются отдельно. Системные шрифты,
перевод заново и усечение не используются. Источники FONT8/FONT16 и семантика
CP866 приняты в N19; runtime-пагинация проверяется отдельно от данного экспорта.

для исполнения уже экспортированного кода, не для анализа EXE.

последние два пункта отложены до N24 по принятой политике.

## Локализация игрового изображения POPAL

`audit_visual_assets.py` независимо читает исходный RES каталог и изображения
через N04 source oracle `audit_assets.py`; converter не вызывается. Проверены
все146 пар ресурсов. Среди111 пар графических ресурсов (77 изображений,
24 анимации,2 шрифта,5 палитр,3 LIGHT)110 побайтно одинаковы. Единственное
графическое различие — POPAL, ресурс145. Остальные11 различий полного
каталога относятся к восьми текстам README/BINTRO/EINTRO/ENDTXT и трём LEVEL.

POPAL содержит шесть кадров с нулевыми индексами0…5. Исходные animation table,
интервалы, параметры отображения, far-поля, заголовки и размеры всех кадров
совпадают. Первые пять изображений совпадают полностью. Последний кадр158×70
различается только тремя исходными пикселями:

| Координата | PKR RU | PKE EN |
|---|---|---|
| x155,y69 | 147 | 0 |
| x156,y69 | 121 | 0 |
| x157,y69 | 41 | 0 |

Это реальное различие source art, поэтому замена только языка меню не
достаточна для полной локализации представления. Профиль мира, animation IDs
и исходные bindings при смене языка остаются неизменными; разрешён отдельный
выбор представления единственного кадра. Приёмка реализации такого выбора
проводится отдельно от данной проверки данных.

Для всех шести кадров обоих языков независимо проверены N04 FRAME_INDEX8,
GPU_INDEX8_POT и ANIM_META: исходные пиксели, нулевые поля POT, геометрия,
интервалы и frame IDs совпали с RAW RES. Последний GPU-кадр имеет storage256×128,
32768 bytes; его ID:

- RU: `0x42441405`.
- EN: `0x82441405`.

Формула: `(language<<30)|(145<<18)|(5<<10)|5`; representation5,
**subindex5 с нулевой нумерацией**, source_kind2. Три отличия в GPU stride256
находятся по offsets17819,17820,17821. Все прочие bytes последнего кадра равны.

`build/nds/n21/generated/frontend_visual.inc` содержит только два ID и
константы `DOK_FRONTEND_VISUAL_POPAL_RU/EN`; исходных пикселей в нём нет.
Два локальных oracle-файла32768 bytes:
`build/nds/n21/visual-popal-{ru,en}.bin`. Полный отчёт с source SHA до/после,
asset IDs, N04 file offsets, SHA каждого кадра, metadata и pins —
`research/evidence/nds/n21/visual-source.json`. Принятый N04 пакет и оба RES
после проверки не изменились. Существующие frontend.dat и frontend_hash.inc
этой проверкой не меняются.
