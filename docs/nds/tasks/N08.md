## Работа

1. Перенести шкалу времени, owners, ёмкость, порядок dispatch, повтор и удаление по оригинальным C/ASM. Не выдавать период героя 416 native ticks за частоту всей логики.
2. Ввести инъецируемые часы для host-проверок и платформенный монотонный источник. Определить pause/resume без накопления меню-времени и сравнение deadlines с учётом wrap.
3. Сохранить значимые исходные особенности перепланирования от времени после callback; сравнить с оригиналом до решения о любом изменении. Интерполяция рендера не вызывает callbacks.

## Границы

Не вводить update60 вместо исходных интервалов. Не переносить сетку времени GBA как оригинальный факт.

## Критерии готовности и проверки

- [x] Одинаковая последовательность service/clock samples даёт одинаковые события при разных чтениях представления. Изменение native polling sequence отдельно не объявляется эквивалентным.
- [x] Проверены wrap, одновременно due события, удаление owner внутри callback, ёмкость и повтор. Опасные native lifetime/rollover пути исправлены явно.
- [x] Пауза не продвигает мир и не создаёт burst после возврата. Безопасная исходная семантика подтверждена независимым исполнением PKR/PKE; pause — отдельная адаптация NDS.

от новых host/ARM9 реализаций, эмулятор отдельно от физической DS/DS Lite.
Совпадение двух новых реализаций не доказывает эквивалентность DOS.
Если проверка не выполнена, назвать причину и оставить критерий открытым.

## Результат

### Реализация и архитектурная граница

Новые strict C11 модули `ports/nds/core/time.c`, `events.c` и публичные
`include/dok/time.h`, `events.h` восстановлены независимо от GBA. Три субагента
отвечали за исходные инструкции, ядро и независимую проверку; root реализовал
DS adapter/probe и интеграцию. Принятые N01–N07 исходники/артефакты сохранены;
GBA/SDL2 код, статусы и handoff не менялись. Общий `ExportNdsTime.java` добавлен
только для целевого read-only Ghidra-экспорта, старые анализаторы не изменены.

Архитектура и API — [N08-time](../spec/N08-time.md), исходные адреса/ABI и
границы oracle — [N08-evidence](../spec/N08-evidence.md), матрица/протокол —
[N08-validation](../spec/N08-validation.md), компактный итог —
[nds-n08-time.json](../../../analysis/nds-n08-time.json).
Сборки — `build/nds/n08/`; первичные доказательства —
`research/evidence/nds/n08/`. Полные exports, отчёты, ROM и payload в Git не входят.

- World clock принимает N03 PlatformServices, переводит uint64 counter в
  uint32 native ticks с точным дробным остатком, без промежуточного overflow.
  Поддержаны все ненулевые uint32 рациональные частоты; backward counter
  отвергается без изменения clock/out. Pause учитывает последний active delta,
  resume исключает menu time, fraction сохраняется. Native deadline comparison
  остаётся unsigned с ранним/поздним поведением через wrap, не signed difference.
- DS adapter запускает SDK `systemCounterSetup()` один раз и использует
  timer2 `/64`, `systemCounterGetTicks()`, descriptor 33513982/64 counts/s.
  Мировая шкала 1193182/119 ticks/s; сокращённое отношение 38181824/1994081929.
  SDK ELF подтверждает 64-bit carry, pending low16 rollover и CPSR restore.
  PIT I/O, потеря DIV-остатков и reset-phase jump DOS не эмулируются.
- Caller-owned typed bank: **512 owners ×72 =36864B**, внутри events 64KiB.
  Owner использует N03 `(epoch,object_id,generation)`, три event slots,
  native capacity 0…4 с условием count<capacity−1. Callback ID заменяет far
  pointer; parameter/context — явный адаптер, native callback получал owner.
  Malloc и SDK-заголовков в ядре нет. Лимит512 не объявлен native world limit.
- Сохранены кольцо C,A,B при вставке A,B,C, insertion order внутри owner,
  live append, shrinking owner bound, copy read→write до callback, source/read
  deadline после callback и `set_interval(array[0])`. Повтор назначается от
  повторного чтения clock после callback; catchup пропущенных периодов нет.
- Destroy текущего owner откладывается до возврата; активация заранее
  зарегистрированного пустого owner публикуется после sweep. Регистрация,
  reset/clear и recursive dispatch внутри callback отвергаются. Object memory
  caller не освобождает во время callback. Fault при clock failure остаётся
  sticky; завершённые side effects не откатываются. Reset требует больший epoch.
- API выполняет один sweep dispatch(0), без busy wait. Отдельно выявлен исходный
  дефект: begin FFFFFFF0, callback+32/cancel, final 10 приводит native к повторению
  sweep до почти полного uint32 цикла. NDS возвращается после одного sweep;
  это **явное safety исправление**, проверенное shared regression, не exact
  equivalence для mid-dispatch wrap. Адреса RU 1038:02B1/03F9/03FD, EN 1010:17AF/17B3.

Renderer/interpolation не вызывает callbacks. Новой фиксированной сетки
update60 или GBA 100tick нет. Один service/clock timeline при 15/30/60
наблюдениях представления даёт одинаковые события; произвольное прореживание
native dispatch меняет запаздывание и не выдаётся за тот же timeline.
Полный игровой цикл ещё не создан. N09–N23 обязаны сохранять эту границу и
проверять фактическую нагрузку/порядок input/service/presentation.

### Доказательства оригинала и проверки

Ghidra 12.1.2 / Java 21 открыл сохранённые PKR/PKE проекты read-only и экспортировал
целевые segments. SHA EXE до/после совпали. Адреса выше — NE-loader
segment:offset, не файловые смещения и не runtime DPMI selectors.
Unicorn 2.1.4 исполнил целые native scheduler functions и настоящий compiler
memcpy, с управляемыми clock/callback/alloc/free boundaries. Это не полная DOS
игра или PC timing. На язык: 16 scheduler cases, 24 callbacks, 8 PIT vectors,
11 stopwatch steps. RU/EN совпали. У уничтоженного owner stale allocation
bytes исключены из active-state сравнения; живые owners и order проверяются.

Финальный unified gate: **17974 shared checks**, 3 clock cases / 7 event groups;
48 независимых rational frequencies, 720 steps/**5760 scalar checks**;
**32 native cases и 242 actual injected clock reads** совпали с новым C.
Host Windows исполнен; Linux binaries только собраны/связаны. ARM9 strict
core/headers/tests собраны; 20 SDK packages сверены. **246** прежних pins
проверены до/после; 24 текущих source pins закреплены manifest.
Дополнительное независимое ревью C подтвердило 12000 exact divmod vectors
(5112 fallback) и 4194304 lifecycle operations с ring/count/fault invariants.
Эти stress checks не заменяют original-instruction conformance.

Финальный melonDS DS **libretro core 1.4.0**, DS mode/software/interpreter:
398 frontend frames, 556 coherently прочитанных trace records при ring 512,
без потерь. Три synthetic timelines дали по 30 callbacks и 12/24/48 render reads.
Реальный SDK clock/scheduler: 62 callbacks (30 до паузы, 32 после), 378 точных
рациональных переходов, 0 callbacks в паузе. Реальная кнопка Start удержала
паузу **126 VBlank**, world 15343→15343; deadline 15425 сохранён, первый resumed
callback 15511. No catchup/burst. SDK counter cadence сверена на 314 VBlank;
это проверка модели эмулятора, не частоты физического кварца.
PAUSED (state3/paused1) и COMPLETE (state5/failures0) экраны просмотрены.

RAM: static/startup 118784 + managed 2293760 + SDK 602112 + reserve 655360
=3670016B. Events bank 36864B, оставшийся tail events slab проверяется canary.
Стек 12288B; .su max suite 1648, main 160, dispatch 112, callback 152B по функциям,
это не полный SDK/IRQ stack peak и не пик полной игры.

### Ограничения и передача

Физическая DS/DS Lite, flashcart/loader, реальный IRQ latency/кварц/FPS
не проверены — по указанию пользователя итоговая N24. Долгий SDK uint32/uint64
uptime rollover не ожидался; большие delta/native wrap проверены инъекцией.
SDK timer2 требует обслуживать IRQ быстрее одного low16 периода (~125 мс).
Native unsigned deadline anomalies намеренно сохранены; непроверенные игровые
callbacks/их интервалы и side effects остаются задачам механик. Игровые
сохранения не добавлены; ROM не читает/не пишет microSD.

Следующий ID — **N09**. Входы N07/N08 приняты. Первый шаг: прочитать её паспорт,
раскладку в плане, исходные movement C/ASM и принять timestamped input/edge
buffer, правила service timeline и независимое camera presentation. Не терять
короткие кнопки, не вращать камеру touch, не переносить удалённую GBA инерцию.
N10/N12/N15 должны заранее регистрировать pools или откладывать создание owner
до конца sweep; callback не может внезапно register новый owner.
