## Контекст нового чата

Обязательно прочитать [AGENTS.md](../../../AGENTS.md), [NDS-план](../plan.md)

## Критерии готовности и проверки

- [x] Схема кнопок полностью совпадает с планом, touch не вращает камеру.
- [x] Измерены перемещение/угол за одинаковое время при 30/60 FPS; направления и скорости сверены с оригинальными векторами.

## Результат

**Готово (эмулятор), 29 октября 2026 года. Следующий ID — N10.**
Все три программных критерия выполнены. Физическая DS/DS Lite, flashcart и

### Принятые решения и исходное поведение

Новые strict C11 модули — `input`, `controls`, `motion`, `camera`; SDK-адаптер
находится в `platform/input/`, интеграционная диагностика — в
`platform/movement_probe/`. Три субагента независимо выполнили original oracle,
motion/camera и input/tooling; root собрал service/renderer integration.

Raw input хранит все 12 кнопок, touch, sequence и uint64 timestamp. Ordered ring64
занимает 2624B, не перезаписывает старые образцы. Controls сохраняет отдельные
фронты до native service. Отказ capture/feed останавливает probe до следующего
SDK poll. Нельзя восстановить физический переход, целиком прошедший между polls.

Раскладка совпадает с планом: Dpad ход/стрейф, Y/A поворот, R Fire, L held Run,
X/B эквивалентный Use, Select next weapon, Start pause/resume. Touch не меняет yaw.
Use срабатывает **при отпускании**, как настоящий consuming reader PKR/PKE:
IRQ make создаёт state3, break оставляет state2, reader принимает только state2
и потребляет его. Одновременный release X+B даёт один `use_triggered`.
FIRE/RUN/ход остаются held-командами. UI очищает очередь и накопленные команды
на входе, после каждого UI poll и при возврате; held и release поглощаются
до нового нормального нажатия/отпускания. Пауза не вызывает dispatch.

Восстановлены исходные WORD/low32/SAR/IDIV, знаки, разгон, торможение, инерция,
порядок противоположных команд и полный distance после трёх подшагов. Противоположные
команды не нейтрализуются: последовательные операции могут оставлять дрейф.
GBA instant-stop не переносился. EN input исправлен на **Ghidra 1050:199C**;
исторический 1068:199C находится внутри графики и входом original input не является.
Полные NE-segment exports/ASM и SHA оригиналов до/после — в
[N09-evidence](../spec/N09-evidence.md), первичный oracle — локально
`research/evidence/nds/n09/original-motion.json`. Файловые offsets, Ghidra segments
и runtime DPMI selectors не смешиваются.

Принятые N07 renderer и N08 time/events подключены без изменений; все прежние
282 pins сохранены. Герой обслуживается исходным event 416, без fixed timestep
или catch-up. Первый callback elapsed 0; stopwatch перезапускается после движения.
Перед каждым callback пересобирается командная маска 00182A3C, остальные world flags
сохраняются. `last_flags=0` явно инициализирован там, где DOS оставляет поле
неопределённым; нулевые начальные накопители не создают активного отличия.

Camera history хранит две подтверждённые позы, отдельно предсказывает не дальше 416
native ticks, использует кратчайшую дугу и не меняет симуляцию. Есть pure interpolation
и reset для discontinuity/epoch/teleport. Heading 360 нормализуется только в
представлении. Адаптер к неизменённому N07 округляет Q16 heading до целого,
ошибка≤0,5°. Общая архитектура — [N09-runtime](../spec/N09-runtime.md).

### Ограничения и передача N10

Реальные DS FPS/latency/stack peak, flashcart/loader/IRQ timing не проверены — N24.
Free flight не является проходимостью: N10 должна заменить `dok_motion_free_flight`
на проверенную collision/occupancy границу. Use/fire/weapon пока только команды,
игровые эффекты относятся к N11/N15. Нельзя копировать GBA архитектуру или менять
инерцию для удобства. Долгое uint64 uptime и полная игровая сессия не проверены.
SDK timer2 требует обслуживать IRQ быстрее low16 периода(~125мс).

Следующая **N10**: прочитать её паспорт, план/handoff и новые N09 specs. Первый шаг —
принять границы world collision/occupancy и camera presentation около препятствий
по PKR/PKE ASM, затем реализовать query/commit. Сохранить порядок трёх подшагов,
полный distance, elapsed/event cadence и free-flight oracle как контроль.
Collision rejection возвращает old x/z, но не отменяет остальные подшаги.
Callback получает полный request; нельзя читать неопубликованный candidate actor
через обход API. N08 запрещает register нового owner внутри dispatch: заранее
регистрировать pools либо откладывать создание до конца sweep. Существенные
решения принять до деталей и оптимизаций; для N10 снова привлечь субагентов.
