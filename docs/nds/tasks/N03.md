# N03: Контракты ядра и бюджет памяти

Статус: **готово (эмулятор)**. Выполнена 29 октября 2026 года.

## Контекст нового чата

Рабочий корень: `C:\Source\DoK-port`. Предыдущая переписка недоступна.
Обязательно прочитать [AGENTS.md](../../../AGENTS.md), [NDS-план](../plan.md)
и [NDS-handoff](../handoff.md), затем этот паспорт.
Направление NDS независимо от GBA и SDL2; их завершение не требуется.
Основа — декомпиляции PKR/PKE, ASM и проверки оригиналов. GBA-код не копировать;
исследования использовать как указатели на доказательства. Исключение — явно
принятые данные баланса из NDS-плана.

**Зависимости:** [N01](N01.md), [N02](N02.md). Проверить фактические результаты и handoff зависимостей.
Планируемые результаты ещё не существуют только потому, что описаны в паспорте.

## Цель

Зафиксировать минимальные C11-контракты независимого ядра и проверяемый бюджет DS mode.

## Работа

1. Определить границы PlatformServices, InputFrame, GameState, SceneSnapshot, AssetCatalog, BalanceProfile и владение памятью. Использовать фиксированные целочисленные типы и логические ID; не копировать packed DOS-структуры.
2. Разделить 4 МиБ main RAM с учётом SDK/ARM7 на код, мир, события, стеки, кэши, звук и буферы. VRAM, DMA, cache coherency и TCM описать отдельно. Зарезервировать минимум 10% управляемой RAM.
3. Создать host-цель ядра без SDL2 и NDS API. Добавить измерители high-water для арен/стеков и проверку пределов; предусмотреть исчерпание ресурса без повреждения состояния.

## Границы

Не восстанавливать полные игровые подсистемы заранее. Не обещать полное совпадение DOS struct layout с host ABI.

Общие требования NDS: DS/DS Lite, верхний кадр 256×192 с коррекцией DOS 4:3
(сцена 154 строки, HUD 38), нижний экран — карта во время игры; мир RU и общий
профиль монстров, RU/EN. Игровых сохранений, autosave и импорта saves нет.
Записываются только настройки. Не менять статусы и handoff GBA/SDL2.

## Критерии готовности и проверки

- [x] Заголовки и ядро скомпилированы strict C11 на host/Linux/ARM9; SDK используется только платформенной единицей GNU C11.
- [x] Бюджет сверён с ELF/link map и runtime heap в DS-эмуляторе; исключено 655360 байт резерва (17,857% ARM9 region). Физическая DS отложена до N24.
- [x] Предельные выделения, OOM и сохранность состояния проверены на host и ARM9; GBA/SDL2 build не подключён к новым типам.

Проверки выбираются по рискам задачи: оригинальные данные/исполнение отдельно
от новых host/ARM9 реализаций, эмулятор отдельно от физической DS/DS Lite.
Совпадение двух новых реализаций не доказывает эквивалентность DOS.
Если проверка не выполнена, назвать причину и оставить критерий открытым.
«Готово» допустимо только после выполнения критериев и передачи результата.

## Результат

**Готово (эмулятор), 29 октября 2026 года.** Все критерии программной приёмки
выполнены. Аппаратная проверка отложена до N24; полное достижение NDS-цели
этим не заявляется. Следующий ID — **N04**, его зависимости N01/N03 приняты.

### Принятые решения и изменения

- [Общая архитектура](../spec/N03-architecture.md),
  [контракты](../spec/N03-contracts.md), [память/SDK](../spec/N03-memory.md).
  Источники — существующие Ghidra/ASM N01 и установленный SDK. Новые игровые
  функции EXE не восстанавливались; packed DOS layout и код GBA не копировались.
- `ports/nds/include/dok/{contracts,memory,memory_budget}.h`, `core/{contracts,memory}.c`.
  Фиксированные ID, world epoch/slot generation, физический InputFrame, raw
  clock scale, immutable descriptors. Типизированный caller-owned GameState —
  оболочка, не загруженный мир; has_world=0. SceneSnapshot задаёт lease и канал
  возврата render-effects на уровне архитектуры, без фиктивной сцены/renderer.
- Caller владеет памятью; core не вызывает malloc. Byte arenas и bounded work
  stack имеют high-water и безопасные отказы. Произвольные typed объекты поверх
  declared char buffers в strict C11 не обещаются; platform получает один
  startup malloc для семи областей, выровненный по 32 байтам.
- `platform/memory/`, `Makefile.n03`, `tools/build_memory.ps1` — отдельный ARM9
  memory probe и сборка. N02 не изменена. `tests/` и `tools/check_core.py` —
  независимые host/ARM9 compile gates. `tools/run_memory_emulator.py` наблюдает
  реальный ARM9 ROM через неизменённый libretro frontend N02, RAM только читает.
- Linker region ARM9 — 3584 КиБ, верхние 512 КиБ исключены по политике порта;
  TCM/VRAM отдельно. Runtime SDK heap limit оказался 0x023F4000, выше linker
  0x02380000. Независимый прогон выявил ошибку простого reduceHeapSize(640КиБ).
  Теперь сначала исключаются 475136 байт превышения, затем резерв 655360;
  финальный heap limit — 0x022E0000. Основание — runtime и установленные CRT/SDK
  objects, а не гипотеза о reclaim ARM7. Старый finding сохранён отдельно.
- ARM9 probe явно flush-ит управляемый блок и sequence/cache lines observation.
  Async GPU/DMA/ARM7 ownership, стеки и lifetime ограничения описаны в спецификациях.
  Субагенты реализовали контракты, память/SDK и независимые тесты/review.

### Доказательства, ограничения и следующий шаг

Компактный итог — [analysis/nds-n03-architecture.json](../../../analysis/nds-n03-architecture.json).
Полные `host-check.json`, `build-report.json`, `source-manifest.json`,
`visual-qa.json`, SDK manifests/CRT disassembly и `emulator/result.json`/PNG
лежат в `research/evidence/nds/n03/`. Последний runtime связан с текущими
harness/ABI/ROM/ELF и полным source manifest. Исходный heap-limit finding
сохранён без копий промежуточных ROM/ELF.

Потолки — архитектурные ограничения, не измеренный рабочий набор полной игры.
Renderer/GPU packets, точные visibility effects, scheduler, мир, каталог
payload и баланс ещё не реализованы. Их semantics зададут N04–N08/N16/N20.
C11-структуры не сериализуются как пакет или сохранение. Игровых сохранений нет.
Полный профиль стеков — N23, аппаратная проверка DS/DS Lite, loader/microSD/FPS — N24.
GBA/SDL2 код, сборочные входы, статусы и handoff не менялись.
