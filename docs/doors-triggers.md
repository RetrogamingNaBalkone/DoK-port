# Двери и сенсорные зоны: G09

Уточнение27 октября, [второй плейтест UI01](ui01-playtest2.md): crop сам
по себе не определяет мировое направление створки. Восстановлен пропущенный
аргумент отражения центральной плоскости у соседней стены (RU10B0:03EE,
BP+1C; вызовы RU1098:49E7/4A77/4E5D/4EED, EN1030:5405/5508/5938/5A3B).
Каждая клетка имеет своё полотно, объект/фаза glyph общие.16 исходных
x86-векторов и mGBA подтверждают разъезд соседних полотен. Ниже описание
исходного crop остаётся верным в координатах текстуры.

Проверено 25 октября 2026 года. Общий модуль — `include/dok/interactions.h`,
`src/interactions.c`; он использует scheduler G06, коллизии G08 и общий мир G03.
В общей GBA-сцене Start вызывает Use. Поступательная инерция по-прежнему отключена,
разгон поворота сохранён. Следующая задача — G10.

## Поля и ABI

Проверены `LES`, знаковые сравнения, `CBW`, `MOVSX`, `IDIV`, порядок PUSH и
far-вызовы. Объект и параметры передаются far-указателями; BP+6 — this,
BP+0A — pointer на изменяемые event bits, BP+0E — источник. Возврат `RETF`,
стек очищает caller. Sensor вызывает virtual slot `vtable+0x14`, передаёт
источник-сенсор и локальную копию DWORD из невыравненного `+0x67`.

| Native field | Смысл в проверенном пути |
|---|---|
| `+15` word | Mutable flags; `0x10` разрешает проход, `8` устанавливается при открытии |
| `+50` signed word | Индекс фазы crop |
| `+52` signed word | Период последующих callback; в исходных дверях 0 |
| `+54` byte | 2: закрыто/открывается, 1: открыто/закрывается |
| `+55` byte | Ready: разрешено Use; 0 во время анимации |
| `+56` signed word | Общая занятость клеток двери, балансируется движением |
| `+58/+5A` words | В этих обработчиках не используются; сохранены без нового смысла |
| `+5C` word | Маска требуемого ключа |
| `+5E` signed word | 1: автоматическое закрытие, 0: повторный Use закрывает |
| `+60` signed word | Число фаз/divisor crop, минимум 8 при Use |
| `+66` signed long | Задержка AUTO и запуска CLOSE из AUTO |
| `+6A` word | Исходные flags, восстанавливаются после полного закрытия |

В runtime `door.extent` занимает бывшие два padding-байта union+18.
Object остался 36 байт, union — 20, карта RAM/actor ABI не изменилась.
Упаковщик записывает начальный extent=1; прежние development-пакеты следует
пересобрать. `dok_runtime_read_u/s(+60)` теперь читает изменяемое поле.
Vtable, far/huge pointers, image scratch и указатели scheduler заменены
индексами объектов, callback ID и ROM views. Native pointer bytes не переносятся.

## Use, замки и движение двери

Use героя проверяет TMap в точке на одну Cell Side перед героем, с исходными
Q15 sin/−cos и SAR15. Это проба одной точки, без raycast до ближайшей стены.
Start edge сохраняется до fixed update. Source — герой; его keys не расходуются.

Door обрабатывает `0x800`, только когда ready не ноль. Тогда выставляется
extent, бит Use очищается **до проверки ключа**. Если маска не ноль, достаточно
**любого** совпавшего бита `(key_mask & keys) != 0`; проверка всех битов неверна.
Source класса 13 использует keys=FFFF и обходит замок. Недостающий ключ отдаёт
`DOK_INTERACTION_LOCKED`; локализованные сообщения и звук интегрируются в G16/G17.

Из состояния 2 планируется OPEN через 416 native ticks. В mode1 одновременно
планируется AUTO через delay. OPEN при phase<extent−1 ставит flags|8,
ready=0, меняет период первого события на signed interval и увеличивает phase.
Проход разрешён строго при `phase > trunc(extent/4)`. Следующий callback после
последней фазы ставит состояние 1, ready=1 и отменяет OPEN.

При mode0 Use в состоянии 1 планирует CLOSE через 416 ticks. При mode1 повторный
Use открытую дверь не закрывает. CLOSE ничего не делает при occupancy>0.
Когда занятость снята, он уменьшает phase; только callback после phase=0
возвращает исходные flags, состояние 2 и ready=1. До этого дверь остаётся проходимой.
Native инвертирует marker `+1B` в конце обоих переходов; будущий automap может
вывести этот бит из состояния 1/2, отдельная mutable копия marker здесь не нужна.

AUTO также ждёт occupancy<1, состояние 1 и ready. Затем ставит CLOSE **ещё через
delay**, отменяя себя. Важно: занятая дверь повторяет AUTO с тем же периодом delay;
нулевой период не подставляется. При delay40000 это две задержки по 4 секунды
до первого шага закрытия, если AUTO сразу застал свободную открытую дверь.

Ready остаётся 1 до первого callback, поэтому несколько ранних Use могут
поставить дубликаты. Сохранён scheduler G06 с тремя слотами, его порядком и
особенностями удаления/компактации. Переполнение фиксируется счётчиком errors;
не создаётся четвёртый слот. Готовность, коллизии и анимация относятся к **общему
объекту glyph**. Дверные панели в двух и более клетках открываются одновременно.

## Время: явное отличие порта

В оригинале DS:C2 содержит сглаженный измеренный FPS, исходно 4; основной цикл
обновляет его как `(10000/frame_ticks + old)/2`, минимум 4
(RUS `1008:0FDF…0FF3`, ENG `1008:14BC…14D0`). Door читает младшее знаковое
слово C2 и применяет минимум 8. При interval0 каждая фаза зависит от фактического
опроса scheduler; это не постоянная native скорость в ticks.

Порт задаёт контрольный профиль **30 фаз**, а scheduler опрашивает по виртуальной
сетке 333,333,334 native ticks. Она не зависит от вывода кадров. Просроченные
визуальные шаги выполняются с собственными now; за poll максимум 128, остаток
не теряется. Проверки героя/зон идут перед движением через каждые 416 ticks.
Это намеренная стабилизация времени, не утверждение о точной DOS cadence.
Сравнение x86/C фиксирует исходный C2=30; правило при другом FPS не доказано
таким сравнением. Переходы кадров медленного DOS не воспроизводились.

## Crop и отображение

Дополнение 26 октября: [после тестирования LEVEL1](level1-fixes.md) введена
отдельная коррекция GBA — при extent>1/phase>=extent−1 панель полностью
исчезает. Описанная ниже остаточная полоска относится к восстановленному
исходному поведению; промежуточный crop и door state machine сохранены.

Native door владеет копией image header, разделяя неизменяемые pixels. В LEVEL
двери используют `0x48` (сдвиг вправо с нулями) либо `0x108` (вниз с нулями).
Сначала выполняется `dimension / extent`, затем умножение на phase. При 96/30
сдвиг X равен 3*phase, не `96*phase/30`; полная открытая дверь может оставлять
узкую полоску текстуры. Геометрия и UV не раздвигаются.

Renderer выполняет тот же сдвиг при семплировании, пропуская нулевую область.
Горизонтальный сдвиг переиспользует точные ROM strips; вертикальный использует
точный Q16 fallback с отсечением начальных строк. Это не общий animated-image
engine G11. LIGHT остаётся row0, остальные режимы crop сюда не добавлены.

## Классы 6, 12 и 13 во всех уровнях

Class6 в плане назывался переключателем, но обе vtable указывают на базовый
event handler: он не потребляет Use, не меняет состояния и не маршрутизирует
glyph. В исходных LEVEL у класса 6 вообще нет дополнительных полей.
Приписывать ему рабочий toggle по названию нельзя. Проверены все 30 деклараций
шести языковых views; видимость billboards остаётся G11.

Class13 находится в FCMap. Герой сравнивает **указатель объекта**, а не номер
клетки, с предыдущим FC-объектом `+DA`; смена клетки на тот же glyph не даёт
нового события. Выход на другой объект и возвращение дают новое событие.
Sensor берёт glyph из байта `+66`, DWORD event из `+67` и вызывает обработчик
целевого объекта. В LEVEL2 glyph `f` отправляет `0x800` двери `h` (ключ8,
mode0, delay0), четыре клетки на язык; в LEVEL3 — двери `k` с теми же параметрами,
шесть клеток. LEVEL1 не содержит class13. RU/EN совпадают в этой маршрутизации.

Class12 опрашивается перед движением каждый hero update, ставит slow bit
`0x4000000` и передаёт stat category `+66`, signed value `+68 / C2` с trunc0.
Реально размещены:

| Уровень | FCMap glyph | Category/value | Поведение G09 |
|---|---|---|---|
| LEVEL1 | B2 | 1000 / 1, две клетки | Условие завершения для G18 |
| LEVEL2 | `<`, `>`, `{`, `}` | 100/102, ±1400 | Сдвиг X/Z через resolver и occupancy |
| LEVEL2 | B2 | 1000 / 1, две клетки | Условие завершения для G18 |
| LEVEL3 | B2 | 1000 / 1, четыре клетки | Условие завершения для G18 |

При контрольном FPS30 conveyor даёт ±46 units за hero callback. Исходный
`+10A4` и порт балансируют MMap/door occupancy; защитные ограничения G08
сохранены. B2 — hexadecimal glyph, а не текстовое имя. Всего 1003 размещённых
class12-клетки на язык: 8 выходов и 995 conveyor-клеток LEVEL2.

Для category1000 оригинал сравнивает score+ D8 с world total+710 и при равенстве
записывает health=−1. Порт отдаёт `DOK_INTERACTION_FINISH` при том же условии;
G18 должен потребить событие и выполнить переход. Здесь уровень не переключается.
Class12 virtual slot+28 возвращает AX=0: клетка не удаляется, повторные callbacks
сохраняются. Неразмещённые варианты ±150 и прочие stat categories сохраняются
в данных; общий `DOK_INTERACTION_STAT` передаёт их будущему G12. Полная система
характеристик, предметы и получение ключей из предметов — G12, не G09.

## Проверки и пределы

- Windows: 13 общих suites; Linux static/Thumb compile. Linux execution и
  CMake/MSVC не выполнялись. Подготовка/проверка ROM-пакета прошла для шести views.
- Оригинальные инструкции Unicorn: по 6000 векторов Door/base handler,
  622 sensor routes и 120 crop-векторов на язык. Проверены состояния, flags,
  потребление event и callback/периоды. Clock/scheduler, sound/UI перехвачены
  в обработчиках; crop исполняется без перехвата callees. Контролируемые far
  pointers заменяют DPMI. Это не полный запуск DOS-сессии.
- Host-сценарии: 108 дверных деклараций, 30 class6, все 20 sensor-клеток,
  все 2006 class12-клеток двух языков. Карты для порта общие RUS; отдельный
  инвентарь обеих исходных карт проверен при анализе данных выше.
- mGBA: общий ARM suite, ключ/горизонтальная/вертикальная дверь RU/EN,
  промежуточный crop, проход/занятость/закрытие, реальный Start, повторный
  вход sensor LEVEL2/3, finish-event, guards и poisoned reset. 12 кадров
  динамических дверей сверены с host по сцене с учётом принятых 120 колонок.
- Регрессии: 1455 камер трёх уровней, HUD/палитра, 443520 strips/linked payloads,
  время/scheduler G06. ROM/ELF/map/PNG — `build/g09/`, отчёты — `analysis/g09-*.json`.

Не проверены физическая GBA, оригинальный BIOS и новая полная DOS-сессия.
Смысл неиспользуемых полей +58/+5A и произвольных event bits вне показанных
путей остаётся неизвестным. Поведение неразмещённых class12 с прочими категориями
не объявляется полной механикой. Звуки, тексты уведомлений и automap — дальнейшая
интеграция; логические события для них уже доступны через sink.

ROM 32 838 040 байт; EWRAM 143 672 (+14 444 к G08), IWRAM code 17 292/data1232.
Startup449 760 cycles, worst статическая камера624 719; ранний бюджет400 000
по-прежнему отложен. Частота30FPS полной игры не подтверждена. Остаток ROM
716 392 байта не считается резервом всей игры. Точные live/test-batch и стек
приведены в `analysis/g09-review.json`.
