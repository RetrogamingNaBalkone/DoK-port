# SP-RC1-REVIEW — дверь LEVEL3, GAMEP1 и границы попаданий

Статус: выполнено, 7 ноября 2026 года. База `83c70a99b9f63e0baacb095cfa0378d677172788`, дерево перед задачей чистое.

## Цель и граница

Ответить на три замечания Windows RC1: дверь комнаты первого ключа LEVEL3,
плавающая ошибка Old Gold `Missing resource: GAMEP1`, попадания у границ ячеек.
Исправить ошибку ресурсов и подготовить проверенный локальный Windows-пакет.
Без публикации нового релиза, без изменений GBA/NDS и оригиналов.
Изменение модели боя не входит в исправление ресурсов: сначала установить факт.

## Материалы и контракты

AGENTS.md, Source Port plan/handoff, SP19, SP-MENU-FLOW;
frontend.cpp, interactions.cpp, projectiles.cpp, movement.cpp, оригинальные RES
PKR/PKE LEVEL3, существующие Ghidra-доказательства SP10/SP11.
Адреса оригиналов брать из соответствующих спецификаций; карту описывать
в нулевых координатах (столбец, строка), отдельно от мировых координат.
Ресурсы выбранной игры должны соответствовать экрану; при изменении каталога
нельзя оставлять экран, требующий ресурсов другой игры.

## Работы и приёмка

1. Прочитать определения двери/сенсоров LEVEL3 и проверить сценарий выхода.
2. Установить точный маршрут GAMEP1 в RC1 и проверить актуальную версию.
3. Добавить регрессию для найденного маршрута/смены ресурсов, исправить причину.
4. Проверить попадание по разные стороны границы без изменения боевой модели.
5. Release/CTest, целевые probes и готовый пакет; обновить паспорт, план, handoff.

## Результат

По уточнению пользователя основной объект проверки — актуальная база будущего
RC2. На ней в настоящих SDL-процессах воспроизведены шесть отказов при конфликте
RES: PKR/PKE → OG на README (`GAMEP1`), OG → PKR на вступлении (`BSPR4`),
исчезновение единственного набора (access violation). Старый RC1 и его «Об игре»
использованы только как дополнительный контроль. Точное описание:
[разбор базы RC2](../spec/rc2-menu-door-hit-review.md).

Исправлен Frontend::datasets: потеря выбранной редакции завершает её экран
и возвращает в главное меню. Покрыты также загрузка, исход, предыстория,
заставка и уведомление с возвратом на такой экран. Старые Archive уже уничтожены
вызывающей стороной, поэтому проверяется сохранённый DatasetId, не старый указатель.
Неподходящие палитры не подставляются. Формат сохранений и боевая модель сохранены.

Подтверждено на PKR/PKE LEVEL3: k без AUTO и delay, внешний сенсор f на шести
клетках; повторный вход закрывает дверь. Возможность остаться в кармане
после закрытия и отсутствие альтернативного пути проверены кодом коллизий.
Медный ключ X и его автоматическая дверь u проверены отдельно: u открывается
без ключа изнутри. В 12 целевых сценариях трёх игр подтверждён клеточный
промах снаряда в соседней ячейке. Эти два игровых поведения не исправлялись.
Опора на оригинал — сами RES и существующие Ghidra-аудиты SP10/SP11,
нового анализа EXE/DOS-измерений не было.
