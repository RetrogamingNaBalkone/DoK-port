# SP20 — Linux/ARM/PortMaster и производительность

## Уточнение цели пользователем — 4 ноября 2026

Худший целевой режим: **RK3326, экран 1024×768, 60 FPS в GL**. Software
оптимизируется как запасной и не обязан достигать этой частоты (прямое
уточнение пользователя). Для текущего
участка допускается расчётная приёмка с явно заданной моделью переноса,
запасом и тяжёлыми сценами; после попадания в этот бюджет дальнейшие
оптимизации откладываются до реального устройства. Это не аппаратная приёмка
полного SP20. Для software измеряем native 1024×768, для GL drawable1024×768;
не подменяем разрешение рендера меньшим внутренним изображением.
`render_benchmark.py record --matrix target` выбирает этот режим для обоих
backend, включая GL nearest/linear. Старые quick/full матрицы сохранены.

Статус: аудит, воспроизводимый стенд и оптимизации обоих рендереров выполнены.
4 ноября 2026 достигнут условный бюджет GL1024×768 по худшему p50; p95 порог
не пройден. Аппаратная приёмка PortMaster не выполнена; полная задача открыта.

## Оптимизации и приёмка — 4 ноября 2026

Реализация, ограничения модели и команды: [отчёт](../spec/render-optimization-20261104.md).
Кеши фаз/ресурсов/HUD, специализация software spans, пакетная GL-подача без
перестановки полигонов, LIGHT+palette LUT, устранение повторных проверок байтов
в immutable-проходе; вне рендера убраны повторная сериализация INI, обновление
неизменного FPS и обращения к аудиоустройству без изменения состояния.

Финальная проверка: 4170 full + 189 matrix + два target-прогона по288 кадров
совпали точно с соответствующими эталонами. Release CTest15/15, Python14/14,
GL mutation/batching, water/door, HUD animation и frontend проверки прошли.
Поставка `artifacts/sdl2/windows-playtest-20261104-render-opt/` запущена в GL
и software1024×768 по5 кадров с отдельными пользовательскими каталогами.

При `T_RK = 30*T_PC + 4,67 мс` худшие p50 GL nearest/linear дают74,8/60,6 FPS;
худшие p95 —48,5/44,5 FPS. Это расчётный ориентир, не подтверждение стабильных60.
Следующий шаг **SP20**: реальный RK3326, GLES/драйвер, полный игровой кадр,
распределение времени кадров и платформенная приёмка. Новые фильтры SP08
требуют отдельных измерений. SP15/SP09 и другие платформы этим не закрыты.

## Цель и границы

Ранние проверки после SP09/SP15, завершение после SP18 согласно плану.
Подтвердить Linux/ARM/PortMaster, управление, звук, сохранения, упаковку
и 60 FPS на RK3326 при штатной частоте. Текущий участок — поиск оптимизаций
software/GL без потери картинки; поведение симуляции не изменяется.

## Материалы и контракты

Читать plan.md, handoff.md, SP07/SP08/SP15 и
[аудит](../spec/render-performance-audit.md). Исходники — ports/sdl2;
эталон оптимизации — прежний кадр того же backend с теми же входами.
Не подменять восстановление оригиналов GBA-кодом. Новые выводы об EXE
требуют Ghidra/ASM и SHA-256; этот аудит EXE не анализирует.
Изображения принадлежат ресурсам/сцене, временные ссылки живут до конца draw;
новый кеш обязан учитывать смену набора/уровня/контекста и версии пикселей.

## Работы и приёмка

Сначала воспроизводимый профиль и baseline кадров; затем по одному кеши,
буферы, GL-подача, shader LUT и raster. Матрица и ограничения подробно
перечислены в аудите. Аппаратная проверка на заявленном устройстве обязательна;
Windows-профиль не является доказательством FPS на ARM.
Затем launcher/поставка, полный платформенный игровой цикл и сохранения.

## Результат первоначального аудита

Ревизия 0a68f872c872d7846db41ef1bcb1f68727c504a1, SDL2-дерево исходно чистое;
предсуществующие изменения ports/nds не затронуты. Изменены только документы.
Найдены повторный texture hash на полигон, crop на кадр, копии динамических
изображений и software framebuffer, мелкие VBO/uniform calls, UI realloc/upload.
Сформулирован кандидат объединения LIGHT/palette без изменения цветов.
Факты подтверждены чтением C++; величина ускорения не измерялась.
Host/DOS/Windows/Linux/устройство: новые исполняемые проверки не проводились.
Команда проверки документов: `git diff --check -- docs/source-port`.
Следующий участок SP20: baseline/profiling harness и первый кеш фаз/ресурсов
с покадровой регрессией; текущий игровой плейтест SP15/SP09 сохраняется.

## Стенд сравнения и пользовательские тяжёлые сцены

Добавлены CMake-цель `dok_render_bench`, `tests/render_bench.cpp`, Python runner
`tools/render_benchmark.py` и тесты сравнивателя. Контракты, команды и ограничения:
[spec/render-benchmark.md](../spec/render-benchmark.md).
Рендереры, симуляция и original RES не изменены. Существующие параллельные
изменения NDS (код/документы/отчёты) не относятся к этой задаче и не затронуты.

Стенд измеряет prepare/scene/ui_convert/gpu_wait/total, фиксирует входы,
хеши ресурсов и исполняемого файла, GL/SDL/build-метаданные. Software:
точные индексы и RGBA; GL: RGBA readback до swap. PNG/diff и JSON вне таймеров.
Кеш сцены сохраняется между фазами, кадр проверяется до/после повторных redraw.
Время игровой симуляции, SDL software upload и present не входят в замер;
GL total включает glFinish и не является обычным игровым FPS.

По уточнению пользователя добавлены низкие потолки LEVEL1, патроны LEVEL2,
финальная толпа LEVEL2 и ружьё/Бабы-яги LEVEL3. Координаты проверены по картам
SDL2; GBA-материалы использованы только как подсказки мест. Важный режим —
синхронный залп семи/двенадцати исходных стрелков, затем обычные callbacks
SDL2 с фиксированным шагом416. Состояния0…13312 тиков фиксируются независимо
от FPS. Искусственные начальные условия (синхронизация, открытые двери,
HP32767) явно отражены в инструкции; это не естественная запись прохождения.

Контрольная база fixture_version4:
`research/evidence/source-port/render-benchmark/baseline-v4/`.
Постоянные изображения и полный manifest локальные, не входят в Git/поставку.
Следующий ID остаётся SP20: применять отдельные оптимизации по аудиту,
сначала снять замеры выбранных stress-сцен с120+ samples и повторными сериями,
затем сравнивать с baseline. SP15/SP09 пользовательский плейтест сохраняется.

### Приёмка стенда — 4 ноября 2026

- Release/CTest **15/15**; Python **13/13**: совпадение, изменение одного канала
  или индекса, разное сжатие одинаковых пикселей, повреждённый/потерянный capture,
  неполный manifest, несовместимые ресурсы/состояния/размеры/cases/GL-драйвер,
  защита существующего вывода.
- Full: **4170 пар, 0 изменений** — семь уровней, software320×200,
  GL640×480 nearest/linear. Baseline warmup2/samples5, повтор warmup3/samples2.
  Совпали idx/RGBA и логические состояния, проверки redraw/мутации World прошли.
- Matrix: **189 пар, 0 изменений** — quick-сцены семи уровней, пять software-
  разрешений и GL480×320/640×480 nearest/linear. Baseline warmup2/samples2,
  повтор warmup1/samples3. Итого4359 пар контрольных кадров.
- Просмотрены GL кадры залпа LEVEL2, патронов и ведьм LEVEL3. В поздних кадрах
  есть impact-состояния, у ведьм видны одновременно летящие снаряды.
  SHA-256 всех RES до/после record совпали.
- Windows GL: NVIDIA GeForce RTX5070. Linux/ARM/GLES/RK3326 не исполнялись.
  Малые выборки и неконтролируемая фоновая нагрузка не позволяют заявлять
  ускорение: это проверка стенда, не сравнительный профиль.

Доказательства в `research/evidence/source-port/render-benchmark/`:
`baseline-v4/manifest.json`, `matrix-v4/manifest.json`,
`repeat-comparison-v4/comparison.json`, `matrix-comparison-v4/comparison.json`.
Comparison-каталоги сохраняют оба manifests с хешами EXE/RES/кадров и samples.
Идентичные повторные capture-каталоги из build после сравнения удалены;
постоянные baseline и отчёты сохранены. Предварительные версии1–3 удалены
как воспроизводимые промежуточные результаты. PNG основной базы перепакованы
с проверкой исходных RGB-строк; idx/RGBA не менялись, отметка есть в manifest.

Команды сборки и unit-проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release
py -3.14 -B ports/sdl2/tests/test_render_benchmark.py
git diff --check -- ports/sdl2 docs/source-port
```

Record выполнялся по инструкции render-benchmark.md с тремя RES и параметрами
таблицы выше. Все точные native-команды записаны в manifests. Команды сравнения:

```powershell
py -3.14 -B ports/sdl2/tools/render_benchmark.py compare research/evidence/source-port/render-benchmark/baseline-v4 build/sdl2/benchmarks/repeat-v4 --output research/evidence/source-port/render-benchmark/repeat-comparison-v4
py -3.14 -B ports/sdl2/tools/render_benchmark.py compare research/evidence/source-port/render-benchmark/matrix-v4 build/sdl2/benchmarks/matrix-repeat-v4 --output research/evidence/source-port/render-benchmark/matrix-comparison-v4
```

Для повторного запуска создать новые каталоги, восстановив candidate через
record; baseline/comparison не перезаписываются. Основной код рендера не менялся,
поэтому старые DOS-прогоны на этом шаге не повторялись.
