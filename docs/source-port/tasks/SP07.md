# SP07 — программная сцена

## Актуальный результат — завершена, 4 ноября 2026

Приняты полнота визуальных bindings/getters, 20 общих анимаций и software
renderer в достижимых исходных режимах. [Полная матрица и адресные доказательства](../spec/renderer-reference-audit.md).
PKR/PKE: 24 синхронных VGA-кадра (старт 90° и 0°/45°/135° на каждом из 6 уровней)
совпали по всем 51200 пикселям; OG — 4 кадра по 54400/54400. Native replay нужен только
для документированных LIGHT/bank-wrap bugs; production их исправляет.
PKR VESA: 9 кадров совпали точно; PKE VESA: 6 точных совпадений и 3 кадра с 1/1/2 доказанными
неперерисованными пикселями старого framebuffer (контрольная заливка 251 сохранена).
Production намеренно очищает кадр. Геометрия всех контрольных поз совпала;
неинициализированные OG center depth slots не считаются значимыми.

640×400 недостижим в данных Kremlin EXE: mode probe принимает только 101h;
OG native только VGA. Дополнительные software размеры — расширение порта.
Восстановлены OG clip 320×170/panel 29, raster/LIGHT/floor sort,
packed ADD/ADC sampler и исходная асимметрия cell bounds трёх профилей.
Динамические размеры/flags/image pointer обновляются в software и GL;
class 6 использует base getter, дверь — crop getter. Вода class 12 сохраняет
явно принятую адаптацию 18 фаз/334 ticks вместо native redraw interval 0.

Release CTest 15/15; 35 software scenes/20 clips с GL readback,
resize/flags/reversal; cadence 7 уровней; 27 monster groups/36 FPS replays;
OG 600 frames/105 рублей/2 палочки/exit; door 1622/1388 PASS.
Команды: `ports/sdl2/tools/check_render_regressions.py`,
`check_trap_matrix.py`, `check_vesa_trap_matrix.py`, `check_framebuffer_history.py`.
Исходные EXE SHA-256 до/после read-only Ghidra неизменны; guest trap bytes
восстановлены, DOS subprocess завершены. Эталоны не перезаписаны.

Пакет для проверки: `artifacts/sdl2/windows-playtest-20261104-sp07`, без RES.
GL modern 160/Hor+, высокая software HUD-панель и отсутствие полной приёмки
GL classic/GLES/фильтров остаются отдельной границей SP08/SP15/SP20.
SP10–SP12 не закрываются renderer-проверками, полных прохождений нет.
Следующий долгосрочный ID — **SP08**, но пользователь велел остановиться
после SP07: **SP08 в этой сессии не запускать**.

## История шагов (статусы ниже относятся к указанным датам)

## Исходные разрешения — 3 ноября 2026, меню

SoftwareScene поддерживает 320×200, 640×400, 640×480, 800×600, 1024×768.
Другие размеры framebuffer отвергаются; окно масштабируется отдельно.
Мир растеризуется native. Камера K/высота области и масштаб оружия — по PKR
ASM. 35 сцен (семь уровней × пять режимов) прошли; VGA HUD12480/12480 для
обоих Кремлей. Высокая панель масштабируется из VGA; DOS VESA pixel match
и исходный VESA OG не заявляются. SP07 остаётся в работе.
Доказательства, команды и ограничения: [меню](../spec/menu-settings.md).

## Вода в плейтесте — 3 ноября 2026, r7

Сообщение пользователя: вода LEVEL2 неподвижна в software и GL. Причина в
общем SoftwareScene: class12 получает неизменный Sprite, crop-фаза отсутствует.
Это не Flic: четыре воды имеют Sprite flags 0x0808/0x0408/0x2008/0x1008.
Исправление применяется к class12 PKR/PKE; профиль OG отдельно не расширяется.

Основание — сохранённые Ghidra NE-листинги
`research/evidence/interactions/{ru,en}/evidence.asm`, а не GBA-реализация.
RU ctor 1068:06d6 задаёт +50=18, +52=0; getter 1068:07a1 обнуляет +50,
запускает callback; callback 1068:0741 при phase<18 передаёт phase, divisor18,
flags0 в image setter 10f8:0592, увеличивает phase и перепланирует событие.
EN callback 1020:0c33, getter 1020:0c93, setter1060:06a2.
Проверены LES, far CALL/RETF, signed CMP/JGE, MOVSX interval, push DWORD0x120000
(два WORD flags0/divisor18), INC word. Far image pointers заменены host Image.
Crop RU10f8:05c9 / EN1060:06d9: пары направлений по порядку right/left/down/up,
циклическая подстановка краёв, shift=(dimension/18)*phase; деление до умножения.
Подробности формата: [rendering-assets](../../originals/rendering-assets.md).

Адаптация времени порта: непрерывные18 фаз с шагом334 PIT/119 ticks (~30 Гц),
как фиксированный шаг дверей. Фаза от World::simulation_ticks, общая для всех
клеток glyph, не зависит от redraw/FPS и не меняется на паузе. DOS interval0
зависел от опроса кадра; его точный pacing и запуск/остановка вне видимости
здесь не эмулируются. Это выбранная стабилизация, не DOS timing parity.
Source Image каждой воды хранится отдельно от кеша ресурсов, каждый сдвиг
считается от исходных пикселей. Software и GL получают один результат;
GL content-cache содержит ограниченное число фаз, shader менять не требуется.

Release CTest14/14. `dok_flowing_surface_probe` проверяет четыре направления,
неделимые на18 размеры, порядок деления, границу шага, wrap и повторный draw.
На LEVEL2 PKR/PKE проверены реальные framebuffer software и GL до/после
100 мс симуляции, неизменный повтор GL при остановленном времени, совпадение
software-кадра после секунды при30/60/144 FPS. В LEVEL1/3 воды объявлены,
но не размещены. Проверка использует искусственные контрольные позиции у воды,
не является прохождением. GL readback выполнен в скрытом окне.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release
build/sdl2/windows/dok_flowing_surface_probe.exe originals/pkr/RUS/PKR.RES originals/pkr/ENG/PKE.RES
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/package.ps1 -PackageName windows-playtest-20261103-r7
```

Пакет: `artifacts/sdl2/windows-playtest-20261103-r7`, без RES. Запуск из пакета
с LEVEL2/skip-intro/frames3 прошёл для GL PKR и software PKE.
SHA-256 EXE до/после чтения сохранённых доказательств совпали:
PKR `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`,
PKE `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
SP07/SP08 остаются в работе; следующий шаг — плейтест воды и дальнейшая
приёмка общих getters/анимаций. Остальные Flic этой правкой не подключены.



Статус: камера, первые primitives и affine raster реализованы. Зависимости SP04–SP06 ещё частично открыты;
это не разрешение считать программный renderer или игровой мир завершёнными.
Перед работой читать план/handoff, `docs/originals/rendering-geometry.md`,
`rendering-reference.md`, `rendering-assets.md` и соответствующие ASM.

## Контракт

Восстановить исходную проекцию, сортировку/видимость, стены, пол/потолок,
спрайты, освещение, прозрачность и clipping. Все подтверждённые DOS-режимы,
без подмены generic raycaster. Кадры начала и контрольных точек всех семи
уровней сверить с DOS. OpenGL — отдельный SP08, не вывод software-текстуры.

## Начальная доказательная база

PKR/PKE NE Ghidra: камера `1100:00f5` / `1060:1025`, трансформация
`10b0:01bb` / `1040:01c1`. VGA W320/H161 задаёт clip320×160,
центр159,79, k8/D200/K4096. Исправленная пиксельная форма сцены320×192.
Оригинальные runtime trig-таблицы в снимках `reference/ru-03`, `en-02`
совпали со всеми722 значениями trunc(sin/cos(n*3.14159265359/180)*32768).
Четыре дверных bounds приведены в `rendering-reference.md`.
OG и VESA не получают эти параметры без отдельной проверки.

## Приёмка и текущие ограничения

Сначала camera/viewport/projection и проверка дверных bounds; затем primitives,
текстуры/LIGHT, сортировка, occlusion, пол/потолок, сцена и DOS-сравнение.
Проекция нескольких точек не доказывает правильность полного renderer.
Результаты, команды и следующие ограничения дописывать после реализации.

## Результат первого шага

`SoftwareCamera` реализует явные low32 IMUL/ADD/SUB, SAR15, signed IDIV,
depth+D, включительный clip и раздельные SAR для центра. Параметры задаются
явно; единственный готовый профиль — Kremlin VGA, не OG/VESA.
Таблицы зафиксированы целыми значениями в `src/trig.inc`; генератор
`py -3.14 -X utf8 ports/sdl2/tools/generate_trig.py` извлекает их из двух
исходных RAM-снимков и сверяет1444 значения с восстановленной формулой.
SHA-256 RAM: ru-03 `c8ff1347518aae86af31b8ed2c6f6443c4c63c9157b4a52bf76d53c7f5c95629`,
en-02 `b667dda83c8504ec4a8c4716aef01d26696ba0daa6433055b3ca1ab9ff827baa`.
Runtime не вызывает host sin/cos, поэтому таблицы одинаковы на разных CPU.

`tools/build.ps1`: CTest6/6. Camera test совпал с четырьмя измеренными DOS door
bounds, viewport320×160/cx159/cy79 и factor1840; проверены оси, low32 wrap,
IDIV fault и viewport scale7. Это ещё не рисование: нет primitives, clipping
поверхностей, rasterizer или игрового кадра. Следующий шаг — вертикальные
плоскости/спрайты с исходными текстурами, затем горизонтальные поверхности.

## Результат второго шага

Добавлены `raster.hpp/cpp` и `geometry.hpp/cpp`: вертикальные плоскости с
depth0 clip и UV, billboard, отражение center-конструктора, native gap sort,
coarse column occlusion. `rasterize` переносит H/V edge walking и spans с
low32 Q16-интерполяцией, включительными границами, LIGHT16 и прозрачностью
после LIGHT только в вертикальном пути. Горизонтальный span всегда opaque.
Флаг0x20 выбирает направление двух цепочек рёбер, не заменён зеркалом sampler.

Источники PKR NE Ghidra: `1120:1074` / `1120:0b12` — vertical/horizontal raster;
`1010:00d2…01bf` — span (разница endpoint+2, DEC перед первой итерацией,
итого включительно); `10b0:0000/06aa/0ccb` — primitives;
`1100:0000/0301` — сортировка/видимость. C сверялся с сохранённым ASM,
но независимое исполнение всего raster в x86 пока не выполнено.
Оригинальные far/huge-адреса текстур/кадра заменены границами host-буферов.
Выход sampler за payload, vertex вне signed16 и немонотонный polygon дают
явную ошибку вместо чтения чужой DOS-памяти. Crop-преобразования пока должен
передавать вызывающий как готовые пиксели; их реализация ещё нужна.

Новая команда `py -3.14 -X utf8 ports/sdl2/tools/check_render.py` запускает
`dok_render_probe` для двух дверей LEVEL1 RU/EN, берёт реальные Sprite/LIGHT,
пишет idx/PNG и `build/sdl2/checks/render-report.json`.
Это отдельная проба primitives, не игровой renderer приложения и не поставка.
Второе полотно отражено по native record: RUS RAM0x2c6722 содержит
X145→118; первое RAM0x281522 — X145→172, обе глубины3360, U0…95.
Не переносить hardcoded отражение row17 из пробы в общий builder: там оно
должно вычисляться по соседям согласно исходному constructor argument.

В заранее ограниченной видимой области (Y64…95; ENG также X≤137) совпали
все1622 RU и1388 ENG непрозрачных индексов с исходным DOS-кадром.
Полные quad содержат1867 ненулевых пикселей; совпадают1626 RU/1395 ENG.
Верх quad и правый край ENG в DOS перекрыты стенами; probe рисует только двери.
PNG просмотрены: размеры/текстуры дверей соответствуют контрольной сцене.
Эта проверка не подтверждает общий порядок мира, наклонные поверхности,
пол/потолок, анимацию или все режимы видео.

CTest7/7: дополнительно synthetic H/V Q16 grid, clip, reversed edge chain,
LIGHT/mapped transparency, near clip, reflection, occlusion.
Далее: горизонтальные primitives, исходный AABB обхода, builder всех классов,
crop/animation state, подключение сцены к SDL. На этом шаге приложение ещё
показывало титульный ресурс; SP07 не закрыта.

## Результат третьего шага: начальная сцена

`SoftwareScene` теперь строит начальный вид шести LEVEL Кремля. Он владеет
кешем оригинальных изображений и палитрой/LIGHT; union Sprite flags сохраняется
для общих ресурсов, анимации пока берут первый кадр с runtime flags8.
Обход клеток воспроизводит исходный четырёхточечный AABB с low32 произведениями
и IDIV; для начального RU LEVEL1 получены X24…33/Z41…53.
Добавлены горизонтальные пары floor/ceiling в одной сортируемой записи,
отрицательная глубина через SAR20, отступы FCMap, потолочные грани,
стены по соседям, center4/7 с отражением по стене-соседу, TMap/MMap billboards.

Дополнительные исходные доказательства (PKR NE Ghidra):

- `1098:30c1` начало — AABB; `35da…362e` — векторы и FCMap-параметры.
  Важно: BP−52 — column X, BP−56 — row Z; называть их по автоматически
  декомпилированным local-именам ненадёжно. Step-вектор BP+fe84 остаётся XYZ,
  это не перестановка осей. Wall-вектор пересобирается в `3bc5…3bf8`.
- `3757…377e` — ceiling-side V-end; `3d43…3d7e` — wall V-start и height.
- `4463…447d` — горизонтальная пара получает постоянные flags0x18.
- `49cc…49e7` / `4e42…4e5d` — reflection=1 и orientations0/90;
  соответствующие ветви при отсутствии стены дают reflection0.
- Edge draw `10b0:0bf5…0cc2` не меняет image bit0x20; center draw `05b2`
  меняет. Это различие сохранено, автоматическое разворачивание всех граней
  было бы неверным. Billboard также не меняет этот бит.

`check_scene.py` прошёл48 рендеров:6 уровней × (исходный вид +7 heading).
Начальный LEVEL1 совпал с DOS по49999/51200 RU и50146/51200 EN индексам.
Это метрика, не попиксельная приёмка: RU остаточные различия находятся
в верхней части сцены; нельзя автоматически списать их на фазу анимации.
Снимки всех шести начальных сцен/JSON — `build/sdl2/checks/scene-*`.
Просмотрены RU LEVEL1–3; настоящий SDL-window с LEVEL1 открылся и завершился
через3 кадра. Native320×160 выводится как320×192, нижняя область пока пустая.

```powershell
py -3.14 -X utf8 ports/sdl2/tools/check_scene.py
build/sdl2/windows/dok_port.exe --res originals/pkr/RUS/PKR.RES --level LEVEL1 --frames 3 --screenshot build/sdl2/checks/sdl-scene.bmp
```

`--level` пока включает статичный initial scene preview. Это ещё не игровая
сессия: нет движения/боевых callbacks, HUD, динамических getters/crop,
обхода активных отдельных слотов0x1000, полной SP06-модели и анимации во времени.
OG явно отклоняется этим preview, пока не проверен его camera profile;
RES/LEVEL OG по-прежнему загружается другими целями. VESA и GL ещё впереди.
Следующий шаг — убрать оставшиеся ограничения сцены и подключить настоящие
ввод/движение по SP09/SP10, не выдавать свободную камеру за игровую механику.
