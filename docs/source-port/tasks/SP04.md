# SP04 — LEVEL и определения мира

Статус: завершена 4 ноября 2026 года в границе определений/валидации LEVEL.
Зависимости SP03 и восстановленные грамматики SP01.
Читать план, handoff, `docs/originals/levels.md`, OG seeds и
`decompiled/old-gold/functions/1ae1_21ea.c` с соответствующим ASM.

## Цель и материалы

Независимые C++ определения семи уровней без платформенной раскладки GBA/NDS.
PKR/PKE: NE Ghidra 1048:004c / 1018:0152, фабрики 1068:0000 / 1020:018c;
таблица readers в levels.md. OG: MZ Ghidra 1a0c:005c,1ae1:0003;
снаряд 1ae1:21ea читает L3c,W58,W5a (короткий диалект).

## Контракты и работы

LevelDefinition владеет параметрами, исходными картами, определениями объектов
и ссылками на ресурсы по имени. Поля с ещё не восстановленной семантикой
хранят native-offset и тип; им не присваиваются придуманные названия.
Сохраняющиеся Sprite/Flic/Sound, байты CP866 и пробелы карт учитываются.
Парсинг отделён от runtime-преобразований знаков и размещения мира.
Явные проверки диапазонов, размеров карт и ссылок; повреждения не дают
частично пригодного мира. Нельзя подставлять пропущенные OG-поля из Kremlin.

## Приёмка

Все семь уровней, 119 OG и по 390 PKR/PKE определений; сравнение всех чисел,
байтов карт и ссылок с оригинальными ресурсами независимым сканером. Проверить
ошибки усечения/переполнения и сохранность пробелов. OG-число объектов проверить
по инвентарю; агрегатное количество само по себе не подтверждает корректность.

## Результат

LevelDefinition/ObjectDefinition/Field реализованы независимо в C++17.
Сверены все 899 определений, typed fields и 21 карта с отдельным byte-regex
сканером; PKR/PKE дополнительно совпали с принятыми stage5-экспортами.
Команда: `py -3.14 -X utf8 ports/sdl2/tools/check_assets.py`.

OG LEVEL4 строка 254 содержит неиспользуемый текст после class12 W66/W68.
Reader MZ Ghidra `1ae1:0699`, ASM `1ae1:06af–06ec` читает только два слова;
остаток сохраняется в ignored_tail и не получает выдуманного игрового эффекта.
Снаряд OG использует L3C/W58/W5A по `1ae1:21ea`, без полей Kremlin.
Это разбор данных, не доказательство runtime-эквивалентности.
Неправильные ресурсные ссылки и ширина карт отвергаются для всех семи уровней;
проверяются glyph всех трёх карт и форматы Image/Animation/Sound ссылок.
Остаток этой итерации закрыт ниже; runtime-конструкторы и callbacks относятся
к SP06–SP12, не к загрузке определений.

## Завершение SP04 — 4 ноября 2026

Прочитаны актуальные план/handoff, паспорт, оригинальные LEVEL-доказательства
и правила хранения. Вход: HEAD `b1830c754991cfc3c653b120728a5d1681f41947`,
незакоммиченные SP18/SP03 и журнал очереди; они сохранены.

Свежий read-only Ghidra-экспорт проверил factory/vtable+4 всех 13 допустимых
классов OG, все readers, типы extractor и значимые ASM-эффекты. Схемы совпали
с C++; таблица адрес → поля, ABI, far pointers и runtime-границы:
[level-reader-audit](../spec/level-reader-audit.md). Хеши OG EXE/RES до/после
совпали. Class8 остаётся коротким; class12 ignored_tail сохранён.

В `src/level.cpp` восстановлен ведущий `+` без двойных знаков; неизвестная
пустая секция, хвост Sprite и переполнение строк карты теперь отвергаются.
Защитная валидация документирована отдельно от исходной грамматики.
Новая `tests/level_boundary_tests.cpp`/цель CMake проверяет все семь LEVEL.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ghidra/export-source-port-level-audit.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release
build/sdl2/windows/dok_level_boundary_tests.exe originals/Old_Gold_3D/OLD_GOLD.RES originals/pkr/RUS/PKR.RES originals/pkr/ENG/PKE.RES
py -3.14 -X utf8 -B ports/sdl2/tools/check_assets.py
py -3.14 -B tools/reports/summarize_reports.py
```

PASS: Release CTest 15/15; 1871 пограничный случай; 899 определений/21 карта,
все декодеры, семь сочетаний RES/26 мутаций. Все три RES неизменны.
Локальные доказательства: `research/evidence/source-port/sp04-level-audit-20261104/`
(`readers.asm`, `vtable-readers.tsv`, Ghidra log/manifest, boundary log/report);
полный assets-report — `build/sdl2/checks/assets-report.json`.
Новых DOS-прохождений или исполнения всех readers под x86 не заявляется:
принимаются данные и безопасная валидация, не весь runtime.

Следующий **SP05**: A03, независимый x86 scheduler и остальная арифметика,
затем FPS-интеграция. API LevelDefinition не изменился; данные до runtime
преобразований, включая L3C/W5A OG, сохраняют прежний контракт.
