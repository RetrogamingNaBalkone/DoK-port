## Уточнённый контракт

FOV всегда автоматический от полного DOS-кадра 320×200, отображаемого как 4:3.
Классический 4:3 сохраняет сцену 320×160 PKR/PKE или 320×170 Old Gold.
Современный HUD освобождает полный кадр (Vert+). Широкий кадр добавляет Hor+.
Уточнение пользователя от 5 ноября (r2): классическая панель резервирует нижнюю
полосу при любом аспекте. Высота viewport и вертикальный обзор сохраняются
как в 4:3 (160/170 строк), мир достраивается только слева и справа.
Панель центрируется, масштаб и пропорции соответствуют центральному кадру 4:3;
По уточнению r3 от 5 ноября по бокам PKR/PKE продолжается голубоватая
металлическая текстура исходной панели вместо однотонной заливки r2.
Надпись центрируется в фактическом сером поле, сохраняя исходный X=4.
Это заменяет прежнее наложение classic на полный широкий viewport.
Fullscreen остаётся borderless: внутреннее разрешение всей композиции определяет
аспект, кадр вписывается в drawable с полями. Размер окна хранится отдельно.
Ручные FOV/аспект удаляются; старые ключи игнорируются. Подтверждение — 15 секунд.
Программный renderer всегда вписывает игровой кадр 4:3 с полями, независимо
от размера окна и предыдущего OpenGL-аспекта. Современный HUD остаётся доступен.
Сообщение классической панели сохраняет исходный X=4 и центрируется только
по вертикали с учётом тени (уточнение пользователя от 5 ноября).
Этот контракт заменяет прежние требования ручного FOV и принудительного аспекта.

## Цель и граница

### Исправление r4 — Windows DPI, 5 ноября 2026 года

По скриншоту пользователя при изменении масштаба Windows искажается bitmap-текст
меню. Проверка действительного процесса через `GetProcessDpiAwareness` выявила
отсутствие DPI awareness у прежнего EXE: 8/8 запусков OpenGL/software показали
только значение 0 (unaware). `SDL_WINDOW_ALLOW_HIGHDPI` сам по себе не объявлял
осведомлённость процесса; Windows могла масштабировать готовое окно.

До `SDL_Init(SDL_INIT_VIDEO)` задаются `SDL_HINT_WINDOWS_DPI_AWARENESS=permonitorv2`
и `SDL_HINT_WINDOWS_DPI_SCALING=0`. SDL выбирает доступный fallback на старых ОС;
выбранные разрешения остаются пикселями. Меню, игровой FOV/HUD, фильтры и
преобразование указателя не меняются. Это исправление Windows-обвязки порта,
нового анализа EXE оригиналов нет; GBA/NDS не затронуты.

Основание API: [SDL DPI awareness](https://wiki.libsdl.org/SDL2/SDL_HINT_WINDOWS_DPI_AWARENESS)
и [SDL DPI scaling](https://wiki.libsdl.org/SDL2/SDL_HINT_WINDOWS_DPI_SCALING).
Регрессия `ports/sdl2/tools/check_dpi.py` запускает настоящий EXE, опрашивает
его awareness через WinAPI и сохраняет меню при 1280×720, 1707×960, 1920×1080,
2560×1440 для обоих backend. Глобальный масштаб Windows скрипт не меняет.
Контроль до исправления — `research/evidence/source-port/sp21-dpi-before/report.json`:
8/8 ожидаемо FAIL, доказано отсутствие DPI awareness.

Исходная ревизия — `5eb0d22`, рабочее дерево до задачи чистое. Проверки r4:
Release CTest 18/18 PASS; `check_dpi.py` 8/8 PASS (во всех процессах зафиксирован
уровень 2, per-monitor aware, вместо прежнего 0), размеры всех PNG точно
соответствуют выбранным пикселям. Та же проверка доставленного EXE — 8/8 PASS.
`check_menu_ux.py` — 17 процессов PASS, `check_package.py` — 8 процессов PASS.
Просмотрен реальный GL readback меню 2560×1440. Настройки экрана Windows не
изменялись; физическая смена масштаба и перенос между мониторами остаются
отдельной открытой приёмкой. Windows 8 fallback в этой среде не проверен.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release -DirectCommands
py -3.14 -B -X utf8 ports/sdl2/tools/check_dpi.py
py -3.14 -B -X utf8 ports/sdl2/tools/check_menu_ux.py research/evidence/source-port/sp21-dpi-menu-ux
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/package.ps1
py -3.14 -B -X utf8 ports/sdl2/tools/check_dpi.py --exe artifacts/sdl2/windows-playtest/dok_port.exe --out research/evidence/source-port/sp21-dpi-package
py -3.14 -B -X utf8 ports/sdl2/tools/check_package.py artifacts/sdl2/windows-playtest --hidden
```

Оба Python-стенда задают `SDL_AUDIODRIVER=dummy`; окна скрыты, пользовательские
настройки изолированы. Полные отчёты и кадры — `research/evidence/source-port/sp21-dpi/`,
`sp21-dpi-before/`, `sp21-dpi-package/`, `sp21-dpi-menu-ux/`.
Компактная сводка — `analysis/source-port/sp21-dpi-summary.json`.
Готовая папка с тремя RES — `artifacts/sdl2/windows-playtest/`.
SHA-256 `dok_port.exe`:
`9558AE8E1C775DF912E470CC0CDD5B4E1CBDAC36B62FEF8A571D6C75B1053C85`.

Два прямых уточнения пользователя: продолжить голубоватую текстуру по бокам
classic и исправить вертикальное центрирование сообщения в серой полосе.
В PKR/PKE фон расширений повторяет участок исходного ресурса ПАНЕЛЬ:
X=193–200, Y=16–35, координаты пикселей ресурса от нуля; верхний скос

## Контракты

Разделить выбранное разрешение сцены, логический размер окна и фактические
пиксели вывода. Auto использует согласованные правила drawable size.
Смена режима не сбрасывает мир; отказ или неподтверждённое изменение
возвращают рабочий режим. HUD, оружие, меню и заставки сохраняют пропорции.
Выбор переживает перезапуск; SP23 затем переносит его в новую схему хранения.
