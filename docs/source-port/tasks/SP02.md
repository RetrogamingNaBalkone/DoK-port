# SP02 — независимая сборка и платформенный каркас

Статус: завершён платформенный каркас 2 ноября 2026 года.
Зависимость: [SP01](SP01.md). Основание: [план](../plan.md), [handoff](../handoff.md).

## Цель

C++17/CMake-проект в `ports/sdl2/`, headless-библиотека и Windows SDL2-приложение.
Никаких зависимостей от реализаций GBA/NDS. Общие инструменты пользователя;
выходы в `build/sdl2/`, пользовательские сборки в `artifacts/sdl2/`.

## Контракты и работы

- Ядро владеет ресурсами через стандартные контейнеры; SDL-типы остаются в приложении.
- Ошибки чтения явно сообщаются, исходные RES неизменяемы.
- Независимые идентификаторы наборов, действий, окна и рендерера по плану.
- CMake создаёт библиотеку, headless-тест и приложение; Windows-драйвер находит
  общий Zig, CMake, Ninja и SDK SDL2, без копирования toolchain в репозиторий.
- Приложение создаёт окно, обрабатывает выход/resize/focus, пишет диагностический
  журнал и определяет пользовательский каталог через SDL_GetPrefPath.
- Добавить ограниченный по числу кадров smoke-запуск для проверки реального окна.

## Приёмка

Чистая CMake-конфигурация и сборка; headless CTest; реальный Windows-запуск
SDL2-приложения и завершение по штатному событию/лимиту кадров. Успешный запуск
пустого приложения не означает игровую готовность. Linux остаётся SP20.

## Результат

Независимые CMake, dok_core, dok_inspect, dok_core_tests и dok_port созданы.
Чистая конфигурация с ABI probe, сборка и CTest прошли. SDL2-окно реально
запущено с тремя RES, ограничение в 3 кадра и BMP-снимок сработали; изображение
просмотрено. Это оригинальный статический ресурс, не отрисованная игровая сцена.
Инструменты, команды и ограничения — [сборка](../building.md).
InputActions/ViewConfig не содержат SDL-типов; игровая обработка фокуса и осей
будет подключена в SP09. Следующий этап — завершить SP03/SP04, затем SP05/SP06.
