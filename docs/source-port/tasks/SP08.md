# SP08 — OpenGL 2 / GLES 2

## Изломы потолка на пользовательском кадре — 3 ноября 2026

Диагностика, без изменения рендера. На присланном кадре классическая панель
и 4:3 с полями; в текущем main этот путь использует software, GL вызывает
Hud::desktop. Сохранённый INI на момент проверки содержит renderer=1 (GL),
но он не доказывает режим в момент снимка: значение могло измениться позже.
Причина выбора software в момент снимка не установлена.

В оригинальном PKR горизонтальный растр1120:0B12 линейно интерполирует UV
по экранным рёбрам и строкам. ASM1120:0FB1–0FD1 вычисляет du/dv через длину
строки;102D–1051 наращивает UV рёбер без деления на глубину. Это допускает
изломы рисунка на стыках клеток при косом взгляде. Software повторяет этот
алгоритм; GL использует GpuCamera и clip W=depth+200 с перспективной
интерполяцией. Геометрический изгиб плоского потолка не добавлялся.

Проверены сохранённый DOS-кадр ru-03/level1-start.idx, software LEVEL1 heading45
и реальный GL LEVEL1 initial. Выходы: build/sdl2/checks/ceiling-original.png,
ceiling-software-45.png, ceiling-gl.png. Это разные позы, поэтому точное
совпадение пользовательского излома с DOS не заявляется. PKR.EXE SHA-256
до/после совпал с12f78afc…d28. SP08 остаётся в работе; следующий шаг при
повторении в подтверждённом GL — получить тот же ракурс и параметры запуска.

## Рывки камеры на течении — 3 ноября 2026, r8

Пользователь сообщил о дёрганом движении на воде LEVEL2. Найдена ошибка порта:
в main.cpp `before` снималась ПОСЛЕ player_surface. Течение уже переместило
героя, поэтому ViewMotion записывал только последующий update_player_motion.
При нулевом вводе delta интерполяции была0, хотя герой сдвигался на±46 единиц
(LEVEL2 ±1400/30) каждый player_tick416, примерно24,1 раза в секунду.
Это дефект общей интерполяции r3, пропущенный проверкой текстуры воды r7.
Вывод основан на исходниках порта; новая интерпретация оригинального EXE не нужна.

ViewMotion::step захватывает позу вокруг ВСЕГО шага: player_surface, slow-флаг,
update_player_motion. Main использует этот общий захват. Изменена только GL-
интерполяция, скорость/коллизии/состояние симуляции прежние. Software по-прежнему
показывает дискретную позу player_tick; плавность software этой правкой не заявлена.
Точность делителя30 для силы течения при player_tick~24,1 Гц остаётся прежним
ограничением адаптации SP11, не доказательством совпадения скорости с DOS.

Release CTest14/14. Дополнение movement_tests: реальный player_surface и
update_player_motion на открытой synthetic-карте, осиX/Z, силы±1400, нулевой ввод,
30/60/144 FPS —12 прогонов. Проверяется непрерывность камеры НА ГРАНИЦЕ каждого
player_tick, промежуточная позиция относительно линейной траектории и отсутствие

а flowing_surface_probe — текстуру, поэтому не покрывали ошибку порядка вызовов.

## Интерполяция движения камеры — 3 ноября 2026, третья итерация

Пользователь отметил рывки при перемещении. По коду World событие player_tick
имеет интервал 416 единиц PIT/119, около 24,1 Гц. GL раньше повторял целую
позицию между событиями даже при 144 FPS. Это диагностика порта, не анализ EXE.

ViewMotion сохраняет разницу поз до/после update_player_motion. GL постепенно
сводит её к нулю за 416 тиков; World::presentation_ticks добавляет дробный остаток
GameClock. GpuCamera принимает дробное смещение XYZ и угла. Короткий путь угла
через 360° учитывается; мышь остаётся непосредственной, задерживается только
поворот клавишами/стиком. Цена обычной интерполяции — один интервал движения,
около 41,5 мс; экстраполяции за подтверждённую позицию нет.
Пауза, смена уровня, повтор и исход сбрасывают интерполяцию. Главный цикл теперь
измеряет elapsed через SDL performance counter вместо миллисекундного счётчика.
Позы симуляции, коллизии, скорость, AI activation и software-камера не менялись.
Монстры/снаряды/анимации пока не интерполируются; это не интерполяция всего мира.

Проверки: Release CTest 13/13, camera tests — равномерное визуальное перемещение
при 30/60/144 FPS, дробный XYZ до проекции, wrap угла, ограничение интервала и reset.
GL probe прошёл; реальные GL окна PKR/OG и software PKE запущены. Старые проверки
HUD/DOS проходят. Интерактивный обход и субъективная оценка плавности остаются
пользовательским плейтестом; GLES не проверен. Команда сборки:
`powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release`.
Сборка: artifacts/sdl2/windows-playtest-20261103-r3. SP08 остаётся в работе;

## Плавная GPU-камера и LIGHT — 3 ноября 2026, вторая итерация

Эта запись заменяет решение об affine LIGHT из первой итерации ниже.
Причина дрожания в коде: GL получал целые x/y, Q15 transform и усечённый
projection factor программной камеры на виртуальной сетке 320×160; на большом
окне шаг вершины растягивался на несколько пикселей. Дробный mouse_remainder
не участвовал в визуальном угле. Это вывод по портовому коду, не анализ EXE.

`GpuCamera` отдельно преобразует координаты в double, проецирует во float,
использует heading − mouse_remainder, клиппирует поверхности по camera depth 0
с интерполяцией UV. RasterVertex содержит необязательные precise-координаты;
software продолжает использовать прежние целые поля. У GPU убрано исходное
отсечение целыми столбцами: перекрытие выполняет depth buffer, сортировка
от дальнего к ближнему нужна для краёв спрайтов при опциональной фильтрации.
Simulation pose/AI/таймеры не меняются. Поворот стрелками/стиком сохраняет
исходную дискретность симуляции; эта работа убирает округление геометрии и
добавляет дробный угол мыши, но не вводит интерполяцию всей симуляции.

LIGHT: сохранены исходные 16 строк, дистанция начала 1920 и шаг 120.
Между двумя строками смешиваются итоговые RGB из исходной палитры, а не индексы.
Глубина перспективно интерполируется по поверхности: общие рёбра получают
одинаковое освещение вместо отдельных affine-приближений на каждом полигоне.
Это намеренная модернизация GL по просьбе пользователя, не побитовый DOS.
Прозрачность спрайта определяется исходным index 0, чтобы затемнённый до
чёрного непрозрачный texel не превращался в дырку.

Nearest по умолчанию; `--filter nearest|linear`, F4 переключает во время игры.
Linear вычисляет четыре palette/LIGHT RGB-образца вручную: GL_LINEAR нельзя
применять к индексам палитры. Прозрачные края смешиваются с учётом alpha.
GL HUD/текст/оружие остаются nearest. В software опция меняет масштабирование
готового кадра SDL, не исходный raster. Значение F4 пока не сохраняется на диск;
при каждом запуске default nearest, если явно не указан CLI linear.

Проверки: Release CTest 13/13; camera tests — 11 углов с шагом 0,01°,
монотонные дробные координаты и near clipping пола. `dok_gl_probe` — 302
кадра LIGHT (H/V, шаг дистанции 12), исходные цветовые anchors и плавный ramp,
стена/спрайт, прозрачность, UI, nearest → linear → nearest.
AI probe: 27 групп, 36 прогонов; OG: 600 кадров. `check_render.py` сохранил
DOS-сверку видимых пикселей software-дверей RU/EN (1622/1388).
Просмотрены GL PKR LEVEL1 nearest, PKE LEVEL2 linear 800×800, OG LEVEL4 nearest:
`build/sdl2/checks/{gl-smooth,gl-linear,og-smooth}.png`.
Полный интерактивный обход карт, аппаратный GLES и субъективная приёмка
плавности пользователем остаются открытыми. Следующий шаг — повторный плейтест.

## Исправления плейтеста, 3 ноября 2026

Причины: depth test был отключён и clip Z всех полигонов был нулём; сортировка
сцены не гарантирует взаимного перекрытия пересекающихся полигонов. Теперь
запрошен 24-bit depth, world включает тест, clip Z = W − 2 (near 1), кадр
очищает depth; UI отключает тест. Прозрачные texels отбрасываются до записи depth.
GL больше не получает динамических монстров со всей карты, только view bounds.

Программный raster.cpp использует abs(depth) и Q16-шаг по X для вертикальных,
по Y для горизонтальных поверхностей. Старый GL интерполировал signed depth
перспективно. Новый Draw передаёт RasterAxis; GL сохраняет перспективные UV,
но LIGHT интерполирует линейно по исходной оси с тем же Q16-шагом. Деление
varying-компонент отменяет перспективную коррекцию именно для света.
Горизонтальные поверхности всегда непрозрачны, как software. Таблицы не менялись:
например, последняя строка PKR LIGHT1 содержит 0/31/206/207/221/222/223/255.
Это проверка ресурсов и портового кода, не новый анализ EXE или доказательство
полной эквивалентности DOS. Координаты здесь экранные/камерные, не адреса EXE.

`build/sdl2/windows/dok_gl_probe.exe` проверяет реальные GL-пиксели против
software на H/V градиентах, перекрытие дальнего спрайта стеной при обоих
порядках рисования, прозрачный спрайт и независимый UI. Пройдено.
Release/CTest 13/13; окно PKR LEVEL1 GL 1280×720, кадр
`build/sdl2/checks/gl-fixed.bmp` просмотрен. GLES и полная геометрия не приняты.

Статус: в работе. Контрольная точка пользователя — базовый игровой GPU-путь,
затем Old Gold и плейтест, без расширения до полной релизной доводки.
Читать plan.md, handoff.md, SP07/SP15. Backend рисует полигоны самостоятельно,
не выдаёт вывод готового software framebuffer за GPU-рендерер.

Общие входы: исходная геометрия, изображения, палитра/LIGHT, dynamic instances.
GL2/GLES2 subset: VBO, attribute/varying shaders, texture2D, clamp/nearest,
без immediate mode, VAO, geometry shaders и обязательных расширений.
Широкий вид сохраняет вертикальный обзор DOS-сцены320×160 с коррекцией1.2,
расширяя горизонтальный; HUD поверх сцены. Software-путь сохраняется.
Проверить настоящее окно GL, resize, software regression и широкие аспекты.
