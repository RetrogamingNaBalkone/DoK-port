# SP10: недоступный рубль OG LEVEL4 в фиксированном времени

4 ноября 2026 года, исследование после неизменяемого пакета r1.
Подтверждён блокер порта, не недостаток четырёхшагового pilot:
при фиксированном elapsed416 рубль **(43,57)** недоступен из южного течения
при исходной геометрии. Полное прохождение здесь не выполняется; оно у SP16.

## Образец и исходные данные

OLD_GOLD.RES SHA-256 `e376855167b64a7190ec2da0ba9bd1da129ba178c4033aebadebca3f08b2be25`.
Нативные инструкции и адресная система — [movement audit](movement-audit.md),
read-only Ghidra MZ, не file offsets и не runtime-селекторы.

LEVEL4: cell side336, Min Dis165. Рубль находится в(43,57), центр14616/19320.
Слева(42,57) и сверху(43,56) стена class2 flags02. Справа(44,57) бочка
class6 G flags08. Южная граница pocket — Z19488; ниже неё row58 с class12
category100/value100, чистое течение по X. Узкая щель допускает X14613…14618.
Это исходные данные; pilot не менял стены/бочку или силу течения.

SP16 передал конечную позу перед callback примерно X14618/Z19599 и записи
`research/evidence/source-port/sp16-flow/routes/og4.replay`, `og4-stderr.log`.
Собственные точечные проверки используют X14616/Z19599; карты не заменяются.
Стартовая поза локального fixture задаётся явно: это контроль функции,
не заявление о прохождении от spawn и не телепортация в игровом replay.

## Независимый native player callback

`ports/sdl2/tools/check_current_bank.py` исполняет исходный OG `1ae1:1e16`:
lookup TMap/FCMap → apply_stat100 `1ae1:18b9` → single current move
`1ae1:0ee1`/world resolver → class12 callback → motion `1ae1:0908`.
Сам current, collision, MMap, quarter-steps и bob исполняют native инструкции.
Только stopwatch read контролируется. DOSBox/SDL audio не запускаются.
Это не запись DOS-сессии и не модель внешнего main/death loop.

Исходный чистый X+100 переводит `(14616,19599)` в **`(14716,19656)`**:
resolver использует безусловный midpoint по Z и создаёт перпендикулярный
скачок назад к центру реки. При обычном управлении это повторяется до того,
как центр героя успеет пересечь FCMap boundary и выйти из течения.

Полный digital sweep исходного callback:360 heading×8 сочетаний forward/
strafe, run включён. В каждом случае одинаковый исходный local fixture.

До current `(14616,19599)`, после current `(14716,19656)`, после motion
**`(14618,19339)`**, то есть центр уже в денежной клетке(43,57).
Подбор происходит на следующем callback. Никаких pregrant, новых скоростей
или удаления геометрии нет. Более поздний native callback действительно
допускает движение, исключённое новой фиксированной cadence порта.

## Почему это не только конечный набор входов

Проверены все **990** допустимых северных overlap-поз:
X14613…14618, Z19488…19652. Для каждой footprint проходим, а native current
X+100 возвращает Z**19656**. Это исчерпывает целочисленные позы узкого входа,
в которых центр ещё находится на течении, а footprint уже перекрывает row57.

При elapsed416/running исходный speed60 даёт distance120 на ось и три
quarter-step по30. Независимые оси могут иметь любую величину от−1 до1.
Консервативная граница суммарного северного перемещения с учётом обоих
Q15 округлений: `3 * (30 * sqrt(2) + 2) < 134`, что меньше165.
Она покрывает дробные оси, fine angles и поворот между callback.
Integer heading sweep подтверждает ограничение непосредственно в native коде.

Из южной реки в карман ведёт только эта щель: остальные три соседние клетки
твёрдые. Пока центр остаётся на row58, следующий current снова возвращает
его к19656. Resolver не может дать северный midpoint до пересечения границы:
midpoint этой строки равен19656, её северный edge равен19653. Следовательно,
вход не достигается накоплением коротких шагов; нужно устранить именно
создаваемый течением перпендикулярный сброс, а не улучшать horizon pilot.

Это вывод для исходного current100 и неизменных твёрдых соседей. Он не
распространяется на изменённый RES, удалённую бочку или неизвестные моды.

## Реализованная минимальная адаптация

Общий native resolver и движение без принудительного current сохранены.
Только OG class12 category100/101/102: если чистый current по одной оси
создал native snap по другой, `move_actor_current` ограничивает current по
его исходной оси до первой твёрдой границы, сохраняя поперечную координату.
В свободной реке исходные100 units остаются100; баланс, карты, speed60,
run и cadence не меняются. Generic `change_player_stat` не изменён:
несвязанные предметы/переносы сохраняют native путь `move_actor_to`.

Ограничение проверяет последовательные участки короче одной клетки.
Занятый интервал вдоль оси не короче клетки, поэтому два свободных конца
такого участка не могут перескочить препятствие. На первом занятом участке
целочисленный binary search находит последнюю свободную точку. Проверяются
footprint, projectile occupancy и реальные границы карты. Commit MMap и
door counters выполняется один раз обычным общим кодом. Сохраняемого состояния
новая адаптация не добавляет.

Для контрольной позы допустимый current теперь X14618/Z19599 вместо
X14716/Z19656. Обычные последующие северные движения накапливаются
и пересекают FCMap boundary. Это намеренная адаптация композиции current
к фиксированной cadence порта, **не эквивалент native midpoint** и не
доказательство ошибки исходного DOS resolver.

`dok_movement_tests OLD_GOLD.RES` проверил локальный исходный bank через
обычные `player_surface`, `update_player_motion` и `player_pickup`: при
30/60/144 FPS за3 player ticks рубль подобран, score1, конечная поза14618/19329.
Дополнительные synthetic fixtures проверяют signed X/Z±100, свободные
100 units без изменения, door occupancy и неизменный native snap generic
category100. Это local fixture с явно заданной позой, не полный маршрут.
Полный replay перегенерирует SP16. Неизменяемый пользовательский r1 не
переписывается; исправление относится к следующей сборке.

Доказательства: `research/evidence/source-port/sp10-current-bank/`:
`native-digital-sweep.json`, `native-bank-invariant.json`, `native-late-witness.json`,
`report.json` и `cpp-regression.log`. EXE/RES SHA-256 до/после совпали.

# Полный sweep14400 native callbacks, около5 минут:
