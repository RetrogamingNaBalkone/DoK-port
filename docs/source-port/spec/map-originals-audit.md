# Исходная карта PKR/PKE — проверка для SDL2

4 ноября 2026 года. Исследование для запроса убрать подсказки и вернуть
оформление карты оригиналов. Здесь фиксируются исходные правила Кремля;
современная компоновка и GBA-реализация не используются как архитектурная основа.

## Образцы и адреса

- PKR.EXE SHA-256: `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`.
- PKE.EXE SHA-256: `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
- Map draw: PKR `1098:1290…30C0`, PKE `1030:1374`.
- Проекты Ghidra: `research/ghidra/projects/{ru,en}/Kremlin.gpr`.
- Read-only экспорт: `tools/ghidra/InspectAutomap.java`, результаты
  `research/evidence/automap/{ru,en}/{automap.asm,automatic.c,*.bin,manifest.json}`.

Адреса означают **сегмент:смещение NE-загрузчика Ghidra**, не файловое смещение,
не индекс NE-сегмента и не DPMI-селектор. Вход `__cdecl16far`: far this на BP+6,
`LES` для указателей, `RETF`, стек очищает вызывающая сторона. Геометрия/классы —
signed WORD, marker — BYTE; координаты VGA-примитивов передаются DWORD.
Автоматический C хранится как исследовательский материал, не код движка.

## Оформление и правила

В исходном режиме 320×200 шаг клетки **3×3**. Верх карты — Y7, левая граница
X64, правая X256 для мира64×64. Ось X обращена: большему world X соответствует
меньший screen X; Z направлена вниз. Прямоугольники и линии включают конечные
точки. Пиксели не заменяются современными цветами, рамками или легендой.

Вся поверхность заливается marker объекта glyph32 (`+1B`, в LEVEL1 индекс128).
Все остальные цвета также берутся из byte marker исходного объекта; палитра —
GAMEPn уровня. Первый проход закрашивает исследованные клетки FCMap, кроме
marker фона и исключённого marker glyph219. Затем накладываются элементы MMap;
при пустом классе0 берётся соответствующая TMap.

- Стены class2: контуры только у исследованного соседа, который не class2.
- Class4/7: центральные линии, каждое из двух направлений имеет независимую
  проверку двух соседей; линии не соединяются через class2/4/7.
- Class8/12: маленькие внутренние квадраты видны без предмета карты.
- Class3/6/10/13 и class9 с `state+A2 != 4`: внутренние квадраты показываются
  только при native world+0C (наличие предмета карты).

**Предмет карты не раскрывает неизученные клетки.** Проверка visited остаётся
обязательной для всех элементов. Class1 дополнительно отмечает свою клетку
visited непосредственно в функции карты.

Указатель героя — три исходных пикселя: два с индексом0 и кончик marker героя
(`+1B`, в LEVEL1 индекс7). Например, относительно левого верхнего угла клетки:
heading0 — `(2,1,0),(2,2,0),(2,3,7)`; heading90 —
`(1,2,0),(2,2,0),(3,2,7)`. Остальные направления и точные угловые границы
проверены исходным x86 и сохранены в `pkr-native-report.json` ниже.

## Как возникает visited

PKR render function `1098:30C1` после прохода отрисовки обходит record pointers:
`1098:53E9…542A`, запись `visited[record.cell+4]=1` в `1098:5417` при flags+6 bit1.
Это не отметка квадратного окружения героя и не проверка прямого попадания
пикселя в framebuffer.

`1100:0301` вызывает сортировку `1100:0000` по убыванию signed DWORD depth+7,
затем идёт с конца, от ближних records к дальним. Массив свободных экранных
колонок начинается в DS:AA5A. Для record запрашивается горизонтальный диапазон
через виртуальный метод +4. После ограничения viewport bit1 сбрасывается и
устанавливается только если найдена хотя бы одна свободная колонка. У records
с flags bit2 эти колонки одновременно закрываются. Поэтому итоговый visited
зависит от горизонтального перекрытия более близкими непрозрачными records,
а не только от попадания геометрии в область обзора.

ASM подтверждение: `1100:03D1` test bit2, `03F1` clear bit1,
`0425` test свободной колонки, `043B` set bit1, `0450` закрытие колонки;
ветвь без bit2 — `046E…04CE`. Копии C и соответствующего ASM находятся в
`research/evidence/source-port/sp15-map/pkr-visited-column-pass.*`.

## Ввод и время карты Кремля

Tab переключает карту **по отпусканию**, не по удержанию. В PKR
`10C0:1800…1844` вызывает для сканкода0F helper `1070:02AB`, который возвращает
true только при keyboard-table byte==2, после чего очищает latch через AND1.
Далее инвертируется input-object+8B и формируется action bit`0x02000000`.
В PKE та же последовательность: `1050:1B63`, helper `1028:02B7`.

IRQ исходной клавиатуры экспортирован новым read-only скриптом
`tools/ghidra/ExportSourcePortMapInput.java`: PKR `1070:0109…01EA`,
PKE `1028:0115…01F6`. PKR `1070:017C` записывает3 на make,
`1070:01B3` делает AND2 на break. Поэтому3 — удержание,2 — отпускание.
Ghidra-журналы подтверждают read-only режим и discard всех изменений проекта;
EXE SHA до/после совпали. Выходы —
`research/evidence/source-port/sp15-map/{pkr-input,pke-input}/`.

Исходный `game_poll_input` исполнен в Unicorn на обоих образцах. Последовательность
байтов Tab `0,3,3,2,0,3,2,0` даёт mapflag `0,0,0,1,1,1,0,0` —
**16 исходных сценариев PASS**. Только NE-селекторы двух far keyboard calls
релокированы в непересекающиеся Unicorn-сегменты; логика функций не заменялась.
Команда и отчёт:

```powershell
py -3.14 -B research/evidence/source-port/sp15-map/pkr-input-check.py
```

`research/evidence/source-port/sp15-map/pkr-input-report.json`.

Карта **не останавливает мир**. В main PKR `1008:0DAF` безусловно вызывается
event dispatch `1038:0284`, затем `1008:0DF3` проверяет map action и только
задаёт world+748. Scene build/render `1098:30C1` вызывается безусловно в
`1008:0E44`; overlay caller `1098:5435` в `1008:0E84` рисует map при world+748.
При активной карте пропускается weapon overlay (`1008:0ECD…0EEC`), но не события
игрока, монстров, дверей и снарядов. Карта не является блокирующим меню паузы.
В PKE то же: main `1008:0AA9`, безусловный event dispatch `1010:163A`,
scene `1030:3571`, overlay caller `1030:6136`. Указатель world+748 используется
конструктором/main/draw и не проверяется в player/AI callbacks.

Это подтверждено исходными ASM/вызовами; отдельная интерактивная DOS-сессия
с ходьбой при открытой карте для этой проверки не запускалась.

## Независимая проверка раскрытия в SDL2

`SoftwareScene::discovered_cells` проверена против **настоящих coherent DOS RAM
captures SP07**, а не против вычисленной нами модели. Из captured DS:AA38/AA3A
(PKE:AAE8/AAEA; OG:1FDC/1FDE) прочитаны count и far array исходных render records.
Оставлены записи с итоговым flags+6 bit1; cell берётся из native record+4.
Для NE far pointers разрешаются по сохранённым LDT descriptors, для OG — по
реальному segment×16+offset. Все полученные клетки присутствуют в накопленном
visited исходной RAM; этот дополнительный assert прошёл.

Сравнение **22/22 PASS**, все missing/extra sets пусты:

- PKR и PKE: LEVEL1–3, heading0/45/135 — 18 кадров.
- OG LEVEL4: heading83/0/45/135 — 4 кадра.

Камера, object pose/flags/door extent и изображения берутся из соответствующих
native state captures SP07. После применения snapshot getter port API возвращает
те же per-frame cells, что исходные final descriptors после горизонтального
occlusion. Probe на каждом кадре также проверяет неизменность render pixels и
мирового состояния; modern1200×540/FOV110 не меняют discovery.

```powershell
py -3.14 -B ports/sdl2/tools/check_map_discovery_native.py
```

Оригиналы EXE/RES всех трёх игр неизменны до/после. Полный отчёт с командами,
позами, обоими cellsets, SHA compressed RAM/native states/capture reports/probe
и оригиналов: `research/evidence/source-port/sp15-map/discovery-native-report.json`.
Исходные captures — `research/evidence/source-port/sp07-render/{ru,en}-level{1,2,3}-vga-08`
и `og-dos-03`. Компактная сводка с SHA отчётов:
`analysis/source-port/sp15-map-native-summary.json`.

Граница: это равенство **текущего набора раскрываемых клеток**, а не равенство
накопленной истории visited после неизвестного прежнего маршрута DOS. Исходные
renderer captures и state snapshot задают конкретные воспроизводимые условия;
проверка не доказывает все возможные динамические сцены или весь DOS main loop.
