## GL-текстуры

`GlRenderer::set_texture_filter()` (включая диагностические режимы):

| Значение | Режим |
|---|---|
| 0 | Nearest, прежний путь индекс → LIGHT → палитра |
| 1 | Linear, прежняя интерполяция четырёх цветов после LIGHT |
| 2 | Mipmaps: ближайший mip-уровень, билинейная фильтрация внутри него |
| 3 | Trilinear: интерполяция двух соседних mip-уровней |
| 4–6 | Анизотропная выборка с максимумом 2/4/8 отсчётов |

`make_mip_atlas` создаёт **16 независимых цветовых пирамид**, по одной на строку
LIGHT. Палитра и LIGHT применяются к каждому исходному индексу до уменьшения.
Уменьшение — среднее по площади, включая последнюю строку/колонку нечётного
размера. Для прозрачного вертикального материала индекс 0 имеет RGBA=0;
остальные цвета хранятся в premultiplied RGB. Обычные материалы сохраняют
непрозрачный индекс 0. Пирамиды прозрачного и непрозрачного материала различаются.

Все уровни одной пирамиды размещены горизонтально в плитке; 16 плиток занимают
сетку 4×4. При выборке координаты ограничиваются центрами крайних текселей
конкретного mip-уровня: GL_LINEAR не читает соседнюю строку LIGHT или уровень.
Shader интерполирует две строки LIGHT, затем два масштаба, усредняет отсчёты
анизотропии и один раз делит RGB на alpha перед обычным alpha-blending.
Палитровые индексы не усредняются. Автоматическая генерация mipmaps индексной
текстуры и hardware anisotropy индексного материала не используются.

Footprint вычисляется через dFdx/dFdy исходных UV в текселях. Собственные оси
матрицы J·Jᵀ задают длинную/короткую ось. Для обычных mip-режимов LOD зависит
от длинной оси; для анизотропии — от короткой оси и ограничения числа отсчётов.
Отсчёты распределены вдоль длинной оси. Это анизотропия в shader, а не обещание
одинаковой стоимости с расширением EXT_texture_filter_anisotropic.

Кэш зависит от содержимого и размеров изображения, прозрачности, палитры и
LIGHT. При смене палитры/LIGHT цветовые атласы удаляются. При давлении свыше
64 МиБ удаляются материалы, не использованные в предыдущем world-проходе;
живой рабочий набор сохраняется, поэтому 64 МиБ не являются жёстким лимитом.
Размер атласа проверяется против GL_MAX_TEXTURE_SIZE. Immediate/deferred пути
используют одинаковые цвета и сохраняют порядок полигонов.

Desktop GL использует обычные производные GLSL. Для GLES 2 требуется
OES_standard_derivatives; без него `mip_filters_supported()` возвращает false,
а расширенные режимы используют Linear. Настоящая GLES/RK3326-приёмка,
точность mediump, стоимость и пределы текстур остаются SP20.

## Масштабирование программной сцены

С [SP-XBR-GPU](../tasks/SP-XBR-GPU.md) software-кадр при доступном GL2/GLES2
выводится отдельным GL-presenter. `Display::gl()` остаётся nullptr: мир и его
растеризация по-прежнему software. Отказ создания контекста/базового shader
возвращает прежний SDL Renderer. Для presenter не требуется depth buffer.

`frame_filter=0/1/2` сохраняет Nearest/Linear/Sharp Bilinear.
`frame_filter=3` — экспериментальный xBR-lv2, CORNER_C, smooth tips, масштаб 3.
Адаптация формул Hyllian, лицензия MIT поставляется в LICENSES.txt.
Источник: <https://github.com/libretro/glsl-shaders/blob/master/xbr/shaders/xbr-lv2.glsl>.
RGB и alpha смешиваются в premultiplied представлении. GPU-путь загружает
исходный кадр, обрабатывает его отдельным GLSL 1.10 / ES 1.00 shader в цветовой
текстуре 3× и выводит через Nearest в выбранный прямоугольник. Программа
компилируется лениво и независимо от shader основного GL-рендерера.
Текстура/FBO переиспользуются до изменения размера и освобождаются с Display;
прежние FBO и viewport восстанавливаются, readback для фильтрации нет.

Новые обязательные API/расширения/версии ОС не добавлены: используются
существующие необязательные FBO entrypoints. При их отсутствии, ошибке
shader/FBO или превышении размера промежуточной текстуры остаётся CPU xbr3.
Если CPU-результат 3× не помещается в GL_MAX_TEXTURE_SIZE, видимые выходные
пиксели выводятся ограниченными плитками с тем же Nearest, а не oversized upload.
ES-shader требует доступный fragment highp для точной сетки/цветовых сравнений;
без него опциональный shader отклоняется и используется CPU fallback.
Это не повышает минимум GLES2 или Windows 8 x64. При отсутствии OpenGL целиком
software продолжает работать через SDL Renderer.

Для одинаковых contour decisions luma представлена отношением 897:1761:342
вместо дробных коэффициентов с делением; пороги масштабированы соответственно.
Веса на фиксированной сетке 3× кратны 1/8: CPU хранит таблицу, GPU привязывает
веса к тем же точным значениям. Это устраняет нестабильный выбор стороны
равного контура из-за FMA/округления. В сравнении с прежним float CPU возможны
локальные изменения на таких границах; новая CPU/GPU пара проверяется с
допуском 1 уровень канала, включая настоящие кадры трёх игр.
Если увеличения нет, используется исходный Nearest без промежуточного буфера.

Фильтруется сцена, включая находящиеся в ней спрайты. Оружие, HUD, сообщения,
меню и FPS рисуются отдельно. xBR также поддерживается GL-функцией вывода
готового RGBA-изображения, но обычная GL-сцена сразу рисуется в целевом размере
и xBR-фильтра текстур мира не получает. Просмотр показывает характерное
сглаживание пиксельных контуров и заметное изменение мелкой травы/текстур;
поэтому вариант остаётся экспериментальным и не включён по умолчанию.

## Настройки и совместимость

INI v1 расширен ключами `video.mip_filter=0..5`, `video.frame_filter=0..3`,
`gameplay.saves_enabled=0|1`. Прежний `video.linear` сохранён. Значение
`AppSettings::texture_filter()` возвращает 0 для Nearest или 6 для Smooth.
Любой прежний `linear=1` или `mip_filter=1..5` выбирает Smooth; чтение нормализует
ключи в `linear=1,mip_filter=5`. Nearest записывается как 0/0. Остальные настройки,
включая выключатель сохранений, не сбрасываются. GL-фильтр и масштабирование
software независимы; F4 переключает Nearest/Smooth либо четыре software-варианта.
CLI `--filter` принимает nearest/smooth; прежние linear/mipmaps/trilinear/
aniso2/aniso4/aniso8 остаются совместимыми именами Smooth.
`--frame-filter` принимает nearest/linear/sharp/xbr.
CLI-переопределения не попадают в профиль без явного пользовательского изменения.

## «Геймплей → Сохранения»

Строка стала регулируемой настройкой Вкл./Выкл. с пояснением об отсутствии
сохранений в оригиналах. По умолчанию Вкл. сохраняет поведение существующих
профилей. Значение применяется сразу и сохраняется в профиле. Сброс геймплея
включает сохранения и инерцию. Отключение не удаляет слоты и резервные копии.

Выкл. делает недоступными ручное и быстрое сохранение/загрузку в паузе,
загрузку в меню игры и после смерти/Game Over. Навигация пропускает эти строки.
`save_allowed`, открытие списка слотов, quickload_request и главные обработчики
request_save/load_game/quickload проверяют флаг. Отложенная запись отменяется,
если флаг выключен до её исполнения. F5/F9 не читают и не пишут игровое состояние.
Профиль/settings.ini продолжает записываться. Повторное включение возвращает
доступ к существующим слотам без преобразования формата сейвов.
