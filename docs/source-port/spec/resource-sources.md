# Источники RES: контракт SP03 → SP15

4 ноября 2026 года. Это политика современного порта, не функция DOS.
Исходные reader/декодеры и адреса доказательств сохранены в SP03 и
`docs/originals/resources.md`; новый анализ исходных EXE не выполнялся.

## Идентичность и выбор

`Archive::same_resources` сравнивает имена, размеры и все байты полезной
нагрузки точно, без хеша. Порядок записей разных имён, файловые смещения,
межблочные промежутки, кеш-поля каталога, хвосты имён после NUL и хвост
файла не участвуют. При повторяющихся именах сохраняется порядок их
нагрузок: различающиеся затенённые записи не теряются. Reader сохраняет
первое совпадение имени; профиль с отсутствующим ожидаемым именем не распознаётся.
Изменения внутри нагрузки консервативно считаются разными источниками.

`ResourceSources` владеет архивами и путями. Индекс источника стабилен до
уничтожения реестра; указатели/ссылки в `sources()` могут инвалидироваться
при добавлении, поэтому UI хранит индексы, а не указатели между изменениями.

- `add(path, archive)` отвергает неизвестный каталог, одинаковую копию
  сворачивает в существующий индекс и сохраняет её путь как алиас.
- Единственный источник набора выбирается автоматически.
- Новый отличающийся источник того же набора сбрасывает `selected(dataset)`
  в `nullopt`, в том числе после предыдущего явного выбора. Повторное добавление
  одинаковой копии выбор не меняет и неоднозначность не снимает.
- `select(dataset, index)` разрешает только индекс источника этого набора.
  Недопустимый выбор бросает исключение и не меняет состояние.
- `find_source(path)` ищет загруженный путь или алиас после нормализации
  абсолютного пути. Имена не используются для определения игрового профиля.

Приложение до `add` разбирает все LEVEL и их ссылки. Ошибка файла остаётся
его отдельной диагностикой; пригодные источники других наборов сохраняются.
В список доступных игр попадают только `selected` источники. При конфликте
первая копия не остаётся скрыто активной.

## Доступный CLI и следующий интерфейс

Повторяемый `--res-source PATH` явно выбирает уже загруженный `--res PATH`,
включая алиас одинаковой копии. При нескольких указаниях для одного набора
действует последнее. Несуществующий/отвергнутый источник — ошибка CLI.
Выбор выполняется до создания мира. Пример:

```text
dok_port.exe --res first.res --res second.res --res-source second.res
```

SP15 подключает экран выбора: показывает кандидатов и их полные пути,
по подтверждению вызывает `select`, затем пересоздаёт список доступных игр.
Также SP15 отвечает за сохранение пользовательских путей и выбора.
Сейчас экранного выбора нет; диагностируется необходимость `--res-source`.

При существующем World (включая паузу) загрузка/смена источника запрещена.
Текущий обработчик SDL_DROPFILE показывает уведомление без изменения реестра
или архивов. Перед перестройкой источников из главного меню закрывается музыка;
`Frontend::datasets` получает новые указатели. Нельзя переносить смену источника
в паузу без предварительного завершения сессии и уничтожения её зависимостей.

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release
py -3.14 -X utf8 -B ports/sdl2/tools/check_assets.py
py -3.14 -X utf8 -B ports/sdl2/tools/check_resource_sources.py
py -3.14 -B tools/reports/summarize_reports.py
```

Отчёты: `build/sdl2/checks/assets-report.json` и
`build/sdl2/checks/resource-sources/report.json`. Временные изменённые RES
удаляются после проверки, оригиналы не меняются. Проверки источников включают
каждый из трёх наборов, перепаковку, отличающиеся нагрузки, ошибочный выбор,
неизвестный каталог, сброс выбора новым вариантом и сохранение выбора дубликатом.
Процессные сценарии включают пустой запуск, конфликт, явный выбор и алиас,
некорректный файл рядом с корректным, доступность другого набора при конфликте,
неизменность World/ticks/pose/HP/maps при добавлении копии и варианта в паузе.
Это проверки ресурсов и жизни ссылок, не прохождение уровней.
