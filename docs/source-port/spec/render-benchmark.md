# Стенд рендереров SP20

`ports/sdl2/tools/render_benchmark.py` запускает Release-цель `dok_render_bench`
и сравнивает результаты. Python 3.9+ и стандартная библиотека; Pillow не нужен.
Для Windows используем общие Zig/SDL2 из `docs/building.md`, Python 3.14.
Это инструмент разработки; игровые рендереры и их алгоритмы не изменены.

## Что измеряется

Каждая сцена имеет фиксированные карту, позу, время, дверь и состояние боя.
Сначала выполняется прогрев (по умолчанию 10 кадров), затем 120 повторов
одного состояния. В JSON сохраняются все времена и mean/p50/p95/p99/max:

| Стадия, мс | Содержание |
|---|---|
| prepare | Начало кадра, bounds, списки динамических изображений |
| scene | Общая сцена и software raster либо GL submission, включая texture cache |
| ui_convert | Оружие, HUD, преобразование цветов; в GL также их подача/загрузка |
| gpu_wait | Завершающий glFinish; у software почти нулевой служебный интервал |
| total | От начала кадра до окончания работы, включая завершающий glFinish |

GL перед кадром дожидается предыдущей работы, после кадра вызывает glFinish.
Это **синхронная задержка отрисовки**, не GPU timer query и не установившийся
FPS игры с перекрытием CPU/GPU. Часть ожиданий драйвера может попасть в scene
или ui_convert; gpu_wait нельзя объявлять полным временем GPU.
Swap/present не вызывается, запрашивается VSync off; фактический swap interval
записан. Software измеряет создание native кадра и ARGB conversion, но не
SDL upload/масштабирование/present. Его total не сопоставлять напрямую с GL
как полный пользовательский кадр. Чтение GPU, PNG, сжатие и диск вне таймеров.
AI/симуляция подготавливают fixture до измерения, аудио выключено.

Счётчики world_polygon_submissions/submitted_vertices/submitted_image_bytes
считают входы публичного GlRenderer::polygon. Последний означает сумму размеров
изображений на входах, **не** фактически загруженные GPU-байты; после batching
число polygon submissions не равно числу физических draw calls.
polygons — существующий счётчик сцены до software sort/cull.

Стенд не эмулирует RK3326 и не предсказывает его FPS. Для сравнения скорости
нужны одинаковый компьютер, режим питания/частоты, фоновые нагрузки, разрешение
и драйвер. Запустить несколько независимых серий; пять samples подходят лишь
для проверки механизма. p99 при малом числе samples практически равен максимуму.
Подпись устройства/прошивки/частоты задаётся через `--label`.

## Сцены и координаты

`--suite quick`: initial, heading45 и дробное смещение GL-камеры для каждого
уровня. В software дробный offset не применяется по существующему контракту.
`--suite full`: initial, восемь углов, дробная камера, stress-сцены ниже,
30 фаз каждого различающегося изображения/режима сдвига двери (первое размещение), по 18 фаз
каждого из четырёх направлений воды PKR/PKE. Вода проверяется там, где она
размещена. OG получает свои карты/ресурсы без кремлёвских stress-координат.

`--suite stress` предназначен только для PKR/PKE и включает места пользователя:

| Сцена | Клетка камеры X/Z, угол | Подтверждение |
|---|---|---|
| LEVEL1, низкий потолок | 57/52, десять углов, в том числе 89/90/91° | FCMap inset400 проверяется при запуске |
| LEVEL1, западный низкий потолок | 20/33, 90° | Исходный FCMap |
| LEVEL2, финальный массовый залп | 31/50, 180° и 135° | Ряд оригинальных монстров Z47, двери Z48 |
| LEVEL2, патроны | 50/41, 270°; 51/41, 315° | Два ряда патронов и решётки, снимок проверен |
| LEVEL2, залп в комнате патронов | 51/41, 270° | Монстры в X50…59/Z40…43 |
| LEVEL3, ружьё и Бабы-яги | 20/30, 270° и 315° | Оригинальное оружие и ряд ведьм X24 |

Это **нулевые индексы runtime-клеток SDL2 World**, мир X/Z = cell×480+240,
Y камеры −300. Строки LEVEL при World-load разворачиваются; исходный номер
строки текстового ресурса не переносить напрямую. Координаты не являются
адресами EXE. Места из GBA PERF04/05, g21-investigation и benchmark_battles_gba
использованы как исследовательские подсказки и сверены через `dok_inspect --json`
с картами SDL2 PKR; архитектура, баланс и код GBA не переносились.

Массовый залп — явно заданное стрессовое условие. Герой помещается в комнату,
HP/maxHP=32767, выдаются исходные оружия и ключи; двери внутри arena открыты
до phase29/extent30. Исходные карты, расположение и определения врагов сохранены.
Монстры в arena пробуждаются; способные стрелять (`number(0xa6)>0`) одновременно
выпускают **по одному своему штатному снаряду** через Projectiles::spawn,
повёрнутые к герою. Искусственный первый залп обходит естественную задержку
и LOS-условие AI. Далее исполняются обычные monster/projectile/weapon callbacks
фиксированными шагами 416 тиков. Герой стоит; это не прохождение и не
естественно записанная сессия. В финальной комнате PKR/PKE семь стрелков,
в комнате LEVEL3 двенадцать. Бояре без дальнего оружия не получают его искусственно.

Сохраняются состояния после 0/1/2/4/8/16/32 шагов (0…13312 тиков): начальный
залп, полёт и столкновения. В отчёте есть число стрелков, живых снарядов,
impact-состояний и отпечаток логических входов представления. Эти величины
сравниваются до пикселей, поэтому изменение боя не выдаётся за оптимизацию
того же кадра. Состояние после 0 шагов уже содержит выпущенные снаряды.

Не покрыты все фазы всех анимаций, эффекты получения урона/смены оружия HUD,
весь набор игровых сообщений, frontend и все положения камеры на всех картах.
Для отдельных оптимизаций дополнять fixtures и менять fixture_version.
Существующие игровые, GL/LIGHT, HUD и DOS-проверки сохраняют своё назначение.

## Запуск

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1 -Configuration Release
py -3.14 -B ports/sdl2/tests/test_render_benchmark.py

py -3.14 -B ports/sdl2/tools/render_benchmark.py record --res originals/pkr/RUS/PKR.RES --res originals/pkr/ENG/PKE.RES --res originals/Old_Gold_3D/OLD_GOLD.RES --output research/evidence/source-port/render-benchmark/baseline --suite full --warmup 2 --samples 5
```

Для разработки обычно достаточно `--suite quick` (по умолчанию); для
согласованных тяжёлых боёв — `--suite stress` и только два кремлёвских RES.
Команда выше проверяет полную картинку с короткими замерами. Для профиля скорости
выбрать quick/stress и `--warmup 10 --samples 120` (или больше), повторить серии.
Полный набор содержит тысячи кадров и заметно дольше небольшого stress-набора.
`--renderer software|gl|both`, `--level LEVEL2` сокращают выборку.
По умолчанию `--matrix quick`: software320×200, GL640×480 nearest/linear.
`--matrix full`: все пять software-режимов и GL480×320/640×480 nearest/linear.
Матрица разрешений и набор сцен выбираются независимо.

После изменения и повторной Release-сборки выполнить **ту же команду record**
с теми же RES/параметрами, но новым каталогом, например
`--output build/sdl2/benchmarks/candidate`. Затем:

```powershell
py -3.14 -B ports/sdl2/tools/render_benchmark.py compare research/evidence/source-port/render-benchmark/baseline build/sdl2/benchmarks/candidate --output build/sdl2/benchmarks/comparison
```

Каталоги не перезаписываются. Выбирать новый каталог для каждой серии;
исходный baseline сохранять до приёмки изменения. Результат record с complete=false
не допускается как эталон. На Linux указать `--exe /путь/к/dok_render_bench`;
нужны SDL video и настоящий GL-контекст для GL. Native GLES-контекст в этом
стенде пока не реализован; нельзя объявлять Linux/ARM/GLES проверенными по Windows.

## Сравнение и отчёты

- `manifest.json`: хеш EXE, ресурсов до/после, исходного дерева, git HEAD/status,
  host/label, точные команды, native-метаданные и SHA-256 каждого capture.
  Нативный отчёт включает compiler/build type, SDL, GL vendor/renderer/version,
  размеры, время, позу и номера fixtures. Старый бинарник автоматически не
  пересобирается: перед record обязательна сборка.
- `*.idx.zlib`: индексный software-кадр целиком, включая оружие и HUD.
- `*.rgba.zlib`: RGBA8, верхняя строка первой; точные итоговые цвета обоих путей.
  Сжатие без потерь проверяется обратным преобразованием; временный raw удаляется.
- `*.png`: удобный просмотр того же кадра. SHA-256 проверяется на целостность;
  критерием эквивалентности служат распакованные пиксели, не кодирование PNG.
- `comparison.json`: число отличающихся пикселей, прямоугольник различий,
  максимальная/средняя разница каналов и времена до/после по каждой сцене.
  Для индексов численная разница индексов не является расстоянием цветов.
- `diff-00000-rgba.png` / `diff-00000-idx.png`: пурпурные изменённые пиксели на чёрном фоне.
  Даже один изменённый канал или индекс приводит к неуспеху. Допусков нет.

Exit code: **0** — кадры точны; **1** — различаются; **2** — ошибка входов,
несовместимые параметры/ресурсы/состояния, неполный прогон или повреждение.
GL требует одинаковых vendor/renderer/version, иначе нужен отдельный baseline.
Software и GL между собой не сравниваются: у них намеренно разные проекция,
свет и HUD. Изменение времени не меняет exit code: шумные замеры нельзя
использовать как автоматическое доказательство ускорения или регрессии.

Каждый native case дополнительно сравнивает кадр после прогрева и после
измерения, а также проверяет, что render не изменил логические входы мира.
Это ловит зависимость результата от количества redraw.
Эталон подтверждает отсутствие изменений относительно текущего SDL2,
но не означает полной эквивалентности оригинальному DOS.

Постоянные baseline/доказательства хранить локально в research/evidence,
кандидаты — build/sdl2/benchmarks. Они содержат изображения исходных игр,
поэтому не включаются в Git и пользовательскую поставку. После принятия
оставлять актуальный baseline и отчёт, не накапливать одинаковые серии.
