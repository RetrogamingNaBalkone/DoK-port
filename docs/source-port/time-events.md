## Доказательства

PKR/PKE: NE-адреса Ghidra и исходные ASM-контракты перечислены в
[исследовании оригинальных событий](../gba/time-events.md#очередь-оригинала).
Этот документ используется только как источник исследований оригиналов.
OG: MZ-адреса Ghidra, не файловые смещения:

- `2a8d:0112`: schedule, условие count < capacity−1, вставка владельца в кольцо.
- `2a8d:0223`: cancel; `0238`: clear; `0266`: изменение interval слота0.
- `2a8d:0278`: dispatch; `02bc…02df` копирует source SI в destination DI;
  helper `1000:1126` загружает source из BP+6 в DS:SI, destination BP+Ah в ES:DI,
  CLD/REP MOVSW и RETF8. Размер записи16 байт передаётся в CX.
- `0304/0308`: unsigned CMP/JC; `031d`: far callback с owner-pointer,
  без opaque parameter; `0324…034f`: новый clock-read и обновление source SI.
- `0353…0365`: keep продвигает write DI, read SI всегда растёт, count живой.
- `0368…03d5`: уплотнение, удаление пустого owner, уменьшаемый предел обхода.

Автоматический C использован для навигации; перечисленные эффекты проверены
по сохранённому `decompiled/old-gold/listing.asm`. Разметка far-pointer и
16/32-битные поля заменены логическими ID и явными типами C++.

## Контракты переноса

`GameClock` хранит рациональный остаток перевода наносекунд в PIT/119 и 64-битное
время; предоставляет native uint32. Не имитирует сброс IRQ-счётчика и фазовые
скачки DOS. `Stopwatch` сохраняет native wrap и начинает новый отсчёт после stop.

`Events::dispatch` — один sweep исходного dispatch(0), без busy wait. Он получает
функцию часов и маршрутизатор `(OwnerId, CallbackId)`; opaque parameter хранится,
но в callback не передаётся. Callback ID0 и owner ID0 зарезервированы.
При capacity4 доступны три события. Статические слоты владельца не перемещаются
при append; `std::map` сохраняет ссылки при создании других владельцев.

Сохранены: C,A,B после вставки A,B,C; equality deadline; uint32 wrap и unsigned
сравнение; новый срок от clock после callback без догоняющих периодов; живой append
в текущего owner; копирование до вызова с обновлением исходного слота; изменение
interval именно слота0; сокращение внешнего обхода при удалении пустого owner.

Явные защитные изменения относительно DOS:

- Destroy во время dispatch помечает владельца, не освобождая память до завершения
  sweep. Его оставшиеся callbacks пропускаются. ID переиспользуется после sweep.
- Активация пустого owner из callback публикуется после sweep в порядке вызовов.
  Так глобальный cursor не переключается под обработкой другого массива.
- Clear из callback завершает текущий callback и очищает события всех владельцев
  перед возвратом dispatch. Владельцы сохраняются; новые schedule до очистки
  возвращают false. Это выбранный SDL2-контракт, не восстановленный DOS-эффект.
- Рекурсивный dispatch бросает logic_error; cancel/set interval вне callback
  возвращают false. Исключение игрового callback является ошибкой сессии;
  транзакционного отката его действий нет.

World теперь регистрирует событие героя и предоставляет `advance_events`:
один sweep на каждый native tick, host elapsed не теряется. Тест с внешним
обработчиком получил одинаковую трассу при30/60/144 FPS. Это выбранная адаптация
кадрового опроса DOS; исходное запаздывание кадров не воспроизводится.
На момент первого этапа игровые callbacks ещё не были подключены; теперь
они проверены отдельным cadence-стендом на семи исходных картах. Вызов dispatch один
раз на кадр **не обеспечивает независимость логики от FPS**. При интеграции
нужен отдельный график опроса логики и проверка сценариев 30/60/144 FPS;
нельзя объявлять эту приёмку выполненной по тесту GameClock.

## Проверки и воспроизведение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/sdl2/tools/build.ps1
py -3.14 -X utf8 ports/sdl2/tools/export_clock_oracle.py
py -3.14 -X utf8 ports/sdl2/tools/check_clock_oracle.py
```

CTest core/arithmetic/clock/events: 4/4. Events проверяет порядок, equality,
запоздание, compaction, interval0, live append, отложенную активацию, shrinking
bound, wrap, чтение часов после callback, destroy, clear и рекурсию.

Экспорт открывает сохранённые проекты Ghidra read-only/noanalysis. Скрипт
`tools/ghidra/ExportSourcePortClock.java` получает исходные байты и листинг;
никакой декомпиляции EXE вне Ghidra нет. SHA-256 образцов до/после совпал:

| Образец | SHA-256 |
|---|---|
| PKR.EXE | `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28` |
| PKE.EXE | `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b` |
| OG.EXE | `7965e1d67128f196fbcf2bc449d97197f355c6b81cf043608fc9e01103ea043f` |

Unicorn2.1.4 исполнил по1133 вектора для PKR `1130:0187…01bb`, PKE
`1078:181d…1851`, OG `2a5b:015b…0199` (конец исключён). Все3399 результатов
совпали с C++ `original_pit_ticks`, стек восстановился. Проверены раздельные DIV,
переполнение произведения, фаза uint16, base wrap и детерминированные случайные
входы. AX содержит counter, DS — исходные globals. Фрагменты не включают порты,
IRQ, сброс10001 или far-запись результата: полные аппаратные часы не проверены.
