воды заменяют прежний диагностический пол/потолок и row0-only.

## Экран и управление

Mode 4, две страницы VRAM и индексный RAM-кадр 240×160. Поле 240×144 сохраняет
видимые DOS-пропорции; нижние 16 строк полностью отведены сообщениям.
В углах поля отображаются реальные значения HP100 и E0. Сообщение внизу
использует исходный FONT8 и CP866: «Уровень 1»/«Level 1».
Политика дальнейшего HUD и ключей описана в [gba-ui.md](gba-ui.md).
Текущий начальный инвентарь пуст; полноценный HUD, ключи и меню остаются G12/G17.

**Select** переключает RU/EN, повторное нажатие возвращает русский.
Геометрия,33864 байта mutable мира и пиксели сцены сохраняются; меняется
нижнее сообщение. START+SELECT вызывает диагностический panic для сброса.
Движения героя в этом статическом прототипе ещё нет.

## Реализация и границы

- `include/dok/renderer.h`, `src/renderer.c`: caller-owned workspace,
  class2 edge planes и начальные class4/7 center planes. Размеры текстур
  и низкие16 бит масштабирования, FCMap высоты, clipping depth0 и сортировка
  опираются на G04. Все ресурсы заимствованы из ROM; heap/парсинга LEVEL нет.
- `gba/renderer_probe.c`: загрузка общего мира, минимальный HUD, палитра,
  аппаратный таймер, VBlank-показ полного back buffer и guards.
- `gba/divmod.S` и `gba/memory.c`: ARM/Thumb EABI division helpers.
  16 signed/unsigned quotient+remainder vectors проверяются на ARM при старте;
  native random oracle проверяет C-деление. Поля диагностики закреплены
  static assertions, адреса verifier получает из ELF.
- `tools/render_tool.c`: независимый host запуск того же bounded renderer;
  `scripts/verify_renderer_host.py` отдельно проверяет карту/ресурсы,
  геометрию ворот G04, границы UV, сортировку и полностью составляет HUD
  из FONT8 для точного сравнения с ARM.

Текущий renderer поддерживает начальный heading90 и ограниченный профиль
геометрии. Пол и потолок заполнены диагностическими цветами из LEVEL,
текстурирование этих поверхностей ожидает G10. Используется LIGHT row0;
дистанционное освещение пока не перенесено. Перспективные U для неравных
глубин используют явно описанную Q7-аппроксимацию. Полная исходная raster
интерполяция, column occlusion, анимации и billboard-объекты остаются G10/G11.
Для уже изменённой двери renderer возвращает неподдержанный profile.
Подробности — [геометрия](gba-renderer-geometry.md),
[ресурсы и host/ARM](gba-renderer-assets.md).

## Измерения

Аппаратные Timer0/1 в mGBA насчитали **10 175 200…10 187 755 CPU cycles**
на построение/рисование сцены, HUD и перенос 38400 байт в скрытую VRAM-страницу.
Ожидание показа и загрузка языкового view в интервал не входят. Нормальный
интервал показа —36…37 VBlank, наблюдаемая частота≈1,637 FPS. Сравнение
выполнено с бюджетом561792 cycles — два аппаратных кадра,≈29,864 FPS.
Это измерение исполнения GBA-кода в эмуляторе, не FPS Python frontend.

Workspace ARM —54 284 байта, весь static EWRAM —89 776 из262 144;
свободно172 368 байт. В IWRAM зарезервировано8192 байта stacks/BIOS.
Watermark main stack показал2400 байт использования и5536 байт нетронутого
запаса; верхняя область IRQ/BIOS исключена. Это предел наблюдавшихся путей,
а не доказательство для будущей полной игры.

Результаты: [render-benchmark.json](../analysis/render-benchmark.json),
[render-host-verification.json](../analysis/render-host-verification.json).
Прошли framebuffer guards, RU→EN→RU, побайтная сохранность мира/геометрии,
сброс после заполнения EWRAM значением A5 и все три полных сравнения
38400 индексов с512 байтами палитры. Capacity1 вариант корректно вернул
ошибку без нарушения guards/мира.9 native тестов и Linux/Thumb compilation
прошли; CMake, физическая GBA и оригинальный BIOS не проверялись.

Полный игровой цикл/AI/звук ещё не исполняются. Производительность требует
отдельной работы перед итоговой интеграцией; этот прототип не годится как
доказательство выполнения цели30 FPS. Методика и текущие ограничения:
[gba-renderer-verification.md](gba-renderer-verification.md).

## Воспроизведение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba-renderer.ps1 -CrossChecks
```

Команда собирает native инструменты, сверяет runtime/пакет, собирает ROM,
исполняет его в mGBA и сравнивает RU→EN→RU с независимым host oracle.
Пакет и ROM детерминированы; повторная полная сборка дала тот же SHA ROM.
Отдельная быстрая сборка при готовом пакете:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-gba.ps1 -RendererProbe -OutDir build/gba-renderer -Verify
```

Оригиналы и полный пакет остаются в игнорируемых каталогах, в Git не входят.
