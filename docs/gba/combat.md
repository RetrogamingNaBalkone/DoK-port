# Оружие, снаряды и урон: граница G13

29 октября 2026: [плейтестовое уточнение столкновений](ui01-laser-hits.md)
проверяет начальную клетку и промежуточные клетки диагонального подшага,
устраняя пропуски близких целей между точками дискретного полёта.
Дальнейшее описание native порядка остаток/четверти относится к исходному
восстановлению; новая дополнительная проверка — осознанное исправление GBA.

Модуль `ports/gba/src/combat.c`, интерфейс `ports/gba/include/dok/combat.h`, GBA-адаптер
`ports/gba/platform/combat_probe.c`. Это редактируемый переносимый C, а не автоматический
псевдокод. Общий ROM содержит ружьё и лазер, полёт, попадания, промахи,
эффекты, расход общего заряда и удаление событий. AI получает отдельные
уведомления; окончание визуальной анимации не запускает AI-переходы.

## Проверенные источники

Образцы — оригинальные PKR.EXE и PKE.EXE, пути и SHA-256 из
`analysis/inventory-{ru,en}.json`. Скрипт `tools/ghidra/analyze-combat.ps1` сверяет
SHA до и после, открывает сохранённые проекты `research/ghidra/projects/{ru,en}/Kremlin.gpr`
с `-readOnly -noanalysis`. `InspectCombat.java` сохраняет actor/world сегменты,
листинг, автоматический C и manifest в `research/evidence/combat/{ru,en}/`. Оригиналы и
проекты не меняются; автоматический C не компилируется и не поставляется.

Все адреса ниже — **NE loader Ghidra**, не файловые смещения и не runtime
DPMI-селекторы. NE-сегменты в Unicorn загружаются по одному: их числовые
индексы нельзя одновременно трактовать как real-mode selectors, поскольку
полученные физические диапазоны перекрываются.

заряд; native readiness уже перешла в состояние 2 до попытки allocation.

## ABI, арифметика и порядок действий

Исходный ABI — 16-битные слова, 32-битные far pointers `segment:offset`,
`RETF`, обычно очистка аргументов вызывающим кодом. В listing проверены
`LES` для объектов, ширина копирований `MOV EAX`, знаковые `IMUL`, `IDIV`,
`CWD/CDQ`, `SAR` и условные переходы. Графовые ссылки в новом C — индексы;
DOS vtable, far/huge pointers и адреса драйверов не переносятся.

В `1068:2675…26B0` устанавливаются владелец, x, z и heading. Y из локальной
позиции владельца **не копируется**: высота остаётся из шаблона снаряда.
Поэтому умножение промежуточного localPosition.y на 3/4 у вызывающей функции
нельзя объявлять фактической высотой снаряда. Это проверено выполнением
оригинального участка с заведомо различными y владельца и шаблона.

Начальное событие назначается через 416 native ticks. При обычном полёте:

1. Снимается собственная занятость старой клетки.
2. Множитель времени `(elapsed << 8) / 416` ограничивается 256…2048.
3. Скорость берётся через младшее signed word; `IMUL/SAR8` задаёт дистанцию.
4. Шаг разбивается по `-(cell_side >> 2)`. **Сначала остаток**, затем полные
   четверти клетки. На каждом шаге сначала движение, затем lookup контакта.
5. MMap имеет приоритет; при пустом объекте/другом снаряде выбирается TMap.
   Снаряд не повреждает объект того же класса, что его владелец.
6. После шага исполняется `ADD16 damage, floor; SAR16 damage, 1`, включая
   переполнение перед арифметическим сдвигом. Попадание наносит урон до decay.

Точки PKR: `1068:2907…2963` — time scaling/division; `2970…2986` — первый
move/lookup с остатком; `2A58…2A93` — class immunity/event mask;
`2C53…2C5D` — точные `ADD AX`, `SAR AX,1`. EN decay — `1020:32F6…3300`.
В показанных обработчиках принятия удара нет дополнительного сравнения y
или layer. Параметр native +5A у всех player templates равен 0; новое
назначение этому полю не придумывается.

Base принимает удар, если нет flags 8 и 16. Door class 7 блокирует при
отсутствии бита 8; открытая дверь его пропускает. Живой монстр принимает
контакт; мёртвый не поглощает снаряд. Player принимает контакт и при нулевом
здоровье, но повторно не вычитает здоровье. Политика same-class immunity
применяется до этих обработчиков.

При принятом контакте выбирается POPAL для class 1/9, MIMO для остальных.
Native сохраняет ссылку эффекта в +7F, но в этой же итерации ещё обновляет
**flight** animation из +48. Следовательно, сразу после контакта виден
flight frame 0, выдерживается его интервал, а следующий callback показывает
effect frame 1. Effect frame 0 в этой конкретной цепочке не отображается.
Эффект не двигается. После последнего кадра он снимает занятость и событие,
становится пригодным для повторного использования. Compact состояния:
1 — полёт, 2 — контакт с оставшимся flight image, 3 — effect playback;
верхний bit 0x40 означает занятость клетки, 0x80 — отложенный новый owner.

Контакт отводит позицию назад на четверть клетки. При положительной высоте
цели y настраивается по высоте цели и половине текущего изображения снаряда,
умноженной на масштаб. Занимаемая клетка вычисляется после этого отвода;
она остаётся неизменной на всём effect playback.

## Слоты, события и компактная занятость

Native world scan идёт по всем 256 glyph slots от 0 к 255. Первый NULL либо
объект с flags 0x400 побеждает; старый объект перед заменой уничтожается.
Новый `dok_combat.slots[256]` хранит отдельные 40-байтовые записи и сохраняет
этот порядок. ROM glyph dictionary не меняется: static definitions нужны
для декодирования геометрии и предметов. Runtime flags 0x400 разрешают
повторное использование соответствующего номера; RECLAIM сообщает старый
object ID до allocation, GBA сразу снимает его visual events. Будущие AI
owners G15 должны уничтожаться тем же уведомлением. Flagged static objects
не рисуются и не участвуют как живые цели.

Каждый projectile имеет ровно одно событие. Поэтому вместо ещё одного
256-owner массива с тремя событиями применяется специализированное кольцо:
вставка после cursor, newest-first при следующем sweep, unsigned deadline
comparison и `deadline = now + signed_interval`. Сохранён native
mutable-count skip после удаления owner. Внутри собственного callback
удаляемый слот не переиспользуется; новый owner публикуется после sweep.
Рекурсивный poll отвергается. Удаление/clear не оставляют событий.

Отдельный `occupied[512]` занимает один bit на клетку. Только combat меняет
эти bits: после шага снаряд занимает клетку, если static MMap содержит
пробел и другой снаряд её ещё не занял. Spawn не стирает glyph владельца.
Движение и cleanup снимают только собственный bit. Динамический номер glyph
не записывается поверх static map, actor occupancy, TMap, FCMap или visited.
Collision получает borrowed overlay callback и context для одного активного
production world; четыре footprint corners проверяются за O(1). При
инициализации следующего уровня context устанавливается заново. Этот интерфейс
требует снять callback через `dok_collision_overlay(0,0,0)` перед уничтожением
borrowed world/combat context; нельзя оставлять ссылку на вышедший из scope
stack-local объект. Production context статический, host test снимает его явно.
Такая форма представления отличается от native byte map, а проверенные игровые эффекты
занятости сохранены. Runtime/Object/player ABI не растут.

За пределами корректного мира compact снаряд завершается MIMO вместо
неограниченного полёта через native edge-clamp. Это осознанная защитная
политика для повреждённых/диагностических позиций; на исходных закрытых
границах уровней контакт со стеной наступает раньше. Шаблоны, баланс и
таблицы оригинальных карт не меняются.

## Оружие, рендер и GBA

Готовность разрешена в состояниях 7 и 3, выстрел ставит 2. Анимационный
callback увеличивает кадр, на последнем кадре получает 6; следующий проход
возвращает к 3 и кадру 0, затем к 7. Native state 3 уже разрешает выстрел.
Число кадров/интервалы читаются из исходных анимаций, а не из произвольного
cooldown. Скрывание: state 0, shifts 1→2→3, state 4; переключение selected
на pending, появление state 1, shifts 2→1→0, state 5; затем state 7.
Подбор первого оружия выбирает его сразу, как определено G12.

GBA A стреляет. Одновременное новое нажатие L+R циклически запрашивает
следующий имеющийся slot; hide/show идёт в simulation time. Select по-прежнему
переключает язык, Start выполняет Use. `gba_combat_poll` вызывается из общего
416-tick movement catch-up; gameplay clock не привязан к частоте draw.

Рендер располагает 256 positioned sprite instances. Для каждого кадра
выделяется собственный texture index 256…511 с ROM resource/frame, поэтому
два экземпляра одного шаблона сохраняют разные flight/impact images до
растеризации faces. Существующие static image slots 0…255 и геометрические
offsets до sprites сохранены. Игровой код не меняет shared template frame.
Палитра/маска/occlusion остаются общими с G11. Оружие выводится отдельным
overlay перед HUD, со сдвигом скрывания/появления. Это GBA-представление
с исходными кадрами, не утверждение пиксельного совпадения DOS weapon HUD.

## Интерфейс для G14/G15/G16/G17/G18

`dok_combat_spawn(owner_object, template_glyph)` доступен для AI; параметры
enemy projectile 3/4 остаются из исходных LEVEL. `dok_combat_damage` применяет
signed word arithmetic и ограничения здоровья, уведомляет DAMAGE/DEATH.
Sleeping monster state 0 даёт WAKE без вычитания health, как `1068:37CF`.
Это событие требует consumer G14/G15; сам combat не запускает обнаружение,
hurt/attack/death AI animations, не освобождает врага по visual completion.
Активный монстр получает `max(0, SUB16(health, damage))`. G15 обязан
добавить hurt state 3 и собственные AI deadlines по DAMAGE, wake state по
WAKE, gameplay cleanup по DEATH/RECLAIM. G18 обрабатывает смерть героя.
SHOT/IMPACT/MISS/EMPTY/WEAPON готовы для звука и HUD; G13 не воспроизводит
звук. События несут явные object IDs, slot IDs и значения.

## Воспроизведение и проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/gba/scripts/build-gba-combat.ps1 -CrossChecks -OriginalEvidence
```

Host проверяет оба оружия, empty/low charge, allocation refusal без расхода,
hide/show, full/reuse, wake/damage/death, lifecycle cleanup, native ring order,
mutable-count skip, callback-time creation и occupancy release.
`verify_combat_original.py` выполняет исходные x86 readiness, slot scan,
position-copy, ADD/SAR и monster SUB/clamp; destructor boundary перехватывается.
Spawn копирование проверяется до scheduler closure builder `1068:26B4`;
полный ctor с этим скрытым stack ABI не объявляется выполненным.
Sleeping wake ветка проверена листингом, не исполнена в этом x86 probe.

ARM-сценарии, final ROM/hash, фактическая память и ограничения фиксируются
в `analysis/gba/g13-combat-gba.json` и `analysis/gba/g13-review.json`. Полная
DOS-сессия и физическая GBA не проверены. Цель 30 FPS остаётся G20.


## Подключение G15

G15 реализует прежние AI seams: [ai-combat.md](ai-combat.md). DAMAGE переводит
живого врага в state3; health<=0 запускает последовательную death animation
и persistent corpse cleanup. Контактная атака наносит герою5 HP после полного
attack cycle; снаряды используют `dok_combat_spawn` и native glyph3/4.
Corpse не получает bit0x400 и не освобождает свой glyph slot.
