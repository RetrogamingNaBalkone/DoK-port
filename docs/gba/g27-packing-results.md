# G27: точная упаковка foreground и ранний admission

## Решение для релиза

2 ноября 2026: **G27 готова; native renderer H11 не открывать для текущего
релиза**. Проверены конкретные альтернативы старым shear-фрагментам: исходные
колонки без изменения выборки и точный atlas из полос 8→9 строк, с dedup и
слиянием уже видимых слоёв. Ни один вариант не обеспечивает и вместимость
тяжёлых сцен, и перенос sampling с CPU на PPU. Ранний фильтр стоит35–1002
ARM-инструкции, но не дал успешного GPU raster. Production остаётся G22.
Следующий ID — **G25**.

Результат **не переоткрывает ранее отклонённые гипотезы**: конкретные основания
по каждой приведены ниже. Это не заявление о глобальном пределе GBA.

## Образец, происхождение и выборка

Свежая сборка `g22_split_active` и повторная сборка после диагностических
правок совпали с `artifacts/gba/DoK-port_G22.gba`:
SHA-256 `53fdf1b1b868effecfd68c8feb87ffb60bcc72190a4d01f38d8684a781860247`.
Общие Zig 0.13.0, Python 3.14, mGBA libretro с replacement BIOS; core и ELF
закреплены в manifest. Адреса относятся к GBA RAM/ROM, не DOS EXE/NE/Ghidra.
Оригинальные EXE не анализировались и не изменялись.

Старый `research/experiments/g20a-sector-shear-final-v4/` содержит исходники,
`prototype-build.json` и `build-report.json`, но ROM удалена прежней очисткой.
Build report указывает старый SHA `484099f8…deaae` и основу 2775. Эти данные
не выданы за проверенную сегодня ROM или за G22 captures. Поэтому снята
новая серия, а происхождение старого отчёта записано отдельно.

**54 captures**: шесть тяжёлых поз G22 + PERF01–03 на обоих языках (18),
затем по шесть близких ракурсов на каждом уровне/языке (36). Близкие ракурсы:
80/160/320 world units от первого class9 актора, два направления. Это
синтетические stress-позиции камеры; collision-valid маршрут не заявлен.
Миры заморожены, камера и данные обеих локализаций заданы явно.

Production `dok_renderer_draw` повторно выполняется в Unicorn с реальной RAM
mGBA. Hooks снимают параметры source/v/step и цвета до изменения coverage.
`raster_rect` — вложенный fast path `raster`, не вторая грань; после проверки
драйвера его двойной учёт исключён и вся серия выполнена заново.
Coverage и 44 B stats совпали во всех replay. **743658** записей вертикальных
граней дополнительно совпали с готовым production foreground. Потолочные
spans в это число не входят.

Для sector-fed варианта class2 стены и низкий потолок остаются на CPU;
проверяются все остальные реально отрисованные грани, включая предметы,
акторов, двери и иные классы. Исходная coverage даёт кандидату даже больше
помощи, чем прежние sector histories: все скрытые пиксели уже удалены точно.
Это осознанная оптимистическая граница, а не бесплатный runtime prepass.

## Проверенные способы упаковки

**1. Колонки исходной текстуры.** Для каждой непустой колонки в каждой
девятистрочной физической полосе записана точная последовательность source V,
которую G22 показывает через свою проверенную функцию `scene_source_y`.
Проверена возможность представить её одним положительным 8.8 PD с произвольной
фазой, сохранив каждую исходную выборку. Проверка даже разрешает фазу, которая
не обязательно получается целочисленным OAM origin: отказ окончателен для
этой полосы, успех ещё не означает полноценного GPU packet.

Из **84316** непустых band-column случаев **17902** не имеют такого affine fit.
Ещё **58** случаев имеют конфликт source mask: один source texel должен быть
одновременно показан и скрыт в разных destination rows после coverage.
Отбрасывать эти пиксели ради fit запрещено. Разбиение на более мелкие куски
увеличивает команды; замена строки заранее выбранными цветами приводит к
следующему варианту и сохраняет работу CPU sampler.

**2. Точный per-face band atlas.** Уже выбранные цвета укладываются в legal
8×8, 16×8, 32×8 OBJ textures; соседние непустые tiles одной грани объединяются.
PA=128, PD=227, doubled canvas, исходная карта 8 logical→9 physical rows.
Матрица одна; padding прозрачен; одинаковые payload/размеры делят atlas.
Проверены полное восстановление каждого слоя и все 240×144 физических
пикселей после affine mapping. Потерь силуэтов, скрытых пикселей и перестановки
видимых цветов нет. CPU sampling/coverage для построения такого atlas уже
выполнены — этот вариант сам по себе их не ускоряет.

**3. Merged oracle.** Слои дополнительно объединяются по уже вычисленной
окончательной видимости, затем применяются те же tiles/dedup. Это более
сильное уплотнение, но оно требует готового результата CPU raster; перекрытия
не восстановлены бесплатно из одной камеры или bbox. Используется для
проверки, достаточно ли вообще одного сокращения числа fragments.

Лимиты взяты из существующего sector GPU backend: **64 scene OAM**, **16 KiB
atlas**, **32 matrices**, модель **1210 OBJ cycles/строку**. Scan model резервирует
поиск 64 UI slots, 136 верхних и 48 нижних UI pixels. Оружие не добавлено:
это оптимистическая оценка вместимости. Альфа не уменьшает стоимость пустой
части canvas. Для уже превысивших 128 total OAM модель scan не описывает
реальный список PPU; одного OAM-отказа достаточно.

RU и EN frozen результаты совпали; таблица — один язык. Scan — модельный
расход на пиковую строку, не wall-clock CPU и не измерение FPS.

| L1/3640 | 50 | 1300 | 29 | 850 |
| L1/2242 | 0 | 264 | 0 | 264 |
| L2/1592 | 172 | 3056 | 63 | 1390 |

Per-face проходит **2/54**, обе позы пустые для GPU (L1/2242). Все **52 непустые**
сцены отвергнуты. Atlas достигает **27008 B** при бюджете16384 B; матрицы уже
сведены к одной и причиной отказа не являются. Близкие views требуют64–92 OBJ,
но даже64 переполняют scan budget из-за перекрывающихся doubled canvases.

Merged проходит **8/54**, из них только6 непустых — L1/520, L1/3640 и L2/2871
на обоих языках. Все близкие views, PERF01–03 и остальные тяжёлые виды не
проходят. Даже этот вариант с готовыми CPU pixels не даёт универсального
тяжёлого GPU пути. Из успешных isolated packets не выводится общий выигрыш.

Шесть непустых merged packets дополнительно загружены в реальную PPU mGBA:
**230400 pixels exact**, включая прозрачный фон и границы полос. Диагностическая
ROM `g27_packet_oracle`, SHA `ab732d93aac056819bd6e4b7fa5e890204c2fab67dc1f4dbb2480daa8b78515b`,
выполняет CPU MMIO writes, отключает IRQ/DMA и показывает только injected OBJ.
Она проверяет atlas/affine/alpha oracle, **не** рабочий renderer, UI-композицию,
переходы или скорость игры. Первый host-only MMIO harness был заменён:
прямая запись libretro memory не обновляла внутренний register cache PPU.
Неудачный harness не интерпретировался как потеря pixels кандидатом.

## Ранний admission и цена fallback

`g27_admission.c` проходит уже спроецированные face bounds, исключает class2,
оценивает число горизонтальных групп по четыре tiles и вертикальных полос,
останавливается после превышения64. Никаких alpha/texture reads и заполнения
atlas до этого gate нет. Это дешёвый фильтр конкретной схемы, не доказательство
scanline fit и не универсальный optimal packer.

Функция собрана для ARM7TDMI: **288 B**, **35–1002 исполненных ARM-инструкции**
на54 captures в Unicorn. Это не cycles: waitstates, IRQ и DMA не моделируются.
Стековый резерв production не меняется; функция в production не включена.
Стоимость исходной проекции остаётся prerequisite, а не исчезает.

Итог относительно точного per-face packer: **2 false accept, 0 false reject**.
50 сцен отвергнуты рано; из4 принятых две пустые, две — L1/3640 RU/EN —
поздно отвергаются по scan1300>1210. В каждом таком late reject выполнены
**3282 open sample reads**, **2924 visible samples** и подготовлен atlas
**6848 B** с50 commands, после чего нужен обычный CPU путь. Эти операции
не скрыты в среднем и не переведены в выдуманные native cycles. Это объём
подготовки, не заявленная добавка к G22: сохранённый CPU raster можно использовать
при fallback, но тогда sampling уже выполнен на CPU и не ускорен GPU. При early
reject дополнительных texture/atlas операций0; остаются инструкции gate.

Более строгий фильтр мог бы просто отвергать и эти два вида, но успешного
непустого per-face GPU raster от этого не появляется. Поэтому его доводка
не открывает native-прототип и не считается оптимизацией текущего G22.

## Проверка ранее отклонённых гипотез

| Гипотеза/вариант | Измеренная причина прежнего отказа | Что установила G27 | Решение |
|---|---|---|---|
| H04 / G23, тёмная даль | 0,499% warm и0% live PERF; mask не отменяет coverage/alpha | Доля дальней работы не выросла; packing не устраняет эти операции | Не переоткрывать; снята с текущего релиза |
| H08 / G24, span cache | 656 B cache даёт мало полезных samples, dispatch дороже экономии | Atlas строится каждый кадр из уже sampled colors; нет нового persistent места или reuse | Не переоткрывать оба проверенных кеша |
| H10 / G26, аппаратный потолок | Постоянный transport и меньший geometry cache; dirty UI не покрывает проигрыш | Нет вместимого тяжёлого GPU layout, убирающего transport; успешный oracle предварительно растеризован CPU | Не переоткрывать backend |
| Sector clip/bitmap | Дороги BSP/static/CPU planes и динамический проход | G27 не удешевляет BSP или плоскости; точный atlas сохраняет sampling | Не переоткрывать |
| Sector GPU/shear | OAM/scan/atlas overflow, дорогое приготовление до fallback, потеря alpha | Ранний gate ограничивает цену части отказов; непустой per-face путь всё ещё не помещается, exact source mapping не доказан | Не переоткрывать: быстрый отказ не является быстрым GPU raster |
| H02/H03/H06 | Проверенные diagnostic/UV/sparse kernels не окупились | Нет нового удаления счётчиков, UV или sparse kernel и парного выигрыша | Не переоткрывать |
| H05/H09 | Не отклонены: G25 должна проверить качество96 строк/LOD | G27 не даёт новой приёмки качества и не меняет их scope | Следующая задача G25 |

Контрольная сборка: host/UI tests и Linux/Thumb cross-build прошли. Полные
долговременные входы и результаты — `research/evidence/gba-g27/`, включая
сжатый `captures.json.zlib` с manifest/source parameters и точными цветами.
Повторный offline replay не требует нового запуска игры. Сборки и журналы —
`build/gba/g27/`; aggregate — `analysis/gba/g27-packing-20261102.json`, Git
summary — `analysis/summaries/g27-packing-20261102.json`.

Native renderer не реализован и FPS нового renderer не заявлен. Новая полная
release/transition/live регрессия для packet oracle не выполнялась; он не
предлагается в поставку. Физическая GBA/original BIOS/full playthrough не
проверены. Production ROM прежняя; G21/BUG02, NDS/SDL2 и оригиналы не менялись.
Передача — **G25**, с актуальными планом, бэклогом, handoff и её паспортом.
