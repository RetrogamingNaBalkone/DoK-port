# G20: профиль полной игры и оптимизация без усечений

26 октября 2026 года. **Проход оптимизации проверен; цель 30 FPS не достигнута.**
G20 не объявляется полностью готовой. По уточнению пользователя следующий
шаг — G20A: определить допустимые усечения на основании измерений.
В этом проходе качество графики и игровые лимиты не сокращались.

Прежний документ G06A сохранён без потери содержимого в
[историческом профиле](gba-performance-g06a.md); его числа не относятся к G20.

Итоговый реестр — [gba-final-budget.json](../../analysis/gba/gba-final-budget.json).
ROM/ELF/map: `build/gba/g20/dok-diagnostic.{gba,elf,map}`. ROM 32 890 604 байта,
SHA-256 `a56330bf11dc6f3e5906d71b8d2dbb20b2c36a55c9f3e63c8c8eb5baa44c5c94`.
Исходный frozen G18 сохранён отдельно, SHA-256
`46e4bfa412dd1abb6b729d4a9ed014802e99430b1dbc47ffb70d2de077eeb3c0`.

## Граница изменений

Сохраняются 120 независимых колонок сцены, их вывод в 240×144, интерфейс
240×160, все исходные текстуры, освещение, прозрачность, геометрия и дистанции
видимости. Не уменьшались число врагов/снарядов, частота callback или точность
игрового времени. В частности, при перегрузке долг симуляции сохраняется.

Это оптимизация существующего восстановления, а не новый анализ EXE.
Адреса ниже — **GBA memory-mapped addresses**, не NE-сегменты и не DPMI-селекторы.
Оригиналы не менялись: SHA-256 всех 22 файлов совпали до/после pipeline и
с сохранённым реестром очистки перед G20. Новая эквивалентность целой DOS-сессии
не заявляется; прежние Ghidra/native evidence остаются в своих документах.

## Что ускорено и почему это сохраняет результат

- Учёт закрытых пикселей пола/потолка перенесён в IWRAM bitmap:
  120 колонок × 5 words. Интервалы для стен восстанавливаются по требованию;
  поиск начала/конца серии пропускает сразу пустые 32-битные слова.
  Индексы покрытия, порядок примитивов и непрозрачность цвета 0 пола сохранены.
- Обычный горизонтальный span рисует ARM-функция `dok_gba_surface_span`.
  Она сохраняет signed Q16, clamp, исходные texel и LIGHT lookup, удвоение
  пикселя по X и callee-saved registers. Сдвигаемые поверхности сохраняют
  общий путь crop/wrap. Отдельно проверен пустой span после выравнивания X.
- Пересечения рёбер вычисляются только для активных рёбер; U/V — для выбранных
  левого и правого. Замена повторных wrap32 ADD на MUL+ADD алгебраически точна.
  Выбор первого при равных X и включение граничных строк сохранены.
- Общие вершины клеток пола/потолка используют небольшой EWRAM cache на кадр.
  Одинаковые perspective factor и screen X вычисляются один раз. Tag включает
  координаты и epoch; rollover epoch сбрасывает cache. Проверены коллизии
  cache в обзорах и переход через rollover. Горизонтальный bbox отсекается
  только при полном выходе всех четырёх уже вычисленных X за экран.
- Стартовые divmod-векторы убраны из IWRAM в ROM; face order перенесён
  в EWRAM. Резерв стеков не уменьшался. Для принятого режима массивы первого
  интервала/счётчиков хранят только 120 используемых колонок.
- Исправлена ошибка именно порта: отдельный texture index клона снаряда
  больше не индексирует массив LEVEL definitions при проверке door crop.
  Условие ограничено object_count; к исходным ошибкам PKR/PKE это не относится.
- Прямоугольники интерфейса заполняются выровненными 32-битными записями
  с байтовыми краями. FONT8/FONT16 и отдельные пиксели текста не менялись.
- Пять неизменяемых class9 LEVEL-параметров (`+A6`, `+A8`, `+AE`, `+BA`, `+E7`)
  AI читает из типизированных полей, сохраняя signed byte/word truncation.
  Mutable overrides byte-adapter на этих offsets отсутствуют; fallback остаётся.
- Индексы четырёх углов коллизии разделяются между MMap и TMap. Порядок
  проверок и short circuit сохранены. Для GBA-карты 64×64 с клеткой 480
  применяется точная ROM-таблица `(n >> 4) / 30` из 1920 байтов; отрицательные
  и внешние координаты сохраняют clamp либо отказ соответствующего caller.
  Другие размеры используют общий путь деления.
- `pack_animation_index.py` полностью проверяет 24 неизменяемые анимации
  общего пакета и создаёт 1016 байтов ROM-индексов для 157 кадров.
  Исходные bytes, interval, frame order и изображения остаются в G03 package.
  Совпадение pointer **и** size разрешает переиспользовать offline validation;
  произвольные buffers и несовпадающие views проходят обычный проверяющий decoder.
- Диагностический hash геометрии обновляется при новом camera request,
  а не на каждом последующем кадре из-за ненулевого номера старого запроса.
  Snapshot завершённых stage timestamps отделён от следующего строящегося кадра.

Дополнительная bitmap строк была измерена и отвергнута: её синхронизация
замедляла кадр. Переключение всех cold-функций в Thumb тоже не оставлено:
оно увеличивало потребность в IWRAM. История измеренных проб собрана в
`analysis/gba/g20-experiments.json`; это история экспериментов, не финальные ROM.

## Методика CPU

mGBA libretro `0.11-212-7a12d6d`, SHA-256 core
`5cac11c643d7f8dfa50c68855f2f2240ff7cc0b4cd0312dd9e17a639c85667e4`,
replacement BIOS. Zig 0.13.0 из общей установки. WAITCNT остаётся штатным
`0x4317`; overclock EWRAM не используется.

Timer2/3 по `0x04000108/10C` измеряет CPU с квантованием 64 cycles.
Бюджет двух VBlank — **561 792 cycles**. Таймер включает input/time/motion,
AI/visual/combat, renderer, weapon/UI/flow draw и копирование полной страницы
DMA3. Ожидание показа и публикация диагностики находятся вне этого таймера.
Измеренная частота показа дополнительно включает их стоимость.

`verify_performance_gba.py` сравнивает G18 и G20: 488 полных индексных кадров,
три мира × два языка, повороты через 5°, близкие границы клеток, углы карты,
четыре направления воды × фазы 0/1/9/17. **Все 38 400 байтов каждого кадра,
включая HUD, совпали.** Capture hold добавляет VBlank за пределами CPU timer;
его интервалы нельзя выдавать за обычный FPS. Скорость по медианам всей
этой выборки выросла в **1,80 раза**.

## Полная игра, снаряды и PCM

`profile_game_gba.py` выключает capture hold во всех измеряемых интервалах.
Камера фиксируется для повторяемости; D-pad/Fire, часы и callbacks в live-сценах
работают. Сохраняются исходные карты общего release package. По обоим языкам
проверены четыре класса нагрузки на каждом уровне:

1. Стартовый renderer с циклическим PCM 22 050 Гц, замороженная simulation.
2. Обычная живая simulation в стартовой позиции, без принудительного wake;
   30 последовательных выводов с поворотом/Fire. Состояние и HP исходные.
3. Искусственное заполнение всех native free projectile slots (141/139/98),
   замороженная simulation, renderer и реальный PCM продолжаются.
4. Все размещённые враги принудительно разбужены, полная очередь снарядов,
   затем живые AI/motion/combat/visual и PCM. HP=32767 — test fixture для
   исключения Game Over, не изменение release balance. Шесть выводов на мир.

Таблица — русский presentation; английский проверен отдельно в JSON.
Динамические сцены G18/G20 проживают разное wall time за одинаковое число
выводов и потому не считаются сравнением одного и того же динамического состояния.
Для замороженных кадров есть отдельная точная попиксельная проверка.

В обычных сценах долг остаётся меньше 416 ticks: логика сохраняет свою
частоту при 5–7 FPS. В all-awake stress появляются большие долги; лимит
128 fixed steps за проход не позволяет немедленно их погасить. Долг не
отбрасывается. Нельзя заявлять сохранение реальной скорости игры при такой
нагрузке или скрывать проблему средним FPS. Отдельная регрессия времени
подтверждает rational clock, rollover, reset и точные debt vectors.

При 57–100 принудительно активных владельцах основная стоимость — уже
логика, а не изображение. Максимальная измеренная sight-проба — 76 итераций,
упора в защитный предел 5000 не было. Ускорение одного рендера не решает этот
stress. Это искусственная нагрузка, не заявление о типичной DOS-сессии.

## Память и отсутствие переполнений

| Область | Использовано | Остаток / предел |
|---|---:|---:|
| EWRAM, статически | 253 376 B | 8 768 B до 256 KiB |
| IWRAM code/data | 24 268 B | 308 B до отдельного резерва стеков |
| System stack, high water | 2 368 B | 5 568 B watermark margin |
| IRQ stack, high water | 80 B | 80 B margin, включая BIOS saves |
| Stack + BIOS reserve | 8 192 B | не уменьшался |
| VRAM, две страницы Mode4 | 76 800 B | 21 504 B не занято payload |
| Верхняя граница страниц VRAM | offset 79 360 | до 98 304 B |
| BG palette | 512 B | OBJ palette/OBJ VRAM не выделены |
| ROM | 32 890 604 B | 663 828 B до 32 MiB |
| Heap | 0 B | динамического выделения нет |

Linker сохраняет границы EWRAM/IWRAM/ROM. Watermarks и frame guards проверены
на camera sweep, игровых нагрузках, reset, UI/flow, AI и audio. Переполнений
в проверенных сценариях нет; **это не доказательство для любых будущих сцен**.
Audio underruns — **0**, в том числе в долгих all-awake кадрах и всех 23 PCM.
Физическая GBA и оригинальный BIOS не проверены.

## Проверки и воспроизведение

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ports/gba/scripts/build-gba-performance.ps1 -CrossChecks
# Только повторная проверка неизменённых готовых артефактов:
powershell -NoProfile -ExecutionPolicy Bypass -File ports/gba/scripts/build-gba-performance.ps1 -RegressionOnly
```

Pipeline использует общие Zig, Python, mGBA и существующий Unicorn из
`C:/Source/wasdify/build/research-deps`; копии toolchain не создаются.
Для парного pixel oracle нужен сохранённый frozen `build/gba/g18/` с указанным SHA;
пересборка G18 из текущих исходников этим эталоном не становится.
Остальные проверки можно запускать отдельными скриптами из driver.

Выполнены Windows host suite, UI/flow, Linux static/Thumb compile checks,
4096 ARM sampler vectors, 2048 bitmap-edge vectors, 30 720 значений точной
cell table, 48 исходных RU/EN animation resources / 308 кадров через ARM/Thumb
decoder, проверки callee-saved registers/stack и отказа truncated RAM buffer.
Unicorn не измеряет аппаратное время: CPU/IRQ/DMA измерены отдельно в mGBA.

На финальном ROM прошли flow всех 6 миров и 14 text resources, UI/FONT8/FONT16,
renderer, sprite playback/вода, interactions, time, 28 AI combat cases и все
23 звука с actual PCM capture/correlation. Прежнее пользовательское listening
G16 остаётся прежним; нового прослушивания G20 пользователем не было.
Root просмотрел renderer RU, CP866 BINTRO и projectile capture; их SHA
записаны в `analysis/gba/g20-visual-review.json`. Основное доказательство отсутствия
усечений — точный paired oracle и проверки source pixels, а не эти три PNG.

## Остаток и G20A

Даже лучший непустой стартовый обзор превышает бюджет в 2,45 раза;
обычные полные кадры — примерно в 4–5,6 раза. G20 остаётся открытой по
производительности. Это не математическое доказательство невозможности
другого алгоритма без усечений и не утверждение, что исчерпаны все возможные
архитектурные переписывания.

[G20A](tasks/G20A.md) должен сопоставить стоимость дальнейших изменений,
потери на настоящем разрешении и реальный выигрыш полной игры, затем определить
приемлемые усечения. Сокращения изображения не должны скрывать стоимость AI,
а dropping ticks, лимиты врагов или смена правил не считаются графической
оптимизацией. В G20A пока не внесено ни одного изменения качества.
