# Проверка первого GBA renderer — G05

Проверка исполняет настоящий ARM/Thumb ROM в общем mGBA Libretro через
`ports/gba/scripts/verify_renderer_gba.py`. Python frontend подаёт Select и читает
экспортированную память эмулятора; renderer исполняется внутри GBA CPU.
Финальные измерения сохраняются в `analysis/gba/render-benchmark.json` и
`build/gba/gba-renderer/renderer-run-log.json`. Финальный прогон прошёл 25 октября 2026
на mGBA0.11-212-7a12d6d, replacement BIOS. Проверки корректности прошли;
цель 30FPS **не достигнута**.

## Что проверяется

- Начальная камера общего LEVEL1: `(15120,-300,22800)`, heading90. Это базовая
  RU-карта общего профиля, а не отдельная начальная EN-позиция DOS.
- Статичное поле 240×144 и нижняя область сообщений 240×16 в Mode4.
  Кадры RU → EN → RU снимаются из действительно видимой VRAM-страницы.
  `DISPCNT` сверяется с диагностическим номером страницы.
- Все 33864 байта mutable мира до/после переключения языка совпадают.
  В диагностической phase2, после завершения renderer, читаются все
  `face_count×48` байт face records. Проверяются их побайтное равенство,
  SHA256 и совпадение независимо пересчитанной FNV1a signature с подписью ROM.
  Это проверка согласованности GBA renderer между языками,
  не независимое доказательство эквивалентности DOS-рендера.
- Сравниваются непосредственно 34560 индексов сцены над сообщением;
  локализованное сообщение обязано измениться, возврат RU восстанавливает
  весь 38400-байтный видимый кадр. UI в углах входит в сравниваемое поле.
- Guard words `0xD04FCAFE` непосредственно до/после framebuffer сохраняются.
  После emulator reset выделенная EWRAM заполняется 0xA5; startup обязан
  восстановить `.data`, `.bss`, исходный мир и русский язык.
- Main System stack имеет watermark `0x0D15EA5E` в адресах GBA
  `03006000..03007EFF`. Нижняя непрерывная нетронутая часть даёт измеренный
  запас, верхняя изменённая — high-water. Проверяется запас не менее 512 байт.
  IRQ/BIOS выше 03007F00 исключены. Это измерение выполненных путей,
  не граница будущей полной игры.

## Время кадра

В ROM аппаратные Timer0/1 каскадом считают CPU cycles: renderer, компактный
HUD и копирование 38400 байт в скрытую VRAM-страницу половинными словами.
Ожидание показа, загрузка языкового view и разовая диагностическая подпись
геометрии находятся вне таймера. Разовая подпись может влиять на интервал
показа при старте/переключении; для steady-state cadence исключаются первые
восемь completed draws каждого такого участка.

Бюджет — два аппаратных кадра, `2×280896=561792` cycles. При частоте
16777216Hz это около 29.86 обновления/с. Счётчики min/max/over-budget относятся
к действительно исполненным таймерным участкам; интервалы показа считаются
по VBlank номерам только между соседними наблюдёнными draw IDs. Host wall
time не используется как FPS GBA. Превышение бюджета фиксируется результатом,
а не скрывается или превращается в заявление о достигнутых 30FPS.

## Воспроизведение

```powershell
C:/Source/wasdify/.venv/Scripts/python.exe ports/gba/scripts/verify_renderer_gba.py --build-dir build/gba/gba-renderer
```

До запуска нужны финальные `dok-diagnostic.gba`, `.elf`, `.map` и
`build-report.json` от RendererProbe. SHA ROM сверяется с build report;
адреса диагностики получаются из ELF, а не из жёстко заданных EWRAM offsets.
Скриншоты 240×160, исходные индексы `.idx` и RGB555 palette `.pal` остаются
в ignored build. Оригинальные EXE и DOS в этой проверке не запускаются.

## Границы результата

G05 — статичная сцена с минимальным подмножеством геометрии. Измерение
не включает AI, движение, звук, полную локализацию интерфейса и полную игру.
Сопоставление с G04 формулами/эталонами и native renderer проверками ведётся
отдельно. Физическая GBA и оригинальный BIOS этим headless запуском
не проверяются.
