# G05: Первый GBA-рендер настоящего уровня

## Контекст нового чата

Рабочий корень: `C:\Source\DoK-port`. Сначала прочитать `AGENTS.md`,
`docs/gba/plan.md`, `docs/gba/handoff.md`. Главная цель — GBA; SDL2 не является
зависимостью. Этот паспорт не предполагает доступности предыдущей переписки.

**Зависимости:** G01, G02, G03, G04. Проверить их фактические результаты в плане и файлах.
Выполнять только границы этой задачи; соседние задачи — отдельные чаты.

## Анализ

Выбрать и измерить графический режим, разрешение вычисления и формат кадра. Mode 4 рассматривать как кандидата; проверить ширину VRAM-записей и синхронизацию. Определить минимальное подмножество исходной геометрии для статичного вида, оставшиеся ограничения записать.

## Реализация

Показать стены настоящего LEVEL1 из начальной камеры героя, с понятным диагностическим заполнением пока не реализованных поверхностей/объектов. Использовать единый ROM и общий профиль/карты G03; языковой переключатель ru/en не меняет геометрию. Подключить измерение стоимости кадра, сравнение с целью 30 FPS и показ потребления памяти.

## Критерии готовности

На GBA-эмуляторе есть узнаваемый статичный вид настоящего уровня, не только тестовая карта. Положение камеры согласуется с world-отчётом принятой базовой карты. Есть скриншот, map и измерение времени относительно цели 30 FPS; сама цель не выдаётся за измеренный результат. Ограничения первого рендера перечислены.

Проверки выбирать по реальным рискам задачи. Сравнение C/Python полезно, но само
по себе не доказывает совпадение с работающей DOS-игрой. Если тест или запуск
не выполнен, указать это явно и не отмечать соответствующий критерий готовым.

## Результат

Готово 25 октября 2026 года. `docs/gba/gba-renderer.md` и тематические
`gba-renderer-{geometry,assets,verification}.md` описывают реализацию,
доказательства и ограничения. `ports/gba/include/dok/renderer.h`, `ports/gba/src/renderer.c`,
`ports/gba/tools/render_tool.c`, `ports/gba/platform/renderer_probe.c` показывают реальный LEVEL1
из общего G03-пакета с проекцией G04; heap и парсинга LEVEL на ARM нет.

Экран240×144 + сообщения240×16; HP/energy числами поверх углов поля.
Select меняет RU/EN без изменения мира. ROM
`build/gba/gba-renderer/dok-diagnostic.gba` —2782924 байта,
SHA `d41d04f79a380dd3fae8b9f9691a8acd1344634b597b5c5c572dce554db53177`.
PNG, ELF, map и raw captures находятся рядом.

`ports/gba/scripts/build-gba-renderer.ps1 -CrossChecks` прошёл целиком:9 native тестов,
Linux/Thumb compilation, runtime/packing oracle, реальное исполнение ROM
в mGBA и точное сравнение трёх кадров с host oracle. Проверены33864 байта
неизменного мира,1344 байта faces,34560 scene indices,38400 индексов с HUD
и512 байт palette RAM; guards, capacity failure и poisoned-RAM reset прошли.
Сохранены `analysis/gba/render-benchmark.json` и `analysis/gba/render-host-verification.json`.

Статический EWRAM89776 байт, workspace54284. Main stack high-water2400,
нетронутый запас5536 байт; IRQ/BIOS исключены из watermark. ROM при повторной
полной сборке совпал побайтно. Физическая GBA/CMake/оригинальный BIOS не проверялись.

**30 FPS не достигнуты:**10175200…10187755 cycles против бюджета561792,
около1,637 FPS, превышение18,13 раза. G05 требует измерить стоимость первого
кадра, а не объявить целевую частоту достигнутой; этот критерий выполнен.
Пол/потолок пока диагностические, LIGHT row0, ограниченный cardinal90 profile,
Q7-U аппроксимация для разных глубин; billboard/анимации/полный HUD ещё впереди.

Текущая задача закрыта по последнему поручению пользователя. Следующий ID —
G06; он в этом продолжении не начинался.
