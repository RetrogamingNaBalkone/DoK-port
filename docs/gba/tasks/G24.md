# G24: размещение и композиция частичного raster cache — H08

**Статус: готова к началу.** Очередь после G23; результат G23 не является
технической зависимостью. Создана по запросу пользователя после G22.

## Входы

Прочитать `AGENTS.md`, GBA `plan.md`, `gba-backlog.md`, `handoff.md`,
`performance-audit-20261101.md`, `g22-hypothesis-results.md`.
Текущая база `g22_split_active`, SHA-256
`53fdf1b1b868effecfd68c8feb87ffb60bcc72190a4d01f38d8684a781860247`.
Собрать `ports/gba/scripts/build_gba_frontend.py --out build/gba/g24/control
--variant g22_split_active` общим toolchain из `docs/building.md`.
Код: `ports/gba/src/renderer_static_cache.inc`, hardware transport в
`ports/gba/platform/`. Проверки: `verify_gba_static_cache.py`,
`benchmark_battles_gba.py`, `check_g22.py`.

Geometry cache уже существует и не кеширует пиксели. EWRAM занято 261476 B,
свободно 668 B; IWRAM свободно 1664 B при отдельном резерве 8192 B.
Новый полный framebuffer в этот бюджет не помещается.

## Работа

1. Снять стабильность потенциальных raster-слоёв в стоячих боях PERF01–03,
   при движении, дверях, разрушении и воде. Не считать камеру достаточным ключом.
2. Предложить ограниченный tile/span/слой cache либо обосновать отказ:
   точные размеры, lifetime/aliasing существующей памяти, invalidation,
   восстановление coverage/depth относительно акторов и UI.
3. Доказать, что схема сохраняет leases и не использует рабочий буфер одновременно
   в несовместимых фазах. Не уменьшать стековый резерв и не вытеснять данные
   без проверки Mode4/menu/fallback.
4. Если схема помещается, провести ограниченный прототип и paired A/B.
   В противном случае сохранить отрицательный memory/composition результат.

## Готовность и передача

Есть проверяемая схема размещения и invalidation или доказанный отказ от
конкретной схемы. Прототип при наличии проходит PPU/coverage/leases,
map/door/water mutations и игровой trace, CPU/p95/presented FPS по G22.
Не объявлять cache принятым по одной стоячей сцене; при выборе в поставку
выполнить полный G20D/G21 regression и отдельно отметить аппаратную проверку.
Обновить паспорт, бэклог, аудит и GBA-handoff. Следующий ID — G25.
Выходы: `build/gba/g24/`, `research/evidence/gba-g24/`, отчёт в `docs/gba/`,
сводка по report policy. Оригиналы, G21/BUG02, NDS/SDL2 не менять по факту работы.
