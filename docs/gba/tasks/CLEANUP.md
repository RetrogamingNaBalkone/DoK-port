## Дополнение: 3 ноября 2026 года

По запросу пользователя выполнена повторная очистка всего репозитория и
исправлены источники накопления GBA-выходов. Правила и восстановление старых
данных: [обслуживание хранилища](../../storage-maintenance.md).
Точные объёмы и проверки: [итоговый отчёт](../../../analysis/storage-cleanup-20261103.json).

Проверенные причины: постоянный кэш Zig внутри проекта, банки `.bin`, которые
не учитывала очистка объектов прототипа, и оставляемая frontend-сборщиком
временная базовая ROM/ELF/объекты. Исправлены владение кэшем между процессами,
регистрация банков до записи, очистка через `finally` и явное сохранение базы
в G20D/G22 там, где она повторно используется. Флаги отладки описаны по ссылке.

Новая реальная сборка `g22_split_active` побайтно совпала с опубликованной
Beta2, SHA-256 `53fdf1b1b868effecfd68c8feb87ffb60bcc72190a4d01f38d8684a781860247`.
После неё собственные временные базовые ROM/ELF/объекты, банки и сессия кэша
отсутствуют. 22 оригинальных файла и 4926 архивных файлов проверены по SHA-256.
Холодный `zig objcopy` дважды не смог запустить дочерний процесс в sandbox;
контрольная сборка успешно завершена вне этого ограничения. Полная игровая
и аппаратная регрессия не повторялась: игровой ROM совпал побайтно.

`artifacts/` полностью исключён из Git, уже отслеживаемые файлы удалены только
из индекса. Исследовательские наблюдения сохраняются в проверенных ZIP;
устаревшие выходы компилятора удалены. Перед старой машинной проверкой следует
восстановить нужные полные отчёты по инструкции обслуживания.

Игровые статусы других направлений не менялись. Выбранная GBA-версия остаётся
Beta2; следующий игровой ID — G21.

## Изменения скриптов

- `prototype_gba_bsp.py` и `research_gba_fps.py` удаляют собственные объектные
  выходы через `finally`, в том числе после ошибки компилятора. Учитываются
  только пути `.o`, переданные компилятору в текущем вызове. Базовый каталог
  не может совпадать или пересекаться с выходным каталогом. Для ручной
  перелинковки или использования результата как новой базы есть `--keep-objects`.
- `verify_packing.py` создаёт повреждённые и повторные пакеты в уникальных
  временных каталогах и удаляет их при успехе и исключении. Итоговый JSON
  сохраняет команды, размеры и хеши; пути временных пакетов после проверки
  больше не существуют.
- Общий код — `scripts/experiment_cleanup.py`. Каталоги наследуют права
  родителя: стандартный `TemporaryDirectory` Python 3.14 с режимом `0700`
  оказался недоступен в текущей Windows sandbox. Это проверенное ограничение
  данной среды, не утверждение обо всех установках Python.
- `scripts/clean-experiments.ps1` повторяет описанную ограниченную очистку.
  Без аргументов выводит оценку, с `-Apply` удаляет файлы и пишет новый
  датированный отчёт. Проверяет абсолютные пути и запрещает reparse points.
  Запускать после завершения сборок, которые используют кэш и объекты.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/clean-experiments.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/clean-experiments.ps1 -Apply
```

## Проверки и результат

- Проверены очистка после успеха и исключения, `--keep-objects`, сохранение
  остальных артефактов и базовых объектов, отказ для пересекающихся каталогов
  и объекта за пределами выходного каталога.
- Проверены временные каталоги после успеха и исключения; Python syntax check.
- Выполнена реальная сборка `source_control` новым сборщиком. ROM побайтно
  совпал с `build/gba/select-menu-fix/dok-diagnostic.gba`; ROM/ELF/map/отчёт
  остались, объектные выходы удалились. Проверочное дерево затем удалено.
- Реальный `build/gba/host/dok-rom-assets.exe` отклонил 23 повреждения текущего
  `assets.bin`; временные пакеты удалились. Ошибочная ветка проверена отдельно.
- SHA-256 429 файлов до/после очистки совпали: все файлы оригиналов и
  `artifacts/gba`, а также сохранённые файлы выбранных контрольных деревьев.

Полная игровая регрессия не запускалась: код игры, рендера и форматов не менялся.
Анализ исходных EXE не выполнялся, адресная система здесь не применяется.
