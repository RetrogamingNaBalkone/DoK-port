# G27: offline GPU packing/admission тяжёлых сцен — H11

**Статус: готова к началу.** Плановая очередь после G26, без зависимости
от успеха аппаратного потолка. Создана по запросу пользователя после G22.

## Входы

Прочитать `AGENTS.md`, GBA `plan.md`, `gba-backlog.md`, `handoff.md`,
`performance-audit-20261101.md`, `g22-hypothesis-results.md`,
`gba-sector-clip-trial.md`, `gba-sector-shear-trial.md`.
База на момент постановки — `g22_split_active`, SHA-256
`53fdf1b1b868effecfd68c8feb87ffb60bcc72190a4d01f38d8684a781860247`;
сверить актуальный handoff перед созданием captures.
Исследовать `ports/gba/scripts/gba_sector_gpu_assets.py`,
`verify_gba_sector_gpu.py`, `ports/gba/platform/sector_gpu.S` и
`hardware_sector_gpu.inc`, сохранённые `research/experiments/` по старым отчётам.
Общий toolchain — `docs/building.md`; GBA-код не переносить в NDS/SDL2.

## Работа и границы

1. Найти сохранённые тяжёлые views и проверить SHA/defines/происхождение.
   При отсутствии нужных captures снять их воспроизводимо на закреплённой базе.
2. Offline проверить альтернативную упаковку: atlas capacity, OAM, scanline
   limits, affine transforms, точные силуэты/coverage и стоимость подготовки.
   Успех только на пустых/лёгких views не достаточен.
3. Разработать ранний дешёвый admission до дорогой подготовки. Измерить
   false accept/reject и затраты на fallback, не прятать их в среднем.
4. Показать вместимость на тяжёлых сценах всех уровней, RU/EN и крайних
   близких ракурсах. Не терять реальные пиксели ради успешного admission.

## Условие открытия native-прототипа

Есть воспроизводимый replay с доказанной вместимостью, корректными силуэтами
и ограниченной ценой admission/подготовки. Только после этого оформить паспорт
native A/B. Ускорение пустого fallback не считать ускорением GPU raster.
Если вместимость не доказана, сохранить конкретные причины отказа.

## Готовность и передача

Скрипт replay, manifest входов, машиночитаемый отчёт и Markdown-решение
«открыть native / не открывать». Выходы — `build/gba/g27/`, долговременные
входы/доказательства — `research/evidence/gba-g27/`, сводка по report policy.
Обновить паспорт, бэклог, аудит и GBA-handoff. При доказанной жизнеспособности
оформить и проверить ограниченный native-прототип до перехода к G25;
не запускать новый native scope без паспорта. При отрицательном результате
либо после такого прототипа следующий ID — G25. Пользователь выбрал сначала
способы сохранить изображение, затем компромиссы качества.
Глобальный предел скорости не объявлять; аппаратные проверки отдельно.
Оригиналы, G21/BUG02 и другие платформы не изменять по факту этой задачи.
