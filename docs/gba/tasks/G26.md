# G26: модель постоянных затрат аппаратного потолка — H10

**Статус: готово, 1 ноября 2026, модель и эмуляторные transport probes.**
Новый native backend H10 для текущего релиза не открывать. Следующий ID — G27.
[Модель, числа, команды и ограничения](../g26-transport-model.md).

## Зафиксированный результат

- G22 pin воспроизведён до и после изменений. UI-only и fixed BG3 probes
  отделили постоянный transport от sampling, без grid/feedback/auto selection.
- HBlank payload: Mode1 18 B/строку, UI-only 50 B, Mode2 68 B; двойные affine
  frames 5800/11592 B, Mode4 hold 5796 B, geometry payload 28637→17041 B.
- 18 warm поз RU/EN на ROM, по30 samples: UI transport +3,678…+5,636% CPU;
  BG3 −26,494…+14,389%, медиана+9,795%. Локальные L1 выигрыши не обобщаются.
- По18 PPU-пар: UI exact; BG3 до1009 изменённых фоновых pixels при exact
  foreground/overlay/coverage/leases. 54 held transport snapshots.
- Конкретная dirty-OAM/weapon схема помещается (до32 B ключа), но даже
  условное бесплатное удаление всей добавки UI/setup и copy оставляет
  28–44 тыс. cycles проигрыша в L3. Она отклонена на стадии модели;
  нового native-паспорта нет, возврат к подбору старых порогов не планируется.
- Скрипты `check_g26.py`, `audit_g26.py`, `report_g26.py`; evidence в
  `research/evidence/gba-g26/`, полный локальный report и Git-summary по policy.
  Host/UI, Linux/Thumb build, PPU/timing, summary и diff checks выполнены.
- Физическая GBA/original BIOS, полный live/spatial и release regression
  диагностических probes не выполнялись. Production SHA прежний;
  G21/BUG02, другие порты и оригиналы не изменены.

Далее сохранены исходные входы и критерии. H10 не входит в оптимизации
текущего релиза; ограничения модели не являются обещанием будущей задачи.

## Работа

1. На текущем layout построить модель Mode1/Mode2: DMA/VRAM/OAM, UI,
   background transport, foreground, режимные переходы и VBlank budget.
2. Отделить постоянную цену от успешного HW raster и CPU fallback.
   Сопоставить модель с существующими paired measurements; при необходимости
   добавить узкие instrumented probes, не выдавая их за production CPU.
3. Предложить конкретное изменение transport/размещения, устраняющее измеренную
   причину проигрыша. Показать вместимость памяти, UI и расписания DMA.
4. При отсутствии решения закрыть задачу отрицательной моделью и оставить H10
   условно отложенной. Не повторять grid/threshold/feedback на прежнем transport.

## Условие открытия native-опыта

Модель указывает реальную экономию и допустимое размещение без сокращения
резерва стеков/игровых правил. Только после этого оформить паспорт native
forced A/B, переходов и auto selection. Успех модели ещё не принятие рендера.

## Готовность и передача

В `docs/gba/` есть модель с единицами, источниками, проверенными фактами,
неопределённостями и решением «открыть native / не открывать».
Обновить паспорт, бэклог, аудит и GBA-handoff; следующий ID — G27.
Промежуточные данные — `build/gba/g26/`, доказательства —
`research/evidence/gba-g26/`, compact summary по report policy.
Нет фиксированного FPS gate; аппаратную приёмку не подменять моделью.
Оригиналы, статусы G21/BUG02, NDS/SDL2 не менять.
